# Dynamic Components

> See also the online doc [Components](https://openvaa.org/developers-guide/frontend/components) (or [locally](</apps/docs/src/routes/(content)/developers-guide/frontend/components/+page.md>))

This directory contains dynamic components used throughout the OpenVAA frontend application.

| Component                           | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ContactSupport`                    | A block that leads the user to support: an optional lead-in and one button. Its `action` is `'help'`, a link to the support section of the Help page, or `'email'`; `variant` and `iconPos`, the position of the button's icon, are passed to the button. It reads the app context: outside the Contestant App there is no Help page, and it always leads to an email.                                                                                                                                                                                                                                                                                                                                            |
| `EmailSentPanel`, `EmailSentResend` | The body of the "email sent" screen and its one action. The body is fixed sentences chosen by its `wording`, the address the user typed in bold in the first of them, a support sentence whose words are the link, the action it is given and a polite status region; it shows nothing the server answered. The action is a "Send again" button whose label ends with the seconds left; it is unavailable, and still a tab stop, while seconds are left or a request is in flight; it also serves the "Send again" of an address awaiting its confirmation link, under test ids its caller gives. The class `ResendCountdown`, exported beside them, computes the seconds from the time the last request settled. |
| `LogoutButton`                      | The one Log out of both apps, given the app's own sign-out. It opens a modal first when the app passes a warning of what is left undone or the page holds unsaved changes, and logs out at once otherwise. The Contestant App passes its warning from its own context and its sign-out navigates; the Admin App passes the login to leave to after a sign-out that worked.                                                                                                                                                                                                                                                                                                                                        |
| `GateOutlet`, `SetPasswordGate`     | The protected layouts' gate outlet, which renders the view of the gate the server load reported in place of the page and moves focus to it when it replaced another view without a navigation, and the set-password view both apps show a user whose account has no password. Each app's wrapper passes the view its address, its `setPassword` and its Log out.                                                                                                                                                                                                                                                                                                                                                  |

For auto-generated component documentation, see the [generated components documentation](https://openvaa.org/developers-guide/frontend/components/generated).
