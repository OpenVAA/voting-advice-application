<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| downstream repo file → upstream build | `instance/staticSettings.json` is authored in a downstream repository and read by the app-shared build; it is trusted repo content but must not be able to break invariants upstream owns |
| build-time settings → browser | merged values are inlined into the client bundle and later into CSS and HTML attributes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-191-01 | Tampering | resolveStaticSettings / mergeSettings | mitigate | `mergeSettings` skips `__proto__`/`constructor`/`prototype`; `z.strictObject` at every level rejects unknown keys; unit case with a JSON `__proto__` key asserts no pollution |
| T-191-02 | Tampering (CSS/attribute injection) | colours, font.name, font.url, logo.url | mitigate | `HexColorSchema` six-digit hex only; `FontNameSchema` restricted charset; `AssetUrlSchema` same-origin path or `https:` only, no quotes/brackets/parentheses/whitespace/`..`; each has rejection cases |
| T-191-03 | Elevation / config drift | dataAdapter | mitigate | `resolveStaticSettings` rejects any `dataAdapter` key before merge, so `assert:hosted-settings-parity` and the probe keep reading the true `pageSize` |
| T-191-04 | Denial of service (build) | JSON.parse of overlay | accept | a malformed file fails the build loudly with the file named; that is the intended behaviour, not a vulnerability |
| T-191-05 | Information disclosure | path override | mitigate | the overlay path is fixed (`../../instance/staticSettings.json`), no env override; tests inject paths through the factory only |
</threat_model>
