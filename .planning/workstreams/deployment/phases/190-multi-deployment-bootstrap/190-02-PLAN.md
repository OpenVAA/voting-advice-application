<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub event (ref, repository id) -> resolver | The ref is chosen by whoever pushes; the repository id is set by GitHub |
| map JSON -> workflows | The map is reviewed upstream data; a typo targets the wrong stack |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-190-05 | Spoofing | resolver ownership | mitigate | entries filtered by `github.repository_id` (numeric, set by GitHub); a downstream entry in the upstream file is inert upstream and the other way round |
| T-190-06 | Elevation of privilege | dynamic environment name (RESEARCH Pitfall 9) | mitigate | resolver exits 1 on no match or ambiguity, so no later job names an environment not in the map |
| T-190-07 | Tampering | branch-name injection | mitigate | ref passed to jq by `--arg`, never interpolated into shell or jq source; values reach workflows only through `env:`/outputs |
| T-190-08 | Tampering | malformed key reaching paths | mitigate | key regex `^[a-z][a-z0-9-]*$`, length <= 15, and root directories must exist |
| T-190-09 | Information disclosure | map parse errors | accept | the map holds no secret; output is still suppressed on parse failure |
</threat_model>
