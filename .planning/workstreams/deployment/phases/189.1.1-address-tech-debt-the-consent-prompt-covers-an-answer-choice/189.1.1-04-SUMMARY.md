## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The precondition honours omit_environment**
- **Found during:** Task 1
- **Issue:** The plan's action read SHUTDOWN_TIMEOUT from `local.environment_values` with a default of 30. That map keeps a value the root gives even when `omit_environment` drops it from the task, so the run "44 with SHUTDOWN_TIMEOUT omitted refused" would have passed the check (25 + 15 <= 44).
- **Fix:** `local.shutdown_timeout` reads 30 when `omit_environment` names SHUTDOWN_TIMEOUT, and otherwise `lookup(local.environment_values, "SHUTDOWN_TIMEOUT", "30")`. It lives in `main.tf`, beside `environment_values`, a file not in the plan's list.
- **Files modified:** infra/modules/frontend-service/main.tf
- **Commit:** fa6e6b6d5

## Issues Encountered

- **x86 Terraform under Rosetta.** `/usr/local/bin/terraform` is now Homebrew's x86_64 1.17.2, installed 2026-11-23 17:35. The plugin cache holds only `darwin_arm64` providers, so every init installs the 862 MB `darwin_amd64` AWS provider.
  - Without `GODEBUG=asyncpreemptoff=1`, that provider either timed out starting (`could not create provider instance: timeout while waiting for plugin to start`, twice) or spun at 100% CPU inside Rosetta for 14 to 20 minutes until it was killed (twice).
  - With the variable set, `plan-examples` finished in 24 seconds.
  - Every green result above was made with it. An arm64 Terraform would remove the need. This is the operator's toolchain, so it was left as is.
- **`validate` in the main checkout fails before reaching this plan's files.** `infra/bootstrap/.terraform/terraform.tfstate` caches the S3 backend. With Terraform 1.17.2, `init -backend=false` still asks for AWS credentials (`No valid credential sources found`), and no workstation credential is set. `infra/envs/staging/supabase` hit the same error during the lock regeneration's init, though its `providers lock` succeeded.
  - CI starts with no `.terraform` directory, so `validate` was run in a clean copy of the tracked tree (`git ls-files infra scripts/lib`, working-tree content), where all 8 roots validated.
  - No local `.terraform` directory was touched beyond the one init created in the scratch root and the removal of that one.
- **One registry timeout** during a `plan-examples` init (`registry.terraform.io ... Client.Timeout exceeded`). The registry answered 200 straight after, and the rerun was green.
