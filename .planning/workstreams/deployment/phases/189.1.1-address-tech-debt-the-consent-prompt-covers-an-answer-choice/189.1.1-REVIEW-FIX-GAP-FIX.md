  - `expectOnHome(entity: EntityGrantTarget)` in `contestantEntityPages.fixture.ts`
  - `expectLanded(entity: EntityGrantTarget)` in `contestantEntityHomePage.fixture.ts`

  Two of them also look up the entity's id with the service role. `expectHomeAfterSignIn` waits for any entity home, `contestantHomeUrlRe()`.
- **Not registered.** `fixtures/contestant/contestant-journey.ts` registers none of those three fixtures.

Removing the helper would mean registering another fixture in the journey and resolving its candidate as an entity target. That adds code and does not remove any duplication. The review's other option, a new hard step on `contestantHomePage`, adds a method rather than reusing one, so it is left for a decision.

**Original issue:** The helper waits for `contestantHomeUrlRe()` within `SIGN_IN_REDIRECT_TIMEOUT` and then for the home's status message within `slowPage`. Three fixtures already do the same. The journey's own `contestantHomePage.expectStatusMessage()` is still the soft check with a 5 s timeout. It is safe only because its remaining caller settles the URL first.
