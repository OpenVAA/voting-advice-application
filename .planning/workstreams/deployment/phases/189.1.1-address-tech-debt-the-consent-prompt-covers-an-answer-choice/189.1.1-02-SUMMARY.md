## What changed

- `handleEscape` in `ModalContainer.svelte` now starts with `if (modalContainer?.querySelector('dialog[open]')) return;`. A modal opened inside this one takes the Escape, and this one closes on the next. The docblock's Accessibility list states the rule, and so does the generated docs page.
- A new unit case mounts an outer ModalContainer whose `children` (a `createRawSnippet`) mounts an inner ModalContainer in its `setup`. It opens both and presses Escape twice. After the first press the outer's `onClose` has not run, the outer is open, and the inner is closed with its `onClose` run once. After the second press the outer is closed and its `onClose` has run once. `mountOpen` takes an optional `children` parameter.
- `tests/tests/deployed/voter.smoke.ts` now runs `createResultsPage(page)`, `expectPageVisible()` and `getEntityCards().first()` after `toHaveURL(/\/results/)`. It no longer reads `testIds.voter.results.*`. The `testIds` import stays, because the question heading still uses it. `resultsPage.fixture.ts` is unchanged.

## Task 1: the mechanism, measured

Research A9 assumed that `stopPropagation` does not stop another listener on the same target, so that one Escape would close both modals. The red run showed otherwise. In Svelte 5.57.1, `node_modules/svelte/src/internal/client/dom/elements/events.js` (`target_handler`) calls the handler only `if (!event.cancelBubble)`. The outer listener was registered first, so it ran first, closed the outer and called `stopPropagation`, and the inner's handler was then skipped. Before the guard, one Escape closed the outer modal and left the inner dialog open inside it. That is still the consent-decline defect, so the guard is needed.

The prohibition says the guard holds in either listener order, and it does:
- Outer listener first: the outer defers to the open inner dialog.
- Inner listener first: the inner closes and sets `cancelBubble`, so Svelte skips the outer's handler.

That second red is the one quoted above. Both red runs came before the guard.
