## Task results

**Task 1 (tracer, tdd).**
- **The helper.** `nonTextContrast.ts` computes `contrastRatio` (WCAG relative luminance). `measureBorderContrast` returns 1 for a border with no width or no style. Otherwise it composites the ancestor backgrounds, up to the first opaque one, on a 1x1 canvas, paints the border colour over them and reads both pixels back. The unit test (3 cases: 21, 1, 4.48) passed on its first run.
- **Red on the unchanged CSS.** Each red run failed only its new test, with `Expected: >= 3` / `Received: 1` and annotations `light=1.00`, `dark=1.00`:
  - `tests/e2e-runs/189.1.1-08-red-a11y-20261124T140840Z`: 44 passed, 1 failed.
  - `tests/e2e-runs/189.1.1-08-red-tracking-20261124T141009Z`: 23 passed, 1 failed.
  - Both `--failed-test ... --failure-contains 'Received:    1'` verdicts exited 0, with 0 did-not-run.
- **The fix.** One rule in the un-sublayered `@layer utilities` block of `app.css`, `:where(.checkbox) { border-width: 2px; border-color: var(--input-color, var(--color-base-content)); }`. Its comment says why it sits there: daisyUI's border lives in a nested utilities layer, and both themes set `--border: 0px`. `--input-color` is not set anywhere.
- **Green after.** `...-green-a11y-20261124T141147Z` passed 45 and `...-green-tracking-20261124T141314Z` passed 24.
- **Tracer gate.** I re-ran the plan's `<verify>` and it exited 0.
