## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The stub sends `access-control-allow-origin: *` and holds only one request**
- **Found during:** Task 1, the first run (exit 1, `shutdown_inflight_status=error: socket hang up`, `shutdown_inflight_exit=running`)
- **Issue:** the plan's stub answered every request with `[]` after 1500 ms. A diagnostic start outside the script showed two causes, neither of them the server's. Without the CORS header, SvelteKit's server fetch refused each cross-origin answer and postgrest-js retried it with a 1, 2 and 4 s back-off. Adding the header stopped the retries, which confirms the cause by A/B. Even with the header, the page's loads call the stub in three sequential rounds, so holding each request kept `GET /` open for about 5.2 s. That is past `SHUTDOWN_TIMEOUT` (3), where adapter-node closes every connection.
- **Fix:** the stub sends the header PostgREST sends, and the in-flight leg arms it to hold only its next request for 1500 ms.
- **Files modified:** scripts/check-shutdown-exit.mjs
- **Commit:** af96eb126

**2. [Rule 2 - Robustness] A warm-up request before the in-flight leg's measured request**
- **Found during:** writing the summary, while weighing the CI runner's speed (about 4.3 times slower on E2E)
- **Issue:** the measured request was the server's cold first render, about 565 ms beyond the stub's hold. The response must end within 3.3 s of the request, so that cold render was margin a slower runner could spend.
- **Fix:** one unsignalled `GET /` first. The measured request then took 1525 ms, of which 1500 were the hold.
- **Files modified:** scripts/check-shutdown-exit.mjs, evidence/189.1.1-10-checks.md
- **Commit:** 961441dbb

**3. [Note] The step-order case uses the test's existing line reader.** The plan said "the repo's YAML parser, as other tests here read workflows". `deploymentChecksWiring.test.ts` reads `main.yaml` with its own `jobRuns`/`jobLines` for every other case, so the new case does the same.
