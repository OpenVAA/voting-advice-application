The corrected premise. In the installed Playwright an input action waits for the document navigation it starts, through its redirects, so a hold on any hop of the sign-in chain was absorbed by the click and the helper's wait then passed at once (attempts 1 and 2, both green). What reaches a URL wait is only the part of a chain the action leaves unanswered. That part is all of a client navigation, which the action never waits for. For a document navigation it is whatever is left when a same-document navigation on the old page releases the action early. The unplanned red is the second case: its trace records the click released on a navigation event naming the sign-in screen's own address, 515 ms before the post's 303, by a source not established.
