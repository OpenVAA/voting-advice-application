### `DataConsentPopup.svelte` (component, event-driven)

**Analog:** `apps/frontend/src/lib/dynamic-components/dataConsent/DataConsentInfoButton.svelte` — the only Modal in this directory; same title key.

Imports / ref:
```svelte
<script lang="ts">
  import { Modal } from '$lib/components/modal';
  import { getAppContext } from '$lib/contexts/app';
  ...
  const ctx = getAppContext();
  const { t } = ctx;
  let modalRef: Modal;
</script>
```
Modal + close via ref (keep the `<!-- bind: keep — ... -->` comment convention):
```svelte
<!-- bind: keep — modalRef is plain let Modal; single ref read in onclick -->
<Modal bind:this={modalRef} title={t('common.privacy.dataCollection.title')}>
  ...
  {#snippet actions()}
    ... onclick={() => modalRef?.closeModal()} ...
  {/snippet}
</Modal>
```
Today's body to preserve (current file, `<Alert bind:this={alertRef} ...>`): the `gap-md grid grid-flow-row` wrapper with `dynamic.privacy.dataConsentIntro.popup` and `<DataConsentInfoButton class="!inline" />`, and `<DataConsent onChange={...} description="none" />` in `actions`. Change: `onChange` sets a `chosen` flag then `modalRef?.closeModal()`; `onMount(() => modalRef?.openModal())` (ModalContainer has no auto-open); `onClose` handler calls `setDataConsent('denied')` when `!chosen` (D-02, D-18: Escape, ✕ and backdrop all decline), then forwards the caller's `onClose`. Keep `closeOnBackdropClick` default `true`. `t` and `setDataConsent` are stable refs (safe to destructure); never destructure `userPreferences`. Switch from `getComponentContext` to `getAppContext` (needed for `setDataConsent`; root layout renders it inside `appCtx`). Update the `@component` docblock (no longer "an `<Alert>`").

Anti-pattern: no own `keydown` listener in the popup — everything goes through ModalContainer's `onClose`.

## Shared Patterns

- **Red-before-green guards (WR-03):** every new guard ships with the mutation that defeats it shown red — `mutate()` in `deploy-workflow.test.ts`, `expect_failures` runs in tftest, unguarded `handleEscape` for the nested-Escape test, pre-fix CSS for the contrast assertion.
- **Consent decline path:** `setDataConsent('denied')` from `getAppContext()` is the single writer; it resets the tracking buffer and emits no event, which is D-05's observable. All dismissals route through ModalContainer's `onClose`.
- **jsdom dialog polyfill:** `ModalContainer.svelte.test.ts` `beforeAll`/`afterAll` — reuse in any test mounting a Modal.
- **Evidence:** `KEY=value` lines in the phase `evidence/` (before-state keys from `.planning/todos/pending/2026-11-21-voter-consent-prompt-covers-an-answer-control.md`: `A11Y_VIEWPORT`, `A11Y_FINDING`, `A11Y_ESCAPE_CLOSES`, `A11Y_CENTER_HITS_DIALOG`).
- **Comment hygiene:** no historical narrative or planning refs in touched comments (e.g. rewriting the `grantConsentViaPopup`/`dismissConsentPrompt` docblocks and the deploy.yml TLS comments).
- **E2E:** targeted per-project runs within the phase; one full suite at the end vs 729 passed.
