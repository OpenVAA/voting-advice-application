## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| dashboard download → repository | The Supabase root CA enters the tree here as the trust anchor | Trust anchor (integrity-critical) |
| GitHub runner → session pooler | The migrations and settings steps authenticate after the TLS handshake under verify-full | Database password, schema |
| operator's shell → hosted staging database | The destructive reset and the privileged writes (bootstrap, grants) | Service credentials, all staging data |
| approved job → hosted project and AWS stack | Writes that only a later commit can follow | Deployments, hosted settings |
| ci-evidence branch → Actions runner | The commit's own workflow file runs | Source tree (no `.planning/`) |
| keyboard input → stacked modal dialogs / drawer | One Escape reaches every open ModalContainer / DrawerHost listener and the browser's own handling | Consent decision |
| modal dialog → the page under it | The top layer must keep the page unreachable while a choice is pending | Consent decision |
| browser localStorage → consent state | The stored decline keeps the prompt closed and limits what is sent | Analytics consent |
| candidate → consent controls of the terms view | A control the candidate cannot see is a choice they cannot make | Analytics opt-out |
| service role → privileged RPCs | Only the service role may take a caller slot | Rate-limit state |
| migrations → schema/ | Two sources of one database, tied by the equivalence check | Schema |
| ECS stop signal → server process | A kill before the drain ends cuts requests and the analytics flush | In-flight requests |
| planning record → external reviewer | The relay legal brief leaves the team; what it says is relied on | Prose only |
| public REST API / runs → evidence | Read-backs and logs that must not carry keys, hosts or addresses | Sanitised evidence |
| committed lockfile → node_modules | The install reads only what `yarn.lock` already pins | Dependencies |

## Residuals and Warnings (unregistered, non-blocking)

These came up in the audit but are not register rows and do not count toward `threats_open`.

- **R-1: the Supabase CLI connection under verify-full (assumption A5; residual on T-17, T-19, T-34). RESOLVED 2026-11-27, and observed in the pipeline the same day (deploy run 45960590610).** A local measurement against a TLS Postgres with throwaway CAs (`evidence/189.1.1-A5-cli-tls.md`, script `evidence/189.1.1-A5-cli-tls.sh`) showed what the pinned CLI 2.118.0 does on `--linked`:
  - On its pooler path it honours `PGSSLMODE`/`PGSSLROOTCERT`: it refuses a wrong root, the committed root against a server it did not sign, and a wrong host. This is the path the runner took, since the staging direct host is IPv6-only.
  - On its direct path, taken whenever `db.<ref>.supabase.co:5432` accepts a TCP connection, it verifies nothing under `verify-full`.

  **Fix:** `infra/scripts/push-migrations.sh` now gives the CLI `--db-url` built from the `PG*` variables, never `--linked`. That address holds no password, sslmode or sslrootcert, so the CLI verifies exactly as psql does; it refuses an address that does not name the project. `push-migrations.test.ts` is 39/39 (19 red against the previous script), and the `--db-url` measurement refuses all three bad cases, even with the direct host reachable. **Observed:** deploy run 45960590610 of `804835bbf` printed `push_connection=pooler`, `push_up_to_date=yes` and `drift_status=0` in "Push the migrations" (`evidence/189.1.1-R1-deploy.md`).
- **W-2: the pooler host and two IPv4 addresses were unsanitised in `189.1.1-RESEARCH.md`. RESOLVED 2026-11-27:** the file now reads `POOLER` and `ADDRESS` under the evidence convention, with a note at its head. Earlier commits still hold the old text on the public branch; history is not rewritten. Impact stays low: the host is in committed source (`infra/scripts/check-drift.test.ts`, `probe-hosted.test.ts`), and the addresses are public DNS answers. The same host also appears in other phases' records (184-04-PLAN, 184-20 evidence, 189.1-REVIEW-FIX); those are outside this phase and left as they are.
- **W-3:** the review-fix commits 9e87109df..085a96df5 came after the T-58/T-64 closure check. Two fixtures the deployed smoke imports now import named timeout constants besides `TIMEOUTS`. The diff is values and comments only, and the deployed-smoke guards pass 20/20. The smoke ran on staging over these fixtures in deploy run 45960590610 and passed (`evidence/189.1.1-R1-deploy.md`, `W3_SMOKE_ON_STAGING=passed`).
- **W-4:** 15 of 22 SUMMARYs have no `## Threat Flags` section. The audit found no new surface beyond R-1 and W-2.
- **I-5:** the operator ran the `identity_provider` restore (`evidence/189.1.1-12-restore-idp-mode.sh`) under a recorded ruling, but it was not bound through `attempt.sh`. It is outside T-31.
