### The first design run, not evidence of the tree

The first run used a stub that held every request for 1500 ms and sent no `access-control-allow-origin`. It exited 1 with `shutdown_inflight_status=error: socket hang up` and `shutdown_inflight_exit=running`. A diagnostic start outside the script showed why, and neither cause is the server's: SvelteKit's server-side fetch refused each cross-origin `[]` without the header, so postgrest-js retried it with its 1, 2 and 4 s back-off; and the page's loads call the stub in three sequential rounds, so holding each request kept `GET /` open for about 5.2 s even with the header, past `SHUTDOWN_TIMEOUT` (3), where adapter-node closes every connection. The stub now sends `access-control-allow-origin: *`, as PostgREST does, and holds only the first request after the in-flight leg arms it.

One observation from that run, outside this plan: after adapter-node closed the connection at `SHUTDOWN_TIMEOUT`, the abandoned render kept retrying its loads, and the process stayed alive until they ended. A render that outlives `SHUTDOWN_TIMEOUT` therefore holds the process for as long as its own upstream calls take; the check's in-flight leg holds one request for 1.5 s, inside the timeout, and does not measure that case.
