## Deviations from Plan

**1. Plan 21's unplanned red and its fix.** The input red is `tests/e2e-runs/189.1.1-21-contestant-entity-selection-20261125T202703Z`. In it the sign-in helper's 10 s wait ran out with the chain in flight, and 48 tests did not run. It is fixed by `5b924d557` (`INPUT_UNPLANNED_RED_FIXED_BY=`). Its record stays under plan 21's `TARGETED_RED_1_` and `UNPLANNED_RED_RUNS=` lines.

**2. The first execution's two green attempts and the corrected premise.** The first execution (83d5b2dab) held the post twice, and both runs were green, because a click waits for the document navigation it starts. The operator re-planned on 2026-11-26 (option B). This execution adds the same-document release the unplanned red's trace records, and the planned red then reproduced at once.

**3. The hold on the post in place of the redirected document.** A redirected request is never routed in Playwright 1.63 (`REDIRECT_NOT_ROUTABLE=`). The scratch therefore holds `POST /contestant/login/email`, the first request of the same chain (`SCRATCH_DELAY_TARGET=`).

**4. [Rule 3] Two representative projects were not practical.** The admin-access and contestant-identity-provider runs pulled in the perm chain (602 and 629 tests), because their setups stand behind it. Those runs are recorded under `REP_RED_ATTEMPTS=`. The closure was then read through `tsx` and only practical projects were used: the admin representative moved to admin-account-flows (the last test of its serial describe), and the identity provider's three files got `NO_REP_` lines.

**5. [Rule 1] `AUDIT_A9` (`expectSaysLinkFailed`) is in practice settled.** `pressContinue`'s own poll waits until the address has left the confirm page. Its committed line keeps `client-nav` and the swept 20 s budget, which changes no passing run. A note was appended (`AUDIT_A9_NOTE=`) rather than rewriting a committed line.

**6. The representative verify's timeout pattern.** Task 2's second verify, as written, exits 1 on REP_2 alone. Playwright prints a predicate expectation's timeout as `Timeout:  10000ms` (two spaces), and the check's `new RegExp("Timeout:? "+o+"ms")` takes one space. Every practical wait of contestantLoginPage.fixture.ts is a predicate. With that one pattern written `Timeout:?\s+`, the whole verify prints `REPS=5 RED_RUNS=3 HELPER_FILES=8 INLINE_FILES=3 OK`, trace checks included. This is recorded as `TASK_2_REP_VERIFY_AS_WRITTEN=` and `TASK_2_REP_VERIFY_WITH_WHITESPACE=`. The plan file was not edited (prohibited); the plan's owner should widen the pattern.

**7. The REP_5 scratch hash.** contestant-journey.spec.ts is changed by the sweep, so the regenerated `git diff` of its re-applied scratch hashes differently. It differs only in its `index` line and hunk offsets. The recorded hash is that of the one saved diff file applied in both runs.
