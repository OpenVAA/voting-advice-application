  <action>
    Per D-10 and D-14. Create `build-push-image.sh` (executable). Flags: `--repository-url <url>` REQUIRED; `--platform <p>` OPTIONAL, default `linux/arm64`; `--self-test`; `-h`. Environment: `OPENVAA_ACCOUNT_ID` (default `471112560111`), `AWS_REGION` (default `eu-north-1`). Order of checks, each refusal printing one `refused=<reason>` line and exiting 1: `dirty-tree` (`git status --porcelain` not empty); `not-a-commit-id` (`git rev-parse HEAD` not 40 lower-case hex); `head-not-pushed` (no line of `git ls-remote origin` carries the HEAD id); `account` (`aws sts get-caller-identity --query Account --output text` fails or differs; the line names the expected account only). Then `aws ecr describe-images --repository-name <name from the URL> --image-ids imageTag=<sha>`: when it finds the tag, print `tag_exists=yes image_digest=<digest>` and exit 3. Otherwise log in with the password piped from `aws ecr get-login-password` into `docker login --username AWS --password-stdin <registry host>`, run `docker buildx build --platform <p> --target production --build-arg BUILD_SHA=<sha> --provenance=false --sbom=false -f apps/frontend/Dockerfile -t <url>:<sha> --load .` from the repository root, `docker push <url>:<sha>`, read the digest back with `describe-images`, and print `image_tag=<sha>` and `image_digest=<digest>`. Exit 0 pushed, 1 refused or failed, 2 usage, 3 tag exists. A failing build or push prints `failed=<step>`.

    `--self-test` builds a temporary bare repository as `origin` and a clone, and checks: a dirty clone is refused with `refused=dirty-tree`; a clean clone with an unpushed commit is refused with `refused=head-not-pushed`; a clean, pushed clone passes the three git checks and stops before any AWS call (the self-test sets `AWS` and `DOCKER` command variables to a stub that fails the test if called beyond the account check, and a stub account of `000000000000` makes the script print `refused=account`). Each case prints `self_test <name> PASS|FAIL`; the status is 0 only when all pass.

    Create `build-push-image.test.ts` in the infra suite: spawn `bash infra/scripts/build-push-image.sh --self-test` from the repository root and expect status 0 and every case `PASS`; spawn it with `--bogus` and expect status 2.

Each request is `curl -sS -o /dev/null -w '%{http_code}' --max-time 10 <url>`, its status read directly. On a stop file, the end of the duration or SIGTERM/SIGINT, it prints `requests=<n> non_2xx=<m> first_utc=<t> last_utc=<t>` and exits 0 when `m` is 0, 1 otherwise; 2 on usage. Each case prints `self_test <name> PASS|FAIL`. Create `request-loop.test.ts`: spawn the self-test, expect status 0 and no `FAIL`.
