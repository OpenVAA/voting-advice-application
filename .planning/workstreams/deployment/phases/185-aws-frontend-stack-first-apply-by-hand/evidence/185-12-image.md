## The refused second push (Task 2)

Recorded 2026-11-12 (UTC), 21:07 to 21:09.

```
SECOND_PUSH_EXIT=1
SECOND_PUSH_REFUSED=yes
DIGEST_UNCHANGED=yes
SCRIPT_TAG_EXISTS_EXIT=3
```

The refusal, as the push printed it (it names no registry host; `<registry>` stands where the push's
first line named it):

```
tag invalid: The image tag '712947a1bd44a735f66ee8f51610f4748d76cd30' already exists in the 'openvaa-frontend' repository and cannot be overwritten because the tag is immutable.
```

- **The second image.** A two-line Dockerfile, `FROM <registry>/openvaa-frontend:<sha>` and
  `LABEL org.openvaa.check="second-push"`, built with `--provenance=false --sbom=false` and tagged
  `<registry>/openvaa-frontend:<sha>` (exit 0). Its image id differs from the first image's, so its
  manifest is a different one.
- **The push.** `docker login` with the password from `aws ecr get-login-password` on standard input
  (exit 0), then `docker push` of that tag, exit 1. The push log
  (`The push refers to repository [<registry>/openvaa-frontend]`) lists all 15 layers as
  `Layer already exists`, and its last line is the refusal above, which names the tag's immutability.
  `docker logout` exit 0.
- **The tag afterwards.** `aws ecr describe-images --image-ids imageTag=<sha>` exit 0 reads the digest
  `sha256:bab8fa75c6094a2cecab07282826bffa4d9746bf7ee56fc7231b8283ea937bea`, equal to `IMAGE_DIGEST`
  (`test` exit 0), and the repository still holds one image.
- **The script again.** `build-push-image.sh --repository-url <registry>/openvaa-frontend` from the
  same worktree (still clean) exit 3, printing
  `tag_exists=yes image_digest=sha256:bab8fa75c6094a2cecab07282826bffa4d9746bf7ee56fc7231b8283ea937bea`
  and on standard error that the registry already holds the tag and nothing was built.
- **Clean-up.** The derived image's local tag removed (exit 0), then the first image, which the
  derived one had left untagged and whose `BUILD_SHA` is the commit id, removed by its image id (exit
  0). The worktree removed (`git worktree remove --force`, exit 0, no longer listed), and the log
  directory `$L` removed. The registry's copy is untouched.

Two runbook lines were corrected on the way, both in Step 4 of the staging AWS runbook:

- Item 4's pushes now write `"${SHA}:refs/heads/$B"`. Written `"$SHA:refs/heads/$B"`, zsh reads
  `:r` as a modifier and drops it, and the first push was refused with `src refspec <sha>efs/heads/…
  does not match any` (exit 1, nothing pushed).
- Item 8 now searches the push log for `tag invalid|immutable`. Its pattern
  `immutable|already exists` matched the first `Layer already exists` line instead of the refusal.
