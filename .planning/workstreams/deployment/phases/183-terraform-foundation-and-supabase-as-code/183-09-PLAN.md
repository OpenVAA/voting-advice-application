<objective>
Build the guard that fails `yarn lint:check` when Terraform under `infra/` attaches an inline IAM policy, wire it, cover it with a spec, and record it failing.

Purpose: INFRA-17's repository half ("a check in the repository fails on an inline user policy, seen once"). This plan sees the guard red by running it against a fixture root. Plan 183-13 sees it red through `yarn lint:check` itself with a planted file, and plans 183-14 and 183-17 cover the account half.
Output: the guard, its fixtures, its `lint:check` link, its gate spec, and a dated red-control record.

Decisions this plan takes, from the pattern map's open points:
- How the file set is found: a directory walk with `readdirSync`, not `git ls-files`. A planted, uncommitted file must be a finding, and a walk makes `--root <dir>` trivial. The walk skips directories named `.terraform`.
- Comments: no comment blanker. A comment that names a banned form is a finding; the header says so, and `infra/` comments say "an inline policy".
- Fixture form: a directory, `scripts/fixtures/no-inline-iam-policies/`, with a clean root, a violating root and the expected findings.
- How the spec exercises the guard: as a child process, so the guard exports nothing and no copy of it is made.

Decisions implemented: D-08 (the guard, its banned forms and its self-test), A-01 (the permission-set form and the exclusive-policies rule).
</objective>
