<objective>
See both new guards fail through `yarn lint:check` itself, each as its own recorded step, without a planted file ever existing in the checkout that three phases share; then see the three repository gates on the finished tree.

Purpose: the roadmap's wording for both guards is that `yarn lint:check` fails, seen once (criteria 2 and 5). Plans 183-09 and 183-26 saw the guards fail when run directly. This plan closes the gap between "the guard fails" and "the chain fails because of it".
Output: one evidence file.

The red controls run in a throwaway `git worktree` under `$TMPDIR`, made from a commit that already holds both guards. The order is fixed: the guards are committed first, then the scratch checkout is made from that commit. A violation is planted only there. The shared checkout is never changed by a red control, so no other phase's executor can pick a planted file up, commit it or trip over it.

The plan has one checkpoint, raised only in one case: `yarn lint:check` is red at a link that is not this phase's, so the chain cannot reach the new guards. The plan then records what it can see directly and stops for the operator instead of leaving INFRA-17 and SUPA-11 without their observation.

Apart from that checkpoint, the plan can end without finishing in one more way, which needs no operator: when a whole-repository gate finds another phase's uncommitted tracked change, the task ends with a blocked result returned to the orchestrator, which re-runs it once that work is committed.

Decisions implemented: D-08 and D-13 (each guard seen failing through `lint:check`).
