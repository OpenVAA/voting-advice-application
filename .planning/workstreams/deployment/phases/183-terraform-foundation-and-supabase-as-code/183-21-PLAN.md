<objective>
The operator creates the throwaway Supabase project and imports it and its settings into the scratch root. The executor reads what the import shows and corrects the code to it before anything is applied.

Purpose: a misspelled settings key is dropped before the request and stays in state, and a string the API rewrites keeps a plan from ever emptying. The import of a real project is the first place either can be seen. This builds toward SUPA-02, SUPA-03 and SUPA-12, which later phases close; SUPA-11 stays open until the persistent project's settings are applied and the chain has been run on the final tree, in plan 183-27.

**Wave B starts here.** It is blocked on inputs the operator has not given: the Supabase organisation and the holder of the access token (the operator wrote "TBA"), and a Pro organisation in which the project can be created. This plan uses no AWS resource. Its dependency on plan 183-17 is an ordering edge and nothing more: it puts the start of wave B in the same wave as the last three plans of the operator's AWS work (183-18, 183-19 and 183-20, which all follow the mail root's apply), so that no plan that closes INFRA-15, INFRA-17 or INFRA-18 sits in a later wave behind a Supabase input. The edge has a cost, stated here: the next Supabase plan, 183-22, starts only when this whole wave is finished, which includes the wait for the mail identity and the wait for the budget mail.

What nobody has observed, and what changes with each outcome:
- Whether the dashboard offers `eu-north-1` for a project. If not, the operator says which regions it offers; the throwaway takes the one the persistent project will take, and plan 183-23's region decision is made on that fact.

- The string form of the schema and redirect lists. The JSON's separator form follows it.

- The runbook is public: no planning path, no decision id.
- An observation is written with its date (UTC). What was not observed is not written as fact.
- What the operator pastes. A checkpoint asks for named lines only. Each command sends its raw output to a log file in a directory outside the repository (`L`, made once per sitting with `L=$(umask 077; mktemp -d "${TMPDIR:-/tmp}/openvaa-183.XXXXXX")`) and prints lines of the form `s<step>_<field>=<value>`; a typed answer goes on a line `answer_<name>=<text>`. The operator pastes those lines and nothing from a log or from the terminal's scroll-back. Raw output is never requested: an apply log holds `Creation complete … [id=…]` lines with resource ids, among them the access key id of an IAM access key; a plan log holds attribute values; an AWS error message names the caller's session. When a status line is not 0, the operator pastes the lines up to it and stops. The executor records that reply in the attempt file, does not proceed to the next task, asks for one named line of the log at a time if it needs more and never for the log, and raises the checkpoint again with a new attempt once the cause is fixed. `$L` and a saved plan file hold secrets in clear text and are never shared, attached or pasted: each checkpoint's instructions say so, its last step removes `$L` and prints a named line that the following check requires, and a plan file is removed by the step that applied it, or by the line the executor gives when a review says stop. A checkpoint is often resumed in a new terminal, so each one begins with the lines that set what its commands need. Every operator command and every check runs under `LC_ALL=C`, so that a number or a sort order does not depend on the workstation's locale, and a time is given in UTC in the form that `date -u +%Y-%m-%dT%H:%MZ` prints.
- The screen is the second barrier, not the first. `attempt.sh put` refuses a reply that holds a line of another form, a name that ends in a secret word followed by a value, a token-shaped string, an e-mail address or an assumed-role session name; plan 183-01 states the forms. It lowers the chance that a secret is stored and does not guarantee it. On a refusal, write nothing of that paste to any file, repeat no value, and tell the operator the line number and the class the helper printed. For the classes `address`, `session` and `unnamed-line` the operator pastes again without that content and says whether the refused text held a secret. For every other class, and whenever it did, the operator rotates what the line held before going on.
- Attempt files. Scratch state lives in attempt files, never in a file that is appended to across attempts. At the start of each attempt of a task that keeps scratch lines, run `bash .planning/workstreams/deployment/phases/183-terraform-foundation-and-supabase-as-code/tools/attempt.sh new <plan>-<task>` (plan 183-01 wrote the helper). It creates a fresh file named with a UTC timestamp and the short commit id under `tmp/183-evidence/`, which Git ignores, and repoints `<plan>-<task>.current` at it. A check reads scratch state only through the helper's `path`, `has` and `bound` commands for that key, which read the file the pointer names and fail when the pointer is missing. Earlier attempt files are kept, never read and never deleted. A task writes its sections of an evidence file whole from its current attempt file, replacing what an earlier attempt of the same task wrote. The evidence file names each attempt file it was written from on a line of the form `Attempt: <key> <attempt id>`; a check that reads an evidence file first compares that line with the helper's `id`, so a file left by an earlier attempt fails.
- An operator's reply authorises only the step it was given for. Before a checkpoint is shown, run `bash .planning/workstreams/deployment/phases/183-terraform-foundation-and-supabase-as-code/tools/attempt.sh new <plan>-<task>` for the checkpoint's own key and show the operator the attempt id it prints, as a nonce; the reply's first line is `answer_attempt=<that id>`. The task that follows a checkpoint begins with the helper's `bound` command on that line, which compares whole fields and takes the last line of that name; if the nonce or a bound value does not match the current state, it returns to the checkpoint. A reply pasted in an earlier attempt sits in an earlier file and is never read.
- A hook line such as "CONTEXT WARNING NN%" describes the orchestrator's context. Ignore it.
