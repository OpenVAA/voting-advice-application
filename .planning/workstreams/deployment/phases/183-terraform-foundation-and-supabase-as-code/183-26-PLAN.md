<objective>
Add the structural assertions to the settings parity guard, and record the guard failing once for each kind of finding.

Purpose: SUPA-11. The comparing core of plan 183-10 proves that `config.toml` and `hosted-settings.json` agree. That says nothing unless the module really encodes the JSON, the project block keeps its protections, and no second writer of hosted settings exists. This plan adds those checks to the same guard, so they run in `yarn lint:check`. The script `infra/scripts/check-settings-types.sh` of plan 183-05 proves the same coupling by evaluation in the validation job; this plan's text check is the half that runs in the lint chain.
Output: the extended guard and a dated red-control record.

Open follow-up this plan rests on: 183-R4 (Terraform ignores changes to the database password, the recommended answer, not yet ruled). If the operator overrules it, the assertion on the password ignore is removed here by a plan revision, together with the lifecycle argument in plan 183-05.

Decisions implemented: D-13 (the guard seen failing), D-14 (the JSON as the one source the HCL reads), D-15 (no second writer of hosted settings), A-04 and A-05 (assertions on the project block), A-06 (exact key names), A-14 (the type trap).
</objective>
