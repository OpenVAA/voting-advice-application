    It also declares `aws_ecr_lifecycle_policy` named `frontend` on that repository, with its policy built by `jsonencode` and two rules: priority 1 expires untagged images older than `var.untagged_expiry_days` days (`tagStatus` `untagged`, `countType` `sinceImagePushed`, `countUnit` `days`); priority 2 keeps the newest `var.max_images` images (`tagStatus` `any`, `countType` `imageCountMoreThan`). With immutable tags every deployment adds an image, and this bounds the storage.

    `variables.tf` declares `repository_name` (string), `untagged_expiry_days` (number, default 7) and `max_images` (number, default 50). `outputs.tf` exports `repository_name`, `repository_arn` and `repository_url`.

    Write `infra/modules/registry/README.md`, a short public note saying what the module creates and stating one limit plainly. Tags are immutable, so every deployment adds an image, and the lifecycle policy keeps only the newest `max_images` images. An image older than that is expired and cannot be deployed again, so the number bounds how far back a rollback can reach. The default stays at 50 and the limit is recorded, not raised: whoever builds the deployment pipeline keeps `max_images` above the number of images pushed within the window a rollback must cover, or raises it. The note cites no phase. Format it with `node_modules/.bin/prettier --write`. Repeat the limit in the SUMMARY, addressed to phases 185 and 187.
