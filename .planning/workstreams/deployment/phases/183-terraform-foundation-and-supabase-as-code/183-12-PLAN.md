  <behavior>
    - `--self-test` feeds canned inventory lines to the evaluator and exits 0 when a clean set passes, a set with one user carrying an inline policy fails, and an empty set is reported as "nothing examined" where the mode requires at least one entity.
    - `--assert-no-inline-user-policies` exits 0 when no IAM user has an inline policy, 1 when one has or when the user list could not be read.
    - `--assert-managed-only <path-prefix>` exits 0 when every role and user under the path has no inline policy and at least one such entity exists, 1 otherwise.
    - With no argument it prints the full inventory and exits 0 unless a call that must succeed failed.
    - An unknown argument exits 2 with a usage line; `-h` and `--help` print the header.
    - Its output holds no e-mail address, no session name and no error text of a failed call, in any mode. `--self-test` feeds the collector's formatting canned input with an address in a user name, in a tag value, in an SES identity and in a caller ARN, and a user named like a person outside the path `/openvaa/`, and fails if any `@`, any session name or that user's name reaches the output.
  </behavior>
  <action>
    Write a bash script in strict mode with a header in the shape of the two analogs: one line on what it does, usage for each mode, an exit-code table (0, 1, 2), and three statements: every call is read-only; the script prints names and counts and no credential, so `set -x` must not be added; and its output is written to be pasted into a public record, so it prints no e-mail address, no session name and no error message of a failed call. It sets `AWS_PAGER` to empty and `LC_ALL` to `C`, so that its sorting and its output do not depend on the workstation's locale, and takes the account id and the region from `OPENVAA_ACCOUNT_ID` (default `471112560111`) and `AWS_REGION` (default `eu-north-1`).

    Separate collecting from judging. A collector prints one line per entity in a fixed form: `user <name> inline=[…] attached=[…] groups=[…] tags=[…]`, `group <name> inline=[…]`, `role <name> path=<path> inline=[…]`. An IAM user is printed by name only when it lies under the path `/openvaa/`, where this project creates its own service users and no person's account lives. Every other user is printed as `user-<n>`, with `n` its position in the order `aws iam list-users` gives: a user name is often a person's name or an e-mail address, and these lines go into a public record. The operator can tell which user a line means by running `aws iam list-users --query 'Users[].UserName'` on their own machine. The caller identity follows the same rule: an assumed role is printed as `assumed-role/<role name>`, an IAM user as the word `user`. A tag is printed by its key alone, except the tag `InvokedBy`, whose value is one of AWS's own words and is printed. An evaluator reads such lines on standard input and decides. That split is what lets `--self-test` run with no credentials.

    The full inventory prints, in order, the sections the research lists and nothing that is a secret: the caller identity as the account id and the role or user name, with the session name cut off and never the raw `Arn`; whether the account belongs to an organisation, as `yes` or `no` and nothing else, because that call also returns the management account's e-mail address (it fails in a standalone account, which is a normal answer, so capture its status instead of letting strict mode end the script); the account summary counts; every user, group and non-service-linked role with its inline policy names; the OIDC providers; the hosted zones with name, id, private flag and record count; for `eu-north-1`, `eu-west-1`, `eu-central-1` and `us-east-1` the SES account state, the domain identities by name with their verification status, and the identities that are e-mail addresses as a count only; the budgets with name, limit and actual spend; the image repositories in the region with their tag mutability; and the bucket names. A call that fails prints `error <section> <error code>` under its section heading, the code being the word in parentheses in the CLI's message (for example `AccessDenied`) and never the message, which names the caller's session, and the script goes on, except in the assert modes, where an unreadable user or role list is exit 1: a check that examined nothing does not report success.

    The assert modes print the offending lines and a one-line verdict on standard error.
