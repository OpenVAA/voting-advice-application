<objective>
The operator enters the delegation for `staging.openvaa.org` at Cloudflare; the executor verifies it from outside and writes down what was changed.

Purpose: INFRA-18 ("a Route 53 hosted zone serves `staging.openvaa.org`, and the records the operator must change at the current DNS host are documented") and the first sentence of criterion 4. This plan closes the observation of the zone answering; the mail identity's verification is plan 183-19.

Blocked on: plan 183-17 (the zone must exist and its name servers be known).

What nobody has seen yet, and how this plan handles each way it can go:
- That Cloudflare accepts NS records for a subdomain of this zone. Cloudflare documents it for zones on its own name servers, and public DNS showed on 2026-10-11 that this zone is one. If the dashboard refuses, the operator pastes the message and the plan stops for a revision of the delegation approach.
- That public resolvers answer soon. A resolver that cached the earlier `NXDOMAIN` can keep it for up to 30 minutes (the parent zone's negative-cache time). The check on the parent's own name server does not wait for that, and it is the one that decides.
Output: the filled delegation record and a dated evidence file.

Decisions implemented: D-05 (one NS record set at Cloudflare, nothing at or under the name, the records written down), A-12 (the parent zone is at Cloudflare and unsigned).
</objective>
