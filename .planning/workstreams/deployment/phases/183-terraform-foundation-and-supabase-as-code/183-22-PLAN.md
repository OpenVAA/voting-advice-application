Have the operator make and save the first plan after the throwaway project's import, and read it against the stop rules before any apply is asked for.

<execution_rules>
Binding on every task of this plan.
- The executor never applies and never holds a credential. It does not run `terraform plan`, `apply`, `import`, `state` or `show`, and does not call the Supabase API or CLI. The operator runs those and pastes output back.
- No apply is requested in this plan. The apply of the plan read here is plan 183-24's first task.
- The access token and the database password are never pasted and never recorded. A plan prints the password only as `(sensitive value)`.
- A plan that shows a destroy or a replacement of the project, or a change of its password, is never applied. That holds for the throwaway project too: the rehearsal exists to see the rule work.
- What the operator pastes. A checkpoint asks for named lines only. Each command sends its raw output to a log file in a directory outside the repository (`L`, made once per sitting with `L=$(umask 077; mktemp -d "${TMPDIR:-/tmp}/openvaa-183.XXXXXX")`) and prints lines of the form `s<step>_<field>=<value>`; a typed answer goes on a line `answer_<name>=<text>`. The operator pastes those lines and nothing from a log or from the terminal's scroll-back. Raw output is never requested: an apply log holds `Creation complete … [id=…]` lines with resource ids, among them the access key id of an IAM access key; a plan log holds attribute values; an AWS error message names the caller's session. When a status line is not 0, the operator pastes the lines up to it and stops. The executor records that reply in the attempt file, does not proceed to the next task, asks for one named line of the log at a time if it needs more and never for the log, and raises the checkpoint again with a new attempt once the cause is fixed. `$L` and a saved plan file hold secrets in clear text and are never shared, attached or pasted: each checkpoint's instructions say so, its last step removes `$L` and prints a named line that the following check requires, and a plan file is removed by the step that applied it, or by the line the executor gives when a review says stop. A checkpoint is often resumed in a new terminal, so each one begins with the lines that set what its commands need. Every operator command and every check runs under `LC_ALL=C`, so that a number or a sort order does not depend on the workstation's locale, and a time is given in UTC in the form that `date -u +%Y-%m-%dT%H:%MZ` prints.
- The screen is the second barrier, not the first. `attempt.sh put` refuses a reply that holds a line of another form, a name that ends in a secret word followed by a value, a token-shaped string, an e-mail address or an assumed-role session name; plan 183-01 states the forms. It lowers the chance that a secret is stored and does not guarantee it. On a refusal, write nothing of that paste to any file, repeat no value, and tell the operator the line number and the class the helper printed. For the classes `address`, `session` and `unnamed-line` the operator pastes again without that content and says whether the refused text held a secret. For every other class, and whenever it did, the operator rotates what the line held before going on.
- Attempt files. Scratch state lives in attempt files, never in a file that is appended to across attempts. At the start of each attempt of a task that keeps scratch lines, run `bash .planning/workstreams/deployment/phases/183-terraform-foundation-and-supabase-as-code/tools/attempt.sh new <plan>-<task>` (plan 183-01 wrote the helper). A check reads scratch state only through the helper's `path`, `has` and `bound` commands for that key, which read the file the pointer names and fail when the pointer is missing. Earlier attempt files are kept, never read and never deleted. A task writes its sections of an evidence file whole from its current attempt file. The evidence file names each attempt file it was written from on a line of the form `Attempt: <key> <attempt id>`; a check that reads an evidence file first compares that line with the helper's `id`, so a file left by an earlier attempt fails.
- An operator's reply authorises only the step it was given for. Before a checkpoint is shown, run `bash .planning/workstreams/deployment/phases/183-terraform-foundation-and-supabase-as-code/tools/attempt.sh new <plan>-<task>` for the checkpoint's own key and show the operator the attempt id it prints, as a nonce; the reply's first line is `answer_attempt=<that id>`. Store the reply with the helper's `put` command for that key, which writes nothing unless that line names the current attempt and the screen passes, under a first line `OPERATOR_REPLY=received attempt=<id> plan=<NN> task=<T> head=<commit id>` followed by the bound values the task names. `head` is the full forty-character id from `git rev-parse HEAD`, and every commit id and checksum in such a line is written in full, never shortened. The task that follows a checkpoint begins with the helper's `bound` command on that line, which compares whole fields and takes the last line of that name; if the nonce or a bound value does not match the current state, it returns to the checkpoint. A reply pasted in an earlier attempt sits in an earlier file and is never read.
- An observation is written with its date (UTC). What was not observed is not written as fact.
- A hook line such as "CONTEXT WARNING NN%" describes the orchestrator's context. Ignore it.
