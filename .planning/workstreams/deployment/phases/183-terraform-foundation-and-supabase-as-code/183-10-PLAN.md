<objective>
Build the comparing core of the guard that fails `yarn lint:check` when a security-relevant key of the local `config.toml` and the hosted settings in the HCL disagree, wire it, and cover it with a spec.

Purpose: SUPA-11. This plan writes the part that reads the channels, classifies every key and compares. Plan 183-26 adds the structural assertions (that the module really encodes the JSON, that the project block keeps its protections, that no second writer of hosted settings appears) and records the guard failing once per class. Plan 183-13 sees it fail through `yarn lint:check`. The requirement stays open until the hosted settings have been imported and applied and the chain has been run on the final tree (plans 183-21 to 183-27).
Output: the guard, one fixture, its `lint:check` link, its gate spec.

Decision this plan takes, from the pattern map's open points: the guard takes injectable paths. `--config <file>`, `--settings <file>`, `--static-settings <file>` and `--envs-dir <dir>` each replace one input, so the guard is seen failing without an edit to a real file. An unknown argument is exit 2.

Open follow-up this plan rests on: 183-R4 (Terraform ignores changes to the database password). It does not change this plan's comparing core; it changes one structural assertion of plan 183-26.

Decisions implemented: D-13 (every live key classified, `max_rows` three ways, three redirect entries, rate limits not compared), D-14 (Node built-ins, the JSON parsed, `config.toml` read by lines), A-06 (exact key names).
</objective>
