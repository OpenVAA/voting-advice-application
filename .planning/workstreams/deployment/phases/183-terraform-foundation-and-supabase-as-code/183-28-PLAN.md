<objective>
Write the runbooks of the zone and mail root and of the Supabase roots, and the file that will hold the delegation record.

Purpose: the operator runs every apply from a runbook the agent writes (D-10). `DELEGATION.md` is where INFRA-18's record of changed records is kept; it is a file of its own so that the delegation plan and the mail-identity plan, which run in the same wave, do not edit one file. The Supabase runbook carries the rules that protect the hosted project.
Output: two runbooks and `DELEGATION.md`.

One source for the commands. The checkpoint plans of this phase hold the exact commands, and they are on disk in their final form when this plan runs. The runbooks transcribe them, and each task's second check fails when a command of those plans is missing from its runbook. If a checkpoint plan is revised after this plan has run, the same check is run again and the runbook is brought back in line before the operator is asked to act.

Open follow-ups the runbooks' steps rest on, each on its recommended answer and not yet ruled: 183-R3 (the DMARC report address), 183-R4 (Terraform never sends the database password), 183-R5 (the SMTP settings are applied in phase 184, so no runbook step here applies them). None of these ids is written into a runbook.

Decisions implemented: D-05 (the record of the records changed at the parent zone), D-06 (the mail identity's steps and the production-access request), D-10 (a runbook the agent writes, secrets per session), D-12 (the rehearsal on the throwaway project), D-15 (import only; one writer of hosted auth settings), A-02, A-04, A-05, A-12, A-13.
