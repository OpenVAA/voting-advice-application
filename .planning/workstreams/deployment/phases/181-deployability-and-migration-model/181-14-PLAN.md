<objective>
Observe `SIGTERM` reaching the Node process and the request in flight finishing (D-15), measure whether the process then exits by itself (A-13, RESEARCH Pitfall 9), and act on the measurement.

Purpose: a rollout in phase 185 stops tasks with `SIGTERM`. adapter-node drains on the signal but never calls `process.exit`, so the process ends only when nothing else holds the event loop. Whether that is so for this application is not known without a run.
Output: the `--sigterm` leg of the topology check and its record. `shutdown.ts`, its test and a change to `hooks.server.ts` are created only if the process is measured lingering.

What changes if the measurement goes the other way: if the container exits only when the stop timeout kills it, Task 2 adds one listener for `sveltekit:shutdown` that runs registered tasks and then ends the process, and the leg is run again. Phase 182's relay must flush its queue on the same event; when the listener exists, phase 182 registers its flush through it and adds no second listener. The record's `SHUTDOWN_HANDLER=` line tells phase 182 which case holds.

`requirements` lists SUPA-10 as the phase's only closing requirement; this plan builds toward INFRA-09, which phase 185 closes.
</objective>
