<objective>
Stand the production image behind a local reverse proxy and check, by script and with negative controls, that it behaves as criterion 3 requires (D-14, D-15, A-11). The `SIGTERM` leg is plan 181-14.

Purpose: `ORIGIN`, `ADDRESS_HEADER` and `XFF_DEPTH` are adapter-node configuration, not application code. Only a run behind a proxy shows that a form post survives the origin check and that a forwarded address cannot be spoofed. Phase 185 re-runs this check when the CDN changes the proxy depth.
Output: a compose file, an nginx configuration, the check script, and one record.

The check runs on demand, outside the gate suite. No CI job is added.

Follow-up 181-R4 is planned on its recommended option: the diagnostics response reports the resolved origin, which gives "a redirect is built on the public origin" a direct observable. The application issues no absolute redirect of its own (its redirects are paths), so the check also follows the login form post and records where it lands. If the operator overrules 181-R4, the origin observation is dropped and the login post stands alone.

If the spike recorded `HARNESS_FULL_MODE=failed`, no isolated instance with an auth service exists. The login leg is then recorded as `LOGIN_LEG=deferred` and runs in the window of plan 181-16; every other observation runs here.

`requirements` lists SUPA-10 as the phase's only closing requirement; this plan builds toward INFRA-06, which phase 185 closes.
</objective>
