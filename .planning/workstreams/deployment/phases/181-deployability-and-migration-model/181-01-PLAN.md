- Attempt rule. Scratch state belongs to one attempt, and no check may read a line that an earlier attempt wrote. An attempt begins each time a task that keeps scratch lines is started, each time its gates are run again, and each time it is resumed after a stop at the clean-tree rule's checkpoint. It begins with three steps, in this order: take the attempt id, `$(date -u +%Y%m%dT%H%M%SZ).$(git rev-parse --short=12 HEAD)`; create the attempt file `<record>.<attempt id>.txt` in the scratch directory with a command that fails when that file exists (then wait a second and take a new id), and write `ATTEMPT=<attempt id>` as its first line; write that file's base name as the only line of the pointer file `<record>.current` in the same directory. `<record>` is the tracked record's file name without `.md`: `181-01-toolchain` for Task 1 and `181-01-baseline` for Task 2. The pointer names the current attempt, and every step and every verify command reads the attempt file it names and no other. Files of earlier attempts stay in place: never read, never copied from, never deleted, and no line of theirs counts. The status file and the output file of a background command carry the attempt id too (`<record>.<attempt id>.<gate>.status` and `.out`); before the command starts its status file must not exist, and a status is read only from a file of the current attempt id. In an attempt file a line that begins with an upper-case key and `=` is a verdict line and each key is written once; quoted output is indented by four spaces so that it cannot read as one. The tracked record is a byte-for-byte copy of the current attempt's file, made with `cp` after the task's last tree sample and not edited afterwards. A missing pointer, a pointer that names no attempt file, a key written twice, or a tracked record that differs from the current attempt's file fails the verify command; the repair is a new attempt, never a pointer or a record written by hand.
- Clean-tree rule. Executors of phases 182 and 183 work in this same checkout. The install of Task 1 and the baseline gates of Task 2 run only on a tree with no uncommitted tracked change at all. Before them, run `git status --porcelain --untracked-files=no` and `git rev-parse HEAD`. If the status prints anything, copy its output verbatim, indented, into the current attempt's file under a heading `TREE_STATUS_OUTPUT`, with the tree line as `no`, and into the checkpoint message, leave the tracked record untouched, and stop: return a blocking checkpoint that names each path and says that another phase's executor has uncommitted work in this checkout. Each record names the `HEAD` it was made on. If `HEAD` or the status changes while the gates run, that run is not evidence.
