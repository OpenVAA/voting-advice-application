<interfaces>
The manifest contract. Plans 181-12 and 181-17 read it as written here.

File: JSON, UTF-8, LF. Real path after the freeze: `apps/supabase/supabase/migrations.manifest.json` (beside `migrations/`, not inside it).

Shape:
- `baseline.name`: string, the baseline's name (`initial_schema`)
- `baseline.file`: string, `00001_initial_schema.sql`
- `baseline.commit`: string of 40 lower-case hex characters, the commit whose tree first held these baseline bytes
- `migrations`: array, in version order, of objects `{ "file": string, "sha256": string }` with `sha256` 64 lower-case hex characters over the file's bytes. The first entry is the baseline's file.

A migration's version is the five digits at the start of its file name. File names match `^[0-9]{5}_[a-z0-9_]+\.sql$`.

Checker signature: `checkFrozenMigrations({ migrationsDir, manifestPath })` returns `Array<string>`. Paths are absolute or relative to the working directory. It never throws for a content problem and never exits the process.

Each finding is a string: the rule's kind, then `: `, then a file's base name (`manifest.json` for the manifest), then the detail. A finding never holds a directory path, so one fixture yields the same text from any working directory.

The rules. This table is the whole of the checker: it has no rule outside it. The guard exports it as `FROZEN_RULES`, an array of `{ id, kind, fixture }` in this order, and builds every finding through one helper from an entry of that array.

| id | The rule | kind | fixture |
|----|----------|------|---------|
| `manifest-exists` | the manifest file can be read | `MALFORMED MANIFEST` | `missing-manifest` |
| `manifest-json` | it parses as JSON | `MALFORMED MANIFEST` | `malformed-manifest` |
| `baseline-members` | `baseline.name`, `baseline.file` and `baseline.commit` are present and are strings | `MALFORMED MANIFEST` | `missing-baseline-member` |
| `baseline-commit-shape` | `baseline.commit` is 40 lower-case hex characters | `MALFORMED MANIFEST` | `bad-baseline-commit` |
| `migrations-array` | `migrations` is a non-empty array of objects with string `file` and `sha256` | `MALFORMED MANIFEST` | `empty-migrations` |
| `baseline-first` | the first entry's file is `baseline.file` | `BASELINE NOT FIRST` | `baseline-not-first` |
| `name-pattern` | every listed name matches the name pattern | `BAD NAME` | `bad-name` |
| `version-unique` | no entry has a version an earlier entry already has | `DUPLICATE VERSION` | `duplicate-version` |
| `version-order` | no entry has a lower version than the entry before it | `NON-INCREASING VERSION` | `non-increasing-version` |
| `version-contiguous` | among the distinct versions, each one above the baseline's has its predecessor | `VERSION GAP` | `version-gap` |
| `file-exists` | every listed file is in the directory | `MISSING MIGRATION` | `missing-file` |
| `file-hash` | every listed file's sha256 equals the recorded one | `EDITED FROZEN MIGRATION` | `edited-file` |
| `file-listed` | every `.sql` file in the directory is listed | `UNLISTED MIGRATION` | `unlisted-file` |
| `baseline-not-empty` | the baseline file is longer than zero bytes | `EMPTY BASELINE` | `empty-baseline` |
| `baseline-has-table` | the baseline file holds a line beginning `CREATE TABLE public.` | `EMPTY BASELINE` | `baseline-without-table` |

How the rules combine, so that each fixture yields exactly one finding:
- A `MALFORMED MANIFEST` finding ends the check, and so does `BASELINE NOT FIRST`: nothing else can be judged against a manifest that cannot be read or whose anchor is wrong.
- An entry that fails `name-pattern` is reported once and takes no part in the three version rules. It still takes part in `file-exists`, `file-hash` and `file-listed`.
- An entry reported by `version-unique` is not also reported by `version-order`. `version-contiguous` looks at the set of distinct versions, not at their order, and reports one finding for each version whose predecessor is absent.
- A file reported by `file-exists` is not hashed. A baseline reported by `baseline-not-empty` is not also reported by `baseline-has-table`.
</interfaces>
