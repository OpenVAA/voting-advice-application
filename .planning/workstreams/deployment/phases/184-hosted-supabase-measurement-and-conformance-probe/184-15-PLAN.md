  <decision>Run the bootstrap with the server's logging settings as plan 184-10 recorded them, or not</decision>
  <context>
    The bootstrap binds the service-role key as a parameter and keeps it out of a failed statement's log, but a server that logs the parameters of statements that succeed, or of slow ones, logs it all the same, and the script cannot change those settings (STATE 181-11 blocker). RESEARCH Item 6 gives which values are safe. Raise this checkpoint only when one of the seven values recorded in `evidence/184-10-throwaway-reads.md` would log a successful or slow statement's parameters; show the seven values and say which one. When none would, do not raise it: write `LOGGING_GATE=pass` in the evidence of Task 3 and go on. Rotating the key afterwards is not a fallback: rotating a legacy key means rotating the JWT secret, which signs every key and session.
  </context>
  <options>
    <option id="session-timeout">
      <name>Run the bootstrap with a session statement timeout below every duration threshold that would log parameters (`PGOPTIONS='-c statement_timeout=5s'`), when only duration thresholds are unsafe (recommended in that case)</name>
      <pros>No statement of the bootstrap can run long enough to reach the threshold; a millisecond transaction is unaffected</pros>
      <cons>Does not help when every successful statement is logged with its parameters (`log_statement` of `mod` or `all`)</cons>
    </option>
    <option id="ask-platform">
      <name>Stop, and ask Supabase to change the setting, or change it where the dashboard allows, then read the seven again</name>
      <pros>Removes the exposure at its source</pros>
      <cons>Waits on someone else; the throwaway's sittings pause</cons>
    </option>
    <option id="accept">
      <name>Run the bootstrap as it is and accept the logged key</name>
      <pros>No wait</pros>
      <cons>The service-role key is in the platform's logs; only a JWT-secret rotation removes it, which re-signs every key and session</cons>
    </option>
  </options>
