  <action>
    Per D-13, D-14, D-16. Write the four modules with the interfaces stated in the context.

    `expected.mjs`: `readExpected` resolves files against the repository root (three levels above `infra/scripts/probe/`), reads `project_ref` from `<root>/terraform.tfvars` with a line read of `name = "value"` (a trailing comment allowed), requires 20 lower-case letters, reads `api.max_rows` from `infra/modules/supabase/hosted-settings.json` with `JSON.parse`, and reads `pageSize` as a line inside the `dataAdapter` block of `staticSettings.ts` by the same rule as the parity guard's `readPageSize`. Any file that cannot be read or any value that is missing or malformed throws `ProbeInputError` naming the file and the value. It holds no expected value of its own (D-16).

    `sources.mjs`: `collect` runs the preflight of each source named in `sources` before any read of that source. It sends the token as `Authorization: Bearer <token>`, from `env.SUPABASE_ACCESS_TOKEN`; an absent or empty token is a `SourceError('management', 'SUPABASE_ACCESS_TOKEN is not set')`. A non-200 status, a network error, a body that is not JSON or a missing named field is a `SourceError` whose reason gives the endpoint path and the status only, never a body. From each body it keeps the named fields and drops the rest at once; nothing keeps a whole body.

    `checks.mjs`: register `api.max-rows` with source `management`. It passes when the served `max_rows` is a number (`typeof` check, so the string "50000" is a finding) equal to the JSON value and to `pageSize`; when the JSON and `pageSize` disagree the finding says so. A finding is one line of prose that holds no `=`, no `@`, no run of 32 or more hexadecimal digits, and no secret word (secret, secrets, password, passwd, pass, pwd, token, tokens, key, keys, credential, bearer, authorization) directly followed by `:` or `=`, so that an operator can paste it past the screen of the attempt helper.

    `probe-hosted.mjs`: a header block in the anatomy of the parity guard's (what it reads, the three sources it will have with only `management` present here, the environment variables `SUPABASE_ACCESS_TOKEN` and the test seam `PROBE_MANAGEMENT_API_URL`, that it never takes the service-role key, the exit codes 0 all pass, 1 any fail, 2 could not run or usage error). Arguments: `--root <dir>` (required, resolved against the repository root when relative), `-h`/`--help`; anything else, a duplicate flag or a missing value is exit 2 with the usage on stderr. Flow: read expected (a `ProbeInputError` prints `COULD NOT RUN expected: <message>` and exits 2); collect only the sources that some registered check uses (a `SourceError` prints `COULD NOT RUN <source>: <reason>` and exits 2 with no check line); run the registry; print `PASS <name>` or `FAIL <name>: <finding>` to stdout in registry order; print one summary line to stderr; set `process.exitCode`.

    `infra/vitest.config.ts`: the shape of `tests/vitest.config.ts`, with `root` at `infra/` and `include: ['scripts/**/*.test.ts']`, and a header saying `infra/` is not a workspace, which root script runs it and how to run it alone.

    `infra/scripts/probe-hosted.test.ts` (Vitest, `node:http`, and the asynchronous `spawn` of `node:child_process`, not its blocking twin, because the stub server runs in the same process and a blocking child would starve it):
    - pure: `api.max-rows` passes for the real JSON value served as a number; fails with `500` in the finding for 500; fails for the string "50000"; with a JSON value that differs from `pageSize` the finding names both;
    - end to end: a temporary root directory holding a `terraform.tfvars` with `project_ref = "abcdefghijklmnopqrst"`; a stub on 127.0.0.1 that answers `/v1/projects/abcdefghijklmnopqrst` with 200 and `/postgrest` with a body holding `max_rows` and a `jwt_secret` field; the entry spawned with `process.execPath`, `PROBE_MANAGEMENT_API_URL` pointing at the stub and `SUPABASE_ACCESS_TOKEN=probe-test-value`. Cases: correct value, exit 0 and stdout exactly `PASS api.max-rows`; served 500, exit 1 and a `FAIL api.max-rows:` line; preflight answering 503, exit 2, stdout holding `COULD NOT RUN management` and no `PASS`/`FAIL` line; token unset, exit 2; `--root` missing, exit 2; the stub records that it received the bearer header; the `jwt_secret` value appears in neither stdout nor stderr; every stdout line passes the screen rules above (asserted with regular expressions in the spec).
