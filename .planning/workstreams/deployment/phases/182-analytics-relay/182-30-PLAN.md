<interfaces>
The report the script reads is `<run-dir>/results.json`, written by `tests/scripts/e2e-run.sh` (Playwright's JSON reporter): nested `suites`, each with `file`, `specs` and child `suites`; a spec has `title`, `file` and `tests`; a test has `projectName`, `status` (one of `expected`, `unexpected`, `flaky`, `skipped`), `annotations` and `results`. A result of a failed test holds `error` (an object with `message`) and `errors` (a list of objects with `message`); the error text of a test is every such `message` of all its results, with terminal colour sequences removed. The top-level `stats` holds the counts `expected`, `unexpected`, `flaky` and `skipped`.

From tests/scripts/e2e-evidence.mjs (anchor: `const declarativeSkip = annotations.includes('skip') || annotations.includes('fixme');`): a test with status `skipped` did not run when its `results` list is empty and it carries neither annotation; otherwise it is a declared skip.

Create `tests/scripts/e2e-spec-verdict.mjs`, started as
`node tests/scripts/e2e-spec-verdict.mjs <run-dir> [--passed <spec file>]... [--passed-test <title part>]... [--failed-test <title part> [--failure-contains <text>]...]... [--no-other-failures] [--no-flaky] [--allow-did-not-run] [--skipped-baseline <file>] [--print-skipped]`

A `--passed` value is the base name of a spec file. A `--failure-contains` value belongs to the `--failed-test` value directly before it.

    - Report with spec file `a.spec.ts` holding two tests, both `expected`: `--passed a.spec.ts` exits 0 and prints `VERDICT OK`.
    - Same report, one of the two tests `flaky`: `--passed a.spec.ts` exits 1 and prints a line starting `VERDICT FAIL:` that names the file and the test.
    - `--passed missing.spec.ts`, a file no test of the report belongs to: exits 1, and the line says no test of that file is in the report.
    - A test with status `skipped`, empty `results` and no `skip` or `fixme` annotation anywhere in the report: any invocation exits 1 and names the test as one that did not run; with `--allow-did-not-run` that test alone no longer fails the run.
    - `--skipped-baseline <file>`: exits 0 when the sorted list of declared skips, one line per test in the form project, file and title joined by ` › `, equals the file's lines; exits 1 and prints the lines only in the report and the lines only in the baseline when they differ. An empty baseline file and a report with no declared skip are equal.
    - `--failed-test "stores no session id"`: exits 0 when at least one test whose title contains the text is `unexpected`; exits 1 when the test passed, and exits 1 when no title contains the text.
    - `--passed-test <part>`: exits 0 when at least one title contains the text and every such test is `expected`.
    - `--failed-test X --no-other-failures`: exits 1 when a test whose title matches no `--failed-test` value is `unexpected`. `--no-other-failures` with no `--failed-test` value at all exits 1 when any test is `unexpected`.
    - `--no-flaky`: exits 1 when any test of the report is `flaky`, and names it.
    - `--print-skipped`: writes the sorted declared-skip lines to standard output and nothing else there; the verdict line goes to standard error.
    - A report that holds no test at all (an empty `suites` array with stats of zero): exit 1 with a line that says the report holds no test, under every flag combination. The cases: no flag; `--no-other-failures --no-flaky --skipped-baseline <an empty file>`; `--allow-did-not-run --no-other-failures`; `--print-skipped`. An empty run is never a green run.
    - A test with a declared skip (a `skip` or `fixme` annotation) inside a spec file named with `--passed`: exit 1, naming the test as skipped. The same report without `--passed` for that file, and with a baseline that lists the test, exits 0: a declared skip is acceptable only as a baseline line, never inside a spec that is claimed as passed.
    - A cut-off report, whose `stats` say that tests ran while its `suites` array is empty or absent: exit 3, like a missing report, because a truncated file is not a report.
    - A report whose `suites` tree is not empty but holds fewer tests than its `stats` count (the sum of `expected`, `unexpected`, `flaky` and `skipped` is 5, the tree holds 2): exit 3 for the same reason. Equal numbers, and a tree that holds more than `stats` says, are judged by the flags as usual.
    - `--failed-test "holds only allow-listed state" --failure-contains "appContext-sessionId"`: exits 0 when a test whose title contains the first text is `unexpected` and its error text contains the second; exits 1, naming the test and the missing text, when that test failed with another message, for example `Test timeout of 30000ms exceeded.`; the text is found in `error.message` and in an `errors` entry alike, and through colour sequences; two `--failure-contains` values after one `--failed-test` must both be found; `--failure-contains` with no `--failed-test` before it exits 2.
    - `--passed a.spec.ts` on a report whose only spec file is `tests/x/extra-a.spec.ts`: exits 1 saying no test of that file is in the report, because the base name must be equal and a common ending is not enough. On a report that holds `tests/x/a.spec.ts` and `tests/y/a.spec.ts`: exits 1 saying the name matches more than one file. A `--passed` value that holds a `/`: exit 2.
    - No `results.json` in the directory, or one that is not valid JSON: exit 3. No run directory argument, an unknown flag, or a flag without its value: exit 2.
