## A. Phase 175 — four items that depart from an earlier decision

### A1 — A refused name save does not cost the user's other edits (175 U-12; departs from D-05)

An admin can confirm an organization while its user has the profile open. The user's next save of a
name is then refused by the database. D-05 said the save is one update that "fails whole — image and
colour with it". As built, the store sends the answers, then the logo and colour, then the names in a
statement of their own: a refused name leaves the rest stored, the staged names are discarded, the
fields lock, and a message says the other changes were saved.

- [ ] **(a) Keep it as built** — ★ RECOMMENDED — the user loses only the edit that was refused.
- [ ] **(b) D-05 as written: one update, all or nothing** — one line changes in the store and five
      store cases turn. A refused save that carries a logo would then leave an uploaded file in
      storage that no row names (found while building; D-05 did not foresee it).

### A2 — A candidate's first and last name are required while they are editable (175 U-05; departs from D-14)

D-14 added a "name required" clause for organizations only. Your C2 ruling made a candidate's names
editable while unconfirmed. As built, both are required and non-blank while editable: a blank one
shows the required badge and the profile counts as incomplete. Saving is never blocked (U-06).

- [ ] **(a) Keep it as built** — ★ RECOMMENDED — an unconfirmed candidate cannot leave the public
      name empty and read "complete".
- [ ] **(b) D-14 as written: no name requirement for candidates** — two values in the per-type
      descriptor change, with the component cases that read them.

### A3 — The voter app hides an organization with missing answers when its own setting is on (175 U-19)

The Contestant app warns "your profile won't be shown" when answers are missing. For an organization
that was untrue: the voter-side filter read the candidate key only. As built, a new setting
`entities.hideIfMissingAnswers.organization` (shipped `false`) drives an organization arm in the
voter filter. This is the phase's one change to voter-side behaviour. With the setting at its
default nothing changes for voters.

- [ ] **(a) Keep it as built** — ★ RECOMMENDED — the warning is true, and a project opts in.
- [ ] **(b) Remove the arm; the organization's warning is not shown** — two commits are reverted and
      one descriptor value changes. An organization with missing answers is then always shown.

### A4 — A third identity in the phase's E2E dataset (175 U-30; departs from D-18)

D-18 named two organizations. The dataset also holds an unconfirmed candidate with no opinion
question addressed to candidates. It is the only way the "no questions" page, and a candidate's
editable name fields, are reached and scanned in a browser.

- [ ] **(a) Keep it** — ★ RECOMMENDED
- [ ] **(b) Two organizations only** — the neutral page and the candidate's editable names lose
      their browser tests and four of eighteen accessibility scans.
