## Problem

The template format has no invitations block, and `writer.ts` seeds none. The only dev-seed path to
`create_invitations` is the method `SupabaseAdminClient.createInvitations`, which a script calls
directly. A developer who wants a local project with invited entities — an email invitation to try the
sign-in link, a code to try code registration — writes that script by hand, and no built-in template
shows the invitation states the Contestant App has screens for.

Phase 177.1 read "the seed writer" of its criterion 5 as that method and left template support out of
scope: no criterion asks for it.

## What a solution needs to decide

1. **The block's shape.** An `invitations` key on the template, each item in the keys
   `create_invitations` reads, naming its entity by `external_id` (the function already resolves one
   inside the project), with the `nominations` key and the confirmation that Phase 177.1 adds.
2. **One confirmation per call.** `p_confirm_entity` is one value per call (177.1 D-04), so a block that
   mixes confirmed and unconfirmed entities is written as two calls, or the block carries the value per
   group.
3. **Where a generated code goes.** A code exists in plaintext only in the function's answer and cannot
   be read back. The writer has to print it, write it to a file outside the repository, or the template
   uses email invitations only.
4. **Validation and tests** for the new key in `permittedKeys.ts` and the template schema, and whether
   the `e2e/*` templates may use it (the E2E suite seeds its invitations through the fixture today).
