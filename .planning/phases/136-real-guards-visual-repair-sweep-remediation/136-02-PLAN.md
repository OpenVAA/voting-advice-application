# Plan 136-02 — F12 subset matchers + F14 unused matcher

## Context (from the sweep)

**F12:** nine `expect.arrayContaining` assertions prove a filter *excludes* things using a **subset**
matcher — 6 in `@openvaa/data`, 2 in `@openvaa/filters`, 1 in `nomination.test.ts`. A filter that
becomes a no-op and returns everything **passes all nine**. One test is literally titled
`'Should exclude those where filter is different'`. These sit on the matching pipeline's input path.
The repo already knows the right shape: `constituencyGroup.test.ts:54` pairs the matcher with a size
check. Fix is mechanical — `expect.arrayContaining(ids)` → `toEqual(ids)` (order-insensitive variant
if ordering is genuinely unspecified: sort both sides, or `toEqual(expect.arrayContaining(ids))`
PLUS a length assertion — but prefer plain equality).

**F14:** `supabaseDataWriter.test.ts:303` builds the File→path substitution matcher the test is named
for, then never uses it.
