## Decision record for this plan

### DR-21 — The proof is split into a cheap repeatable half and one expensive half

The research sketches a proof whose negative control is a full-suite run on the pre-conversion code,
reproducing a specific historical failure signature. That is a third and fourth full-suite slot, needs
a checkout of superseded code, and produces evidence that cannot be re-taken later.

This plan takes a stronger and cheaper shape:

- **The red/green pair lives in a committed test** at the query layer. It seeds contamination into the
  default project and asserts both halves in one run: the project-scoped query returns none of it (the
  green half) and the same query without the project filter returns it (the red half). The red half is
  the negative control, it is automated, and it re-runs forever — unlike a one-off historical
  reproduction.
- **One additional full-suite run** is taken with the contamination genuinely present in the database
  and with no reset, so the end-to-end claim is exercised at the level the historical failure occurred
  at.

Together these say: the residue is real, it is invisible to a project-scoped read, and the suite is
green in its presence. Recorded deviation from the research's sketch, with the reason: a re-runnable
automated negative control is worth more than a one-off reproduction of a historical red, and it costs
one full-suite slot instead of two.

### DR-22 — The contamination run is taken after the criterion-3 pair, never between it

Running the unit-test suite between the two criterion-3 runs would confound a failure between "the
reset is not needed" and "the contamination is invisible". This plan therefore runs strictly after plan
`161-07`'s pair is green and accepted, as a third run in the same unreset database.
