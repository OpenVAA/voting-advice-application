## Decision record for this plan

### DR-23 — The documentation fix is subordinate to a mechanism fix

`CR-02` can be discharged by editing three documents. That is the weaker half and, taken alone, it
recreates the defect class the phase already fell into once: the instruction and the behaviour drift
apart and nothing notices. `161-VERIFICATION.md` records that the preflight asserts the served
*checkout* and never the served *project*, which is precisely why a wall of assertion failures carried
no line naming the cause.

This plan therefore lands the mechanism FIRST (task 1) and the documents SECOND (task 2). After task 1,
following the old instructions produces a named abort in global setup rather than a silent empty app —
so even a reader working from a stale copy of the documentation is safe. The documentation edit then
tells the truth about a system that already enforces it.

### DR-24 — The self-test goes in the SAME invocation, not behind a flag in a second one

`161-REVIEW.md` WR-02 proposes `"assert:project-scoped-queries": "… --self-test && node …"`. That
works, but this repository already contains a strictly better pattern and this guard should match it
rather than invent a second convention.

`scripts/assert-no-session-in-loads.mjs` runs its fixture check inside `main()` under the comment
`── The self-test, in this same invocation ──`, and prints
`self-test flagged N line(s) … (matching the committed expectation)` on every ordinary run. The
consequence is the property we want: **the spelling wired into `lint:check` is the self-proving
spelling.** There is no second command a future edit can drop, and no flag anyone has to remember.

The `--self-test` flag is kept for direct invocation, but it stops being the only path that proves
anything. Recorded deviation from the review's proposed fix, with the reason.

### DR-25 — Non-vacuity is asserted as a floor, not as an exact count

`161-REVIEW.md` reproduced the failure by breaking `ACCESS_RE` so that `examined` fell to 0 while the
exit code stayed 0. The fix is to fail closed on `examined === 0`.

It is deliberately a floor (`> 0`) and not an exact expected count. An exact count would redden on
every ordinary refactor that adds or removes a legitimate call site, which trains the reader to update
the number without thinking — the failure mode where a guard becomes a formality. The self-test in
DR-24 supplies the precision: it asserts exact expectations against fixtures that only change when
someone means to change them.

### DR-26 — The join fix ships as a new migration, and the schema file is edited to match

`00005` is applied. Editing it in place would leave every existing database carrying the unqualified
joins with nothing to detect the divergence, and `assert:schema-migration-parity` compares the schema
files against the migration set, so both sides move together or the gate reddens. New migration
`00007`, matching edit to `schema/503-entity-rpcs.sql`, and a parity manifest refresh.

### DR-27 — The RLS gap is named in the summary and carried, not fixed here

Measured during verification: `schema/302-rls.sql` defines 13 `anon_select_*` policies and **zero** of
them reference `project_id`. That is the reason CR-01 is a tenant-attribution defect rather than a read
amplification — the entity row was already anon-readable directly.

It is out of scope here. Phase 162's criteria 2 and 5 already own read-grant scoping. This plan fixes
the join, and the summary records the RLS measurement as carried-forward input to 162 so it is not
rediscovered a third time.
