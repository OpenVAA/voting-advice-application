<objective>
Close CR-01, the CORPUS axis. `INVOKE_RE` is the one matcher the guard's own docblock says is deliberately
unanchored so it "reads the same over whatever corpus it is handed", yet the 161-16 matrix disposes its two
computed cells as `reported-by COMPUTED_ACCESS_RE` — a matcher `checkOutsideSource` never calls. The
disposition is corpus-blind, and the shape it waves through is UNCOUNTED at exactly the address check 7 was
widened to cover.

This plan closes it directly rather than restating it as a residual, and makes the DEFECT CLASS
unrepeatable: a `reported-by` disposition that names a matcher running over a narrower corpus than the
matcher under test is now a named test failure, with both corpora derived from the guard's own source text.

Purpose: an Edge Function invocation whose function name the guard cannot read must be reported at every
address the guard walks, not only inside the adapter directory.
Output: two new matchers wired into the one check that runs over both corpora, five violating fixture shapes
and four near-miss controls, a derived corpus map, and one honestly stated residual.

Implements D-J1 ("What guard catches an unparameterised query?", roadmap criterion 2): the guard, not a
reviewer, is what catches a query missing its project parameter — and this plan closes the corpus axis on
which that decision was not yet honoured.
</objective>

<assumption_delta_decision>
The deterministic detector fired on this phase, and the genuine architectural transition it points at is
CR-02's, not CR-01's — it is answered in full in `161-18-PLAN.md`. CR-01 carries a smaller, related delta
that is recorded here so it is not absorbed silently:

- **Noun that is now primary:** *the corpus a matcher is exercised over* — previously an implicit property
  of the guard's call graph, mentioned in prose in three docblocks and nowhere measured. It becomes an
  explicit, derived value (`CORPUS_OF`).
- **Decision:** `promote`. The corpus becomes a first-class derived attribute of every matcher and every
  `reported-by` disposition is checked against it. The alternative — a hand-authored `corpus` field on the
  disposition, which the code review's own suggested fix sketched — is rejected: a constant that must be
  edited in lockstep with the guard's call graph is precisely the defect class this phase exists to end. The
  derivation is possible here (the call graph is plain top-level function bodies), so a hand-authored table
  is not the fallback the planning guidance permits.
- **Invariant test encoding the generalized intent (suggested, and included in Task 3):** run the derivation
  against a SYNTHETIC guard source in which `checkOutsideSource` also calls `checkEscapeHatches`, and require
  `CORPUS_OF` to report `both` for `COMPUTED_ACCESS_RE` in that source. That goes red the instant somebody
  replaces the derivation with a constant.
</assumption_delta_decision>
