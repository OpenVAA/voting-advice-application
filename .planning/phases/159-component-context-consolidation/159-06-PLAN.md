<objective>
Collapse the two tracking-service layers to one type and one implementation, remove the internal-only
members from the consumer-facing surface, and relocate the shared reactive-handle type module into the
context utilities directory.

Purpose: D-H4 chose "one type, one implementation; narrow the consumer interface" and the criterion
explicitly forbids a comment-only fix. The second type layer exists to bridge two handle shapes that
have since converged, so it is now an almost pure no-op. The narrowing is subtler than it looks: the
context forwarder copies own-enumerable property descriptors rather than declared type members, so
editing only the type files would leave the runtime surface exactly as wide as before. Criterion 5's
handle-type relocation rides along because it touches the same implementation file.

Output: one narrowed tracking type, one implementation, a selective forward, four context classes with
their re-declarations removed, an updated spread test, and the relocated handle type module.
</objective>
