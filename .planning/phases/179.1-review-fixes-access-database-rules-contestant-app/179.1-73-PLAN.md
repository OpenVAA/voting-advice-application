## Rulings carried by this plan

1. **The sign-out sites, derived again at run time** by `git grep -n -E "\.signOut\(" -- apps/frontend/src ':!*.test.ts'` and classified by this rule: a server request that signs out calls `withdrawLogoutCount` first; a sign-out made inside a request that has already called it (the grant gate's in `sessionAdmission.ts`, the mailed link's and the confirm page's before a verification, which plan 72 covered) needs no second call; the hook's own sign-out settles instead and is not touched (rule 7); a sign-out made in the browser goes through the logout endpoint first (`supabaseDataWriter.ts`, `_logout`). Read at planning, the sites that call it: the `POST` of `routes/api/auth/logout`, before its `signOut`, and `signOutToLogin`, before its `signOut`, which then takes the request's `cookies`, `request` and `url` beside `locals` (its two calls in `routes/contestant/(protected)/+layout.server.ts` pass them). A site the run-time list adds or removes is reported with the rule's reading of it, in `$U/179.1-73-sites.txt`.
2. **Each site keeps its contract (`PROH-179.1-54`).** The helper is called once, first; the endpoint's `json` answers and statuses, and `signOutToLogin`'s redirect or error page, are as before. A withdrawal before a sign-out that then fails leaves the session with no count: the count was the browser's request to end that session, and the failure is shown to the user as before (`common.logoutFailed`).
3. **The browser test.** The fixture's `endSessionWithNoSignal()` posts to the logout endpoint with the context's cookies, which is a sign-out the server makes with no page told of it; after it, the count a closed tab left is gone at once, before any sign-in. On plan 72's tree the count stays until the next sign-in, so the test is red there at `expectNoLogoutDeadline`.
