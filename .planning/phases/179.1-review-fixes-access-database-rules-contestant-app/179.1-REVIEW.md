### Warnings

#### DB-WR-01: The registered-entities record can still be lost when two first sign-ins of one identity run at once for different (project, type) pairs

**File:** `apps/supabase/supabase/functions/identity-callback/index.ts:16, 319-338` (with `apps/supabase/supabase/migrations/00018_identity_entity_find_or_create.sql:133-141`)

**Issue:** `identity_entity_find_or_create` serialises the find-or-create on the user and writes `registered_entities` into `auth.users.raw_app_meta_data` inside its transaction. Each request then calls `supabaseAdmin.auth.admin.updateUserById(userId, { app_metadata: … })`.

The module comment at line 16 describes the auth service's behaviour: it "writes the whole of `app_metadata` from the copy it read when the update began". GoTrue loads the user, merges the top-level keys in memory, and writes the whole `raw_app_meta_data` column back. Making each request's metadata write follow *its own* RPC does not prevent a lost update when two requests want *different* record entries.

Here is the interleaving, for request A (project P, candidate) and request B (project P, organization, or another project):

1. A's RPC commits `{P:{candidate:c}}`.
2. A's `updateUserById` starts, and GoTrue loads the user with `{P:{candidate:c}}`.
3. B's RPC is no longer blocked, because A's lock ended with A's transaction. It commits `{P:{candidate:c, organization:o}}`.
4. A's GoTrue write stores its loaded copy plus A's keys, which is `{P:{candidate:c}}`. The `organization:o` entry is gone.

The user still holds the editor grant on `o`, but no record names it. On the next organization sign-in the RPC reads no entry and creates a second organization with a second grant. That is the duplicate-entity outcome D-19/B4 was meant to remove.

The window is narrow: it needs simultaneous first sign-ins of one person for two different targets. It is also not limited to this function. Any GoTrue-side write of `app_metadata` made with a stale copy can wipe the record the same way, such as a future admin update or a provider update on verification.

**Fix:** Keep the record out of a column the auth service rewrites in full. Store it in a table the function owns, for example:
```sql
CREATE TABLE private.identity_registrations (
  user_id uuid NOT NULL REFERENCES auth.users (id) ON DELETE CASCADE,
  project_id uuid NOT NULL REFERENCES public.projects (id) ON DELETE CASCADE,
  entity_type public.entity_type NOT NULL,
  entity_id uuid NOT NULL,
  PRIMARY KEY (user_id, project_id, entity_type)
);
```
`identity_entity_find_or_create` would read and insert there under the same advisory lock, and could even use `INSERT … ON CONFLICT DO NOTHING RETURNING` instead of the lock.

If the record must stay in `app_metadata`, there is a second option. Have the RPC also write `identity_provider` / `identity_match_*` (and the null-outs of the removed claim keys) with a SQL `jsonb` merge under the lock. Then drop the `app_metadata` argument from the later `updateUserById`, which leaves it carrying only `email_confirm`. As written now, the line-16 comment claims the race is closed, which it is only for requests with the same (project, type).

#### TS-WR-02: `stop_own_mock_issuer` runs on every exit, so the wrapper kills an issuer it did not start, including the one whose port it just refused

**File:** `tests/scripts/e2e-run.sh:1037` (call site), `tests/scripts/e2e-run.sh:262-298` (function), `tests/scripts/e2e-run.sh:782` (refusal)

**Issue:** `cleanup()` calls `MOCK_ISSUER_STOP_REPORT="$(stop_own_mock_issuer)"` on every exit. That includes exits before Playwright started:

- `prepare_identity_provider` refusing with "port 9443 already has a listener" (line 782).
- The `FRONTEND_PORT` refusal (line 1232).

The issuer on 9443 can legitimately belong to someone else. Playwright's `webServer` uses `reuseExistingServer: !process.env.CI`, so a developer may hand-start `mockOidcIssuerEntry.ts` for local iteration or run a concurrent `yarn test:e2e`. Both carry this checkout's absolute entry path. In that case the wrapper:

1. refuses the run because 9443 is held,
2. then SIGTERMs, and after 30 s SIGKILLs, that holder's whole process group.

That contradicts the header's own contract: "at teardown it kills only processes in its own spawned process group" and "refuses to start when port 8777 or 9443 is already held".

A second problem is that the match `*"$MOCK_ISSUER_ENTRY"*` is an unanchored substring. A checkout at `/x/a/repo` holds `/a/repo/tests/tests/support/mockOidcIssuerEntry.ts` in its command line, so a checkout at `/a/repo` would match it too.

**Fix:** Stop the issuer only when this wrapper started the Playwright run that spawns it, and anchor the match on the argument boundary:

```bash
PW_STARTED=false   # set to true right after `PW_PID=$!`
...
if [ "$PW_STARTED" = true ]; then
  MOCK_ISSUER_STOP_REPORT="$(stop_own_mock_issuer)"
  printf '%s\n' "$MOCK_ISSUER_STOP_REPORT" | sed 's/^/e2e-run.sh: /'
fi
...
case " $command " in
  *" $MOCK_ISSUER_ENTRY "*) ;;
```
