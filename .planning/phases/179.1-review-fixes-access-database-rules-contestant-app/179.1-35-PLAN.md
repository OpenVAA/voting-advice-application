## Rulings carried by this plan

1. **Deleted, not wrapped** (orchestrator; the operator's truth says "rather than a separate component"). No new wrapper is written at any point: callers render `Input`. `PasswordField` keeps its two remaining callers until plans 36 and 37 move them, and plan 37 deletes it. Each of those commits is proven by a full control, so the suite is green throughout.
2. **Required follows `EmailField`** (orchestrator): callers pass `aria-required="true"` and not `required`, so there is no native `required` and no badge. Two pinned assertions change: `input.required` in `PasswordSignIn.svelte.test.ts` and in the moved case. They are the only assertions rewritten for this ruling.
3. **The catalogue is not touched** (orchestrator): the two unread keys of `components.passwordInput` stay. `showPassword` and `hidePassword` are read by the toggle as they are, and `common.password` is the label. No message file is edited, which also keeps clear of the operator's held edits (`et/components.json` is one of them).
4. **The kind writes its value on every input event** (orchestrator), through `bind:value` with a getter and a setter. Consumers need this: the admin login's `canSubmit`, `PasswordValidator`'s rule list, the edit-clears-error handlers. It stays out of `isTextKind`, whose values are committed on `change`, and the binding also takes in text typed before the page's script ran.
5. **Test ids stay** (orchestrator): the control's `password-field` is passed by each caller, as a `data-testid` reaches any kind's control through the rest props; the toggle's `password-field-toggle` is fixed in `Input`, as `multilingual-toggle` is. A kind does not default a `name`: callers pass `name="password"` where the default was used, and three server actions read that field.
6. **`passwordrules`** goes on the union's `password` member, as a documented optional prop, because it is outside the HTML attributes the base type carries. It reaches the control through the rest props unchanged (measured). Plan 36's first field is the caller that gives it.
7. **The row's background is the caller's to say.** `Input` paints its row for the page behind it. The two sign-in pages are `bg-base-300`, so `PasswordSignIn` passes `onShadedBg` as `EmailField` does. Plans 36 and 37 settle it for their callers.
