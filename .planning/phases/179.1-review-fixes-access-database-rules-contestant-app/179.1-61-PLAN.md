## Rulings carried by this plan

1. **The ruling, as recorded:** "BROWSER SIGN-OUTS ONLY. Every browser-side sign-out (both apps' Log out, the Admin handleError browser path, the cross-tab SIGNED_OUT signal) removes drafts; no removal on a load that merely finds no session, so a lapsed session keeps its draft." `signOutToLogin` and `handleError` on the server cannot reach `localStorage`, and remove nothing.
2. **One function.** `contestantDrafts.ts` holds `EDITED_ANSWERS_KEY_STEM`, moved from `contestantUserDataState.svelte.ts`, which imports it and goes on exporting it for its callers and tests, and `discardContestantDrafts()`, which removes every `localStorage` key under the stem's prefix with `removePersistedByPrefix`. The store's `reset` calls it. The admin modules import the module by its path, not through the contestant context's barrel.
3. **Where each sign-out removes.**
   - The Admin App's Log out: `adminContext.logout`, after the sign-out worked. A failure keeps the draft, as the Contestant App's does: `T-179.1-104` stands as the operator kept it.
   - `handleError` in the browser: after a sign-out that worked, and after one that failed when `isSessionGone()` answers true, before the redirect plan 59 made. It removes directly, because its load can run before the Admin App's layout has mounted, on a link from a page with no subscriber.
   - Another tab's sign-out: the Admin App's subscriber removes on `'elsewhere'`, signed in or not. The Contestant App's resets on `'elsewhere'`, as plan 60 made it.
   - The Contestant App's subscriber on `'here'` with no logout of its own running, the `handleError` link from the Contestant App: it resets, which drops its handles before the drafts go, so they cannot be stored again.
4. **The tests' prefix.** The E2E fixtures copy the stem once today, in `contestant-entity-selection.ts` with a comment naming the app's module. It moves to `tests/tests/utils/contestantDrafts.ts`, which that fixture and `headerLogout.fixture.ts` import, so no third copy is made.
