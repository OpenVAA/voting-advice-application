1. **No wrapper** (orchestrator): the setter renders `Input` itself. The old component stays on the tree for the admin login until plan 37; this plan's commit is proven by a full control, so the suite is green with it there.
2. **Required follows `EmailField`** (orchestrator): the fields pass `aria-required="true"` and not `required`.
3. **The catalogue is not touched** (orchestrator): `common.password` and `common.passwordConfirmation` are the labels, and the toggle reads its existing texts. No message file is edited, which also keeps clear of the operator's held edits.
4. **Test ids stay** (orchestrator): each field passes `data-testid="password-field"`, the toggle's id is fixed in `Input`, and the blocks' ids go on the two `Input`s' containers.
5. **The row's background is the caller's to say.** `Input` paints its row for the page behind it. The password-reset page is `bg-base-300`, the settings page `bg-base-200` and already passes `onShadedBg` to its other `Input`, and the set-password gate has the default `bg-base-100`. So `PasswordSetter` gains an `onShadedBg` prop, given by the settings and password-reset pages and not by the gate.
