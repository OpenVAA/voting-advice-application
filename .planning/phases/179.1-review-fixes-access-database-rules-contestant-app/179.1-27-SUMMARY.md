## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The endpoint's `locals.currentLocale` is always `en` for the browser's POST**
- **Found during:** Task 1, before the change, by running paraglide's `extractLocaleFromRequest` on the three URLs (observed): `/api/oidc/authorize` resolves to `en` even with the cookie `PARAGLIDE_LOCALE=fi`, because the `url` strategy comes first and reads any unprefixed path as the base locale; `/fi/api/oidc/authorize` resolves to `fi` and `deLocalizeUrl` routes it to `/api/oidc/authorize`.
- **Fix:** the registration screen posts to `localizeHref(AUTHORIZE_ENDPOINT)`; the endpoint reads `locals.currentLocale` as planned. A unit case pins the localized post.
- **Files:** `register/+page.svelte`, `register/page.svelte.test.ts` · **Verification:** `179.1-27-green`, unit green · **Commit:** `5e2af76b6`

**2. [Rule 1 - Bug] The probe speaks HTTP/1.1, not HTTP/1.0** — a 1.0 request makes the server close first, the TIME_WAIT case the wrapper's own server note says Docker Desktop answers by dropping a later connection on the same port. With 1.1 the server keeps the connection and the probe closes it first. Inside the container's own `timeout 10`. Commit `c52a6e310`.

**3. [Rule 3 - Blocking] The new helpers are defined above `self_test`** — `self_test` runs during argument parsing, before the identity-provider section, so a helper defined there is `command not found` to it (`179.1-27-selftest-green-1`, kept). Commits `c52a6e310`, `9e6cf1b4c`.

**4. [Rule 2 - Missing critical] The refusal cases require status 1, and the unspecified address is refused too** — the first draft's refusal cases accepted any non-zero status and passed on `command not found`; the bind decision also rejects an all-zero address (threat T-179.1-61). Commit `c52a6e310`.
