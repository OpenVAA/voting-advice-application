## Rulings and deviations carried by this plan

1. **Five parallel requests** make the negative control: the old function reads the record, looks up, inserts and writes the record in separate round trips, so parallel requests for a fresh identity create more than one entity; the case asserts exactly one. A red that is not observed keeps its ledger row `pending` and is reported, never written as confirmed.
2. **The account step (5) is unchanged**: it is `email_exists`-tolerant, so the parallel requests resolve to one account before the locked call (research).
3. **`toNameCase` is made independent of `\b`**, which does not see a word start before a non-ASCII letter (`ÖSTERBERG`); `smartNameCase` calls it only for a name with a letter that equals its own upper-case form.
4. **The identity-lookup todo is not folded** (execution rules PL-05).
