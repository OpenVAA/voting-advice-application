The plan expected the `e2e-tests` job to fail on the known SSR-500 (`2026-09-03-ci-e2e-ssr-500`), with the dev server answering 500 after the identity-provider preparation. **That did not happen.**

- Playwright ran 643 tests and ended **249 passed, 2 failed, 392 did not run**.
- Both failures are the scan `contestant-nav-reason-open` (light and dark), at `tests/tests/specs/a11y/contestant-a11y.spec.ts:323`. That line is `expect(getByTestId('contestant-entity-selection-group').last()).toHaveAttribute('data-entity-type', 'organization')`, which failed with `Timeout: 5000ms` and `element(s) not found`.
- The 392 that did not run are the projects that depend on `contestant-a11y-scan`.

Under CLAUDE.md's E2E rule this CI run is red. Plan 31 only observes, so it changes no code. The item is filed as **open** in `deferred-items.md` for the phase to settle before its close.

Its cause is **UNCONFIRMED**. The uploaded run directory has no Playwright error context or trace. The hypothesis: the step uses the default 5000 ms `expect` timeout while the steps around it wait `TIMEOUTS.slowPage`, and the CI runner is several times slower than this host.

This does not touch E4: the wrapper printed both lines before Playwright started. It also means the SSR-500 todo did not recur on this tree, which plan 32 or the orchestrator may want to note in that todo.
