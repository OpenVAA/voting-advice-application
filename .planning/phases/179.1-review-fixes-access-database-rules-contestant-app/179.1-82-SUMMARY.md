# Phase 179.1 Plan 82: the page's removal at a domain host, and overImgBgColor's description Summary

**Two jsdom files at `https://example.org/` and `https://app.example.org/` assert every host-only and `Domain=` expiry the modal's Continue and a Log out write, red with `expireEveryCopy`'s `Domain=` loop removed while the `localhost` file stays green; `overImgBgColor` is now described as the top bar's colour on a page with a header image.**

## For the operator's reading

- **What changes for a user.** Nothing a user sees. The plan adds tests and changes two descriptions.
- **What changes for a developer.** The page's removal of the logout count is now tested at a host that is a domain name. Without the `Domain=` expiries those tests fail. Before, every page-side test ran on jsdom's `localhost`, where no `Domain=` expiry is written. Removing the loop left the old file green, and that is now on record (`179.1-82-mut-0`).
- **What changes for a deployment.** The type's docblock and the publishers' guide now say what `overImgBgColor` does. It is the background of the header's top bar on a page that sets a header image, and the image is drawn below the top bar.
- **What stays unproven (rule 17).** No real browser on a real apex deployment has removed a planted copy. The new tests run in jsdom, whose jar keys a cookie by name, domain and path. A browser that keeps a `Domain=<host>` copy apart from the host-only one is shown only by the strings the page writes, not by a jar that holds both. This goes on plan 85's UAT list.
