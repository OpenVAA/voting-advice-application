## Rulings and deviations carried by this plan

1. **Two mechanisms, one outcome** (research Pitfall 8): the two functions name the refusal and the writer recognises it; a PostgREST update hides the row instead, so the page refreshes and reads the lock. Either way the note renders and the generic failure does not.
2. **The nomination editor shows the reason the editor already uses for a lock that ends nomination editing** (`NotEditableNote` reason `nominationsAnswersLocked`, "editing has ended in the application, while nominations themselves are not locked"); the questions and profile pages show `answersLocked`.
3. **The E2E case lives in `perm-answers-locked`**, the project that owns the settings singleton during its slot; it sets the lock off, opens the page, sets the lock on and saves, and leaves the lock on as its setup set it.
