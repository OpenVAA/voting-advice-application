## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The plan's function binding at the sign-in form wiped the caller's error**
- **Found during:** Task 1, the unit run after the kind was added
- **Issue:** with `bind:value={() => password, handlePasswordEdited}`, four cases of `PasswordSignIn.svelte.test.ts` failed: an error set by the caller was gone at first paint. `ensureValue`'s `value ??= ''` compiles to `value(value() ?? '')` (observed, by compiling that line with the repo's Svelte 5.57.1), so the setter runs at mount whatever the value is, and that setter cleared `error`.
- **Fix:** a plain `bind:value={password}` and the handler removed. `Input`'s `handleInput` clears the bound error on an edit, and the case that pins it is green. `ensureValue` was not changed, since it serves every kind.
- **For plans 36 and 37:** a caller's setter on this binding is called at mount. Filed in `deferred-items.md`.
- **Files modified:** `PasswordSignIn.svelte`
- **Commit:** `1d61f707c`

**2. [Rule 3 - Blocking] The toggle's test id in `testIds.ts`**
- **Found during:** Task 1. The plan's fixture step needs the id, and the rules require it to come from that file.
- **Commit:** `1d61f707c`

**3. [Rule 3 - Blocking] `yarn -s` in Task 1's verify**
- **Found during:** Task 1. As the orchestrator's corrections anticipate. The script as written is kept, with that stage restated beside it.
- **Commit:** none

**4. [Rule 2 - Missing control] Two more red controls, and cuts for the unit cases**
