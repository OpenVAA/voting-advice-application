# Phase 179.1 Plan 03: Bulk Import Constituency Links and Seed Settings Validation Summary

**`bulk_import` now writes the links between elections, constituency groups and constituencies. An election item can carry `constituency_groups` and a constituency-group item can carry `constituencies`, each a list of references. The function takes them off the item and writes the two join tables in the same transaction, after the constituencies and before any nomination. The dev-seed client sends every seed's links this way, so the constituency rule of plan 04 can move into the nomination trigger without breaking a seed. The dev-seed writer also checks every `app_settings` row with the shared `StoredSettingsSchema` before it writes any of them.**

### Migration 00012

- **The function.** `00012_bulk_import_constituency_links.sql` re-creates `public.bulk_import (jsonb)` with the same body text as `schema/501-bulk-operations.sql`. It does not restate privileges.
  - It takes the link key off an election or constituency-group item with `-`. A value that is not an array raises `Collection "<c>" item <id>: <key> must be a JSON array of references`.
  - The links are written at the top of the `organizations` turn. That point comes after the constituencies turn, whether or not the payload holds constituencies, and before nominations.
  - Each reference is resolved with `resolve_external_ref` and checked to be a row of the item's own project. The rows are written with `INSERT … ON CONFLICT DO NOTHING`.

### The dev-seed client

- **What `bulkImport` sends.** It sends the links as `constituency_groups: [{external_id}]` on an election item and as `constituencies: [{external_id}]` on a constituency-group item. This holds for all six key forms `LINK_SENTINELS` accepts, and the forms are read through the new pure helper `importLinkFor`. A row that names no link, or an empty list, sends no key.
- **What `linkJoinTables` writes.** It passes over the join entries and writes only the `election_ids` / `constituency_ids` references of question categories and questions. `upsertJoinRows` is gone.

## Deviations from Plan

### Auto-fixed / restated

**1. [Rule 2 - Security] A link must name a row of the item's own project**
- **Found during:** Task 1.
- **Issue:** `resolve_external_ref` casts a uuid-string reference without looking it up, and the join tables' insert policies check only the election's or the group's project. A project admin could therefore have linked a project-A election to a project-B group through the import (threat T-179.1-07).
- **Fix:** each resolved reference is checked to be a `constituency_groups` or `constituencies` row of the item's project, and is refused otherwise. Two `BIL:` cases cover this, one as the service role and one as the project admin. Both were red on the old function.
- **Committed in:** `396c5cef7`.

**2. [Rule 3 - Blocking] The client's payload cases are in a new file, not `writer.test.ts`**
- **Issue:** `writer.test.ts` mocks `SupabaseAdminClient` away, and its header states that it makes no `createClient` and no `.rpc()` call. `bulkImport`'s payload cannot be observed there.
- **Fix:** the cases are in `packages/dev-seed/tests/supabaseAdminClient.links.test.ts`, which mocks `@supabase/supabase-js` as `supabaseAdminClient.invitations.test.ts` does.

**3. [Rule 3 - Blocking] Files the plan did not list**
