## Rulings and deviations carried by this plan

1. **The lock key is the user id** (execution rules PL-04): by the time the function runs, the identity has been resolved to one account; no claim value enters the call.
2. **The record is written inside the transaction** into `auth.users.raw_app_meta_data` (research): written later by the Edge Function, a second caller taking the lock after the first's commit would still see no record. `postgres`, the definer's owner, holds UPDATE on `auth.users` locally (research, verified); hosted Supabase is assumed the same (research assumption A1) and is recorded for the deployment workstream by plan 30.
3. **The function lives in `506-invitation-rpcs.sql`** beside the other service-role definer functions and their REVOKE / GRANT block; the block's count in its comment rises by one.
4. **The identity-lookup todo is not folded** (execution rules PL-05).
