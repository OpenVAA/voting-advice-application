## Rulings carried by this plan

1. **The module,** `apps/frontend/src/lib/auth/logoutAnnouncement.ts`, beside `logoutDeadline.ts` and imported directly, as it is (not through `$lib/auth`'s barrel). TSDoc'd exports:
   - `LOGOUT_ANNOUNCEMENT_CHANNEL = 'openvaa-logout'`, the name the review gives.
   - `LOGOUT_ANNOUNCEMENT_WINDOW_MS = 5_000`, the operator's "about 5 s".
   - `announceLogout(): void` posts one message on the channel.
   - `listenForLogoutAnnouncements(): () => void` records the time of each announcement it hears, by `Date.now()`, and returns the function that stops it.
   - `heardLogoutAnnouncement(): boolean` is `true` when an announcement was heard and no more than the window has passed since, at the moment it is asked.

   Behaviour:
   - **One channel object per document**, opened by the first listener and closed when the last one stops. `announceLogout` posts on that object while one is open, so a document never hears itself: `BroadcastChannel` delivers to every other object of the name, the same document's included, and never to the one that posted. With none open it opens one, posts and closes it at once; a message posted before `close()` is still delivered.
   - **Outside the browser it does nothing.** `typeof window === 'undefined'` is checked first, because Node, which renders on the server, has a global `BroadcastChannel` of its own. Where `typeof BroadcastChannel === 'undefined'` it does nothing either. A constructor or a `postMessage` that throws is caught. A Log out never fails on the announcement.
2. **The announcer.** `AuthContextProvider.logout` runs `withdrawAnyCount()`, then `announceLogout()`, then `prepareDataWriter().logout()`, the order of the review's sketch. The announcement is made before the request, so a Log out that then fails has still announced. A follower that hears it and then meets no `SIGNED_OUT` within the window does nothing with it. The class docblock's sentence on `logout` says both.
3. **The followers.** Each context's constructor adds `onMount(listenForLogoutAnnouncements)` beside its existing `onMount` of `onSignOut`; the stop function is that mount's cleanup. The reason is decided when the client announces `SIGNED_OUT`, in the synchronous part of the follow, before its first `await`:
   - In the Contestant App, `#runFollowSignOut` builds its login route as `this.#loginRoute(heardLogoutAnnouncement() ? 'loggedOutElsewhere' : undefined)`.
   - In the Admin App, `#leaveAfterSignOutElsewhere` builds `{ route: 'AdminAppLogin' }` with `errorMessage: 'loggedOutElsewhere'` only when `heardLogoutAnnouncement()` is `true`.

   Nothing else of either follow changes. Drafts are discarded and the context resets as before (`PROH-179.1-40`). The guards stand down. The full-load fallback leaves to the same route. A page that reads as signed out does not leave. A `SIGNED_OUT` while this context's own logout runs changes nothing. Each context's class or method docblock that says the login page names the other tab now says when.
4. **The writer's words (`PROH-179.1-59`).** `SignOutOrigin`'s TSDoc and `_onSignOut`'s say what `'elsewhere'` covers: any sign-out this document did not start. That is one another tab made, which the client is told of, or one the auth client made by itself when it found the session gone or a refresh refused. Comment lines alone change.
5. **The unit fakes.** `logoutAnnouncement.test.ts` stubs the global `BroadcastChannel` (`vi.stubGlobal`, undone after each case) with an in-memory fake. The fake delivers a posted message, after a microtask, to every other open instance of the same name and never to the one that posted, and nothing after `close()`. Each simulated document is a fresh module instance (`vi.resetModules()` and a dynamic import). The time is moved with `vi.useFakeTimers()` / `vi.setSystemTime`. No case opens a real channel: Node's keeps its worker alive. The context and auth test files mock `$lib/auth/logoutAnnouncement` with a box whose `heard` value each case sets. A test file that constructs a context for real (derived by `git grep -l -E "initContestantContext|initAdminContext|initAuthContext" -- "apps/frontend/src/**/*.test.ts"`) gets the same mock if, and only if, the unit suite shows an open handle or a failure from it. The summary names any such file.
6. **The browser proof** (rule 10). The round adds and rewrites no E2E test. The two tests of the other-tab sentence already go through a real second tab's Log out, which now announces. The held change is driven once through `contestant-entity-selection` before the commit, as the tracer's end-to-end check. `admin-access` runs behind the whole perm chain, so it is driven in the targeted run of `perm-closed-project` after the commit, with both titles pinned. A red of either title stops the plan per rule 16, with the run directory: the window is not widened.
