# Phase 179.1 Plan 87: Every locale's strings compared with English Summary

**The untranslated-catalogue guard now compares every locale but `en`, and also catches a placeholder like `SV Send feedback`. The 43 strings that really are the same word in their language are allowlisted with a reason each. Nine Danish and Swedish strings that were English are now written as the operator approved, and the English feedback mail subject is spelled `Feedback`.**

## For the operator's reading

What changes for a user:
- A Danish reader sees `Websted` instead of `Website` on an entity's links.
- A Swedish reader now sees:
  - the video controls `Ljud av` and `Spela igen`;
  - `Högst` as the numeric filter's upper label;
  - `Analys` as the privacy page's analytics heading;
  - `1 allians` and `{numShown} allianser` in the results' alliance counts;
  - `Skicka feedback` on the feedback button, where it read `SV Send feedback`;
  - `Respons` as a failed feedback's mail subject.
- A failed feedback's English mail subject reads `Feedback`, not `Feedack`.

What the guard now does: an English string put into any of `da`, `et`, `fi`, `fr`, `lb` or `sv` fails the unit suite unless the allowlist names it as the same word in that language, a proper name or an abbreviation. The same holds for English behind the locale's tag. Each entry is pinned to its value, so an entry fails once its reason is gone.

What stays unproven:
- **The strings on screen.** No spec reads these keys, so the targeted run proves only that the catalogues compile and that a locale switch still works.
- **A native reader.** All nine strings are machine translations.
- **`sv` `components.video.unmute`.** It reads `Avslöja` ("reveal"). No comparison reads it, because it is not `en`'s value (ruling 9).
