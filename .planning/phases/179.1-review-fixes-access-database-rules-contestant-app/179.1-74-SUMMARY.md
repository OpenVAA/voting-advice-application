# Phase 179.1 Plan 74: The login screen says why after the server's sign-out at a count's end Summary

**After the request hook signs a browser out at the end of a logout count, the login page's load reads the settled marker the hook wrote and the Contestant App's login screen says "You have been logged out automatically, because a logout you started was not cancelled in time." in the existing notice, which the focused heading names as its description; the two sentences of G-3 are in seven locales in the approved words.**

## For the operator's reading

A user whose logout count ran out in a tab that then closed, and who comes back to the Contestant App in that browser, now lands on the login screen with the notice under the title: "You have been logged out automatically, because a logout you started was not cancelled in time." (in their locale). The notice is the existing red inline message with `role="alert"`, and the heading the page focuses on arrival names it with `aria-describedby`, so its accessible description is the sentence. Nothing a link can put on the address bar is rendered: only the closed set of reasons has a sentence, and the address bar's reason is shown first when it names one. The second sentence, "You have been logged out in another tab or window.", is written in the seven catalogues and mapped, but no path puts it on the screen yet; plan 75 builds that path, and the path of a count's end in its own tab.

What stays unproven:

- **What a screen reader says.** The heading's description is asserted as Chromium computes it, not heard. VoiceOver, NVDA and TalkBack go on the UAT list.
- **The `fr` and `lb` sentences**, both keys, are machine translations the checkpoint approved and are flagged for a native reader.
- **C3's later tab.** A tab that reaches the login page only after another tab has met the server's sign-out finds the marker already removed and shows no reason, as C3 decided.
- **Every engine but Chromium**, and real phones.
