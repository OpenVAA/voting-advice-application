# Phase 179.1 Plan 57: A slow sign-out shown in progress, and a loading button named once Summary

**Both apps' header Log out now bind Button's `loading` to a reactive `leaving`, so a slow sign-out shows a spinner on a disabled button, and the spinner inside a loading Button is `aria-hidden`, so the button is named `Loading…` once.**

## For the operator's reading

What a user now meets: when they press Log out in the header and the sign-out is slow, the button shows a spinner in place of its icon and is disabled until the sign-out ends, in the Admin App and in the Contestant App where the button signs out at once (no unsaved change and nothing counted, so no modal). The header button is then named `Loading…` (it is an icon button, so the loading text replaces its `aria-label` and `title`). Any loading button of a text variant, such as the logout modal's Log out, is now named by its loading text once rather than `Loading… Loading…`.

Where the Contestant App's Log out opens the modal, the header trigger now also spins while the modal's Log out or the count's end runs the sign-out, because both read the same `leaving`. That was not tested by a run of its own (inferred from the code: the trigger and the modal's Log out bind one state).

What stays unproven:
- The look of the spinner in the header at 320 to 390 px and in dark mode; no run was made of it, and the visual project does not cover the header Log out.
- What a screen reader says when the pressed button becomes disabled and loses focus to the body (ruling 3). On success the page leaves; on failure the button is enabled again with the message shown. No focus is moved by this plan.
- What VoiceOver, NVDA or TalkBack say for the loading name; the tests read what Chromium computes and no more.
- WebKit, Firefox, iOS Safari and Android are not driven.

Observed and inferred: the red of each new test and the green with the change are observed (runs below). The diagnosis's mechanism (the Admin App's plain `let`, no `loading` on either trigger) is confirmed by these runs: each test went red at `toBeDisabled` with the button still named `Log Out`, and green with the bindings.

Files touched that the plan did not list: none. The spec header of `contestant-entity-selection.spec.ts` (group 6) gained one clause naming the new test; that file is in the plan's list.
