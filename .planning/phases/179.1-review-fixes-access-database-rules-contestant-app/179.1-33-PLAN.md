## Rulings carried by this plan

1. **Key on `page.data.session`** (orchestrator; G-179.1-6). Never add `token` back to a load: everything a server load returns is serialised into the HTML, and `routes/admin/layout.server.test.ts` fails such a member by name.
2. **The header button beside the gates' own controls is accepted** (orchestrator): `SetPasswordGate`, `TermsOfUseGate`, `IdentityProviderGate`, `NothingToEdit` and `ReadFailure` keep their controls and gain the header's beside them. The pair on the entity home was the original design.
3. **The modal closes on navigation, not on a timer or an unmount** (orchestrator). The guard lives in `LogoutButton`, which alone knows the modal is its own. It tracks whether the modal is open through `TimedModal`'s `onOpen` and `onClose`, because `ModalContainer`'s close on a modal that was never open removes its `hidden` class for good (the transition it waits for never runs).
4. **A closed `<dialog>` in the header on every page is accepted.** It is `TimedModal`'s own, it existed on the entity home already, and the debug session counted 0 dialogs by role while closed. No `view-transition-name` is added, and `dialog[open]` still strips the names while it is open.
5. **The entity for the modal case.** `test-e2e-base-or-sel` has no seeded answers (`packages/dev-seed/src/templates/e2e/base.ts`), and `TEST_LOGOUT_ENTITY_EMAIL` edits it and has no stored session, so that user can open the modal and sign out without touching a stored session. That the modal opens for this entity is **inferred from the dataset, not measured**: `179.1-33-red-2` shows it. If it does not open, the executor reports which task the entity lacks and picks the next entity of the base dataset with an incomplete task; the assertion is not weakened.
