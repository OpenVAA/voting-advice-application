# Phase 179.1 Plan 07: Row-Level Security Reads the Grants Table Summary

**`public.user_can` and `public.user_has_account_grant` now read the caller's rows of `public.grants` for `(SELECT auth.uid())` and no longer read the token's `grants` claim. A grant deleted mid-session therefore denies the user's next read and next write made with the same token.**
- **What changed:** migration `00017`. No policy, no other function and no index changed.
- **What it costs:** every RLS list read stays within 2× of its before median, and the full E2E close took 1.001× the median of its three predecessors.

- **`user_can`:**
  - It loops over `SELECT gr.scope, gr.role, gr.target_type, gr.target_id FROM public.grants gr WHERE gr.user_id = (SELECT auth.uid())`.
