## For the operator's reading

**The user who walks away (ruling 2, `T-179.1-89`).** A user who presses Log out with an unsaved edit and walks away stays signed in, with the edit, behind the native question, until someone answers it. No count ends that session and no count discards that edit, because a count nobody is watching is not agreement. The cost is real and is accepted: on a shared computer the session stays open. It is bounded by what the user was told: the modal's sentence that they will be logged out automatically is never shown in this state, and the prompt that is shown says the page still holds their changes. If a guard becomes active while a count is running, the count's end goes through the same `logout` and asks; it never discards. E2E test 5 pins this state. **This is yours to overrule, and overruling it costs one condition in `LogoutButton.svelte`.**

**A visible change for a user who is present (ruling 3).** With an unsaved edit on the page the native question takes the modal's place. They are asked once, not twice, and they do not see how many questions are left. With nothing unsaved the modal and its count work as before.

**`AdminLogoutButton` has the same order and not the defect (ruling 6).** No route of the Admin App mounts `PreventNavigation` (`git grep -q -F PreventNavigation -- apps/frontend/src/routes/admin`: exit 1, in Task 3's verify), so its navigation cannot be refused. It is not changed. Plan 42 records that phase 179.2's account flows must use the registry if they mount a guard.

**A residue in the full-load path, unconfirmed (ruling 4).** The full load is `location.assign` inside `leaveUnasked`, whose flag is cleared as soon as that call returns. If the browser fires `beforeunload` after that, and a guard is still active, a second native prompt could appear after the user's yes. `#reset` runs straight after and clears the store, so this could only concern a guard whose `active` reads something `#reset` does not clear. This is inferred from reading the code: it was **not observed**, and no known route reaches this state, because with the guards stood down nothing cancels the navigation. The path is proven by a unit case with a stubbed `location` alone.

**One thing the plan's verifies could not do as written.** `yarn -s` does not exist in this Yarn. Task 1's verify as written exited 1, and with that one stage restated as `yarn workspace` it exited 0; see the deviations.
