## Rulings carried by this plan

1. **What is compared.** The strings a reader reads: a plain message, and each text of a variant message (the values of its `match`). A variant message's `declarations` and `selectors` are code, identical in every locale by necessity, and are not compared. A string with no letter once its `{placeholders}` are removed (an emoji, `—`, ` • `, `{score}%`, an empty string) carries no word to translate and is not compared; the rule is stated in the test's TSDoc. A plain message is keyed by its translation key (`common.info`); a text of a variant message by its translation key, the variant's index and its match key (`questions.category.numQuestions#0/numQuestions=1`).
2. **Which locales.** The per-value case compares `fr` and `lb`, the locales whose catalogues the phase machine-translated (`COMPARED_VALUE_BY_VALUE`). The whole-file case covers every locale but `en`. Measured at planning, no file of `da`, `et`, `fi`, `fr`, `lb` or `sv` has every compared string equal to `en`'s. `da`, `et`, `fi` and `sv` hold 22, 5, 4 and 18 compared strings equal to `en`'s. They are not compared value by value, because the ruling and the gap name `fr` and `lb`, and plan 85 records this as an open residue with no ruling attributed.
3. **The measurement, at planning.** The checkpoint's derivation command (Task 1) prints 53 `fr` and `lb` strings equal to `en`'s: 31 in `fr` and 22 in `lb`. The planner reads nine of them as English left untranslated: `components.select.placeholder` in both locales, `questions.arguments.con`, `.pro` and `.proCategory` in both, and `questions.arguments.title` in `lb`, where the catalogue writes the word as `Argumenter`. Their machine translations are in `$P/179.1-81-approved-strings.json`, committed with this plan. The other 44 are the planner's proposed allowlist, with a reason for each, in Task 1's table. The executor derives the set again at run time. Where its derivation differs from the table, the executor presents the derivation with the difference named, and the planner's reading does not override it.
4. **The allowlist's shape.** `SAME_AS_BASE_LOCALE` is a TSDoc'd array of `{ locale, file, key, value, reason }`, one entry per approved string, `reason` one short phrase (a proper name; an abbreviation written the same; the same word in French; the same word in Luxembourgish). An entry pins its value. A third case fails on an entry whose key is gone, or whose `en` or locale value is no longer `value`, so the list cannot keep an exemption the catalogues no longer need.
5. **How the four files are written.** The catalogues are prettier-formatted, and `questions.json` keeps its short arrays inline, so a re-serialised file would differ in lines no string changed (measured: `JSON.stringify(…, null, 2)` reproduces both `components.json` files but neither `questions.json`). Each approved value is therefore replaced in place, on the line that holds its key. The rest of each file stays byte for byte: `git diff --numstat` shows 1 line in each `components.json`, 3 in `fr/questions.json` and 4 in `lb/questions.json`.
6. **The byte-copy case stays.** `no catalogue file of another locale is a copy of the base locale's` and `SAME_IN_EVERY_LOCALE` stay word for word; the new cases sit after it.
7. **The targeted run.** No spec reads a string of `components.select` or `questions.arguments`. The only project that drives a page in `fr` or `lb` is `contestant-entry-phone` (the French sign-in and Admin login at 390 px), derived by `git grep -n -E "locale: '(fr|lb)'|goToPage\('(fr|lb)'\)" -- tests/tests/specs`. It is this plan's targeted run, judged with no delta.
