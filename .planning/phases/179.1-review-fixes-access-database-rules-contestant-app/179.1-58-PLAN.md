## Rulings carried by this plan

1. **G-7's cause, as measured.** The suspected late write is eliminated: the sentence and the title are in the accessibility tree in the same task as `showModal()`, about 210 ms before focus reaches Continue. Over an unsaved edit the dialog's name is `Log Out` and the warning is only in `aria-describedby`; VoiceOver on macOS 14 and later does not speak a description on entry (UNCONFIRMED for this version; WebKit bugs 209279 and 260835). The count's modal sounded fine because its name carries its warning. So the fix puts the warning in the name.
2. **The name, by C3.** (a) The dialog's `aria-label` over an unsaved edit is `t('common.logoutUnsavedChanges')`, and its visible title stays `common.logout`. (b) The title is `t('contestantApp.logoutModal.unsavedTitle')`, shown and used as the name. In both, the hidden description copy leaves the unsaved sentence out over an unsaved edit, so a reader that speaks name and description does not hear it twice, and the visible body keeps it. `ModalContainer` writes `aria-label={title}` and then spreads its other props, so an `aria-label` the button passes through `TimedModal` and `Modal` names the dialog (read).
3. **7B's two causes.** `Close Close` is CONFIRMED in the accessibility tree: with no actions `Alert` renders a text Close `Button` and a ✕ whose `sr-only` label is also `common.close`. With no actions the ✕ gets `aria-hidden="true"` and `tabindex="-1"`: pointer users keep it, and assistive technology and the keyboard meet the text Close alone. This reaches every `Alert` with no actions, `Notification` among them, with no visual change. `Log Out Log Out` is UNCONFIRMED: focus returns to the header's `Log Out` in the frame in which the message, named `Log Out`, appears. The message's title therefore becomes C4's string: (a) `t('error.general')`, (b) `t('common.logoutFailedTitle')`. Whether VoiceOver still doubles a title in the Admin App, where focus does not move, is the operator's re-check.
4. **The other side finding is done.** The doubled `Loading…` name was plan 57's.
5. **What the tests can and cannot show.** They read `toHaveAccessibleName`, `toHaveAccessibleDescription` and the buttons in the accessibility tree, in Chromium. What a reader says goes on plan 66's list as a VoiceOver re-check, with the Admin App's message as the differential for the title.
