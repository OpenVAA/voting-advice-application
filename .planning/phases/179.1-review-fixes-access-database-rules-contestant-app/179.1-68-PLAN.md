## Rulings carried by this plan

1. **The operator's answer at 179.1-67 is the precondition.** This plan builds option `a`: WR-01 fixed by the browser-kept expiry, WR-03 fixed by the tab's record, WR-02 accepted as designed and stated in the docs, IN-08 fixed with the rework. Any other answer stops the plan before Task 1, and the planner revises plans 68 and 69.
2. **The two cookies.** `COOKIE.logoutPending = 'logout-pending'`, new, TSDoc'd: an opaque id of the count's opening, 32 hex characters from `crypto.getRandomValues` (which needs no secure context, unlike `crypto.randomUUID`), kept 400 days so it outlives a closed browser as the session does; or the settled marker `passed`, which the server writes after it has signed a request out. `COOKIE.logoutDeadline = 'logout-deadline'` keeps its name and is re-documented: the same id, with `Max-Age` equal to `Math.ceil` of the count's seconds plus `LOGOUT_DEADLINE_GRACE_SECONDS` (10), so the browser drops it at the deadline by its own clock. Both are written by the page, `Path=/`, `SameSite=Lax`, `Secure` on HTTPS, not `httpOnly`. They name no user and carry no time.
3. **The state, one pure function for the server and the page.** `cookieValues(header, name)` returns every value of one name in a `Cookie` header or a `document.cookie` string, in order. `logoutDeadlineState(pendingValues, deadlineValues)` answers `'settled'` when any pending value is the marker; `'none'` when no pending value is a well-formed id; `'duplicated'` when more than one distinct well-formed id is pending; `'counting'` for one id and at least one deadline value; `'runOut'` for one id and no deadline value. A well-formed id matches `^[0-9a-f]{32}$`.
4. **The hook.** `logoutDeadlineHandle` reads both names from `event.request.headers.get('cookie')` through `cookieValues`. On `'runOut'` it signs out as plan 67 left it and, after a sign-out that worked or found no session, sets `logout-pending` to the marker in the same response; on `'duplicated'` it signs nothing out and expires every copy of both names it can name, host-only and with `domain` set to each of `parentDomainsOf(event.url.hostname)`, and logs a line naming the cookie alone; on any other state it does nothing. It calls no `Date.now` (`PROH-179.1-42`).
5. **The page.** `writeLogoutDeadline(countSeconds)` writes both cookies. `clearLogoutDeadline()` expires both names, host-only and for each parent domain of `location.hostname`, but only when `logout-pending` holds the id this document wrote (Task 2). `settleLogoutDeadline(discardDrafts, trigger)` keeps plan 67's shape on the state: `'settled'` calls `discardDrafts` once and expires every copy, on either trigger; `'duplicated'` expires every copy and discards nothing; `'runOut'` is left for the server; `'counting'` is left on `'navigation'`, and on `'document'` is removed only by a fresh document of the tab that wrote it (Task 2; Task 1 keeps plan 67's removal of a count still to come so the tracer stays one change).
6. **The tab's record (WR-03).** `writeLogoutDeadline` keeps the id it wrote in the module (this document's open count) and in `sessionStorage` under `LOGOUT_TAB_RECORD_KEY = 'logout-deadline-tab'`, which survives a reload of the same tab and is not shared with another. A `'document'` settlement removes a `'counting'` id that equals the record and is not this document's own open count, and clears the record: the tab that held the modal was reloaded, and the modal went with its document as a navigation closes it. A restored page whose modal still counts holds the id as its own and keeps it. A page of another tab has no record of it and keeps it. `clearLogoutDeadline` clears the module's id and the record.
7. **`parentDomainsOf(hostname)`.** The proper parent domains of a host name with at least two labels each, nearest first: `a.b.example.org` gives `b.example.org` and `example.org`; `example.org`, `localhost`, an IPv4 address and an IPv6 address give none. A browser refuses a public suffix, so the list needs no suffix table. A copy planted with a path other than `/` is not reached; the auth page says so, and the `__Host-` prefix, which would close it over HTTPS, is not built.
8. **The tests, with no fixed wait.** A page clock behind the server's is `page.clock.install({ time: Date.now() - 5 * 60_000 })`, a Playwright clock that moves the page's JavaScript time and not the browser's cookie store, which is what a device whose clock is off has. The time that passes while a tab is closed is the removal of `logout-deadline` from the context, which is what the browser does at its expiry.
