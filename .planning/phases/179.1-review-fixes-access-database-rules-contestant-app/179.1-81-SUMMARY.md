# Phase 179.1 Plan 81: The untranslated-catalogue guard compares each string Summary

**translations.test.ts now compares every fr and lb string with en's against a 44-entry allowlist that pins each value. Every locale but en is held to a whole-file rule. The nine English values the comparison found are translated as the operator approved them, and one targeted run (r3) is green.**

## For the operator's reading

- **What changes for a user.** A French or Luxembourgish voter now reads, in their own language, the headings of a question's argument lists ("Contre" / "Pour", "Dogéint" / "Dofir"), the per-option heading ("Pour {option}", "Dofir: {option}"), the select's placeholder where no label is given, and in Luxembourgish the arguments' title ("Argumenter").
- **What changes for a developer.** The guard now catches an English string added to `fr` or `lb`, a reformatted copy of an `en` file in any locale, and an allowlist entry that no longer applies.
- **What stays unproven.**
  - Nobody has seen the nine strings on screen: no spec reads them.
  - No native reader has read them. All nine are machine translations, and the lb `proCategory` value is the operator's edit, `Dofir: {option}`, which is also a machine translation awaiting that reader.
  - `da`, `et`, `fi` and `sv` are not compared value by value (ruling 2). They hold 22, 5, 4 and 18 strings equal to `en`'s, measured at planning, and are held only to the whole-file rule.
