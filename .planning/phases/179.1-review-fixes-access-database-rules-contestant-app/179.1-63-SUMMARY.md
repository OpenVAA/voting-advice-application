# Phase 179.1 Plan 63: A count that does not run still signs out Summary

**The logout modal's count is now a wall-clock deadline that the page also keeps in a `logout-deadline` cookie. `logoutDeadlineHandle` in `hooks.server.ts` signs out any request that arrives after that deadline, and the next document removes the drafts. `TimedModal` re-checks the deadline every second and whenever the tab comes back.**

## For the operator's reading

**What a user who walks away now meets.** Say a user opens the logout modal and leaves. If the tab stays open and its timers run, the count signs them out as before. If the tab was asleep, frozen or in the background and the count's time passed, the count ends as soon as the tab is shown, restored, focused or resumed, not 30 seconds later. If the tab or the browser was closed during the count, the session is ended by the browser's next request to the application once the count's time plus ten seconds has passed. A protected page then goes to the login page, and the Contestant App's drafts are removed in that browser's next document. A user who stays meets no change: Continue, the ✕, Escape, a navigation, the modal's own Log out and the count's own sign-out all remove the cookie, and so does a page loaded before the deadline. A sign-out that fails at the count's end is not repeated later by the server.

**What stays unproven.** These stay on the operator's UAT list:
- A real frozen tab, a locked phone and a closed lid. Headless Chromium does not freeze a page. The test moves the page's wall clock and sends `visibilitychange` itself, so it does not show what a device does on wake.
- That Chromium's timers stop during system sleep, so that a lid closed during the count now ends it on wake. This is read, not measured.
- A browser that never makes another request. It keeps a session the auth service accepts, and no script can run in a closed tab to end it.
- The hosted session bound (`[auth.sessions]` time-box or inactivity timeout). It is recorded for the operator and not configured.

**Observed vs inferred.** Observed: both reds and both greens on a dev server, the full held run (692/692) and the close (692/692). Inferred: the server-side sign-out ends the session in the auth service, and not only in the cookies. The test reads the session through the gate's redirect, which needs only the cookies to be gone. `signOut({ scope: 'local' })` calls the auth service's logout for the access token (read from the library, not measured here).
