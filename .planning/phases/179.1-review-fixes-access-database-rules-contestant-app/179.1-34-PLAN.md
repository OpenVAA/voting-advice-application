## Rulings carried by this plan

1. **The overlay-label shape** (orchestrator; the debug session's shape B). `Radio`'s label is the row's overlay, through `containerProps` with `for` and `absolute inset-0`. It holds the input and the name alone. Shape A, where the label holds the content, puts a hint into the radio's name and needs changes to the hint, the unit helpers and the E2E fixture; shape B was measured identical to the present markup on every read signal except the border.
2. **The offset is one scoped rule, not an arbitrary value in the markup.** The rules forbid a numeric spacing class or an arbitrary value in new markup, and the row's content needs to clear a radio that is out of flow. A `<style>` rule in the component states the margin as `calc(var(--size-selector, 0.25rem) * 6 + var(--spacing-md))`: daisyUI's own formula for the radio's size plus `--spacing-md` from `app.css`. It uses `margin-inline-start`, so it holds in a right-to-left locale.
3. **`Radio` itself is not changed** (debug session). The admin pages' raw radios and the checkboxes are out of scope (orchestrator).
