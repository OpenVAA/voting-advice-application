### The reading (E4's Linux half: observed)

- **The bind.** `172.17.0.1` is the gateway of Docker's default bridge on the Ubuntu runner, the address
  `getent hosts host.docker.internal` answered inside the edge-runtime container (RESEARCH assumption A3
  holds on the runner). It is neither loopback (`127.0.0.1`) nor the wildcard (`0.0.0.0`): plan 27's Linux
  branch bound the one address it was meant to.
- **The probe.** From inside the edge-runtime container, the request for `/jwks` on
  `host.docker.internal:8777` was answered `HTTP/1.1 200 OK`: the edge runtime reaches the key server
  through that bridge on Linux, as it does through Docker Desktop's forwarding on macOS.
- The wrapper went on past the probe (status 9 would have refused the run before Playwright), served
  `identity-callback`, started the dev server and ran Playwright. E4 holds on both platforms.

### Why the job failed (context; not the E4 verdict)

The plan expected the E2E jobs' known failure, the dev server answering 500 to the preflight
(`.planning/todos/pending/2026-09-03-ci-e2e-ssr-500.md`). **That is not what happened in this run.** The
preflight passed (`E2E PREFLIGHT OK …/apps/frontend (verified against …)`, `E2E SERVED PROJECT OK

failed with `Timeout: 5000ms`, `Error: element(s) not found`. The 392 that did not run are the projects

`deferred-items.md` for the phase to settle before the close; this plan changes no code (D-23 E4 asks only
