## The binding

The plan says to bind `value` "with the existing edit handler as its setter". The handlers did more than store the value, and they are gone:

| Old handler | What it did | Where it is now |
|---|---|---|
| `handlePasswordEdited` | stored the value | `bind:value={password}` |
| | cleared `passwordError` | `Input`'s `handleInput`, through `bind:error` |
| | cleared `confirmationError` | `clearMismatch`, the first field's `oninput`, which `handleInput` forwards |
| `handleConfirmationEdited` | stored the value | `bind:value={passwordConfirmation}` |
| | cleared `confirmationError` | `Input`'s `handleInput`, through `bind:error` |

`Input`'s `handleInput` clears only its own field's error, so the mismatch needed the `oninput`. It is the only handler logic that moved rather than went. Nothing here runs at mount. In this form a setter at mount would have done no harm, since both errors are this component's own state and are empty at mount, but `oninput` puts the logic where only an edit reaches it. The existing cases `removes the mismatch when the password is edited` and `keeps the password's error while the confirmation is edited` pass unchanged, and the first is red with the `oninput` cut (`179.1-36-unit-mut-no-mismatch-clear`).
