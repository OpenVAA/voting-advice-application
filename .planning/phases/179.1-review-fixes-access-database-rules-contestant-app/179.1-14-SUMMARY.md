# Phase 179.1 Plan 14: the already-registered notice Summary

**A browser that has confirmed an address through the confirm page now carries the httpOnly cookie `registered`. On the registration screen it sees a notice saying it looks as if the user is already registered, with Login and Forgot password; Dismiss removes the cookie through the form action `dismissRegistered`, so the notice stays gone.**

## The cookie

| Attribute | Value |
|---|---|
| name | `COOKIE.registered = 'registered'` |
| value | `'1'`; only its presence is read |
| `httpOnly` / `secure` / `sameSite` / `path` / `maxAge` | `true` / `true` / `'lax'` / `'/'` / `60 * 60 * 24 * 365` |
| set by | `verifyMailedLink`, after `verifyOtp` succeeded for `magiclink`, or for `email_change` with a session. Only the confirm page's POST action calls it; no GET sets it |
| not set for | `recovery`, a failed verification, a missing token or type, the refused types `invite`/`signup`/`email`, an `email_change` that answers no session |
| read by | the register page's load: `registered: cookies.get(COOKIE.registered) !== undefined`. It reads no `url` property |
| removed by | the register page's `actions.dismissRegistered`: `cookies.delete(COOKIE.registered, { path: '/' })` |

The TSDoc on the map entry says what it marks, that it names no account, and who sets and removes it (T-179.1-41).

## The notice

- Page-owned markup in `+page.svelte`: a `<section aria-labelledby>` named by its `h2`, then the sentence and three controls. It sits above the mode selector. Classes are word-named only (`bg-base-100 gap-md p-lg rounded-lg`, `gap-sm`). No `view-transition-name` and no `<dialog>`.
- Login is a link to `ContestantAppLogin` (variant main) and Forgot password a link to `ContestantAppForgotPassword`.
- Dismiss is `<form method="POST" action="?/dismissRegistered" use:enhance>` with a submit `Button` named "Close" (`common.close`). On `success` the page sets its own `registeredDismissed` state and moves focus to the page's `h1` (`tabindex="-1"`), because the focused control went with the notice. Any other result goes to `applyAction`.
- The page's `@component` docblock describes the notice and its dismissal.
