## Rulings carried by this plan

1. **The precondition.** `$U/179.1-70-decisions.txt` records C7. Under (a) the name stays `components.passwordInput.showPassword` (en `Reveal password`) and the other key is removed; under (b) the name switches as now and the key stays. The plan is written for (a); (b) changes only step 3 of Task 1 and the unit and browser cases that read the name.
2. **The toggle (WR-06).** A browser dispatches `click` with `detail === 0` for a keyboard activation of a button (Space or Enter) and `detail >= 1` for a pointer press. `togglePasswordRevealed` takes `{ focusControl }`, and the button calls it with `focusControl: event.detail !== 0`: a pointer press focuses the field with the caret at the end, as now (the button's `onmousedown` `preventDefault()` keeps the pointer's focus off the button), and a keyboard press leaves focus on the button. The button carries `aria-pressed={passwordRevealed}`. Read at planning: `Button.svelte` spreads `restProps` onto its element, so the attribute reaches the `<button>`; the executor confirms it in the rendered markup. The function's TSDoc says both.
3. **The held navigation (WR-04).** SvelteKit gives a `popstate` navigation a `delta` (the number of history entries moved) and restores the position when its `beforeNavigate` callback cancels it. `holdNavigation` keeps `{ href, delta }`, `delta` only for type `popstate`; `holdNavigationWhile`, when the run rejects, calls `history.go(delta)` for a held traversal and `goto(href)` for anything else, and drops it when the run resolves, as now. The replayed traversal is a fresh `popstate` with nothing held, so a page's guard asks as it does for any Back. `holdNavigation`'s parameter type admits the `delta` of the popstate member of SvelteKit's navigation union (`'delta' in navigation`), with no `any`. The module's TSDoc says both forms.
4. **The browser test of WR-04 needs a sign-out that stays under way and then fails.** The fixture's `holdSignOut()` keeps the request until `releaseSignOut()`, which lets it reach the server and so work. One additive step releases it as a failure, answered as `failSignOut()` answers, TSDoc'd and in the header's list; the two existing steps stay as they are. The Back is pressed by the page's own `history.back()` (a fixture step), because Playwright's `goBack()` waits for a navigation the hold cancels. The user and page are those of a test that signs out at once with no modal (nothing unsaved and nothing left to count), on a second page of the app, so there is an entry to go back to.
