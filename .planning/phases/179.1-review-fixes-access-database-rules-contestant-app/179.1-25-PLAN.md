## Rulings and deviations carried by this plan

1. **The delete confirmation is in the card** (a second press of Confirm, with Cancel), not a modal: no `<dialog>` is added (execution rules, code rules).
2. **Edit opens the editor at its details step for the card's contest**, through the parameters the editor's own step selection reads (`stepSelection.ts`); no new route is added.
3. **Delete writes the whole set minus one**, read from the stored set it shows (`readFrom` as the editor passes it), so a set changed elsewhere is refused as `changed`.
4. **'Can add another'** is true while nominations are editable, answers are not locked, and an election of the entity's reach still has a constituency the entity holds no nomination in, read from the data `nominationFacts` already receives; the rule is unit-tested on its own.
