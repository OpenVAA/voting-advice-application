# Phase 179.1 Plan 67: The server settles a logout deadline it has acted on Summary

**A tab that met the deadline sign-out keeps the session it signs in with: `logoutDeadlineHandle` writes `logout-deadline=passed` into the response that signed it out and never acts on that value, the page removes the drafts only on that marker, and plan 63's clearing of the cookie is now pinned by unit and E2E tests shown red by mutation.**

## For the operator's reading

**What a user now meets.** A Log out count left running in a tab that was then closed still ends the session at the browser's next request, in any tab. A tab that was already open meets that sign-out once, at its next request, and lands on the login screen. When the user signs in again in that same tab, without a reload, the session is kept: the server wrote `passed` into the cookie when it signed out, and it never signs out on that value. The Contestant App's drafts of the ended session go at that tab's next navigation, or at the next document load. That load also removes the marker, so the marker never carries into a later session. A page never removes drafts on its own clock. A sign-out the server could not make writes no marker, so the server tries again at the next request.

**The clearing plan 63 promised now fails a test when it goes.** Continue, the ✕, Escape, a close the platform makes and a navigation each remove the cookie. The modal's Log out and the count's end each start their sign-out with the cookie already gone. A failed sign-out at the count's end leaves no cookie, and the session is alive at the server's next request. A reload of the tab that holds the counting modal removes the cookie and keeps the session.

**The operator's answer at Task 2, word for word:** `a`

That is option a as the plan states it: Log out is browser-wide, and the browser keeps the deadline. WR-01 and WR-03 are fixed, and WR-02 is accepted as designed. Plans 68 and 69 proceed as written: plan 68 builds the two-cookie rework (WR-01, WR-03, IN-08), and plan 69 enters the accepted-risk row for WR-02.

**What stays unproven** (rule 12). No run covers:
- cookie handling in WebKit and Firefox;
- Safari's cap on the life of a cookie a page writes;
- a real closed browser;
- a device clock that is off;
- a cookie planted for a parent domain;
- the identity provider's callback and the Admin App's sign-in after a deadline sign-out, which were read and not run.

WR-01, the browser's clock against the server's, still holds until plan 68: the page writes a time by its own clock and the hook compares it with the server's. The guide's § Logout lags the code until plan 68 rewrites it. It does not yet describe the settled marker.
