## How to read this

- **COVERED:** a standing automated test asserts the truth and was seen red at that assertion. For a run-count truth, the run's own files show it.
- **PARTIAL:** a test asserts part of the truth, and the rest is one of these: resting on a step never seen red, using a stub where a real browser path exists, or on a path no browser run drove. Each row names which.
- **MISSING:** no standing test asserts the truth. A one-off check may exist, and the row says so. Most of these hold when read.

## The two weaknesses

Both of `179.1-CR01-VALIDATION.md`'s weaknesses are closed. Each has a control that was red for the reason at issue, read here from that run's `results.json`.

**1. The listener dropping after one dialog: closed by `179.1-44-mut-dialog`.**
- `pressAnsweringPrompt` is gone. `nativeDialogs` calls `page.on('dialog', …)` when the fixture starts, and never removes it.
- With `beforeNavigate` no longer standing down, test 4 went red at its last line, with `confirm` and `beforeunload` in the list and every earlier step passing. The old helper would have seen nothing, and the path ended on the login screen.
- **Limit 1:** it was red in test 4 alone. On the profile and a question the discard empties the guard first, so this mutation raises nothing there. The same line in the other tests is not shown able to fail, though it is the same code.
- **Limit 2:** N1 and N2 do not record, and test 6 clears before its press.
- **Limit 3:** the list is read at the last line, so a dialog after it is not seen.

**2. The "past the count" step unable to catch a live count: closed by `179.1-44-mut-count`.**
- `#logout` no longer asks, so no dismissed question stands between a live count and its `POST`.
- With `TimedModal` no longer stopping its count, N2 and test 1 both went red in `expectStillSignedIn`, `Expected: 200`, `Received: 303`. The live count really ended the session, and the step saw it.
- **Limit 1:** `expectNoSignOutRequest` stopped behind that line and has never been red, as row `44-13` says. It matters if a count's `POST` is still in flight when the server is asked, which by reading could let the first line pass. No run tried this.
- **Limit 2:** the steps exist after Continue and after a navigation only. Tests 3 and 4 install no clock, and the ✕ and Escape have no past-the-count step in a browser.
- **The old test 5 step itself no longer exists:** test 5 now asserts that the count ends the session.
