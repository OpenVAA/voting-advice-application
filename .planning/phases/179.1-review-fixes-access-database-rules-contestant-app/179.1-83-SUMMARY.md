# Phase 179.1 Plan 83: the logout announcement between tabs Summary

**A Log out now posts one message on the `BroadcastChannel` `openvaa-logout` before its sign-out request, and a tab that follows a sign-out it did not start shows "You have been logged out in another tab or window." only when it heard that message no more than 5 000 ms before its client's `SIGNED_OUT`. Every other such sign-out leads to the login page with no reason, in both apps. Targeted run 707 of 707, with both other-tab titles passed.**

## For the operator's reading

- **What changes for a user.**
  - After another tab's Log out, a tab still says "You have been logged out in another tab or window."
  - When the auth client drops the session by itself, the tab now goes to the login page with no reason. That covers a refused refresh, a session `getUser()` finds gone, and a hosted project's session time-box. Before, those cases named another tab.
  - The drafts are discarded in both cases, as before.
  - No new sentence and no change of copy.
- **What stays unproven (rule 17).**
  - The unannounced case in a browser: it is unit-tested only. No browser test makes the auth client sign out by itself.
  - A Log out whose request takes longer than the window. The other tab then gets no reason, because the announcement is older than 5 s at its `SIGNED_OUT`.
  - Safari, Firefox, WebKit and phones, `BroadcastChannel` among them. The targeted run is Chromium alone.
  - A browser without `BroadcastChannel`. Its follower shows no reason (unit-tested).

- **G-179.1-WR16I-1 is closed (A1, the review's WR-01).**
- **The module**, `apps/frontend/src/lib/auth/logoutAnnouncement.ts`, is imported directly, not through the barrel:
  - Each document holds one channel, opened by its first listener and closed when its last one stops.
  - `announceLogout` posts on that channel while one is open, so a document never hears itself. With none open, it opens a channel, posts and closes it at once.

## Decisions Made

- **The time last heard is kept after the last listener stops.** A stopped listener stops hearing new announcements, which the case `is not heard by a document that has stopped listening` asserts. It does not forget one it already heard. The plan does not ask for forgetting.
- **A clock set back does not stretch the window.** `heardLogoutAnnouncement` needs the elapsed time to lie between 0 and 5 000 ms.
- **The announced cases also assert the store's reset** (Contestant App), so "the store's reset called as in the announced case" is measured in both cases.
- **The drafts cases with either answer.** They pass unchanged with the default `heard` `false`. They were also run once with `heard` `true` throughout (`179.1-83-drafts-heard`, exit 0, 4 passed), and the file was restored.
