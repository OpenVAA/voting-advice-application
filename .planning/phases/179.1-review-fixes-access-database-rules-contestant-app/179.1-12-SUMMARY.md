# Phase 179.1 Plan 12: the auth callback hands every mailed link to the confirm page Summary

**`GET /api/auth/callback` no longer verifies anything. It answers a token link with a 303 to `/auth/confirm`, carrying the same `token_hash`, `type` and `next`, in the request's locale.**
- Every E2E spec, fixture and setup that opens a mailed link now does what a person does, through `openMailedLink(page, url)`: it opens the link and presses Continue.
- The mails still name the callback's path; plan 13 changes that.

- **Files changed:** 20 (`git diff --stat 2c76aadad..HEAD`), none new
- **E2E runs:** one full held run, one red control, one red observation, three green controls, the close

## Accomplishments

- **The callback.** With a token and a type it does not refuse, the GET calls `redirect(303, buildRoute({ route: 'AuthConfirm', locale, token_hash, type, next }))`. Search values are passed raw, and an absent or empty `next` is left out. Without a token or a type, or for `invite`, `signup` or `email`, it lands on login with `authError`. It imports neither `verifyMailedLink` nor the claim. The refused set is `REFUSED_LINK_TYPES`, exported from `mailedLink.ts` and shared with `verifyMailedLink`.
- **The helper.** `openMailedLink(page, url)` goes to the link, waits for the confirm page (`waitUntilShown`), presses Continue and waits until the browser has left `/auth/confirm`. It logs nothing.
- **The openers.** The population was derived at run time (below). Every opener calls `openMailedLink`. In the "opened a second time" case both contexts press Continue. The retitled identity-provider case asserts the notice, Continue, and then the login page with `emailTaken`, whose text the fixture reads from the catalogue.
- **Task 2.** Plan 11's three confirm-page cases now open the link as received. The scanner case fetches it with redirects followed. The new case asserts that the first navigation ends on `/auth/confirm` with exactly `token_hash` and `type`, then Continue signs the user in. `confirmPageUrlOf` and `baseLocaleConfirmPageUrlOf` are removed. The two confirm-page scans follow the received link: the callback's redirect lands on the base-locale path, so their reach proof holds.
