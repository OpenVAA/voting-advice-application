## Top 3 Priority Fixes

1. **The disabled, loading Log out loses keyboard focus, and its new label is announced as "Loading"** (F6-1). [MARKUP] `Button` sets native `disabled` when `loading` is true. [PREDICTED] A keyboard or screen-reader user who presses Log out has focus on a button that becomes disabled. Browsers then drop focus to `<body>`, and the user hears "Loading…" (`common.loading`) or nothing, never that a sign-out is running. Fix: keep the button focusable while loading by using `aria-disabled` plus `aria-busy="true"` instead of native `disabled` for the loading state, and refuse the click in the handler (`leaving` already does). Wording is limited by C-copy: pass `loadingText={t('common.logout')}` so the label does not change at all, which needs no new copy.
2. **The password toggle and the held ✕** (WR-06 and IN-04 in `179.1-WR16G-REVIEW.md`). Keyboard activation moves focus into the field, so a second Space types instead of toggling. There is no `aria-pressed`. While the modal is held, the ✕ reads as operable but does nothing. Fix as that review says: focus the field only when `event.detail !== 0`, add `aria-pressed={passwordRevealed}`, and add `aria-disabled={holdOpen ? 'true' : undefined}`.
3. **The admin email field lost its placeholder and native required, and the key is orphaned** (F1-3). [MARKUP] `common.emailPlaceholder` is no longer read anywhere in `src`. `required` became `aria-required`. [PREDICTED] An empty submit cannot happen (`canSubmit` gates it), so the loss is the hint text and the browser's own validation bubble. Fix: pass `placeholder={t('common.emailPlaceholder')}` to `Input`, which restores the earlier copy and keeps the key live. Otherwise remove the key with the operator's leave.

## Detailed Findings

### Pillar 1: Copywriting (3/4)

- **Passes.** [MARKUP] The logout modal's `itemsLeft` and `questionsLeft` now compile to sentences, not keys, in seven locales. `feedback.rating.valueLabel` at 1 reads text. French 0 no longer reads as the singular. `error.403` and `error.loginFailed` read French and Luxembourgish (machine-translated with no native check, as rule 5 allows). The dead `components.video.timeLeft` ("one minutes  left") is removed. This is the round's largest copy gain.
- **F1-1, WARNING, the spinner relabels the button "Loading".** [MARKUP] `Button` substitutes `common.loading` when `loading` is set and no `loadingText` is given. Neither `LogoutButton` passes one. [PREDICTED] The header's "Log out" becomes "Loading…", which describes neither the action nor the state. Fix: priority 1.
- **F1-2, WARNING, the failed-sign-out alert title is generic.** [MARKUP] It now reads `error.general` ("Something went wrong"; fi "Jotakin meni pieleen, anteeksi"). This was accepted at C4=a and fixes the duplicate-name problem, but the title itself no longer mentions signing out. Only the body `common.logoutFailed` does. Recorded, and no change is asked within this grant.
- **F1-3, WARNING, placeholder dropped on admin email.** See priority 3.
- **F1-4, WARNING, the dialog's name over unsaved edits is a whole sentence.** [MARKUP] `aria-label={common.logoutUnsavedChanges}` while the visible `h2` says "Log out". [PREDICTED] The name and the visible title disagree, which runs against WCAG 2.5.3 *in spirit* (the visible label is not part of the name). C3=a chose this over a new title, and it was approved.

### Pillar 2: Visuals (3/4)

- **[OBSERVED]** Voter-results desktop, new baseline against old: the layout is the same. The only visible difference is in the toolbar row. The search field sits about 2 px further right and is marginally wider, and the Filter button area shifts slightly. Everything else, including cards, tabs, header and hero, is identical. This agrees with [RECORDED] 65-SUMMARY. The mobile images were not viewed.
- **Passes.** [MARKUP] The admin login's email field is now the shared `Input` with a visible label (7C), consistent with the password field below it.
- **F2-1, WARNING, every small circular ✕ grows.** [MARKUP] The `:where` rule in `utilities` now beats `btn-sm`'s text size, so the ✕ glyphs of Modal, Alert, Video and Drawer (all `btn btn-circle btn-ghost btn-sm`) render at `text-md` inside a fixed `btn-sm` circle. [PREDICTED] The glyph fills more of the circle. This is not in any baseline image (no visual spec opens a modal). Look at it in UAT.

### Pillar 3: Color (3/4)

No colour token, class or hardcoded colour changed. [MARKUP] **WARNING:** the admin email field now carries `onShadedBg`, which changes its background treatment from the raw `.input`. Its text and border contrast on the frontpage layout were not measured. This holds the score at 3.

### Pillar 4: Typography (3/4)

- **Passes.** [MARKUP] One text size for controls (`text-md`), with an iOS floor of `max(16px, 0.9375rem)` that stops focus zoom. Both rules use `:where()`, so an explicit utility on the element still wins. That is a careful choice.
- **F4-1, WARNING, `-sm` and `-xs` controls lose their size step.** [MARKUP] `btn-sm`, `input-sm` and `select-sm` now render body-size text. Where a design used `-sm` to subordinate a control, such as toolbar filters or secondary buttons, the hierarchy flattens. The operator ruled this app-wide and accepted it. It is recorded, not disputed.
- [RECORDED] The iOS branch is not exercised by any run (Chromium and desktop WebKit lack `-webkit-touch-callout`, according to 65-SUMMARY), so the floor is unverified in practice.

### Pillar 5: Spacing (3/4)

No spacing class or arbitrary value was added. The only arbitrary value is the iOS `text-[max(16px,_0.9375rem)]`, which was moved and not created. [MARKUP] The admin email gains a `mb-md w-full max-w-md` wrapper, which matches the password field's wrapper. **WARNING [PREDICTED]:** larger text in fixed-height `btn-sm` buttons and the results toolbar may crowd or wrap at 320 px and in long locales (da, fi). This was not seen, and the mobile baseline was not viewed in this audit.

### Pillar 6: Experience Design (2/4)

- **Gains.** [MARKUP]
  - **No escape mid sign-out.** The modal is held during a sign-out: Escape, the backdrop, `cancel` and a forced platform close re-open it. A navigation started meanwhile waits for the sign-out and is not prompted.
  - **The count follows the wall clock.** The timer ends on its true time after sleep or freeze.
  - **A closed tab still ends the count.** The deadline cookie removes drafts on the next load.
  - **Spinner and disabled state** on Log out in both apps.
  - **The alert's ✕ is de-duplicated** for assistive technology.
  - **Password field.** It no longer autocapitalises, and a pointer press keeps the caret.
  - **Admin email.** It enables sign-in as you type.
- **F6-1, WARNING, focus lost on the loading Log out.** See priority 1.
- **F6-2, WARNING, WR-06** (the password toggle on keyboard). Cross-reference only.
- **F6-3, WARNING, IN-04 and a silent hold.** [MARKUP] While held, the ✕, Escape and backdrop do nothing and give no feedback. The modal's own Log out is not shown as loading inside the modal; only the header button's `loading` reflects it. [PREDICTED] A user who presses ✕ during a slow sign-out sees nothing happen. Fix: put `loading={leaving}` on the modal's Log out action as well, which uses the same grant (15) and an existing prop.
- **F6-4, WARNING, the contestant header button spins during the modal's own sign-out too.** [MARKUP] `loading={leaving}` is also true when the count's end or the modal's Log out started the sign-out. The grant names "the Contestant App's header button where it signs out directly". [PREDICTED] This is harmless, since the button sits behind the modal, but it is broader than the grant's wording. Record only.
- **F6-5, WARNING, the progress bar can disagree with the deadline after sleep.** [MARKUP] The deadline now follows the wall clock, but the visible bar and `timeLeft` still come from a `tweened` store. [PREDICTED] After a short suspend, the number shown can lag until the next check ends the count. The ending is correct, so this is a minor visual inconsistency.
