| CR-01 | T-179.1-165 | **yes** | The row's mitigation removes the cookie when the modal closes, when the count's own sign-out starts and when a document loads. ## T-179.1-164

The acceptance makes three claims.

1. "The cookie can only end the session of the browser that holds it." **This holds.**
2. "Removing it keeps one's own session." **This holds.**
3. "Writing it from elsewhere needs script on this origin, which owns the session already." **This does not hold.**

The cookie's name carries no `__Host-` prefix. So a response from a sibling subdomain under the same registrable domain can set `logout-deadline=0; Domain=<parent>`. On a host without HSTS, a response injected over plain HTTP can do the same. `hasLogoutDeadlinePassed('0', now)` answers `true`.

Nothing then removes that cookie. The page removes only the host-only cookie (`deadline:73`), and the server removes nothing (CR-01). For as long as the planted cookie lives, the browser is signed out on every request and its drafts are removed on every document load. The harm is limited to the availability of one browser; nothing is elevated.

The row closes in one of two ways. The operator can accept it once the third claim is corrected. Or IN-08's fix can be applied: the server removes every copy it finds, and the cookie takes the `__Host-` prefix over HTTPS.
