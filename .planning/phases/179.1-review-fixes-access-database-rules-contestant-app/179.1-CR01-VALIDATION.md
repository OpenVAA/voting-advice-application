## Weaknesses no summary names

Both are inferred from reading the code, and no run tested them. Each rests on Playwright's documented behaviour of auto-dismissing a dialog when the page has no `dialog` listener.

1. **`pressAnsweringPrompt` cannot pin "asked once" (truths 41-1 and 41-3).** Its poll succeeds the moment `raised` equals `['confirm']`, and `finally` then removes the listener. A second question raised after that is not recorded: Playwright dismisses it, and `expectAskedBeforeSignOut` reads a list that stops at the first. Only the unit cases pin "once", with a fake guard's `ask`. Tests 1 to 5 do not take `nativeDialogs`, the one fixture that records throughout. It listens to every dialog for the whole test, but it is asserted only in test 6.

2. **Test 5's "past the count" step likely cannot catch a live count (truth 41-5).** If a count did run over the edit, its end would go through `#logout`, which asks. With the listener gone, Playwright dismisses that question, so nothing is signed out and no request is sent. Both `expectStillSignedIn` and `expectNoSignOutRequest` would then pass. This is the shape WR-04 faults in plan 33's step, reached by a different route. The product's "no modal" condition is still pinned, by the poll and `expectDialogClosed`, and the count lives in the modal. What is overstated is the step's claim that it observes no count.
