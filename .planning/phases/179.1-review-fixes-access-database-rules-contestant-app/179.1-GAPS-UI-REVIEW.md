## Top 3 Priority Fixes

1. **The password toggle's icon can disagree with the field's state** ([IMAGE] `-desktop-revealed.png`: readable `sample text` beside the open eye, while `-phone-320.png` shows the slashed eye in the same state). The icon tells the user the opposite of what is on screen, on a security control. `Icon.svelte:42` loads the SVG through a dynamic `import()`, which is a likely cause but is **unconfirmed**: the probe that took the image was discarded. Fix: re-take the image after waiting for the icon, and if the lag is real, render both SVGs and toggle visibility, or preload `hide` when the kind mounts.
2. **Typed password text touches the toggle** ([IMAGE] desktop and phone; [LOG] toggle left edge 864 px). Characters sit against the toggle's hit area and its ring, and the last letter of `sample text` reads as cut in the desktop image. Fix: in Input's branch 6.5 (`Input.svelte:737`), add an end padding to the control or a gap between control and toggle, for example `pe-sm` added to this branch's class only. Do not change `inputClass`, which every kind shares.
3. **A loading main button dims its own label to 20%** ([MARKUP] `Button.svelte:155-162`). `isDisabled` includes `loading`, so `group-disabled:text-neutral/20` applies to the label while it reads "Loading". On the confirm page that label is the main feedback that Continue was pressed. Fix: apply `DISABLED_TEXT_CLASS` only when `disabled` is set and `loading` is not, and check the result in a rendered image.

## Detailed Findings

### Pillar 1: Copywriting (3/4)

- **WARNING, notice verb mismatch.** [MARKUP] `messages/en/contestantApp.register.json:49` says "Please log in with your email and password", and the button under it is `common.login`, "Sign in" (`messages/en/common.json:54`). Change the sentence to "sign in".
- **WARNING, notice offers an action it has no control for.** [MARKUP] The same sentence ends "or check your email for the confirmation link", while the controls offered are sign in, forgot password and close.
- **WARNING, dismissal labelled as a generic "Close".** [MARKUP] `register/+page.svelte:330` uses `common.close`. The action removes the cookie that brings the notice, so it means "don't show this again". A specific label such as "Dismiss" would say so, and the component doc already calls it Dismiss.
- **WARNING, casing is mixed across these surfaces.** [IMAGE] "Forgot Password?" beside "I have not set a password yet" and "Sign in"; [MARKUP] "Log Out" in `common.json:55`.
- **Passes.** [MARKUP] Confirm copy is specific per link type, and the signed-in warning states the consequence. "Remove portrait" names the object, and "Reveal password" and "Hide password" are clear.

### Pillar 2: Visuals (2/4)

- **WARNING, icon and field state disagree.** See priority fix 1. [IMAGE] The markup at `Input.svelte:743` is correct, so this is a rendering or timing question.
- **WARNING, heading focus ring on landing.** [IMAGE] `-desktop-empty.png` draws a blue box the full column width around "Sign in", with a small notch at its top edge, and it is the strongest thing above the fields. It is focus placement from the post-navigation reset, so it may not show after a pointer navigation; the image shows only the probe's path. The notice's Dismiss moves focus to the same kind of heading (`register/+page.svelte:85`), so a similar ring is predicted there. [MARKUP]
- **WARNING, two `main` buttons on one page.** [MARKUP] `register/+page.svelte:322` and `:415`. `Button.svelte` says there should generally be one. With the notice shown, "Sign in" and "Continue" compete, and they recommend opposite paths. Consider making the notice's Sign in the plain variant, or hiding Continue's prominence while the notice shows.
- **WARNING, notice mixes alignment.** [MARKUP] Its h2 and `<p>` set no centring, and `h2` in `app.css` has none, so they start-align, while its buttons are centred (`:317-319`) and so is the page's title. To be judged on a rendered image.
- **WARNING, admin login shows two field shapes.** [MARKUP] Native email with a placeholder over an Input row with an inside label. Already filed by plan 37 for phase 179.2, noted rather than counted.
- **Known and filed, not counted:** the toggle's clipped focus ring ([IMAGE] confirmed in `-desktop-toggle-focused.png`, side strokes only; [LOG] toggle 44 px tall in a 44 px row). The blue-looking Log out icon ([IMAGE] confirmed in both preview images, whereas `LogoutButton.svelte:101` passes `color="warning"`). `Banner.svelte:40,107-112` sets `--headerIcon-color` to primary for enabled direct-child buttons, which reads as the cause, but it is [MARKUP] and no pixel was sampled.
- **Passes.** [IMAGE] The Log out icon sits in the header beside Close with clear separation on desktop and phone, and `-desktop.diff.png` shows it as the only strong difference. [IMAGE] Email and password rows share one shape at 1280 and 320 px. [MARKUP] All new icon-only controls have `aria-label` and `title`.

### Pillar 3: Color (3/4)

Tokens only: no hardcoded colour was added on these surfaces.

- **WARNING, two focus-ring colours on one form.** [IMAGE] Blue on the heading in `-desktop-empty.png`, dark on the toggle in `-toggle-focused.png`; [LOG] toggle outline `rgb(51, 51, 51)`. The ring should have one colour.
- **WARNING, disabled colour applied to loading state.** See priority fix 3. [MARKUP]
- **WARNING, lock icon contrast is about 1.45:1.** [MARKUP, plus debug-session figures] The operator's ruling asked for it, so this is recorded and not scored down. But the change sits in `Button`, so every disabled icon Button dims too, including controls where the icon is the only content; plan 39's table lists them. No image confirms any of them.
- **WARNING, radio border contrast unmeasured on the compiled component.** [MARKUP] Plan 34's test reads a width; the 7.59 and 5.67 figures come from a debug session's live DOM.
- **WARNING, the chosen row's fill is weak.** [MARKUP] `EntitySelector.svelte:112` uses `bg-base-200`, `#e8f5f6` on light, on what I infer from the page is a white card, about 1.1:1. The radio's mark carries the meaning, so the "told twice" in the component doc is only nominally true.
- **WARNING, Trash in `warning` is unseen.** [MARKUP] `profile/+page.svelte` passes `color="warning"`, and nothing overrides it there, so unlike Log out it should render red. Plan 38 records that its look and contrast were not measured.

### Pillar 4: Typography (3/4)

- **WARNING, typed password is smaller than its label.** [IMAGE] All three states; `inputClass` uses `input-sm` (`shared.ts:21`). This is the existing Input row style, and on a password field it matters more because the user reveals the text to check it character by character. Masked dots are small too.
- **WARNING, legend is the quietest text in its group.** [MARKUP] `EntitySelector.svelte:98` uses `small-info` (secondary, `text-sm`), while option names are body size. A required question is named in the least prominent type in the group.
- **WARNING, notice's h2 competes with the page title.** [MARKUP] `text-xl` under `text-2xl`, close in size with the same weight.
- **Passes.** [IMAGE] Sign-in hierarchy is clear. [MARKUP] Confirm page uses inherited h1, body text and one bold notice, with no arbitrary sizes.

### Pillar 5: Spacing (2/4)

- **WARNING, no gap between typed text and toggle.** See priority fix 2. [IMAGE] The control has `px-0`, and the row has no gap. Text also ends about 56 px earlier than it would in the email row, so typed values in the two rows are misaligned at the end [inferred from the image's geometry; the email row was empty in every image].
- **WARNING, admin login widths differ.** [MARKUP] Fields are in `max-w-md` (`admin/login/+page.svelte`), while the main Button is `w-full` of the form, inside MainContent's `max-w-xl`. Predicted: a button wider than its fields. Check the project's `max-w-*` scale on a rendered page before fixing.
- **WARNING, Trash has no gap from the thumbnail, and phone width is unmeasured.** [MARKUP] `inputAndIconContainerClass` has no gap, the Trash adds about 56 px to the row, and the thumbnail is `w-60` with `-mr-8`. A long label such as an organization's logo label at 320 px is the case to look at.
- **Passes.** [MARKUP] `mb-md` on the notice and `w-full` on the confirm page's `main` are in the token scale and match the operator's requests. The confirm page's width is guarded by plan 40's geometry test. [MARKUP] `EntitySelector`'s offset uses `--spacing-md` and DaisyUI's own radio size, so no arbitrary value was added; the row's right-to-left case is unmeasured.

### Pillar 6: Experience Design (2/4)

- **WARNING, toggle icon lags or disagrees.** See priority fix 1. **Unconfirmed cause.**
- **WARNING, loading label at 20%.** See priority fix 3. [MARKUP]
- **WARNING, the confirm page has no way back when signed out.** [MARKUP] `auth/confirm/+page.svelte:77` shows Cancel only when signed in, and the page has no header, logo or menu. Someone who opens an unwanted link and is not signed in can only press Continue or close the tab. Closing the tab is safe, so this is minor, but the page gives no sign of that.
- **WARNING, the Trash stages its removal with no visible undo beside it.** [MARKUP] `profile/+page.svelte` says it "stages its removal, which a save stores", and the Trash then goes with the image. I found no undo control in the row; abandoning the page goes through the navigation confirmation. The user is not told the removal is pending until Save.
- **WARNING, no hover state on a whole-row pointer target.** [MARKUP] `EntitySelector.svelte:112` has a fill for `:checked` but none for hover, although the label covers the row.
- **WARNING, header Log out is natively disabled until the modal binds.** [MARKUP] `LogoutButton.svelte:97`. Plan 40's zero-budget measurement shows the screenshot is taken after this, so the disabled paint has not been seen. Now that icons dim, a server-rendered first paint is predicted to show it faint, then coloured.
- **Passes.** [MARKUP] Double-submit is guarded on the confirm page. The notice's Dismiss handles non-success and moves focus. Radios are native, one tab stop, with error wired through `aria-describedby`. The Trash returns focus to the upload button, and is unit-tested. The password value is masked in the server render, and a real `<button type="button">` toggles it.
