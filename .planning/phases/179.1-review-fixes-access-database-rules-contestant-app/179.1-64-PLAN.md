## Rulings carried by this plan

1. **G-4, confirmed by differential (2 of 2 each).** `action="login"` is relative; after Back the address stays `/admin`, the form posts to `/login`, which answers 404 HTML, and `use:enhance`'s JSON parse becomes the root error page's title. With the action set to `/admin/login` the answer is a 303 to the home; with no action it is a 405. The action is `getRoute.current('AdminAppLogin')`, which carries the locale. The test asserts the home and never the parser's message (UAT test 4's decision).
2. **G-2, test code only.** The title becomes `after a sign-out here and a sign-in in another tab: after Back, a reload reaches the home`, and `expectLoginFormStandsWithNoMessage` leaves that test; the link's test keeps it. Its red is the production mutation plan 54 used, `routes/+layout.server.ts` returning an empty `supabaseCookies`, under which the reload ends on the error page (UAT test 2: mut-cookies turns it red).
3. **7C.** The raw `<input type="email">` with its hidden label and placeholder becomes the shared `Input`, `type="email"`, labelled `common.email`, with `id="email"` (the fixture's `#email`) and `name="email"` (the action), `autocomplete="email"`, `validate={false}`, `inputmode="email"`, `autocapitalize="none"`, `spellcheck="false"`, `aria-required="true"`, `onShadedBg`, in the row `class="mb-md w-full max-w-md"` the password field sits in. `Input`'s email kind writes its value on `change` alone, so an `oninput` writes the live value as `EmailField` does; with `bind:value` alone `canSubmit` stays false and `fillAwaitingScript` hangs (read in the diagnosis). `EmailField` itself lives in the Contestant App's library, so the Admin App uses `Input` directly. The visible label is 7C's visual change.
4. **The register page, checked as the gap asks.** `routes/contestant/register/+page.svelte` posts its dismissal to `?/dismissRegistered`, a query-only action that resolves against the address the page stands at. Read whether a redirect can draw that page at another address, as the gate's redirects did the Admin App's form after Back. If one can, its action names the register route absolutely from the route map in this plan's commit, and the summary records the path read; if none can, the summary records why, and nothing changes. No test is written for a path that was not driven.
5. **8B.** The password kind's control is `type="text"` when revealed, with no `autocapitalize`, `autocorrect` or `spellcheck`, so iOS treats it as a sentence field. It gets `autocapitalize="none"`, `autocorrect="off"` and `spellcheck="false"` in both states, explicit values, because WebKit's reading of an empty `autocapitalize` differs from its documentation. If the element's type in Svelte lacks `autocorrect`, the attribute is spread from a typed object rather than the type widened. iOS is unmeasured: plan 66's list.
6. **8C.** The toggle cancels its `mousedown` default, so a pointer press does not take focus from the input, and after the flip its handler focuses the control and sets the caret to the end with `setSelectionRange`, so a keyboard press lands on the input too and no engine selects the contents. Measured in Chromium and desktop WebKit: a bare `focus()` restores the caret; iOS selection on a programmatic focus is unmeasured.
