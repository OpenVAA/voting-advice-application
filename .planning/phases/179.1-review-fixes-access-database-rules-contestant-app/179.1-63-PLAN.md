## Rulings carried by this plan

1. **The planner establishes the bound, as the gap asks.** The hosted time-box and inactivity timeout are Pro-plan-only, act at the next refresh, and bound a session at the setting plus the JWT's hour: an outer bound of hours, never the count's 30 seconds, and a `config.toml` edit the round's rule 7 forbids. A browser runs no script in a closed tab. So the bound is a deadline stored outside the document, a cookie, which the server enforces at that browser's next request; a browser that never makes another request keeps a session nobody else can use without that browser's cookies. The hosted bound goes on plan 66's list as an operator item.
2. **The cookie.** `COOKIE.logoutDeadline = 'logout-deadline'`, TSDoc'd in `lib/cookies/index.ts`: the time at which the count's sign-out falls due, as milliseconds since the epoch, plus a grace of 10 seconds, so a count that runs always signs out through its own flow first. Written by the page, so not `httpOnly`; `SameSite=Lax`, `Path=/`, `Secure` on HTTPS, and a max age of 400 days, the session cookie's own under `@supabase/ssr`'s defaults, so it outlives a closed browser as the session does. It names no user. A user who removes it only keeps their own session.
3. **Who writes and clears it.** `LogoutButton` writes it when the modal opens with a count, and clears it on every close of the modal and at the start of its `leave`, before the sign-out request, so the server never signs out a session the count is already ending, and a failed sign-out at the count's end stays as `T-179.1-104` has it. The root layout clears it when a document loads before its time, and when the time has passed it first calls `discardContestantDrafts`: the count's sign-out discards drafts, and the next document is the first browser step after a closed tab.
4. **The hook.** `logoutDeadlineHandle` in `hooks.server.ts`, between `supabaseHandle` and `paraglideHandle`: when the cookie's time has passed it calls `event.locals.supabase.auth.signOut({ scope: 'local' })`, logs a failure other than a missing session with the error's name alone, and resolves; it leaves the cookie for the browser's step. The cookie removal its sign-out writes reaches the response, and the gate after it reads no session, so a protected route goes to the login page. `hooks.server.ts` is on the boundary's allowlist; the gate's lines do not change.
5. **The in-page count follows the wall clock.** `TimedModal` keeps the deadline `Date.now()` gave when it opened, checks it every second and on `visibilitychange` to visible, `pageshow`, `focus` and `resume`, and ends the count once when it has passed, with plan 62's await. A frozen, suspended or locked document runs no timer; on resume one of these runs before the user can act. Chromium's timers follow a clock that stops during system sleep, so a closed lid now ends the count on wake rather than after the rest of it. What a real device does is UNCONFIRMED and goes on plan 66's list.
6. **The tests, with no fixed wait.** The closed tab: the test rewrites the cookie's time into the past through the context, which stands for the time that passed. The suspended tab: with the page's clock installed and running, `page.clock.setSystemTime` moves the wall clock past the count without firing a timer, which is what a frozen tab sees on resume, and the test asserts a sign-out request within `TIMEOUTS.slowPage`, 10 s, where the relative timer would wait 30 s.
