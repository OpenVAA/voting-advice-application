## How to read this

- **COVERED:** a standing automated test asserts the truth and was seen red at that assertion. For a run-count truth, the run's own files show it.
- **PARTIAL:** a test asserts part of the truth, and the rest is one of these: resting on a step never seen red, using a stub where a real browser path exists, or on a path no browser run drove. Each row names which.
- **MISSING:** no standing test asserts the truth. A one-off check may exist, and the row says so. Most of these hold when read.
- **Would go red:** the test that fails if the truth stops holding. For a step never seen red, this is what the test is written to catch, not something observed.
- **Limit:** something the plan itself says no run shows. It is reported as a limit and never counted as coverage.
- **Tests:** in `tests/tests/specs/contestant/contestant-entity-selection.spec.ts`, each title beginning `the header's Log out`, unless the row names `admin-access`. N1, N2 and tests 1 to 10 are numbered as in `179.1-RULINGS-VALIDATION.md`.
