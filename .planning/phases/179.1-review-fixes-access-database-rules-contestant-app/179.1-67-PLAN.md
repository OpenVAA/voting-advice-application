## Rulings carried by this plan

1. **The mechanism for CR-01: the server settles what it has acted on.** Of the two fixes the review offers, this plan builds the first. `logoutDeadlineHandle`, after a sign-out that answered no error or `AuthSessionMissingError`, writes `logout-deadline=passed` (`LOGOUT_DEADLINE_SETTLED`) into the same response with the attributes the page writes: `path: '/'`, `httpOnly: false`, `sameSite: 'lax'`, `secure` exactly when `event.url.protocol` is `https:`, and a max age of 400 days (`LOGOUT_DEADLINE_MAX_AGE_SECONDS`, the value the page already uses). `hasLogoutDeadlinePassed('passed', …)` is false, so the hook never acts on it again and the action's `goto`, an identity provider's callback redirect and every later request keep the session they carry. The other option, signing out only a session issued before the deadline, is not built: it needs the hook to read the session's token, which `PROH-179.1-38` forbids, it still compares two clocks, and it leaves the cookie in place for ever.
2. **Who reads the marker.** `settleLogoutDeadline(discardDrafts, trigger)` moves from the root layout into `logoutDeadline.ts` (pure but for `document.cookie`, so the hook's module graph gains no runes module) and is called with `discardContestantDrafts` in `onMount` and in a persisted `pageshow` (`'document'`) and in `afterNavigate` (`'navigation'`). On the marker it calls `discardDrafts` once and removes the cookie, on either trigger: a tab that met the sign-out through a client-side request is on the login page by then, where no entity layout holds a draft handle (`leaveEntity` runs when the entity layout unmounts), so the next navigation is a safe place for the removal and the marker never lingers into a later session. On any other value: `'navigation'` leaves it; `'document'` removes a time still to come by the page's clock (plan 63's truth 3), removes a malformed value, and leaves a time that has passed for the server, which signs it out at the next request (ruling 3). Drafts are removed on the marker alone (`PROH-179.1-40`): the page never decides a sign-out by its own clock, which closes the audit's reading of WR-01 where a document removed drafts the server had not signed out.
3. **A sign-out that fails.** On an error other than a missing session the hook logs the error's name, as now, writes nothing, and lets the request through; the next request tries again. The docblock says so. This is a property of CR-01's mechanism, and `IN-01` stays the operator's finding (rule 14).
4. **Duplicates and parent domains (`IN-08`) are not built here.** They belong to the cookie's rework in plan 68, under the operator's ruling.
5. **The tests.** The tracer's E2E signs in again in the very tab that met the sign-out, without a document load: a document load would remove the cookie and hide the defect. The pins of plan 63's truths are shown red by a mutation of the code that clears the cookie, as the execution rules allow for a test of behaviour already in the tree; the unit cases read the real cookie in jsdom through `readLogoutDeadline`.
