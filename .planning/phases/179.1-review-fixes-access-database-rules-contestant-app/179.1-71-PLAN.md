## Rulings carried by this plan

1. **Where the page withdraws.** Both apps' Log out go through `AuthContextProvider.logout` in `apps/frontend/src/lib/contexts/auth/authContext.svelte.ts`: the contestant context binds it as `#authLogout` and runs it in `#runLogout`; the admin context runs `this.#authContext.logout()` in its `logout`. One call there, before `prepareDataWriter().logout()`, is the review's "call it from the contestant and admin logout flows before their sign-out request". The Contestant App's `LogoutButton.svelte` keeps its `clearLogoutDeadline()` in `leave` and in `handleClose`, which withdraw the button's own count as before.
2. **`withdrawAnyCount()`** is the exported form of the private `withdrawEveryCount()`, TSDoc'd: it forgets this document's own count and the tab's record and expires every copy of both cookies, whoever wrote them. When `logout-pending` holds the settled marker (`logoutDeadlineState` answers `'settled'`), it changes nothing: the settlement discards the drafts the server's sign-out ended and removes the marker itself (`PROH-179.1-40`). Outside the browser it does nothing. The settlement's own branches call the private function as before, or the exported one; one body, not two.
3. **`removalDomainsOf(hostname)`**, exported and TSDoc'd beside `parentDomainsOf`: `[]` when the host name holds a `:`, is an IPv4 address or holds no `.`; otherwise `[hostname, ...parentDomainsOf(hostname)]`. `parentDomainsOf` keeps its contract and its test `names none for example.org`, which stays true of it. `expireEveryCopy` uses `removalDomainsOf`; the hook's `'duplicated'` loop uses it in place of `parentDomainsOf`, and the import line follows. The deletes keep `{ path: '/' }` and their other defaults (`PROH-179.1-46`). A browser accepts a `Domain=` attribute equal to the host itself, so the removal names the copy a sibling host can plant.
4. **No E2E for G-2.** Every E2E origin is `localhost` or `127.0.0.1`, for which `removalDomainsOf` is `[]` by rule; the page's removal on a domain host is read and unit-tested, and the planted copy on a real apex host goes on plan 79's UAT list.
5. **The test of G-1 needs a tab with nothing to count.** In the user and question of the test titled `the header's Log out on a question with an unsaved answer and nothing left to count: the modal opens, and its count ends the session with the draft gone`, the modal opens on the unsaved answer alone. A second tab on the candidate's home has nothing unsaved and nothing to count, so its Log out signs out at once, with no modal of its own, which is the review's traced sequence. (A tab with tasks left would open its own modal and overwrite the orphaned count, and the test would pass at HEAD.)
