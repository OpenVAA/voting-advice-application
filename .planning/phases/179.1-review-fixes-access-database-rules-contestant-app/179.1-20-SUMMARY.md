# Phase 179.1 Plan 20: the email and code fields on Input Summary

**`EmailField` and `RegistrationCodeField` now render the input library's `Input`, so every email and code field of the entry flow is the shared `Input`: the registration panel, registration by email, the code's sign-in, the identity provider gate's address step, the email sign-in, the forgot-password page and the settings page. `Input` gained what the fields needed: a bindable `error` that a caller sets and an edit clears, `errorTestId` and `errorReason` on its inline error, and exported `focus()` and `checkValidity()`. Two more changes kept the screens behaving as before. A `validate` prop lets a caller turn off `Input`'s own check of an email or url entry. The text kinds now bind their field, so text typed before the page's script runs survives hydration.**

## What changed

| Where | Before | Now |
|---|---|---|
| `Input` props | internal `error` state only; the error message always `data-testid="input-error"` | `error = $bindable()`, `errorTestId = 'input-error'`, `errorReason` (`data-reason`), `validate = true`; `name` and `autocorrect` typed |
| `Input` exports | none | `focus()` (the one control, else the part's main field); `checkValidity()` (the control's own, `false` for a kind without one control) |
| `Input` edits | the error cleared on commit (`change`) | also cleared on `input` for the text-like controls and the textarea, and a caller's `oninput` is still called |
| `Input` text, url, email | `{value}` one-way, among spread attributes | `bind:value={() => fieldText, (next) => (fieldText = next)}` over a writable `$derived` of the value; on mount, a field whose text differs from the value is taken in as a commit. Number and date keep `{value}` (now branch 6.5) |
| `EmailField` | raw `<input type="email" bind:value required>` with its own label, hint `<p>` and `ErrorMessage` | `<Input type="email" validate={false} bind:value bind:error bind:this onShadedBg containerProps={restProps} …>`. It keeps every prop, the control's test id, name, autocomplete, inputmode, autocapitalize and spellcheck. The control is `aria-required="true"` in place of the native `required`, and `checkValidity()` is `value.trim() !== '' && field.checkValidity()`. An `oninput` hands the caller each keystroke |
| `RegistrationCodeField` | raw `<input type="text" bind:value>` | `<Input type="text" …>`, built the same way: name `code`, `autocomplete="off"`, `autocapitalize="characters"`, `spellcheck="false"`, `autocorrect="off"`, the hint by default. It now also exports `checkValidity()` |

## The two defects held-1 found, and their fixes

1. **A press lost to a layout shift.** `Input`'s email kind judges an entry on `change`.
   - Pressing Continue blurred the field, so `Input` showed "invalid address" under it. The row grew, the button moved, and the click landed where the button had been. `contestant-email-registration` › validation saw the field never focused.
   - The old field showed nothing until submit.
   - Fix: `validate={false}`, so the callers judge on submit as before.
   - This cause was inferred from the failure, not tested on its own. The held-1-r2 run passing is consistent with it.
2. **Text typed before hydration was wiped.** With spread attributes, Svelte writes `value` into an input during hydration without checking the current DOM value. A `fill` made before the page's script ran was overwritten with `''`. This failed the forgot-password, login and email-registration specs, and others.
   - The old field used `bind:value`, which takes the DOM value in at hydration.
   - Fix: a function binding over a writable `$derived` in `Input`, plus a commit on mount.
   - Confirmed in isolation: `diag-1` was red without the binding and `diag-2` was green with it, on otherwise the same tree.

## Commit `dbf6fc5da`: "read a committed entry as the control reports it"

- **Files changed:** two test files, and nothing else.
  - `apps/frontend/src/lib/components/input/Input.externalError.svelte.test.ts`
  - `apps/frontend/src/lib/contestant/components/emailField/EmailField.svelte.test.ts`
- **Why the cases were wrong:** `5c6a85d82` committed the `validate` cases red. They typed values with surrounding spaces (`' not one '`, `' not an address '`, `' someone@example.org '`) and expected the parent to receive them unchanged.
  - An `<input type="email">` or `type="url"` sanitises its own value: the element strips leading and trailing whitespace, in jsdom as in browsers.
  - So the value could never hold the spaces, and those expectations were false whatever `Input` did.
  - The red in `unit-red-1c` was still a real one: each case failed first on its assertion that no error alert is shown.
- **What the commit did:**
  - It types the entries without spaces and compares the parent's value with the control's.
  - It removes one EmailField case, "hands over a committed address as typed". Without the spaces, that case could only compare the control with itself, so it could not be red.
  - The corrected cases were shown red again over the held-1 tree (`unit-red-1d`: 3 failed, all on the no-alert assertions) before the implementation commit.
- **What it did not touch:** no plan check, no verify block and no verdict script. Every check was run as written first and restated only at the known `--dirty-only` slash and `yarn -s` stages, with both logs kept.

## Deviations from Plan

1. **[Rule 1 - Bug] `validate` prop on `Input`.** Found in held-1. It is not in the plan's API list. Without it, the email field showed `Input`'s own error at the moment of a press and the press was lost. Default `true`, so no other caller changes.
2. **[Rule 1 - Bug] The single-line text kinds bind their field and take pre-hydration text in on mount.** Found in held-1 and confirmed by diag-1/diag-2.
   - This changes `Input`'s text, url and email kinds for every caller in one case: text typed before the script ran used to be lost, and is now kept and committed.
   - Otherwise they behave as before. Number and date are unchanged.
3. **[Rule 3 - Blocking] `name` and `autocorrect` typed on `InputPropsBase`.** `HTMLAttributes<HTMLElement>` has neither, and the fields pass both.
4. **EmailField uses `aria-required`, not Input's `required`.** Input's `required` would add a badge to every entry field. The native `required` is gone from the control, so `checkValidity()` answers false for an empty field itself. Every caller already asks for emptiness first, so no caller's logic changes.
5. **Both fields pass `onShadedBg`.** The entry pages are `bg-base-300`, on which Input's default row colour (base-300) would not show.
6. **The error is also cleared on `input`,** not only on commit, for the text-like controls and the textarea. A caller's `oninput` is still called. For the url and email kinds this means their own error disappears as the user types again.
7. **Rewritten unit cases that no longer assert old markup** (the hint's `<p>`, the root's `gap-xs`, the native `required`). Each is named in the ledger rows as loosened. They pass on both trees.
8. **A third and fourth unit red for task 1** (`-1c`, `-1d`), because of the `validate` fix and the premise correction.
9. **Restated checks.** `--dirty-only apps/frontend/src/lib` was restated as `apps/frontend/src/lib/` in both held controls and both verify blocks, and `yarn -s` as `yarn`. Neither the checks nor the verdict script were edited.

**Total deviations:** 3 auto-fixes to `Input` (two bugs, one blocking), 3 design choices recorded, and the known restatements.
**Impact:** the screens behave as before, and the fields keep text typed before hydration.
