# Phase 179.1 Plan 08: Identity find-or-create under a lock Summary

**`public.identity_entity_find_or_create` takes `pg_advisory_xact_lock(hashtext('identity-entity:' || p_user_id::text))`, reads the user's `registered_entities` record inside that lock, and answers `found`, `gone` or `created`. For `created` it writes the entity, the editor grant and the record in one transaction. Only the service role may execute it. Migration `00018` adds it, 44 `IEF:` pgTAP assertions pin it, and the full suite is green (615/615) while nothing calls it yet.**

## Decisions Made

- **`gone` answers `entity_id: null`.** The plan left the id open. A recorded id whose grant or row is gone no longer names the identity's entity.
- **Two refusals beyond the plan's list:** a user id naming no user gets 22023, and a malformed `registered_entities` record (or non-object metadata) gets 22000. Without them, an unknown user would fail later, on the grant's foreign key, after the entity was inserted. A malformed record would either be cast to a uuid and raise mid-function, or be overwritten by `jsonb_set`. The Edge Function's `registeredEntitiesOf` refuses the same shapes.
- The grant is inserted plainly, without `ON CONFLICT`: in the `created` branch the entity is brand new, so no grant can already exist.
