# Phase 179.1 Plan 68: The browser keeps the logout deadline, and only the tab that held the modal removes its count Summary

**The logout modal now keeps its count in two cookies. `logout-pending` holds a random id, and `logout-deadline` holds the same id, which the browser drops by its own clock 10 s after the count ends. The server signs out a request that carries the first cookie without the second, and it compares no time. Only the tab that held the modal can remove a count still running, which it knows by a record in `sessionStorage`.**

## For the operator's reading

**What a user now meets across clocks.** The deadline is the expiry the browser keeps for `logout-deadline`. A device whose clock is minutes off therefore neither signs out a user who is present nor keeps a walked-away user's session late. The new test sets the page's clock five minutes behind the server's, and a request made while the modal counts keeps the session. At the plan's start, the server read that page's time as already passed and answered 303.

**What a user now meets across tabs.** Log out is browser-wide, as you ruled at 179.1-67 (option `a`):
- A count whose tab is closed ends the session in every tab of that browser at its next request, and removes their drafts, just as a count left running does. The guide's § Logout now says so.
- A page opened in another tab during the count leaves the count alone. Closing the count's tab then still ends the session at the browser's next request (tested).
- A reload of the tab that held the modal removes its count, and the session stays (plan 67's test, still green on the two cookies).
- A page restored from the back-forward cache, whose modal is still counting, keeps its count (unit test only).
- More than one pending id at once signs nothing out, and every copy is expired, host-only and for each parent domain. A copy planted for a parent domain makes such a duplicate possible.

**What stays unproven** (rule 12). No run covers:
- cookie handling in WebKit and Firefox;
- Safari's cap on the life of a cookie a page writes (it applies to `logout-pending`'s 400 days);
- a real closed browser;
- a real device clock that is off (the test moves the page's JavaScript clock, not the operating system's);
- a cookie planted for a parent domain, and its removal (unit test only: no E2E origin has a parent domain);
- a page restored from the back-forward cache with its modal still counting (unit test only);
- the identity provider's callback and the Admin App's sign-in after a deadline sign-out (read, not run).

No removal reaches a copy of `logout-pending` planted with a path other than `/`, and the auth page says so. The `__Host-` prefix would close that over HTTPS, and it is not built.
