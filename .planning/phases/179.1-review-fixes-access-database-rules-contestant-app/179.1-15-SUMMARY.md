# Phase 179.1 Plan 15: the read-failure view Summary

**A failed read of the user's entity, or of the user's list of entities, no longer signs the user out. The entity load answers `{ entityReadFailed: true }` and the protected load answers an empty list with `entitiesReadFailed: true`. The entity layout and the app root then show the new `ReadFailure` view: the error message, a sentence saying the user is still signed in, Try again (`invalidateAll()`), the support block and logout.**

## What changed

| Where | Before | Now |
|---|---|---|
| entity `+layout.server.ts`, Stage 3 | `return await signOutToLogin(locals, lang, 'loginFailed')` | `return { entityReadFailed: true as const }`. The failure is logged as before. `signOutToLogin` is no longer imported, and the docblock says the load signs nobody out |
| entity `+layout.svelte` | `<ErrorMessage class="bg-base-300" />` for unusable data | `validity` has a `readFailed` state. Every state but `resolved` renders `<ReadFailure class="bg-base-300" />` |
| `(protected)/+layout.server.ts`, Stage 4 | `return await signOutToLogin(…)` on a failed list read | `return { gate: null, user, entities: new Array<UserEntity>(), entitiesReadFailed: true as const }`. Stage 2's sign-out is unchanged |
| `(protected)/+page.server.ts` | views `nothingToEdit`, `select` | `readFailed` is answered first, before the one-entity redirect and the empty-list view |
| `(protected)/+page.svelte` | two views | `readFailed` renders `<ReadFailure />` and nothing else |

An entity URL opened while the list cannot be read meets the entity load's existing membership redirect, because the list is empty. It reaches the root, which shows the view. Neither load reads a `url` property; every `*.tracking.test.ts` passed unchanged in each unit run.

## The view

`$C/readFailure/ReadFailure.svelte`, with `.type.ts` (`title?`, plus the root `div`'s attributes), an `index.ts` barrel and a TSDoc `@component` block:

- the root `div` carries `data-testid="contestant-read-failure"`, and its classes are merged through `concatClass`
- `ErrorMessage` with `message={title}`: the default is `error.default`, rendered as an `h2`
- `<p>` with `contestantApp.error.readFailed.content`
- the main-variant Try again button (`contestant-read-failure-try-again`). It calls `invalidateAll()` and is `loading` while that runs. If focus fell to the body, it returns to the button
- `ContactSupport` (variant `normal`) and `LogoutButton` (`contestant-read-failure-logout`)

From the context it takes only `t`, by destructuring. The support block and logout read their own reactive accessors through the context. No `view-transition-name` and no `<dialog>` were added. The markup uses word-named classes only.

## New keys (for plan 32's native-speaker list)

- `contestantApp.error.readFailed.content`
- `contestantApp.error.readFailed.tryAgain`

The `tryAgain` translations are the same words as `contestantApp.identityProvider.tryAgain` in each locale. `translationKey.ts` was regenerated and gained exactly these two keys.
