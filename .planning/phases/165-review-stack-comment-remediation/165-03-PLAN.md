<rewrite_rules>
- KEEP: what a policy admits and to whom; the invariant it upholds and why that is safe (security rationale is the point of these comments); non-obvious ordering constraints stated as constraints (for example "project authority is the first disjunct so an admin exits on the first call"); references to other code or tests by file or function name.
- REMOVE: every planning reference; the history of how a rule was decided; measurement anecdotes that do not constrain the code; counts that restate what the code shows and drift when it changes.
- SHAPE: one to three sentences per comment block. Header lists become `-- - item` bullets (the `assert:comment-hygiene` Rule 2 keeps list items on separate lines). Never a `--` comment that joins two list items onto one line.
- NEVER: change a non-comment character, reorder statements, or touch a string literal. `code-identity.mjs` is the proof and it must exit 0.
- Policy expressions are deparsed into `pg_policies.qual` without comments, so no comment in this file reaches the database; the proof obligation is code identity alone.
</rewrite_rules>
