## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `grep -P` is unavailable under bash on this host**
- **Found during:** Task 1
- **Issue:** The plan specifies `grep -n -P` for layers 2-4. Scripts run under bash 3.2, where `grep` is `/usr/bin/grep` (BSD 2.6.0), and it rejects `-P` (`invalid option -- P`).
- **Fix:** `git --literal-pathspecs grep --no-index -I -n -P`. It uses the same PCRE engine the skill's lesson 27 relies on, and it covers untracked and fixture files. `--literal-pathspecs` keeps `[questionId]` paths from being read as globs.
- **Commit:** 78e680294

**2. [Rule 2 - Missing critical] The codemod runs without `--quiet`, and its output is reconciled with its JSON summary**
- **Found during:** Task 1
- **Issue:** With `--quiet` the codemod prints no per-line detail, so the gate could not print each hit as `path:line: text`, which the plan requires.
- **Fix:** The gate parses the codemod's per-file detail, then checks the parsed failing count against `totalHits` + failing residue in `--json-out`. A mismatch is a tool error (exit 2). The codemod still runs in dry-run mode only.
- **Commit:** 78e680294

**3. [Rule 2 - Missing critical] The self-test runs layers 1 and 5 in a throwaway git repository**
- **Found during:** Task 1
- **Issue:** The codemod refuses `.planning/` paths (exit 2), and `assert-comment-hygiene.mjs` scans only tracked `apps/ packages/ tests/` files, so neither can see the fixtures where they live.
- **Fix:** `--self-test` copies each fixture into a `mktemp` repository under `tests/hygiene-fixture/`, together with the lint guard, its classifier library and the guard's two vendored-exclusion files. It then runs the real tools there. If the guard's exclusion list drifts, the self-test reports a tool error instead of a pass.
- **Commit:** 78e680294

**4. [Rule 2 - Missing critical] Fail-closed additions**
- `--base` also includes untracked non-ignored files.
- `assert-absent.sh` greps untracked files (`--untracked`) and exits 2 when the pathspec matches no file. `git grep` exits 1 silently in that case, which would read as "absent".
- `ledger-check.sh` takes `--ledger <path>` so a scratch copy can be observed red.
- `ledger-skeleton.mjs` refuses to clobber a filled ledger (exit 3).
- **Commits:** 78e680294, 3189b55fe, 75bf6fd06

**5. [Rule 1 - Bug] The Write tool decoded the `—` planted in the dirty fixture**
- **Found during:** Task 1
- **Issue:** The file on disk held the em dash character itself, so lint rule 1 had nothing to fire on. Layer 5 still fired through rule 2.
- **Fix:** The literal six-character escape was restored with perl. The self-test now fires both rules (`layer5=2`).
- **Commit:** 78e680294

**6. [Rule 2] An extra fixture, `identity-literal-only.sql`**
- The acceptance criterion allowed adding the literal-only case to the fixtures, and it was added as a committed file. Without `--blank-sql-literals` it exits 1; with the flag it exits 0.
- **Commit:** 3189b55fe

**7. [Rule 1 - Bug] ledger-check reported a duplicated id as an extra id as well**
- **Found during:** Task 3, scratch-copy test
- **Fix:** The set comparison now runs over distinct ids; duplicates are reported by their own check.
- **Commit:** 75bf6fd06
