  <behavior>
    - `configureLogger({ level: 'debug' })` then `log.debug('x')` emits exactly one record.
    - Default (unconfigured) state emits nothing: `log.debug`, `log.info`, `log.warn` and `log.error` all produce zero sink calls, because `level` defaults to `'silent'`.
    - `configureLogger({ level: 'warn' })` drops `debug` and `info`, emits `warn` and `error`.
    - A record carries `level` as the pino numeric (20 debug, 30 info, 40 warn, 50 error), `time` as epoch milliseconds, `msg` as the string body, and `severityText` as the OTel name.
    - `log.error('boom', { err: new Error('kaboom') })` produces `err` as a plain object with string `type`, `message` and `stack` — asserted by `JSON.stringify` round-trip being non-empty, which is the exact failure `console.error` did not have.
    - `configureLogger({ sink })` routes records to the injected sink instead of the console.
    - `attributes` is passed through verbatim and is NOT deep-serialised or spread from arbitrary objects.
  </behavior>
  <action>
    Create `logger.type.ts` exporting `LogLevel` (`'debug' | 'info' | 'warn' | 'error'`), `LogRecord`
    and `LoggerConfig`. `LogRecord` carries `level: 20 | 30 | 40 | 50`, `time: number`, `msg: string`,
    `severityText: string`, optional `err: { type: string; message: string; stack?: string }` and
    optional `attributes: Record<string, unknown>`. `LoggerConfig` carries
    `level: LogLevel | 'silent'` and optional `sink: (record: LogRecord) => void`.

    Create `logger.ts` exporting a `log` namespace object with `debug`, `info`, `warn` and `error`
    methods, each `(msg: string, attributes?: Record<string, unknown> & { err?: unknown }) => void`,
    plus `configureLogger(next: Partial<LoggerConfig>): void`. Hold module-scope state
    `let config: LoggerConfig = { level: 'silent' }`. Default the sink to `console.error` for level
    >= 40 and `console.info` below it, matching the arity-chosen behaviour the old logger had, but
    with the level now stated by the caller rather than inferred.

    Serialise `err` explicitly: read `name`, `message` and `stack` off the value when it is an
    `Error`, otherwise `String(value)` into `message` with `type: 'unknown'`. This is the one place a
    naive implementation is strictly worse than `console.error`, because `JSON.stringify(new Error('x'))`
    is `{}` and every stack trace in the codebase would be lost.

    Read NOTHING from the environment. `import.meta.env.DEV` and `constants.PUBLIC_DEBUG` are a Vite
    compile-time constant and a SvelteKit virtual module respectively; neither exists in app-shared.
    Enablement is injected via `configureLogger` only (D-F5, CONTEXT open question 5). Default
    `'silent'` so that adding the package to dev-seed, llm, argument-condensation and docs is
    behaviour-neutral by construction.

    Do NOT add `pino`. `grep -c 'pino' yarn.lock` is 0; the criterion says pino/OTL-**conformant**
    output, which is a record shape, not a dependency.

    Exported helpers must be function declarations, not arrow consts (`func-style`). Comments comply
    with D-N1: one sentence per line ending in terminal punctuation, or a JSDoc block; no `\uXXXX`
    escapes; no planning references.
