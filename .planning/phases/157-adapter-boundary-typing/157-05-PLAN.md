<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller-supplied filter options -> RPC arguments | Filter values originate in route load functions and reach a database function as typed arguments. |
| adapter -> PostgREST | The fan-out decides how many RPC calls one read issues. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-157-12 | Denial of Service | the nomination RPC fan-out | medium | mitigate | `electionRound` is a scalar, so the fan-out stays two-dimensional. A `FilterValue<number>` third axis would multiply calls as (elections x constituencies x rounds); the prohibition above states it and the acceptance criterion greps for it. |
| T-157-07 | Tampering | RPC parameter handling | low | accept | Values are passed as named, typed RPC arguments (`uuid`, `integer`) rather than interpolated into SQL. The `LANGUAGE sql` function body has no dynamic statement. Residual risk is a wrong-but-valid filter value, which is an authorisation question that RLS and `SECURITY INVOKER` already answer. |
| T-157-13 | Tampering | conflating an empty array filter with no filter | low | mitigate | `convertFilterValue([])` returns `[]` and `convertFilterValue(undefined)` returns `[null]`; both are asserted, so a later simplification cannot silently merge "filter by nothing" with "do not filter". |
| T-157-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan installs no packages; the phase introduces zero new third-party packages per `157-RESEARCH.md` section Package Legitimacy Audit. |
