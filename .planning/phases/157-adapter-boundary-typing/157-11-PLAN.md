<objective>
Remove the auth-compatibility shim **along with the interface shape that required it** (REVIEW-ADP-04,
criterion 4's both halves; the reviewer's comment at `supabaseDataWriter.ts:84`, "Edit the interface
shape so that the withAuth shim is no longer needed if it has no use with supabase").

Both halves, per the roadmap's second correction pass and D-F1:
(a) the ignored parameters on `_setPassword` — `currentPassword` was resolved in `157-10`, and
`authToken` goes here;
(b) **the `WithAuth` type itself**, which is the interface shape the criterion names and the larger
half of the work: 41 references across 6 files, plus the `WithOptionalAuth` derivative that the
single lower-case grep cannot see.

The Supabase adapter authenticates from the session cookie and never reads an auth token, so every one
of these fields is passed as `''` purely to satisfy a type constraint.

Output: the type gone, ten option types re-expressed, every `authToken: ''` call site cleaned, and two
greps returning zero.
</objective>
