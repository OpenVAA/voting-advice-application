<objective>
Replace the client-side question assembly at `supabaseDataProvider._getQuestionData` with a single
`get_questions` RPC call (REVIEW-ADP-03; the reviewer's comment at `supabaseDataProvider.ts:499`,
"Enable filtering by election, constituency and election round. Create a get_questions rpc to that
effect, which returns both categories and their questions").

Purpose: this is the third link of the phase's vertical, and the one where the SQL written in `157-03`
and proven in `157-04` becomes user-visible behaviour. It also removes a measured latent correctness
bug: when the filtered category list is empty, today's code reads EVERY question in the table, because
the `.in('category_id', categoryIds)` narrowing is applied only when `categoryIds.length > 0`.

Output: a rewritten read path, an extended option surface, and unit coverage proving shape parity.
</objective>
