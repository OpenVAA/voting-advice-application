<objective>
Implement the candidate-settings `currentPassword` disposition decided at `157-09`'s checkpoint — the
phase's one product decision, and the reason criterion 4 is not a mechanical rename (D-F1's binding
operator NOTES, REVIEW-ADP-04).

The measured defect, end to end: the form binds a current-password field, `canSubmit` never references
it so the form submits with it blank, `authContext` forwards it, and `_setPassword` destructures only
`password` and discards the rest — while `error.changePassword` tells users in all seven locales that
their current password was checked.

This plan has TWO branches. `157-09` decided which one, from three measured spike verdicts. Execute
exactly one, and record which and why.

Output: a password-change path that carries no parameter nothing reads, and copy that makes only
claims the system enforces.
</objective>
