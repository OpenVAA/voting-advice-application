<objective>
Remove the abstract-interface members criterion 4's second sentence names — the two methods under the
`ADMIN METHODS` TODO block in `supabaseDataWriter.ts` — from implementation and interface alike
(REVIEW-ADP-04; the reviewer's comment at `supabaseDataWriter.ts:381`, "Remove these from here and the
abstract interface").

The TODO the block carries is measurably true: the primary access point IS `SupabaseAdminWriter`, and
its `updateQuestion` and `insertJobResult` are duplicates of the two implementations that exist only to
satisfy an abstract contract. Both `merge_custom_data` call sites are the same RPC call.

What the research did NOT enumerate, and this plan measured: there are **ten** callers, and eight of
them are server-side admin feature code, not context wrappers. So this is a repoint-then-delete, and it
needs a selector module the frontend does not have yet.

This closes the last outstanding piece of **D-F1**, which restated criterion 4 against its real targets:
the ignored parameters (`157-10`), the `WithAuth` interface shape (`157-11`), and the abstract-interface
members flagged in the writer, which are this plan's subject.

Every comment this plan writes complies with **D-N1**: one sentence per line ending in terminal
punctuation, or a block comment, with no planning references. In particular, the `ADMIN METHODS` TODO
block is deleted rather than reworded, because the condition it described stops being true here.

Output: a one-line `lib/api/adminWriter.ts` selector, ten repointed call sites, and two methods deleted
from four files.
</objective>
