<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anon / authenticated caller -> PostgREST RPC | `get_questions` is newly exposed to the `anon` role; whatever it returns is public. |
| RPC parameters -> SQL | Filter values arrive from the browser through PostgREST. |
| `schema/` mirror -> the live database | There is no link. The mirror is never applied, which is the trap this plan's two-edit rule exists for. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-157-RPC | Elevation of Privilege | `public.get_questions` | high | mitigate | `SECURITY INVOKER` so RLS applies to the caller, no `SET search_path`, and an explicit `GRANT EXECUTE ... TO anon, authenticated` naming the full argument list. `157-04`'s pgTAP asserts `prosecdef` is false and asserts the grant, copying the shape from `07-rpc-security.test.sql:33-47`. |
| T-157-07 | Tampering | RPC parameter handling | medium | mitigate | Parameters are typed `uuid` and `integer` and are used in comparisons and `@>` containment, never string-concatenated into dynamic SQL. `LANGUAGE sql` with no `EXECUTE` means there is no dynamic statement to inject into. |
| T-157-08 | Denial of Service | PostgREST overload ambiguity on `get_nominations` | high | mitigate | The migration drops the 3-argument overload before creating the 4-argument one; `157-04` asserts exactly one `get_nominations` row in `pg_proc`. Left unmitigated this returns `PGRST203` at runtime on a migration that passed review. |
| T-157-09 | Repudiation | schema mirror drift | medium | mitigate | Every SQL change is two edits in one commit, with an `-- Applies to schema files:` list in the migration, and the acceptance criteria grep both copies. |
| T-157-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan installs no packages. Per `157-RESEARCH.md` section Package Legitimacy Audit, the phase introduces zero new third-party packages, so there are no `[ASSUMED]` or `[SUS]` entries and no blocking human checkpoint is required. |
