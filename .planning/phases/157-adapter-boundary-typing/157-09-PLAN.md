<objective>
Discharge D-F1's binding operator NOTES — *"Also check that currentPassword and authToken are not used
anywhere else."* — before a single parameter is deleted, and resolve the phase's one product decision.

Two things make this a plan of its own rather than a preamble to the deletion:

1. **The reach is larger than the CONTEXT records.** Measured, `authToken` spans five classes across
   nineteen files, including five route files the CONTEXT omits entirely, a SECOND genuine admin token
   the CONTEXT does not name, and a real `Authorization: Bearer` mechanism that must survive. No task
   may say "remove `authToken`" without a per-file disposition table.

2. **The candidate settings form is a product decision, not a rename.** `routes/candidate/(protected)/settings/+page.svelte`
   collects a current password that Supabase silently discards, `canSubmit` never requires it, and the
   error message shown to users in all seven locales already claims it was checked. That is a
   security-adjacent user-facing defect, and it has a cheap correct answer that neither the roadmap nor
   the CONTEXT anticipated — but only if a three-item spike passes.

Output: one phase-directory document, `157-AUTH-SHIM-DISPOSITION.md`, carrying the reach table, the
spike results, and the recorded branch decision. No source file changes.
</objective>
