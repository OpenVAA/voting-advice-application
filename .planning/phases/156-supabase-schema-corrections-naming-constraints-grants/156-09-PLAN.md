<objective>
Implement the two record items from criterion 8 that are cheap and concrete, leaving the three design
questions to the disposition document in plan 10.

This is the implementing half of roadmap criterion 8 / REVIEW-DB-08. The criterion asks that the
remaining schema-review record items be **dispositioned rather than silently dropped**; per D-E5 that
means two are implemented and three are answered on the record with a pending todo.

**Item 1 — the benchmark suite.** `apps/supabase/benchmarks/` is a 288 KB tree of six subtrees: a
144-line runbook, 38 result JSON files, and pgbench, k6, data and script directories. It compares two
answer-storage approaches, and the schema this repository ships is the outcome of that comparison — so
the RESULT is load-bearing and the APPARATUS is not. Distil the conclusion into the Supabase README and
remove the apparatus behind a commit anyone can recover it from.

**Item 3 — the hard-coded ports.** `config.toml` pins nine ports as literals. The README names four of
them. Document all nine and state the consequence honestly: two checkouts of this repository cannot run
their local stacks at the same time without editing a tracked file.

Purpose: "dispositioned rather than silently dropped" is the criterion's own wording, and the failure
mode it names is a reviewer's question that quietly evaporates. Two of the five get closed by doing the
work; this plan does that work.

Output: a benchmark conclusion that outlives its scripts, a quoted archival SHA, and a port caveat that
is checked rather than assumed.
</objective>
