<objective>
Three constraint-and-validation corrections, each landed in both SQL copies and each proven by
behaviour rather than by inspection.

**Criterion 3 / REVIEW-DB-03** — `public.nominations.election_round` has a `DEFAULT 1` and no lower
bound, so a zeroth or negative round inserts cleanly. Add `CHECK (election_round >= 1)`, proven by an
insert the constraint rejects.

**Criterion 4 / REVIEW-DB-04** — the image-shape validation is 37 lines inlined in one arm of a `CASE`
inside `validate_answer_value`, so it cannot be called, cannot be tested, and cannot be reused. Extract
it into a named utility pair with its own pgTAP coverage. **Measured: there is no image-shape assertion
anywhere in the suite today**, so this criterion creates the first.

**Plus one measured defect the criteria do not name, adopted deliberately** — `app_settings` is the
only one of the 13 foreign keys referencing `public.projects` that lacks `ON DELETE CASCADE`, verified
against the live catalogue, and a project DELETE was observed raising a live foreign-key violation. It
is a one-token edit in the same two files this phase already opens, and a later phase's project
teardown is the thing that breaks without it. **The decision is to fix it here**, and to record that
decision in `156-DISPOSITIONS.md` either way so it cannot silently vanish.

Purpose: all three are the same shape of defect — an invariant that exists in someone's head, or in a
comment, but not in the database. This plan puts each one where it cannot be bypassed.

Output: two new CHECK-guarded behaviours, one extracted and independently testable validation utility,
one corrected referential action, and 22 new pgTAP assertions taking the suite from 272 to 294.
</objective>
