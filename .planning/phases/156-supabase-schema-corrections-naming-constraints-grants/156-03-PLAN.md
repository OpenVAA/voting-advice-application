<objective>
Close the pgTAP fan-out of the rename, so the role-simulated test suite exercises the renamed
vocabulary instead of failing against it.

Plan 02 left the suite red by design: the fixture files still insert the retired role literal, and an
enum column rejects it. This plan renames the fixtures, renames the role-scope test file, and returns
the suite to green — **at the same assertion total, 269**, because nothing is added here.

Measured scope: 56 lines carrying the term across three files — `00-helpers.test.sql` (8),
`05-party-admin.test.sql` (44, plus its filename), `09-column-restrictions.test.sql` (4). No other
pgTAP file references the fixture key.

Purpose: pgTAP is the only layer in this project that exercises RLS and column grants **as a
non-superuser role**. `yarn db:reset-with-data` seeds as `service_role`, which bypasses every column
grant and most RLS, so a green seed says nothing about the predicates this phase is renaming. If the
pgTAP fixtures are not moved, the phase loses the only evidence that the renamed policies still gate
correctly.

Output: a renamed test file with its `05-` ordering prefix intact, renamed fixture keys and claim
payloads, and a green 11-file / 269-assertion run.
</objective>
