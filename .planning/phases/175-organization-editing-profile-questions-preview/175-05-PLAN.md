<long_gates>
**Runs of a committed tree** go through the phase's drivers and are judged by its verdict script.

- Gates: `bash $P/175-gates.sh <label> [--rows <names>]`, evidence under `tests/e2e-runs/175-gates/<label>`, verdict `node $P/175-verdict.mjs gates <label> [--rows <names>]`.
- E2E: `bash $P/175-e2e.sh <label> [--project <name>] [--require-project <name>]...`, evidence under `$R/<label>`, verdict `node $P/175-verdict.mjs e2e <label> …`.

Both drivers refuse a tree with uncommitted changes outside `.planning/`. The gate set's `db-reset` row destroys the local data and refuses while an E2E run is in flight; the gate set therefore runs first and the E2E run after it, never together.

**A run of an uncommitted tree** — the pre-commit proof of this plan — goes directly through the wrapper, which the driver would refuse: `tests/scripts/e2e-run.sh --run-dir $R/<label> --no-db-reset --project <name>`, followed by `node tests/scripts/e2e-evidence.mjs $R/<label>`, and is judged with `node $P/175-verdict.mjs control <label> … --green --dirty-only <path>…`. Before it, confirm nothing listens on the dev-server port.

No run is made in the foreground: a foreground turbo gate can hang past the executor's watchdog. Launch in the shell tool's background mode, for example
`( caffeinate -dimsu bash $P/175-e2e.sh <label>; echo $? > $R/<label>.exit ) > $R/<label>.log 2>&1`
and poll with one short foreground command per poll: a bounded loop of at most 45 one-second waits that ends as soon as the `.exit` marker exists and prints its content, or `running`. Ceilings: 25 minutes for the gate set, 20 minutes for an E2E run. At a ceiling stop, leave the process and the stack alone, and report the label and the log's tail.

Docker is never restarted: a second, unrelated Supabase stack runs on this host. A run the wrapper ended with status 8 and `VOID-host-suspend.txt` is void: keep its directory and make the run again under the next `-rN` suffix of the same label (a verdict given the label reads its newest attempt). Nothing else makes a run void. A red run without the marker is diagnosed and fixed at its cause, then run again under the next suffix; nothing is rerun on an unchanged tree. A did-not-run is a failure. Nothing under `tests/e2e-runs/` is deleted. The `e2e` and `gates` verdicts are taken when the run is made: they refuse a run whose head differs from HEAD outside `.planning/`.
</long_gates>
