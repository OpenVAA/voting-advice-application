**Pattern Applied (per 86.3-PATTERNS.md "Recommended fix shape" §1):**

```svelte
// Capture pre-push stack length BEFORE the first $effect (Pitfall 1 guard).
const topBarBaseIdx = topBarSettings.getLength() - 1;

// Reactive $effect — re-runs when $appSettings updates post page.data merge.
$effect(() => {
  const next = {
    actions: {
      feedback: $appSettings.header.showFeedback ? ('show' as const) : ('hide' as const),
      help: $appSettings.header.showHelp ? ('show' as const) : ('hide' as const)
    }
  };
  topBarSettings.revert(topBarBaseIdx);  // Pitfall 1 guard — revert to baseline before push
  topBarSettings.push(next);
});

// Fire-once $effect for the notification popup (Pitfall 2 guard).
let notificationQueued = $state(false);
$effect(() => {
  if (!$appSettings.access.voterApp) return;
  if (!notificationQueued && $appSettings.notifications.voterApp?.show) {
    popupQueue.push({
      component: Notification,
      props: { data: $appSettings.notifications.voterApp }
    });
    notificationQueued = true;
  }
});

// dataConsent branch stays in onMount per CONTEXT D-10 small-fix gate.
onMount(() => { ... });
```

**Pitfall Guards in Place:**
- **Pitfall 1 (infinite StackedState growth):** `topBarBaseIdx` captured BEFORE the first `$effect` push; each re-run calls `topBarSettings.revert(topBarBaseIdx)` before `push(next)` to reset to baseline. Idempotent stack lifecycle confirmed.
- **Pitfall 2 (popup re-queue on every $appSettings change):** `notificationQueued = $state(false)` toggled to `true` after first successful push; gate prevents subsequent re-runs from re-queueing the same popup.

**Canonical Analog:** `apps/frontend/src/lib/contexts/app/appContext.svelte.ts:93-100` (the `prevAppSettingsData` ref-equality `$effect` pattern). Cells #1/#2 mirror this idiom adapted to the StackedState push API; cell #3 mirrors it adapted to popupQueue.push with a fire-once boolean guard.
