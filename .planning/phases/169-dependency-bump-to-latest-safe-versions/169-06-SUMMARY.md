## Deviations from Plan

### Task 2 deferred pending an operator ruling

**1. [Rule 4 - Architectural/decision] Local Postgres 17 deferred; not failed, and not a D-06 hold**
- **Found during:** Task 2, step 5 (`yarn db:lint:sql` on the fresh PG17 reset).
- **Issue:** the PG17 image's plpgsql_check reports `public.is_valid_choice_id` as "marked as IMMUTABLE, but
  expression is STABLE" (two statements).
  - The function is IMMUTABLE but calls `jsonb_agg` / `jsonb_build_array`, which are STABLE on both 15 and 17.
  - The PG15 image's checker (2.7) does not report it; PG17's (2.8) does.
  - Whether the cause is the checker version or a PG17 planner change is UNCONFIRMED.
- **Why not fixed:** the fix edits `schema/011-validation-functions.sql` and `migrations/00001_initial_schema.sql`.
  - PROH-169-12 forbids that, and so do the plan's empty migrations/schema/seed diff and its "no migration or schema
    file changed" truth.
  - Silencing the lint would weaken a gate.
  - D-14 is an operator overrule with no hold provision, so D-06 does not apply.
- **Ruling:** the orchestrator deferred Task 2 so the phase can continue (2026-10-03). The A/B/C choice stays with
  the operator.
- **What was done:**
  - The PG17 config diff and the Option-A STABLE edit were saved as patches:
    - `tests/e2e-runs/169-gates/06/t2-pg17-config.patch`;
    - `tests/e2e-runs/169-gates/06/t2-option-a-stable.patch`.
    - Both `git apply --check` cleanly on HEAD. Neither is committed.
  - `config.toml` was reverted. This project's stack went back to PG15 with `db:stop` → `supabase stop --no-backup`
    → `db:reset` (only `_openvaa-local` containers and volumes touched).
  - On PG15: `show server_version` 15.8, `db:types` no diff, pgTAP 1335/1335, `db:lint:sql` 0.
  - The todo `2026-10-03-pg17-local-blocked-on-is-valid-choice-id-volatility.md` was filed: A ★ recommended,
    including the orchestrator's call-site check (only `validate_answer_value`'s body references it, and that caller
    is VOLATILE, so STABLE is legal).
- **Impact:**
  - DEPS-08 stays Pending.
  - 169-13's PG17 pgTAP / final-E2E-on-PG17 gate is blocked until the ruling is applied.
  - 169-07 to 169-12 are unaffected and run on PG15.

### Auto-fixed / environment issues

- **Found during:** Task 1, step 3 (`yarn db:start`).
- **Issue:** all ten `docker pull` children waited on `docker-credential-desktop get`.

- **Committed in:** none (environment only); recorded in EVIDENCE § 1 and § 7.
