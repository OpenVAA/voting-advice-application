**Closed the EQTYP-02 regression Phase 165 introduced by making `AccordionSelect` reconcile, cancel and correct instead of initialising once — 0 red / 16 against a contemporaneously measured 4 red / 16 on the byte-identical pre-fix body, with the phase's own no-redraw fix left untouched.**

## Accomplishments

- **Fixed the component, not the symptom.** `AccordionSelect` gained three things, each forced by a measurement rather than by argument: an edge-triggered reconciliation of `expanded` against a resolved `activeIndex`; a cancellable `DELAY.lg` collapse so an orphaned timer can no longer outrank a later intent; and a non-animated state correction so a corrected collapse leaves the DOM where a remount would have left it. No remount was reintroduced and `(located)/+layout.ts` was not weakened — criterion 1 / D-03 stands.
- **Confirmed the mechanism the base measurement had marked UNCONFIRMED, and narrowed it.** Not by instrumentation but from the Playwright trace and the error-context ARIA snapshots of the reds. The defect is not merely "a mount with `activeIndex === -1` stays expanded"; it is the *window after the selection takes*, in which the widget is expanded while a selection is already active and a click on the already-active option re-opens it permanently.
- **Measured the fix over the plan's 16-run bar, and then over three more arms than the plan asked for**, because the first negative control came back green and a 0/16 with no same-day control proves nothing.
- **Ran the full default E2E suite at the fix HEAD on a clean tree: 171 passed, 0 unexpected, 0 flaky, 0 skipped, no retries.**
- **Closed all three blocker records in place** and corrected two factual errors in `165-05`'s account of the defect.

## The confirmed mechanism

On base, every results navigation reran the `(located)` load and blanked the subtree, so `AccordionSelect` was remounted after each selection and its once-only `expanded` initialiser re-ran **by accident**. Criterion 1 removed that teardown deliberately. On the persistent subtree:

1. The results landing has no election in the URL, so the layout's `findIndex` yields `-1` and the widget mounts expanded — its designed behaviour.
2. Selecting an election set `activeIndex` but only scheduled `expanded = false` for `DELAY.lg` (450 ms) later. For those 450 ms the widget is expanded while a selection is already active.
3. The spec's helper snapshots the option count inside that window, so it skips its "expand first" branch.
4. Its follow-up click — delayed a further ~250 ms by the document View Transition's `<html>` pointer interception — lands *after* the collapse, on the now-sole already-active option, which `activate`'s toggle branch re-opens permanently with nothing left to close it.

The end-state ARIA snapshot of every symptom-(a) red shows exactly that: Regional `[active] [selected]`, with Municipal still listed beside it.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 1 — Bug] `activate`'s `DELAY.lg` collapse was fire-and-forget, and the orphaned timer slammed the accordion shut under a re-expanding click**
- **Found during:** Task 2, first probe run after the Task 1 commit
- **Issue:** With the reconciliation collapsing immediately, the still-pending 450 ms timer fired *after* a subsequent re-expand, detaching the option the user was reaching for mid-transition. Measured verbatim as `element is not stable` → `element was detached from the DOM` against an `inert` (outroing) option.
- **Fix:** every write to `expanded` goes through `setExpanded`, which cancels the pending timer first; plus a destroy-time teardown so a collapse cannot fire into a destroyed component
- **Files modified:** `AccordionSelect.svelte`
- **Verification:** the full journey test, red in that probe, passed in all 16 counted runs and in the full suite
- **Commit:** `8d410e654`
- **Note:** this was a latent defect in its own right — a user re-expanding within 450 ms of a selection was slammed shut by the orphaned timer.

**2. [Rule 1 — Bug] A corrected collapse still played the `DELAY.sm` slide outro, keeping the de-selected option in the DOM for 225 ms**
- **Found during:** Task 2, second probe run
- **Issue:** An outroing option is `inert` and mid-flight but still matches `role=option`, so the widget stays observably expanded for 225 ms after it is logically collapsed. Measured in the trace of `tests/e2e-runs/accordion-probe-01`: the count taken at +138 ms read 2, and the follow-up click landed after the collapse.
- **Fix:** a correction sets `correcting`, which drives the option transition's duration to 0, so the corrected DOM matches what a remount would have produced
- **Files modified:** `AccordionSelect.svelte`
- **Verification:** arms A, B and C, and the full suite
- **Commit:** `8d410e654`

### Deliberate departure from the plan's letter

**3. [Rule 1 — required to close the defect] The first selection collapses immediately, not after `DELAY.lg`**

The plan's behaviour bullet says "the `DELAY.lg` collapse-after-select timing [is] unchanged". For the `activeIndex` unresolved → resolved transition it is **not** unchanged: that selection now collapses at once and without the slide. This is unavoidable, not an oversight — the combined 450 ms + 225 ms window *is* the flake, and no reconciliation that leaves the window open can close it. Two things make it the right call rather than a regression: option-to-option switching, which is the normal interactive "collapse after select", keeps `DELAY.lg` entirely untouched; and on base this path never showed the 450 ms beat either, because the remount collapsed it instantly. The change restores base's observable timing while keeping the phase's no-redraw win. Filed in WINDOWS.

### Corrections to `165-05`'s record (not deviations — errors in the prior account)

**4. "Both mechanisms were introduced or newly reachable in this phase" is wrong.** Both pre-exist on base **verbatim**: the accordion initialiser is byte-unchanged, and the root layout already carries `onNavigate` + `startViewTransition` on base — the phase's only change to that hook *adds* a guard making document VTs run **less** often. What Phase 165 changed is that the results subtree now persists. The defect is pre-existing-but-unreachable, not newly written. Corrected in place in `deferred-items.md`.

**5. "`AccordionSelect.svelte` (shared with the candidate app)" is wrong.** Measured: the component has exactly one consumer, the voter results layout. The candidate app does not use it. The escalation to Rule 4 was still correct, but the blast radius was one route, not two apps.

**Total deviations:** 2 auto-fixed bugs, 1 deliberate departure from the plan's letter, 2 corrections to a prior plan's record. **Impact:** the plan's objective is met and its prohibitions are honoured; one of its behaviour bullets could not be honoured as written and the reason is recorded above and in the ledger.
