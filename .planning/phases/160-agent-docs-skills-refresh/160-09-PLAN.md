  <action>
Write `.claude/scripts/audit-skill-routing.sh` implementing two checks over `.claude/skills/**/*.md`
plus `CLAUDE.md`.

**Check A — routing depth.** A *routing layer* is a `SKILL.md` body or the `## Skill Routing` section
of `CLAUDE.md`. A *hop* is a Markdown link or backticked repo-relative path from one Markdown file to
another. Classify each destination file as either *content* or *index* by pointer density: the share
of its non-frontmatter, non-heading, non-blank lines that are pointer lines. A routing layer pointing
at an index which itself points onward is a depth-2 chain and a violation.

Choose the density threshold by measuring the live corpus and reading the distribution, then state
the chosen number **and the distribution that justified it** in a comment at the top of the script.
Do not pick a round number and assert it. Print the measured density for every file the script
classifies, so a reader can re-judge the threshold without re-deriving it.

Known shape to check the instrument against, if it is still present: the spike-findings skill's
`SKILL.md` carried a table whose rows pointed into `references/*.md`, while its 16 `sources/*/README.md`
were reachable from a single mention. That is the depth-2 chain in its clearest form and should score
as a violation if the skill still exists. If Plan 07 removed it, say so in the output rather than
silently reporting a clean run — a check that has nothing to find must report that it had nothing to
find.

**Check B — description discriminativeness.** Extract the frontmatter `description` of every
`SKILL.md`. Flag any opening stem shared by three or more skills, reporting the stem and the sharers.
Measured at plan time, six of eight descriptions opened with the identical stem `Domain expert for
the`; re-derive the current figure rather than asserting that one. Report, do not rewrite: this check
names the skills whose one-liners do not discriminate, and Task 2 decides what to do about each.

Both checks print per-target verdict lines and a final summary naming every count measured. Exit 1
if either check found a violation, 0 otherwise. Prove the instrument red-then-green: construct a
throwaway fixture that violates each check, show the script reports it, delete the fixture, and record
both runs in the summary. A checker only ever observed green is not known to check anything.

<flagged_assumptions>
## Flagged Assumptions

- **A9-1 (HIGH risk).** The pointer-density threshold that separates *index* from *content* is not
  derivable from either cited paper — the papers establish that a second routing level does not help,
  not where the boundary sits in a Markdown file. Task 1 therefore measures the live distribution and
  states the number it chose with that distribution attached, so the threshold is arguable rather
  than asserted. If the distribution turns out to be bimodal with a clean gap, say so; if it is flat,
  say that too, and treat Check A's verdicts as advisory rather than binding until a better
  discriminator exists.
- **A9-2 (MEDIUM risk).** Check B's shared-opening-stem signal detects the failure mode measured in
  this corpus (six of eight descriptions opening `Domain expert for the`). It does not detect a
  corpus whose descriptions are superficially varied but still non-discriminative. It is a floor, not
  a proof of a good selection layer, and the record must not claim otherwise.
- **A9-3 (MEDIUM risk).** Plan 07's `checkpoint:decision` governs whether the largest violator still
  exists when this plan runs. Both branches are live: if the skill was deleted, Check A may find
  nothing and must report having found nothing; if it was kept, Check A should flag it and Task 2
  must dispose of it without discarding content Plan 04 recorded a removal cost for.
</flagged_assumptions>
