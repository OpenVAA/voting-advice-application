## The job, specified

The exact YAML Task 1 appends. It is given here, outside the task body, so the executor has an
unambiguous target rather than a paraphrase to reconstruct.

```yaml
  # A STANDING NEGATIVE CONTROL over the repository's own node-engine guard.
  #
  # scripts/assert-node-engine.mjs is what makes the root manifest's engines.node
  # range bind: it runs from `preinstall` and as a link of `lint:check`. Its
  # ACCEPTING half is exercised constantly — every install and every lint run on a
  # supported Node passes through it. Its REJECTING half is exercised by nobody,
  # because nobody develops on an unsupported Node. A half that nothing exercises
  # is a half that can rot silently: break the comparator, or make the guard
  # return early, and every green run stays green.
  #
  # So this job runs the guard on two runtimes and asserts BOTH directions.
  # Green here means the constraint still binds.
  #
  # It asserts the guard's failure MESSAGE, not merely a non-zero exit. The guard
  # exits 1 for four unrelated reasons — an unreadable manifest, a missing
  # engines key, an empty engines.node, a range outside its accepted grammar — so
  # an exit-code-only assertion would report green while the guard had stopped
  # comparing versions at all.
  #
  # It invokes the guard BY PATH rather than reimplementing the comparison, so
  # deleting the guard breaks this job instead of quietly removing a check.
  #
  # No install, no Yarn, no cache. The guard imports nothing but Node built-ins —
  # the property that lets it run from `preinstall`, before node_modules exists —
  # so checkout plus two toolchains is the whole job.
  #
  # The out-of-range toolchain floats within its major on purpose: every 20.x is
  # out of range for the declared ">=22", so pinning a patch would buy nothing and
  # would break the day that patch left the runner's version manifest. If the
  # declared range is ever widened to admit Node 20, the first assertion below
  # goes red — deliberately. The control would have stopped being a control, and
  # that should be a decision somebody makes rather than one they drift into.
  node-engine-range-negative-control:
    runs-on: ubuntu-latest

    steps:
      - name: "Checkout source code"
        uses: actions/checkout@v4

      - name: "Setup Node.js 20.x (deliberately out of range)"
        uses: actions/setup-node@v4
        with:
          node-version: "20.x"

      - name: "Assert the node-engine guard REJECTS an out-of-range Node"
        run: |
          STATUS=0
          OUTPUT="$(node scripts/assert-node-engine.mjs 2>&1)" || STATUS=$?
          if [ "$STATUS" -eq 0 ]; then
            echo "::error::assert-node-engine exited 0 under $(node -v), which the declared engines.node range does not admit. The rejecting half of the Node constraint has stopped binding."
            exit 1
          fi
          case "$OUTPUT" in
            *'assert-node-engine: this Node is '*) : ;;
            *)
              echo "::error::assert-node-engine exited $STATUS under $(node -v), but not for the version reason. It reported: $OUTPUT"
              exit 1
              ;;
          esac
          echo "rejected as required under $(node -v): $OUTPUT"

      - name: "Setup Node.js 22.22.1 (in range)"
        uses: actions/setup-node@v4
        with:
          node-version: 22.22.1

      - name: "Assert the node-engine guard ACCEPTS an in-range Node"
        run: |
          STATUS=0
          OUTPUT="$(node scripts/assert-node-engine.mjs 2>&1)" || STATUS=$?
          if [ "$STATUS" -ne 0 ]; then
            echo "::error::assert-node-engine exited $STATUS under $(node -v), which the declared engines.node range does admit. It reported: $OUTPUT"
            exit 1
          fi
          case "$OUTPUT" in
            *' satisfies "engines.node": '*) : ;;
            *)
              echo "::error::assert-node-engine exited 0 under $(node -v) without reporting a satisfied range. It reported: $OUTPUT"
              exit 1
              ;;
          esac
          echo "accepted as required under $(node -v): $OUTPUT"

      - name: "Assert the guard's own comparator self-test passes"
        run: node scripts/assert-node-engine.mjs --self-test
```

**Three properties of that shell are load-bearing and must not be "tidied":**

- `OUTPUT="$(cmd)" || STATUS=$?` — GitHub's default shell aborts a step at the first non-zero
  command. A bare failing command substitution would kill the step **before** the assertion ran, so
  the rejecting step would fail for the very outcome it is asserting. The `|| STATUS=$?` suffix makes
  the compound status zero while preserving the command's own status.
- **No pipes.** `pipefail` is not enabled by the default shell, so an assertion travelling through a
  pipe would report the status of the last stage, not the guard's.
- **`2>&1` in the capture.** The guard writes its rejection to stderr (`console.error`) and its
  acceptance to stdout (`console.info`). Capturing only one stream would make one of the two
  message assertions unfalsifiable.
