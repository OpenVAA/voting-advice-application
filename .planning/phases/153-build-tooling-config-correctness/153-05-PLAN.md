**`.lintstagedrc.json` and `.prettierignore` are touched by no other plan in this phase.** Phase 163
does prettier work (adding a SQL parser), but that lands in `prettier.config.mjs`, not
`.prettierignore` — flagged so the two are not conflated.

**⚠ The conditional churn commit is the collision surface.** If the execute-time measurement finds
non-zero churn, the churn commit would touch `.svelte` files under `apps/**` — which is exactly where
**Phase 152**'s 817-line comment sweep works. That is why Task 3 measures first and creates the
commit only if the count is non-zero, and why the churn commit must contain **formatting changes
only**, with the diff reviewed hunk by hunk before it lands. Research measured the churn at **zero**;
budget for zero and treat a non-zero result as a signal that a sibling phase landed something
unformatted, not as expected work.

**The pre-commit hook does not run in this worktree.** `core.hooksPath` is `/dev/null`
(worktree-scoped override; the shared repo config still points at the *other* checkout's `.husky`).
So `git commit` here fires no hook, and the criterion-8 proof **cannot** be obtained by committing.
The proof runs the real lint-staged binary directly in a throwaway repository — which is better
evidence anyway, because it isolates lint-staged from husky.

<open_decision id="OQ-5">
**Question (153-RESEARCH.md § OQ-5):** should the criterion-4 fix delete the redundant wrapper
entries, or convert the config to a `.mjs` file with a function task?

**Planned here:** **delete both entries** — the recommended option. `.husky/pre-commit:1` already
runs `yarn turbo run build --filter=@openvaa/app-shared...` before invoking lint-staged, so the two
entries are redundant re-invocations of a build that has just run. Deleting satisfies REVIEW-CFG-04
literally (*"invokes its commands directly rather than through [a shell wrapper]"*, *"so the
pre-commit hook works where bash is absent"*), keeps the file as JSON, changes no format, and loses
no coverage. Smallest possible diff.

**Alternatives, verbatim from RESEARCH:**
- **(b)** *"Convert to `lint-staged.config.mjs` with a function task — `[() => 'turbo run build --filter=@openvaa/app-shared...', 'prettier --write', …]`. The lint-staged-native way to say 'run this command with no files', verified at `getSpawnedTask.js:102`. Correct, but changes the config file format and keeps a redundant build."*
- **(c)** *"Replace the wrapper with the bare string — ❌ **Breaks the hook** — measured above. Do not plan this."*
- The stated residual of the recommended option: *"someone running `npx lint-staged` outside the hook no longer gets the build; the hook is the only documented entry point."*

**If the operator rules differently:** for (b), delete `.lintstagedrc.json`, create
`lint-staged.config.mjs` exporting the same two glob keys with the build expressed as a
zero-argument function returning the command string, and keep the glob fix and the `.prettierignore`
addition unchanged. Task 2's proof recipe is unaffected — it copies whichever config file exists.
Option (c) must not be implemented under any ruling; it is measured to break the hook.
</open_decision>
