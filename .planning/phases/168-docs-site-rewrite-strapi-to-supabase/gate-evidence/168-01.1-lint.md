### Findings and their status

- **Order-dependence: CONFIRMED** (probes a vs b). Importing the shared config before `eslint-config-prettier` crashes; the reverse
  order loads; each module loads alone.
- **Node-version independence: CONFIRMED** for v24.14.1 (host) and v22.22.1 (CI), every probe identical on both. Not a host problem.
- **The trigger is the shared config's `compat.extends(…, 'prettier')`: CONFIRMED** (probe d). Without the `'prettier'` entry, the
  crashing order loads.
- **`eslint-plugin-svelte` is the cause** (the attribution the v1.2 Phase 19 record made when it renamed `lint` to `lint:local`):
  **REFUTED** by probe (a), which crashes without it.
- **Mechanism (Node's ESM loader asserting because FlatCompat synchronously `require`s the CommonJS `eslint-config-prettier` while that
  module is pending as a sibling static import): UNCONFIRMED.** The simple stand-in for that mechanism, a plain top-level `createRequire`
  of the same module (probes e and f), does **not** reproduce the crash. So FlatCompat's resolution path does something the plain
  `require` does not, and that difference was not isolated. The fix does not depend on the mechanism: it removes the sibling import.
