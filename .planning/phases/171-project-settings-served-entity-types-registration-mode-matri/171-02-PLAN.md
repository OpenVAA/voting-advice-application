<objective>
Plan 2 of the four D-21 fixes: the database read. A project that is closed for voters is the normal state while contestants register, and `anon` cannot read its `app_settings` row. This plan adds one narrow `SECURITY DEFINER` function that returns the Contestant app's public configuration for a project, moves every gate that function touches, pushes the schema through this repository's own workflow, and merges the answer into the provider's closed-project branch (D-09). It also pins the root-level rejection of a bad list value (D-05).

Purpose: without it the login screen of a closed project sees only shipped defaults, so criteria 1 and 3 of the phase would not hold where they matter.
Output: `public.contestant_app_public_config`, its pgTAP file, both census strings, the regenerated migration and types, the provider branch with unit tests, and the database skill's function tables.

**Wave.** This plan depends on 171-01 for the schema members and the shipped defaults. Plan 171-03 follows it instead of running beside it: the two share one working tree and one whole-frontend typecheck, and the guards of 171-03 read through the branch this plan builds.
