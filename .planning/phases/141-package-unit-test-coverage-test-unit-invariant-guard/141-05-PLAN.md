<decisions>
Binding constraints for this plan:

- **CLAUDE.md E2E hard rule (cardinal failure)** — no task may complete while any E2E test is failing.
  There are no known-flaky exemptions: an intermittently failing test is a real defect to be diagnosed,
  never skipped, retried-until-green or annotated. A "did not run" test counts as a failure.
- **CLAUDE.md E2E preflight** — the run must satisfy the served-application preflight, which asserts
  the page under test came from THIS checkout. No flag and no environment variable skips it.
- **`141-VALIDATION.md` § Sampling Rate** — the phase gate is `yarn build` → `yarn test:unit` →
  full `yarn test:e2e` green, preflight-confirmed, on one fresh dev server.
- **Environment prerequisite** (carried in project memory as `project_e2e_execution_devserver_prereq`):
  one fresh dev server on the configured frontend port and a clean database (`yarn db:reset`) before
  the full-suite gate. A stale server steals the port and a dirty database produces teardown-count
  failures unrelated to this phase.
- **`141-VALIDATION.md` sign-off** — set `nyquist_compliant: true` and `wave_0_complete: true` in that
  file's front matter only if the gate's evidence supports it; do not set them optimistically.
</decisions>
