Wire the five `packages/*` workspaces that hold 18 test files and 140 tests no CI command executes,
and prove the wiring turns CI red rather than merely turning the task list longer.

either turns CI red". That is a property of the exit-code path, not of the task list, so the plan
proves it by planting failures and reading exit codes, then reverting.

ledger rows plan 01 opened.

Binding decisions in force for this plan:

- **D-10** — `llm`, `question-info`, `argument-condensation`: RENAME the existing `test` script to
  `test:unit`. Not an alias, not a second entry point. One canonical name per workspace, matching the
  other twelve. `test:watch` stays exactly as each package declares it today (`vitest` for `llm` and
  `question-info`, `vitest watch` for `argument-condensation`).

- **D-12** — all five use bare `vitest run`. No `--passWithNoTests`. Measured consequence: bare
  `vitest run` with zero test files exits 1; with the flag it exits 0. The flag would buy silence
  exactly when a package's tests all vanish — the unfailable-check class this milestone removes.
- **D-13** — the five already-wired packages carrying `--passWithNoTests` (`app-shared`, `data`,
  `dev-seed`, `filters`, `docs`) are **left alone**. Do not harmonise them; it is a recorded Deferred item.
- **D-14 / UNIT-03** — wire only what `141-MEASUREMENT.md` recorded green. Read its
  § Wiring authorisation section before the first edit.
- **Research Pitfall 2** — do NOT satisfy any requirement here through `vitest.workspace.ts`. It is
  deprecated in Vitest 3.2.4, bypasses turbo's build dependency, and replaces the per-workspace
  contract UNIT-04 guards with a single glob.

Never `git checkout .`, never `git stash`, never `git clean`.
