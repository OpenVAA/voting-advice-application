<objective>
Build the standing guard that makes the hole this phase just closed unable to reopen, in both
directions: a workspace that has tests but declares no `test:unit` script fails by name, and a
workspace that declares the script but is not actually executed by turbo fails by name.

The plan lands AFTER the wiring (plan 02) deliberately. The guard is `&&`-chained ahead of turbo in
the root `test:unit` script, so landing it on the unwired tree would leave every commit in between
with a red `yarn test:unit` — the "someone else's schedule" failure UNIT-03 exists to prevent. The
red observations the standing acceptance rule demands are therefore produced by injection: a scratch
workspace, a real un-wired package, a root drifted out of the workspaces globs, and a broken turbo
dry run.

Purpose: research Pitfall 1 is the single most likely way to build a fake guard here. Turbo's
`--dry=json` lists EVERY workspace, including unwired ones, so the obvious "diff `tasks[].package`
against the test-file set" implementation passes at HEAD before any work lands. Plan 01 recorded that
naive variant green on the unwired tree; this plan implements the discriminating variant and proves it
red against inputs the naive one would wave through.

Output: `scripts/assert-unit-test-coverage.mjs`, two root `package.json` script keys, and the CATCH
halves of the UNIT-04 and UNIT-02 ledger rows.

**No tracer task in this plan.** The phase's tracer is plan 02 task 1 — the slice that proved the
script → turbo → exit-code path end-to-end. This plan adds a gate in front of that proven path; there
is no second architecture to trace.
</objective>

<decisions>
Binding decisions in force for this plan:

- **D-07** — the guard wraps the root `test:unit` script, so it fires on the exact command whose
  invariant it protects (every local run and CI `main.yaml:70`).
- **D-08** — plain root-level Node script, no build step, no `tsx`, no workspace imports, zero new
  packages. The constraint is the property, not the path.
- **D-09** — detection rule: a workspace containing at least one test file (`*.test.ts`, `*.spec.ts`,
  `*.test.tsx`, excluding `node_modules`) and declaring no `test:unit` script FAILS, naming the
  workspace. Both directions of SC-4 must be observed.
- **D-16 (supersedes D-09's scope clause)** — the guard scans **both `packages/*` and `apps/*`**, via
  a **single array constant** so the scanned set is visible in one place. All three `apps/*` workspaces
  already declare `test:unit`, so this lands green.
- **D-17 (amends D-08)** — the UNIT-02 cross-check is a SECOND assertion inside the same guard, not a
  one-off artifact. **This knowingly costs D-08's no-subprocess bootstrapping property**: the guard
  now shells a turbo dry run before turbo runs. That cost is stated out loud in the guard's docblock
  rather than left to erode silently. The rest of D-08 holds: no build step, no `tsx`, no workspace
  imports, no new dependency.
- **Research Pitfall 1** — the discriminator is the comparison against turbo's non-existent-script
  sentinel. A cross-check that is green at HEAD is a fake guard.
- **Research Pitfall 3** — exercise SC-4's second direction on a SCRATCH package, never by deleting a
  test file from a real package that now carries bare `vitest run` (which would exit 1 for an
  unrelated reason).
- **Research Pitfall 4 (accepted, not fixed)** — a root-level `.mjs` is linted by nothing here: there
  is no root `lint` script, and `.lintstagedrc.json`'s first glob contains an unseparated
  `mjssvelte` token so `.mjs` matches no lint-staged pattern. `prettier --write .` via `yarn format`
  does cover it. The precedent is `apps/supabase/scripts/lint-schema.mjs`, which lives with exactly
  this property today. The `mjssvelte` token is a pre-existing defect: record it as a follow-up, do
  not fix it in this phase.
- **CLAUDE.md "use TypeScript strictly"** — the guard is deliberately outside TypeScript (D-08's
  no-build constraint). State that tradeoff in the guard's docblock rather than leaving it implicit.
</decisions>
