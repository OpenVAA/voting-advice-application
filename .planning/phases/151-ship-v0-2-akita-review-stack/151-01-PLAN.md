`build-slice.sh` requires `GIT_INDEX_FILE`, `TARGET` and `PARENT` in the environment and fails with
a usage error if any is unset. It runs
`git -c diff.renameLimit=20000 diff --raw -z --abbrev=40 --no-renames "$PARENT" "$TARGET" -- <pathspec…>`
piped through a NUL-safe `python3` transform into `git update-index -z --index-info`, mapping status
`D` to mode `0` with a 40-zero OID, then `git write-tree` + `git commit-tree`. `--abbrev=40` is
mandatory (Pitfall 3) and `set -o pipefail` is mandatory (a pipe failure otherwise reports success
while producing nothing). If the resulting tree equals `PARENT^{tree}`, print `EMPTY: <msg>` on
stderr, echo `PARENT` unchanged, and exit 0.

`verify-identity.sh` takes `TARGET` and `TIP` and performs D-23's two independent checks: the
changed-file count from `git -c diff.renameLimit=20000 diff --name-only TARGET TIP`, and equality of
`git rev-parse TARGET^{tree}` against `git rev-parse TIP^{tree}`. Print both values, then a summary
banner, then exit 0 only if the file count is 0 **and** the tree hashes are equal; otherwise print
remediation prose naming the first differing path and exit 1.

Then run the pipeline once, entirely on throwaway refs, mutating nothing real:
`git fetch origin`; resolve `BASE=$(git rev-parse origin/main)` (C-12 — do not hard-code
`ac30f132a`); materialise the merge target with

Anatomy (lines 614–638), finishing with a catch-all invocation whose pathspec is `.`.

Use a dedicated `GIT_INDEX_FILE` under the scratch directory throughout; the repo worktree must not
