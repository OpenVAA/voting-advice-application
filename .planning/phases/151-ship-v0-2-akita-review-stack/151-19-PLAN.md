## What the skill must carry that the brief did not know

Drafted from this phase's own experience, not from the source brief:

- **The mechanism is index-level tree surgery, not rebasing.** Two plumbing primitives build the
  whole stack in seconds, and byte-identity becomes a property of the construction rather than an
  assertion checked afterwards.
- **The catch-all is a laundering surface, not a safety net.** It makes the tree hash match whether
  or not the partition is correct. The per-slice prediction check is the real evidence.
- **A pure-rename commit must be derived by rule, not by rename detection.** Similarity matching at
  this scale produces confident nonsense pairs.
- **Parse every git stream NUL-safely.** One tracked path in this repository contains a space, and
  whitespace splitting silently corrupts file sets.
- **Fix on the branch first, then cut.** This is what makes the identity claim non-circular, and it is
  worth its one-way cost.
- **Sweep bottom-up and lag the pull requests by one slice.** A cross-slice fix is then a script
  invocation rather than a force-push to a PR under review.
- **Never launder a blind spot as met.** A cited gate's reach must be measured against the tree being
  swept, and its complement named in the same cell.
- **Write the escape hatch before you need it.** The rule for what happens when a fix collides with
  the cardinal test rule must exist before the collision, or it gets invented under pressure.
- **The one pull request nobody will read is the one that needs a scanner.**
