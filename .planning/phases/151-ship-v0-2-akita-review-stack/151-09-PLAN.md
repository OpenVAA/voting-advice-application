<objective>
Cut the bottom three slices of the stack and sweep them: the pure-rename layout move, the Strapi
removal, and the shared packages.

These three carry the least sweep surface in the stack — 01a changes no file contents at all and 01b
is deletions — which makes them the right place to establish the sweep-then-cut loop that plans
151-11 through 151-17 repeat.

Purpose: criteria 1, 2, 4 and 6, applied bottom-up per D-07.
Output: three local branches, three sets of disposition cells, an updated stack manifest.
</objective>

## The loop this plan establishes (D-04, D-06, D-07, D-19)

1. **Sweep** the slice's file set against every applicable checklist item, one agent per item
   (D-19), each agent holding one lens across the whole slice.
2. **Fix** on `feat-gsd-roadmap` first (D-04) — never inside the stack. Re-run unit and lint.
3. **Cut** the slice from the now-fixed tip, then run a partial-stack identity check and a
   remaining-slices catch-all.
4. **Open** the PR for the slice *below*, once this slice has been swept (D-07). Opening lags
   building by one slice; that is an ordering constraint on *opening*, not on building.

If a fix in this slice's sweep touches a file owned by an **already-cut** slice, re-cut from that
slice upward. It is unopened, so this is one script invocation — that is precisely the cost D-07 was
accepted to keep cheap.

If a fix reddens the suite, PD-01 in `151-DISPOSITION.md` § Procedural decisions governs. Do not
improvise.
