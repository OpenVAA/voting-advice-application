  tool and package versions as readily as milestone tags. Its 45 occurrences across 30 files are
  **report-only** here and route to plan 151-08's agents.
- **PATTERNS correction** — `151-VALIDATION.md` says "APPLY-flag convention". The in-repo convention
  in both precedent codemods is a **`--apply` CLI flag** parsed into a constant. There is no
  environment variable. Write it as `--apply`.

  <behavior>
    - Given a line whose trimmed form does not begin with a recognised comment opener and which is not inside an open block comment, the codemod leaves it byte-identical and adds it to the residue report.
    - Given a comment containing an artifact path reference, the reference is removed and surrounding punctuation and whitespace are repaired.
    - Given a comment containing a section anchor, a plan number, or a decision ID in either the long or the bare form, that token is removed.
    - Given a comment containing a phase or spike reference that survives the removals, it is collapsed to the short pointer form, and consecutive duplicate pointers are de-duplicated to one.
    - Given a comment that becomes empty or degenerate after all removals, the whole comment line is deleted.
    - Given a milestone-version-shaped token, the codemod does not rewrite it and adds it to the residue report.
    - Given a TODO-class marker, the codemod does not rewrite it and does not report it as a planning reference.
    - Given no `--apply` argument, no file on disk changes and the process exits 0.
    - Given a glob that matches zero files, the process exits non-zero rather than reporting a successful no-op.

  <action>
Create `hygiene-codemod.mjs` following `store-to-state-codemod.mjs`'s structure exactly: `globSync`
from `node:fs` for enumeration (not a git listing), an explicit hard failure when the glob matches
nothing, a `--apply` CLI flag parsed into a constant with dry-run as the default, a `--files <glob>`
override, and a final line that always states which mode ran.

Extend the precedent's per-line string-literal guard into a **comment-span classifier**. A line is
eligible for rewriting only if its trimmed form opens with one of the recognised comment openers for
its file type — the C-family line and block forms and their continuation form, the markup comment
form, the SQL double-dash form, and the shell hash form — or if the classifier's block-comment state
machine says the line is inside an open block. Every other line is ineligible, is left byte-identical,
and is emitted to the residue report with its path and line number. C-6 requires SQL and shell
support; without it, nine files are silently skipped or, worse, wrongly rewritten.

Apply the seven mechanical rules from Pattern 4 in the stated order, with rule 5 (the milestone
version form) **disabled and routed to the residue report** per Pitfall 6.

The decision-ID rule handles **both** forms (C-5), plus the bare-uppercase task-ID class that
travels with them — identifiers shaped like an uppercase word, a hyphen, and two digits — which is
the same class under a different spelling.

Emit a machine-readable summary to stdout: files scanned, files rewritten, per-rule hit counts, and
the residue count broken down by reason (not a comment span, milestone-version form, Markdown file,
TODO class). The residue report is the handoff to plan 151-08; anything the codemod declines to
rewrite and does not report is silently lost.

Restrict enumeration to the three in-scope trees. Add a hard guard that refuses to open any path
