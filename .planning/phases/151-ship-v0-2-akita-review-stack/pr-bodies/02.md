## Read this first — the stack contract

This is one PR in a **review-only stack of twelve**, cut from the v0.2 "Akita" body of work so that it
can actually be read. Four things follow from that, and all four are deliberate:

1. **Individual PRs need not build, lint, or pass tests. Only the whole matters.** The stack is a
   *reviewing* device: it slices one large final state into twelve diffs, each holding changes of a
   similar nature. Intermediate states are therefore not required to be working states, and several
   are not. See "Why no checks run here" below.
2. **The stack's final state is byte-identical to the development branch's final state.** The twelve
   slices are a re-partition of the same tree, not a re-implementation of it: the top of the stack and
   the tip of the development branch have the same git tree hash, and `git diff` between them reports
   zero files.
3. **Because of (2), the stack does not need to be merged.** It exists to be read. Merging the
   development branch, or merging the stack, produces the identical tree.
4. **Review comments do not have to be implemented inside the stack.** Fixes can land on a separate
   branch targeting whichever of the development branch or the stack is easier at the time.

**No file is shown to you twice in two different content versions.** Every file appears in exactly one
slice's diff, in its final state. You will never review a version that a later PR undoes. (Verified:
every off-diagonal cell of the pairwise overlap matrix is `0`, and the slices plus an empty remainder
reconstruct the target tree exactly. Re-verified after this slice was cut: the four cut slices plus the
untouched remainder produce tree `dc62fbf2b`, which is the development branch's tree hash.)

## Why no checks run here

`.github/workflows/main.yaml` triggers on pull requests whose base is `main`. This PR's base is
`ship/v0.2-akita-01b-strapi-removal`, a sibling branch, so **no checks run — and that is correct
behaviour, not a misconfiguration.** Only PR 1 of the stack fires CI at all.

Had they run, they would have failed at the same place PR 1 fails, and for a reason that has nothing to
do with this PR's contents. Observed on PR 1's run: all three jobs fail at the step **`Setup Yarn 4.6`**
with

```
YN0085: │ - @adobe/css-tools@npm:4.4.1, @alloc/quick-lru@npm:5.2.0, ... and 407 more.
##[error]The lockfile would have been modified by this install, which is explicitly forbidden. (YN0028)
```

Note *which* step that is: `threeal/setup-yarn-action@v2` performs the dependency install itself as part
of its caching, so the workflow's own, more obviously named `Install all dependencies` step is never
reached and is reported `skipped`. The cause is that the root `package.json` still declares `frontend`,
`docs` and `backend/vaa-strapi` as workspaces, while PR 1 moved two of them under `apps/` and PR 2
deleted the third. Those 412 packages dropping out of the resolution are the dependency closure of the
moved-away workspaces. The root `package.json` and `yarn.lock` are corrected in
`ship/v0.2-akita-10-root-config` (PR 11), so **every stack state from PR 1 up to and including PR 10 —
ten branches — cannot `yarn install`.** That is the stack contract's point (1) working as designed.

The green signal that does exist for this body of work is the full suite run against the development
branch's tip, recorded in the phase record.

## What was checked before this PR opened

Every item of `.agents/code-review-checklist.md` was swept against this slice and given a recorded
verdict. **The sweep is exhaustive over the slice's security surface**, which is affordable here because
the slice contains no auth, RLS, adapter or request-handling path — it is library code plus one
maintainer CLI. The twelve applicable cells came out as **2 met, 5 fixed, 4 not applicable, 1 deferred**.

**Five findings were fixed on the development branch *before* this slice was cut**, so what you are
reading is the corrected code and this PR contains no fix of itself:

- A new file opened a blanket `eslint-disable @typescript-eslint/no-explicit-any` over four `as any`
  casts with **no documented reason**, which both the checklist and the style guide require
  (`app-shared/src/utils/mergeSettings.ts`).
- The exported type `DeepPartial<TObject>` in the same new file carried no TSDoc.
- `dev-tools/src/pem-to-jwk.ts` accepted `-----BEGIN ENCRYPTED PRIVATE KEY-----` and handed the blob to
  `jose.importPKCS8`, which takes no passphrase — so an encrypted key produced an unhandled library
  exception while *every other* invalid input in the same file was handled with a message and a non-zero
  exit. The file advertised support it did not have.
- `packages/README.md` asserted **"No other packages currently diverge."** in the same commit that adds
  a diverging package. Five workspaces diverge; the list is now complete.
- `packages/app-shared/README.md` attributed the historic dual ESM+CommonJS build to `apps/strapi/` — a
  path that has **never existed in this repository**. The retired Strapi backend lived at
  `backend/vaa-strapi/`. (`git ls-tree` returns zero entries for `apps/strapi` at both ends of the
  diff.) This turned out to be a pattern rather than a slip: the same never-existed path appears **46
  times across 16 files**, and the remaining 15 are documentation pages reviewed in PR 10.

**One item is knowingly deferred**, and it is recorded rather than hidden: the Developers' and
Publishers' Guides are not updated for these packages — in particular `@openvaa/dev-tools` is missing
from the repo-structure page. Those pages live under `apps/docs/**` and are reviewed in PR 10 of this
stack; editing them here would put PR 10's content in this diff.

**One measurement is worth stating plainly.** 341 files inside this slice's pathspec are byte-identical
at both ends of the v0.2 diff and therefore appear in **no** PR's diff, including this one. They are not
missing from review by accident — they are unchanged by v0.2, so there is nothing to review. The number
is recorded so nobody later mistakes "not in the diff" for "not in the repository".
