## Read this first — the stack contract

This is one PR in a **review-only stack of twelve**, cut from the v0.2 "Akita" body of work so that it
can actually be read. Four things follow from that, and all four are deliberate:

1. **Individual PRs need not build, lint, or pass tests. Only the whole matters.** The stack is a
   *reviewing* device: it slices one large final state into twelve diffs, each holding changes of a
   similar nature. Intermediate states are therefore not required to be working states, and several
   are not. See "Why no checks run here" below.
2. **The stack's final state is byte-identical to the development branch's final state.** The twelve
   slices are a re-partition of the same tree, not a re-implementation of it: the top of the stack and
   the tip of the development branch have the same git tree hash, and `git diff` between them reports
   zero files.
3. **Because of (2), the stack does not need to be merged.** It exists to be read. Merging the
   development branch, or merging the stack, produces the identical tree.
4. **Review comments do not have to be implemented inside the stack.** Fixes can land on a separate
   branch targeting whichever of the development branch or the stack is easier at the time.

**No file is shown to you twice in two different content versions.** Every file appears in exactly one
slice's diff, in its final state. You will never review a version that a later PR undoes. (Verified:
every off-diagonal cell of the pairwise overlap matrix is `0`. Re-verified after the slice above this
one was cut: the seven cut slices plus the untouched remainder produce tree `06f7ab4f4`, which is the
development branch's tree hash, and the partition arithmetic closes at a gap of `0` —
252 + 97 + 119 + 162 + 195 + 533 + 2,934 = 4,292, the comparable file total. The remainder also
decomposes independently, without reference to the catch-all: 213 + 329 + 39 + 37 + 2,316 = 2,934.)

## Why no checks run here

`.github/workflows/main.yaml` triggers on pull requests whose base is `main`. This PR's base is
`ship/v0.2-akita-04-dev-seed`, a sibling branch, so **no checks run — and that is correct behaviour,
not a misconfiguration.** Only PR 1 of the stack fires CI at all. Asserted, not predicted:
`gh pr checks` on the four already-open stacked PRs returns *"no checks reported"* on each.

**Do not read that as "the e2e job exists and was skipped."** The workflow file at this branch's head
is still `main`'s — byte-identical, blob `c2fdcedb2` — and it defines exactly three jobs:
`frontend-and-shared-module-validation`, `backend-validation` and `e2e-tests`. Those are the jobs that
*exist* here; they simply do not fire on a sibling-based PR. The branch-tip workflow, with its newer
Yarn and its additional jobs, arrives with PR 11.

Had the three that are present run, they would have failed at the same place PR 1 fails, and for a
reason that has nothing to do with this PR. Observed on PR 1's run: all three fail at the step
**`Setup Yarn 4.6`** with

```
YN0085: │ - @adobe/css-tools@npm:4.4.1, @alloc/quick-lru@npm:5.2.0, ... and 407 more.
##[error]The lockfile would have been modified by this install, which is explicitly forbidden. (YN0028)
```

Note *which* step that is: `threeal/setup-yarn-action@v2` performs the dependency install itself as
part of its caching, so the workflow's own, more obviously named `Install all dependencies` step is
never reached and is reported `skipped`. The cause is that the root `package.json` still declares
`frontend`, `docs` and `backend/vaa-strapi` as workspaces, while PR 1 moved two of them under `apps/`
and PR 2 deleted the third. Those 412 packages dropping out of the resolution are the dependency
closure of the moved-away workspaces. The root `package.json` and `yarn.lock` are corrected in
`ship/v0.2-akita-10-root-config` (PR 11), so **every stack state from PR 1 up to and including PR 10 —
ten branches — cannot `yarn install`.** That is the stack contract's point (1) working as designed.

**Being honest about the green signal for THIS PR, because it is the one PR where it matters most.**
Every other PR in this stack can point at a local run. This one cannot yet, and saying otherwise would
undercut the suite's whole purpose:

> **The 43 specs in this PR have not been run.** Running them needs a dev server on `:5173` and a
> seeded local Supabase, and this project's own rule is that a did-not-run E2E test counts as a
> failure rather than a pass. **So this PR does not claim a green suite.** The suite is run once, in
> full, against the post-review-sweep tip of the development branch, and that run — not per-PR CI and
> not this PR — is the stack's collective proof. It is the last step of the work that produced this
> stack.

What *was* obtained is real and has a real failure mode: `npx playwright test --list` loads
`playwright.config.ts` with all three config-load guards active and reports 143 tests in 94 files.
A dropped spec, an orphaned probe or a drifted soft-assertion budget would have failed it. It is not
a suite pass and is not offered as one. `yarn typecheck:tests` is clean.

## Two things a reviewer should know are open

Neither is deferred quietly; both are recorded with the reason.

- **Keyboard navigation has no automated gate anywhere in this suite, and the accessibility gate that
  does exist reaches 5 URLs.** The axe scan is default-on and asserts against all four WCAG tags, but
  its route table resolves to **5 distinct URLs × 2 themes** — measured, not estimated — which leaves
  **31 of the 36 page routes never scanned**, including every candidate-app route, every admin route,
  and the voter question flow. The raw-i18n-key scan has exactly the same reach, because its only call
  site is inside the axe helper. And axe is a static-DOM auditor: it does not tab through the UI, so
  the keyboard half of the requirement is uncovered even on the 5 URLs it does reach. Widening the
  route table and adding a keyboard gate is net-new test authorship and is scoped to a later phase.
- **CI sets `retries: 3`, which can turn a flake green.** Accepted, because the remedy already exists
  and is in this PR: `determinism-batch.sh` **refuses to start** with `CI` set, for exactly this
  reason, and fails a batch outright when the flaky count is non-zero; four projects pin `retries: 0`
  where a retry would mask a state-mutating assertion. The full-suite run that is this stack's real
  gate is local and non-CI at `retries: 0`.
