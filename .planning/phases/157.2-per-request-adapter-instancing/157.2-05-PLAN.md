<objective>
Close the site the ruling, the review and the discussion all missed.

**Purpose.** Research finding B measured eighteen configuration sites where the phase's inputs described
seventeen, and the missing one is the busiest: the shared writer-preparation helper the browser contexts use.
Nineteen call sites across the candidate, admin, auth and candidate-user-data contexts funnel **every browser
write** through it, and each one re-configures the same shared writer. Any plan sized against "seventeen
mechanical one-liners" is sized wrong, which is exactly why this site gets a plan of its own.

**Research question 5 settles the lifetime question that an "adapter per request" framing does not obviously
answer.** Both browser sites — the helper and the feedback sender — already configure **per invocation**, not
per context, and both are already guarded to run only in the browser. The Svelte context object never holds an
adapter: the context holds a *function*, and the function holds the adapter for one call. So decision B2(a)
maps onto them with nothing left over. The adapter becomes per-call and cheap; the Supabase **browser client**
stays memoized at module scope, because it owns auth listeners and cookie sync and one per tab is what the
library expects.

**Decision B2(a) is half-built already.** The memoized browser client exists at `src/lib/supabase/browser.ts`
with a docstring saying it is safe to call repeatedly, and nothing imports it. Plan 02 wired it into the
browser arm of the factory; this plan is where it finally gets used.

**One type outlives its value if this plan forgets it.** The admin context's type module imports the module
singleton *as a type*. Plan 07 deletes that value. Re-point it at the factory's return type here, in the plan
that owns the context layer, rather than discovering it as a build break one wave later.
</objective>

  <action>
    Decide the helper's fate and implement it. Both outcomes are defensible and the plan requires the choice to
    be made once, deliberately, and stated in the SUMMARY with its reason.

    Either the helper disappears and each consumer calls the appropriate factory directly, which is the
    smallest surface and matches what the sibling feedback site already does; or it survives as a thin
    synchronous wrapper that selects the right factory and keeps the browser guard in one place, which keeps
    the guard from being copied nineteen times. Choose on the basis of how many consumers would otherwise
    repeat the guard, and say so.

    Whichever is chosen, four properties must hold.

    The browser guard stays. It is the invariant that lets the browser arm pick the memoized client without an
    environment branch inside the adapter, and one of the context specs mocks this module precisely because it
    throws outside the browser — that behaviour is depended upon.

    The signature becomes synchronous. There is nothing left to await once construction is the configuration;
    the current promise-returning shape exists only because the old contract was "configure this shared object
    and hand it back".

    The docstring is rewritten rather than annotated. Its current text promises the same instance back,
    described as an initialisation step, and refers to the adapters as having no initialisation path of their
    own. Every clause of that is false after this phase, and decision B3's NOTE requires the tree to read as
    though the two-step protocol never existed — so no "formerly" note and no deprecation marker.

    The error string that blames the configured adapter type for a missing writer goes with it. It describes a
    selection the factory now makes at construction, and a message describing a decision that is no longer made
    where the message is thrown is worse than no message.

    **Do not delete the file in this task even if the chosen outcome is that it should not survive the phase**,
    and do not touch the consumers. Nineteen call sites still import it; deleting it here would leave the tree
    uncompilable at a task boundary. Task 2 converts the consumers and, if the chosen outcome is removal,
    performs the deletion at the end. In this task the file always still exists, rewritten to configure
    nothing.

    Record the decision and its reason in the SUMMARY, because task 2 acts on it.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser tab → Supabase auth session | The memoized browser client owns the auth listeners and the cookie sync for the tab; duplicating it splits the session's ownership |
| context function → adapter instance | Each browser write must run on a writer that exists for that write only, so one user's tab state cannot leak into a concurrently-issued call |
