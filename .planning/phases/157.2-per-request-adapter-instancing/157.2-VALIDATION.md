## Sampling Rate

- **Per task commit:** `yarn workspace @openvaa/frontend vitest run <the touched spec>` + `yarn workspace @openvaa/frontend lint`
- **Per wave merge:** `yarn test:unit` + `yarn lint:check`
- **Phase gate — E2(a) with the P4 ordering correction:**
  `build` → `lint:check` → `format:check` → `test:unit` → `yarn workspace @openvaa/frontend check` → pgTAP → **`yarn db:reset`** → one fresh dev server on `:5173` → `yarn test:e2e`

  **Why the reset MOVED.** E2(a) as written put `db:reset` first. Phase 157.1 measured why that fails:
  `packages/dev-seed/tests/integration/default-template.integration.test.ts` writes the default template
  (327 candidates, `seed_election_default`) into the **live** local Supabase whenever `SUPABASE_URL` is set,
  and its teardown leaves it. With `test:unit` between the reset and the E2E suite, the voter app sees two
  elections — 157.1's first run was `4 failed, 79 did not run, 67 passed`, deterministic and not flaky. The
  reset now sits immediately before the E2E half. **This is a workaround; the defect is still open** in
  `157.1 deferred-items.md` with three candidate remediations.

## Negative-Control Ledger

**C2 is the phase's central deliverable, per ruling D11: the proof, not the patch.** The concurrency test
must fail on the singleton **by construction** — the interleaving `init A → yield → init B → resume A →
observe B's client`, driven by an explicit `Deferred`, **never a timer**. A test that fails because it lost
a race is not a negative control; it is a flake, and the cardinal rule forbids shipping one.

| # | Instance | RED to record |
|---|---|---|
| 1 | `#supabase` sharing | Pre-fix: request A resumes and observes request B's client. Assert isolation, observe RED |
| 2 | `#fetch` sharing | Pre-fix: same interleave on the `#fetch` vector (live via inherited `logout` / `clearIdToken` / `exchangeCodeForIdToken`, which hit **same-origin** API routes) |
| 3 | Job lifetime | Pre-fix: a second job's `init` rebinds the first job's writer mid-run |
| 4 | Guard self-test | Pre-fix (no rule): a module-scope `new` of an adapter lints clean |
| 5 | REPLACE standing regressions | **One per inherited entry, per zone.** Research measured **three distinct effective rule sets** across six paths — a naïve fourth block deletes 2–7 inherited bans while emitting **zero errors** |
