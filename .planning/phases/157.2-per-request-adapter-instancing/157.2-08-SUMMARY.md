**Two-step adapter configuration no longer exists in the tree — the fetch and the Supabase client are required constructor arguments, so the plain-`createClient` branch ruling D10 blames for the admin outage is unexpressible rather than merely unreached, and the compiler now rejects both an adapter built from nonsense and an adapter built from a config that names no client.**

## Accomplishments

- **The fallback branch is gone by construction, not by convention.** `supabaseAdapter.ts` lost its
  three-branch environment sniff, its `createBrowserClient` call, its `createClient` call, the `$app/environment`

The first line is RESEARCH P3's warning sign (`new SupabaseDataProvider('nonsense')` must not compile) measured
as closed. The second discharges the truth *"a caller who supplies no client does not get an anonymous one; it
does not compile"* in its bluntest form.

**Run 2 — the counterfactual. The constructor was removed from `SupabaseFeedbackWriter` only, and the probe was
narrowed to a config that names a `fetch` and no client:**

```
export const b = new SupabaseFeedbackWriter({ fetch: globalThis.fetch });
```
```
COMPLETED 2706 FILES 0 ERRORS 0 WARNINGS 0 FILES_WITH_PROBLEMS
```

**Zero errors.** Without the subclass constructor the mixin's intersection type falls back to the BASE's
`(config: AdapterConfig)` signature, which knows nothing about `client` — so an adapter with no Supabase client
is a legal construction. This is the hole the plan's third prohibition names, measured rather than asserted.

**Run 3 — the constructor restored, the same probe expression:**

```
ERROR "src/lib/api/adapters/supabase/__ctor_probe.ts" 3:45 "Argument of type '{ fetch: … }' is not assignable to parameter of type 'SupabaseAdapterConfig'.

COMPLETED 2706 FILES 1 ERRORS
```

The pairing is the point: **the required field and the explicit constructor only work together.** Making `client`
required without the subclass constructor would have produced run 2 — a required field the caller is never
checked against. That is the plan's second key link, discharged by measurement.

**1. [Rule 3 - Blocking] The mixin's constructor could not name its parameter (TS2545)**

- **Found during:** Task 1
- **Issue:** The first implementation wrote `constructor(config: SupabaseAdapterConfig)` directly inside the
  mixin's `WithMixin` class. svelte-check rejected it: `supabaseAdapter.ts 19:18 "A mixin class must have a
