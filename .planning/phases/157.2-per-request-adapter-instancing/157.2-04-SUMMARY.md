- **The two admin actions now write their job records as the admin who submitted the form.** Each obtains its writer from `createDataWriter({ fetch, locals })` immediately below the `safeGetSession()` check it already performed, so the client is one whose session the route itself verified. - **Found during:** Task 2, before writing the conversion.
- **Issue:** The task requires the route to use `createSupabaseAnonClient`, which lives at `$lib/supabase/anon`. `157-16` moved this exact path OFF the adapter boundary and struck its allowlist entry, so the boundary guard's `no-restricted-imports` pattern `^\$lib/(supabase|api/adapters)(/|$)` applies to it. **Measured with `ESLint#lintText` at the real path `src/routes/candidate/preregister/+layout.server.ts` before any edit:** *"'$lib/supabase/anon' import is restricted from being used by a pattern. - **Fix:** the guard's own message names the remedy, and `157.2-03` already established the mechanism for precisely this class of problem. `lib/api/dataProvider.ts` — allowlisted, and the seam the guard points at — re-exports `createSupabaseAnonClient`. Construction stays in `$lib/supabase/anon.ts`, and `grep -rn 'createSupabaseAnonClient'` still enumerates every site in the tree that has chosen to run without a session, which is the property that module exists for.
