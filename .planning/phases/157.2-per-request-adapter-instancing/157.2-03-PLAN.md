<objective>
Give a universal load's server pass a client that knows who is asking.

**Purpose.** Six of the eighteen sites are universal loads, and the widest of them —
`routes/+layout.ts:18` — re-configures the shared provider on **every SSR request for every page of the whole
application**. Fact 3 records that nobody named it, and criterion D11-5 requires that the instance Phase 157
added close by the same mechanism as the other two rather than separately. That is what this plan does.

**Research question 2 was the phase's largest unknown and it is settled.** `fetch` alone is not sufficient,
and the tree's own comment claiming otherwise is ruling D10's root cause written down in prose. SvelteKit's
load `fetch` forwards cookies same-domain only, Supabase is a different origin, and even if the cookies
arrived PostgREST authenticates on `Authorization` rather than on them. The mechanism that works is the
official `@supabase/ssr` isomorphic shape, applied once at the root: a server load returns the serializable
cookie array, a universal load branches on `isBrowser()` and builds the client, and children take the finished
client from `await parent()` — legal because a universal load's return value is not serialized, while a server
load's must be.

**Three traps ride along with that mechanism and each is a silent failure.** The root `+layout.ts` already
exists, so it *shadows* the new root `+layout.server.ts`: a missing layout module behaves as `({ data }) =>
data`, but a present one returns only what it returns, and anything not forwarded vanishes for every
descendant. A bare `cookies.getAll()` would carry this application's `httpOnly` cookies into the HTML payload
and defeat the flag protecting them — a data-protection requirement, not a mechanics detail. And `data.supabase`
fires the adapter-boundary selector exactly as `locals.supabase` does, which is why plan 02 put the read inside
the allowlisted factory modules and why no route file here performs one.

**One shape is deliberately left alone.** Two of these loads return unawaited promises for streaming, so the
adapter is captured by a promise that outlives the load's return. Under a per-call factory that is harmless —
the captured instance is that request's own — and it is not a reason to start awaiting them.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server load → SSR HTML payload | Everything a server load returns is serialized into the page; `httpOnly` cookies placed here become readable by client JavaScript |
| universal load SSR pass → Supabase | Which client a load holds decides whose rows PostgREST returns |
| parent load → child load | `await parent()` is the only channel by which a live client reaches a nested universal load |
