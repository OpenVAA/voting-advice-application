<objective>
Create the phase's evidence apparatus before anything it will measure moves.

**Purpose.** Ruling D11 is explicit that this phase's deliverable is *the proof, not the patch*: "a
concurrency test that FAILS on the singleton before it passes on the fix." A proof that is assembled after
the subject has changed is not a proof. Validation measured three spec loci that do not exist — the
concurrency spec, the guard self-test, and any spec at all under `src/lib/server/admin/features/` — and this
plan creates all three plus the register that holds their before-and-after cells.

**Decision C2(a)** puts the concurrency spec beside the adapter (`adapters/supabase/*.concurrency.test.ts`)
because it is a behavioural test that must run in the existing `test:unit` gate; the guard self-test goes to
`lib/_guards/` because that directory means "does the rule fire". **Decision C1(a)** fixes the shape: a
deterministic interleaving against a fake client, driven by an explicit `Deferred`, **timer-free**, failing
on the singleton *by construction*. **Decision E1(a)** requires a recorded RED per behaviour, not one for the
phase, which is why the register has five rows rather than one.

**One structural choice carries the whole negative control: the `obtain()` seam.** The spec must exercise the
adapter the way a call site does. Pre-fix that means the module singleton plus `init()`; post-fix it means the
factory. If those are two different test files, or two different code paths inside one file, the GREEN does
not answer the RED. So the binding is a single named function with a one-line body, and flipping it is the
only difference between the two runs.

**Sequencing (decision E3(a)).** 157.1 has landed and closed; its parse contract is settled at the same call
sites this phase re-scopes. Phase 158 consumes this phase's mechanism and must not start before it.
</objective>
