<objective>
Thread the request's own client into every server-side site — except the one that refuses it on purpose.

**Purpose.** Decision **A2(a)** puts the threading in this phase and the admin restoration's proof in 158.
Fact 10 is why this is threading rather than construction: a correct per-request cookie-bearing client
already exists, is already built exactly once per request in `hooks.server.ts`, and already sits on
`event.locals` — it simply was not reaching fifteen of the eighteen sites. Fact 8 measured that only the two
candidate-protected sites ever passed it.

**Criterion D11-3 names this plan's first site.** The window is `init` at line 30, `await
locals.safeGetSession()` at 33, and `await dataWriter.getCandidateUserData(…)` at 44 — two awaits during which
a second candidate's request can rebind the shared object. Under the factory the conversion is a
constructor-argument change, and the window becomes harmless because the instance is not shared.

**One site is a deliberate exception and it must survive intact.** Research finding D-4 measured that
`candidate/preregister/+layout.server.ts:11` refuses the server client **on purpose**: no Supabase session
exists at that point in the flow, the visitor is authenticated only by the bank-auth cookie, the table it reads
is readable by the anonymous role, and 157-16 moved that route off the adapter boundary and left a firing
guard case behind it. Threading the client here would reverse a settled decision and break a test. It takes
the **named** anonymous client instead — and that naming is the whole content of decision A2's NOTE. A named
anonymous client chosen at a call site with its reason written beside it is not a silent third branch; the
unnamed fallback branch this phase deletes was dangerous precisely because it was reached without anyone
choosing it.

**The operator ruled on `/api/auth/login`.** Research measured zero callers; the only references are two
comments in routes that deliberately bypass it. Ruling D10 classes its 403-versus-400 split as a credential
oracle. Decision B3 removes the configuration call the route makes, so leaving it untouched was never on the
table. **157.2 deletes it; 158's criterion A4 becomes a verification.** The deletion carries the same
evidentiary discipline as the rest of the phase: the zero-caller measurement is recorded first.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated request → adapter | A server load or action must run its adapter on the client whose session it just verified |
| unauthenticated visitor → anonymous read | The preregister flow reads a table under the anonymous role before any Supabase session exists |
| public HTTP surface → credential check | An endpoint whose response differs between "wrong password" and "wrong role" tells an attacker when a password is right |
