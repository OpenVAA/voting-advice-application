<objective>
Take away the shared object, everywhere, so that nothing can reach for one.

**Purpose.** Decision **A1(a)** is that this phase retires the class rather than its instances, and ruling D11
names the mistake to avoid in its own words: two inline patches would close the instances and leave the class
open. Plans 02 through 06 gave every call site a factory. This plan removes what they were calling before, so
that the old way is not merely unused but absent.

**Research finding D-1 changed the size of this task after the decisions were made.** The phase's inputs
counted four module-scope adapter singletons; the tree has **eight**. The four extra are
`adapters/apiRoute/{dataProvider,feedbackWriter}/index.ts`, which have no importer outside their own
directory, and `lib/server/api/adapters/local/{dataProvider,feedbackWriter}/index.ts`, which are live but
whose base class is stateless. None of the four appears in the ruling, the review or the discussion, and each
is a target of the guard plan 09 installs — so each needs a disposition here or the lint gate fails on files
this phase never intended to touch.

**Their dispositions differ and the difference is the point.** The two dead ones are deleted, because they are
unreferenced instances of exactly the banned shape. The two live ones are kept, because their base class holds
no fields, performs no configuration step, and reads constant paths from disk — there is no per-request state
to contaminate. Keeping them is the honest answer, but only if the statelessness is *verified against the base
class* rather than asserted, and only if the exemption is annotated where a reader will find it. An exemption
nobody can audit is indistinguishable from an oversight.

**The directive that tells the rule about them lands with the rule, not here.** Plan 09 installs the guard; a
disable directive written before its rule exists is itself reported by the lint gate, which would make this
plan fail for a reason that has nothing to do with its work.
</objective>
