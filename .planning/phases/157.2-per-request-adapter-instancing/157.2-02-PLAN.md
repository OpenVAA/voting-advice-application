<objective>
Record the contamination, then make it impossible to express.

**Purpose.** This is the plan ruling D11 is about. Its first task runs the proof against the module singleton
and captures the failure verbatim, and only then does the mechanism land. Decision **C3(a)** is explicit that
the recorded failure is what makes the GREEN meaningful, and criterion D11-2 says that without the failing run
recorded the criterion is not met at all.

**Decision B1(a)** picks the mechanism: a per-call factory returning a fresh instance, not `AsyncLocalStorage`
and not a per-method client parameter. Fact 13 is why it is sufficient — every one of the eighteen sites
already has a request-scoped `fetch` in hand, and the server sites additionally have `locals.supabase`.

**The client source is where this phase meets ruling D10.** Research settled research question 2 against the
tree's own comment: SvelteKit's load `fetch` forwards cookies **same-domain only**, Supabase is cross-origin,
and PostgREST authenticates on `Authorization` rather than on cookies — so the sentence at
`supabaseAdapter.ts:40` is false on both clauses and is D10's root cause written down in prose. The factory
therefore takes its client as a **required, explicitly named input** with three arms and no fallback, which is
how decision **A2's NOTE** is discharged by construction rather than by documentation.

**Decision B2(a) is already half-built.** `src/lib/supabase/browser.ts:11-15` is a module-scope memoized
`createBrowserClient` with a "safe to call multiple times" docstring, and nothing in the tree imports it. Wire
it; do not write a second one.

**Research question 4's answer keeps the factories in the four `$lib/api/*.ts` selector modules.** They are the
ESLint-enforced import seam, named verbatim in two guard messages; the replacement import path is banned by
`no-restricted-imports`; and three of the four are already allowlisted for `.supabase`. The fourth,
`adminWriter.ts`, is measured firing today and its allowlist comment miscounts the group as three, so both are
fixed here, in the same commit that makes the file read a client.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP request → adapter instance | Each request's credentials must reach only its own adapter; a shared instance crosses this boundary in-process |
| route file → Supabase client | The `.supabase` read is confined to the four allowlisted selector modules; a read anywhere else is a boundary breach the guard reports |
| universal-load SSR pass → session | On the server pass, a universal load has no `event`; whatever client it is handed determines whose data it reads |
