<objective>
Delete the protocol, not just its uses.

**Purpose.** An object that cannot be re-configured after construction cannot be re-configured **mid-use**,
which is the defect. Decision **B3(a)** removes the configuration method and moves its work into construction,
which also deletes the "client not configured" error as unreachable by construction. Plans 02 through 07 made
every caller stop using the old protocol; this plan makes the old protocol stop existing.

**Decision B3's binding NOTE widens this beyond the four concrete classes.** The removal must also reach the
abstract base and the configuration types, **and it must leave no historical trace** — no deprecation note, no
"formerly" aside, nothing that tells a future reader there used to be a second step. Research enumerated
sixteen loci where the vocabulary of two-step configuration survives in prose or in an error string. Most were
rewritten by the plans that owned their files; this plan owns the adapter core's share and verifies all sixteen.

**Decision A2's NOTE has its hard exit condition here.** The plain client-construction branch on the server
path must end this phase either removed or documented as unreachable from a server request, and "we stopped
calling it" is explicitly insufficient. This plan removes it — together with the environment check around it
and the comment above it, which claims that the framework's request-scoped fetch carries the session cookies.
That sentence is false twice over: cookies do not cross to a different origin, and the service authenticates on
a header the fetch override never touches. It is ruling D10's root cause in prose and it must not survive.

**One measured trap decides how the types are written.** The mixin's constructor annotation erases every
parameter type, and none of the four concrete classes declares a constructor of its own — so today an adapter
constructed from arbitrary nonsense typechecks. Both fixes are cheap and both are taken: an explicit
constructor on each concrete class, whose own signature wins over the mixin's, and the authoritative typed
signature on the factory.
</objective>
