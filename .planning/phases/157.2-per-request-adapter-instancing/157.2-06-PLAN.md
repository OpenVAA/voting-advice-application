<objective>
Make the worst-consequence instance in the ruling impossible rather than unlikely.

**Purpose.** Ruling D11 names this instance directly: the long-running argument-condensation job configures the
shared admin writer once at job start and then runs **for minutes**, across many questions, so a concurrent
admin request can make the first job's writes execute under the second admin's credentials. Facts 11 and 12
measured that both long-running admin features have this identical shape. The rebind window here is not
microseconds; it is the whole job.

**Decision B4(a)** gives each job its own writer for the job's lifetime. It falls out of the factory for free,
and it is the only option under which the cross-admin write becomes *impossible* rather than unlikely. Its
rejected alternatives are instructive and both are prohibited here: re-deriving a writer per write raises what
a job should do when the initiating admin's session expires mid-run, which this phase deliberately does not
open; and leaving the jobs out of scope would leave the worst-consequence instance in the ruling untouched.

**The shape to copy is already sitting one line above the defect.** Both jobs construct a controller at job
start and hold it in the function's closure for the whole loop. The writer becomes its neighbour. Research
found that the caller awaits the job inline inside a form action, so the request *is* the job's lifetime,
which is what makes a job-owned instance sufficient and an ambient request context unnecessary.

**Decision E1(a) applies here as much as to the concurrency test.** This behaviour gets its own recorded RED,
which is why this plan measures before it fixes and why row 3 exists separately from rows 1 and 2.

**One thing is logged and not solved.** A minutes-long job whose initiating admin's token expires partway
through is a real question — the client would attempt a refresh and write cookies onto a response that may
already be committed — and decision B4 declined to open it. It goes to deferred items so that Phase 158, which
inherits this area, meets it as a known deferral.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin form action → long-running job | The action verifies the session and then awaits a job that runs for minutes; whatever writer the job holds carries that admin's authority for the whole run |
| job A's run → job B's start | Two admins can start jobs that overlap in time; a shared writer lets the second one's credentials reach the first one's writes |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-157.2-18 | Elevation | the shared admin writer across two overlapping jobs | critical | mitigate | One job-owned instance per job, constructed at job start and held for the whole run; proved by row 3's before and after |
| T-157.2-19 | Spoofing | a job reading under one identity and writing under another | high | mitigate | `loadElectionData` takes the same client the job writes with |

| T-157.2-SC | Tampering | package installs | low | accept | No packages installed in this plan |
