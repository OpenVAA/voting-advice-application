## Deviations from CONTEXT.md for operator review

1. **D-15's census pattern, `terms_of_use`, also matches the new table's own name.** It is kept as D-15
   states it, which is true today because no function or policy reads the table. The day the Admin rule
   (TOU-F01) joins the table from a function the census turns red; its description says what that change
   must do (narrow the pattern to the retired column name, or exempt the function by name with a reason).
2. **The census reads policies in `storage` as well as in `public`.** D-15 names `public` and `private` for
   function bodies and does not name a schema for policies; storage policies are where file visibility is
   decided.
3. **Two count-based pgTAP assertions change with the column although they hold no terms-of-use string**
   (`09`: the number of columns in the candidates self-edit grant; `21`: the number of output columns of the
   user-data RPC), and the three type satellites change with the RPC column. None is named in CONTEXT.md.
4. **The helper `candidateIdsForUser` is deleted if this plan leaves it without a caller**; it existed to find
   the rows whose column was reset.
5. **The comments under `tests/` that still describe acceptance as a property of the candidate are corrected
   in 172-08, not here.** They are comment text only, so nothing forces them into the column-drop commit;
   they stay inaccurate across one plan boundary.

## File count: why these twenty-one files stay in this plan

This plan lists twenty-one files, above the per-plan file threshold. Everything an ordering constraint does
not force into the column-drop commit has been moved out (the comment sweep over the E2E tree, to 172-08; the
remaining wording in `20-storage-authority.test.sql`, to 172-06). What is left is one atomic commit, and each
file is in it because a gate fails the moment the column is gone:

- the three schema files, the regenerated migration and the regenerated types: the change itself;
- the three type satellites: `yarn assert:rpc-nullability` fails on an override or a disposition row naming a
  column the RPC no longer returns, and the column map would name a column that does not exist;
- `permittedKeys.ts`: its type-level check ties every permitted key to a column of the generated Insert type;
- the two harness files: a helper that still issues an update naming the column throws in every E2E setup
  that unregisters a user first, and the operator ruled that they change in the same commit as the column;
  the teardown comment describes that helper's behaviour and changes with it;
- seven of the eight edited pgTAP files fail on the new schema: fixtures that insert or assign the column,
  the block that asserts the column exists, and two counts that include it. The eighth
  (`05-organization-admin.test.sql`) keeps passing, but two of its checks would name a column that no longer
  exists; it is a two-description edit in a file family this commit already touches. The phase's own pgTAP
  file gains the census, which can pass only once the RPC no longer names the column.

Splitting the commit across two plans would leave a plan boundary with a red pgTAP estate or a harness that
cannot run.
