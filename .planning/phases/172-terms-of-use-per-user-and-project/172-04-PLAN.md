## Deviations from CONTEXT.md for operator review

1. **D-09 says the two named sign-outs move below the gate; the whole entity read moves.** As wired today a
   user with no entity never reaches `userNoCandidate` or `userNotAuthorized`: the entity read throws on zero
   rows and the user leaves as `loginFailed`. So the entire `getContestantUserData` call, with all four of its
   outcomes, becomes the entity step below the gate. The only sign-out left above the gate is a failed
   `getBasicUserData()`, which is a user-level failure.
2. **The load returns one of two shapes** (`{ gate, user }` or `{ gate: null, user, questionData, … }`). The
   layout narrows on `data.gate`. CONTEXT.md did not say the return type changes.
3. **The gate renders with no entity data loaded.** One visible consequence on the gate itself: the header's
   logout signs out directly, where today it opens the unanswered-questions dialog for a user with no answers.
   No spec exercises it. It is the more accurate behaviour and is stated here so it is not a surprise.
4. **A user who holds no contestant entity (an Admin-only user, for example) is shown the gate first**, then
   meets the entity step's outcome. This is D-09's judgement call, restated because it is observable.
5. **The gate view lives in `lib/contestant/gates/` beside the list, not in the component library**
   (`lib/contestant/components/termsOfUse/`, where the pattern map put it), and has no props and so no
   `.type.ts`. It composes a page-level layout piece (`MainContent`), which no component in that library does.
   `TermsOfUseForm` stays where it is, unchanged (D-11).
6. **The gate reruns the load with `invalidateAll()`**, the tree's first bare call of it (the tree uses
   `goto(…, { invalidateAll: true })` elsewhere). A narrower `depends` / `invalidate` pair was not introduced
   for an action that happens once per user per project.
7. **The store members are no longer called after this plan but still exist**; 172-05 deletes them. D-07 does
   not say when; D-20 puts the frontend removal in the contract stage.
