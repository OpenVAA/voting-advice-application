## Sampling Rate

- **After every helper extraction task commit (Plan 86.2-01):** Run a per-spec smoke against the anchor site driving the extracted API.
- **After every propagation task commit (Plan 86.2-02):** Run a per-spec smoke for each touched spec.
- **After all of Plan 86.2-02 lands:** Run the full suite once to verify no cascade-victims emerged from propagation churn.
- **Before `/gsd:verify-work`:** Plan 86.2-03 runs the 3-run cold-start SHA-identity gate (D-06).
- **Max feedback latency:** per-spec smoke < 120s; cumulative gate ~216 min unattended (or ~432 min if Option B pre-refactor anchor capture is chosen — see RESEARCH.md Q1).

## SHA-Identity Gate Spec (D-06)

**Mechanism:** `.planning/phases/86.1-…/post-fix/sha-identity.mjs` (forked from Phase 86 / 85-03; verbatim reuse).

**Invocation pattern** (Plan 86.2-03):

```bash
yarn db:reset
for i in 1 2 3; do
  yarn test:e2e --reporter=json --output=run-${i}.json 2>&1 | tee run-${i}-stderr.log
  sha256sum run-${i}.json >> sha256.txt
done
node .planning/phases/86.1-…/post-fix/sha-identity.mjs run-{1,2,3}.json
```

**Acceptance (D-06):**
1. SHA-identical across all 3 runs (true reliability).
2. Identical to the chosen anchor (Phase 86.1 anchor `8850ee9a…` OR a fresh post-87-post-fix anchor captured by Plan 86.2-03 per RESEARCH Q1 Option B).
3. CASCADE count and "did not run" count count as failures (D-10 + memory `feedback_e2e_did_not_run.md`).

**Failure handling (D-09 spirit):** If SHA-identity fails, the refactor introduced timing changes that must be diagnosed before Phase 86.3 starts. The failure surfaces in Plan 86.2-03's smoke; remediation is a follow-up task within Plan 86.2-03 OR a roll-back of the offending propagation site.
