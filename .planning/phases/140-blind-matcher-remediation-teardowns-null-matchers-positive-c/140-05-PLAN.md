<objective>
Build the shared teardown assertion helper and its row-count probe, route all 27 assertion sites through
it without changing behaviour, and take the instrumented measurement that plan 06's matcher choice
consumes (ASSERT-02 / finding F3, first half).

Binding decisions in force: **D-01** (the F10 count is 136, derived from a measurement — owned by plan
02), **D-02** (F3 MUST measure before it chooses a matcher; this plan is the measurement half and
deliberately ships the pre-change matcher untouched), **D-03** (no UI-SPEC; this phase ships no visual
change). All three are reproduced verbatim in `<decisions>` below because no CONTEXT.md exists to hold
them.

Purpose: the 27 assertions cannot fail — `countDeletedRows` initialises to 0 and only accumulates finite
numbers, so the value asserted is always a non-negative number and the assertion's own failure message
names a state the function provably cannot produce. But the obvious repair is unsafe: two independent
mechanisms make `rowsDeleted === 0` a LEGITIMATE outcome at most sites, and committing a positivity floor
without measuring would redden ~26 teardown projects in one commit — a direct cardinal-rule violation.
So this plan builds the machinery and measures; plan 06 decides.

Output: `tests/tests/setup/shared/assertTeardown.ts`; a `countRowsByPrefix` probe on the tests' admin
client; `ALLOWED_TEARDOWN_TABLES` exported from `@openvaa/dev-seed`; 27 call sites collapsed to one line
each; `140-MEASUREMENT.md` carrying the 27-row table.
</objective>
