<objective>
Close the record: make the summary table complete, ordered and self-describing; state what the pass
does and does not prove; and collect the discarded material in one place rather than leaving it
scattered across fifteen records.

Two things in this plan are load-bearing rather than cosmetic.

First, **ordering**. Phase 142 reads this document to decide what it must remediate. If a row is
merged, reordered or dropped, Phase 142 will read the absence as a withdrawal — which is exactly the
silent scope shrink criterion 4 exists to prevent. § 4's table was created with all fifteen rows
present precisely so that could not happen; this plan verifies the invariant held and states it in
the document, so the guarantee is legible rather than merely true.

Second, **the discarded material**. A pass that records only its successes is a pass whose predictions
cannot be audited. Research predicted PASS for every correctly-designed injection and tagged every
prediction `[ASSUMED]`; a prediction the run overturned is data, and it goes on the record beside the
original prediction rather than replacing it. The same applies to collateral reds: each one is a test
that went red for a reason unrelated to its verdict, and each is the exact material that, left
unlabelled, gets misread as "the assertion caught it".

**This plan ships zero product code and performs no injection.** It touches one planning file. The
source tree is not modified at all.

Purpose: ASSERT-01 requires each finding to be independently confirmed or withdrawn; this plan makes
the resulting set readable as a set, and bounds what it can be used to claim.

Output: `139-VERDICTS.md` §§ 4, 7 and 8 complete.
</objective>

     this document was produced by deliberately breaking working code and watching a test not notice.

     restored after every run, and § 2's environment stamp plus each record's post-gate is the evidence.

  2. **F15-A's regression is a substitute.** The audit's named regression — an implementation that
     ignores question type — is un-injectable, because `packages/question-info/src/` contains no

     (the prompt's question text emptied) is recorded verbatim in § 5.1.2 with its reasoning. Phase 142
     inherits the substitute, not the audit's wording. State this at pass level because a reader of the
     summary alone would otherwise expect to find the audit's regression re-applied.

  3. **F17's green run is degenerate.** `EntityListWithControls.svelte` is not in its test's module
     graph, so the injected effect loop never loaded. The import-graph fact is the evidence; the run
     corroborates it. This pass did not exercise the component's reactivity and does not claim to.

  4. **F17 is out of criterion 1's scope.** It is named in ASSERT-07 but absent from Phase 139's
     criterion 1, because the auditor read it directly and it is therefore not single-source. It carries
     a verdict here under D-06 so Phase 142 does not read its omission as a withdrawal — not because
     criterion 1 required one.

  5. **The vacuous-but-red class is confirmed, not withdrawn.** The three F19 sites pass their own
     assertion inside a file that fails for an unrelated reason. Under D-02 that is `confirmed` with the
