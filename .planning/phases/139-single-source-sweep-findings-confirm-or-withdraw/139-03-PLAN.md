<objective>
Two vehicles, two findings, and the phase's first trap.

F15-A is the trap. The audit's named regression is *"a `generateQuestionInfo` that ignored question
type entirely … keeps all 540 lines green"*. But `packages/question-info/src/` contains zero
references to question type, `QUESTION_TYPE` or `choices` — the prompt variables are built from
`question.name` and a fixed set of instruction constants. **Question type is already ignored by the
shipped code.** There is nothing to delete, so an injection that produces green would prove nothing
new. That absence is *stronger* evidence for the finding than any injection could be — the file's
"Configuration 1 / 2 / 3" organisation is pure theatre — and it means the run half of D-01 must use
a substituted regression. The substitution and its reason are recorded, prominently, in the verdict
and again in § 7; they are not grounds for withdrawal and not grounds for blocking.

F20-5 is the opposite shape: a twelve-line test file against which the audit names two distinct blind
spots, both one-line injections. Both are run and both are recorded, so Phase 142 gets two
pre-specified regressions for the price of one file.

**This plan ships zero product code.** The two source files named in `transient_files_reverted` are
injected and reverted inside the task that injects them.

Purpose: ASSERT-01 — confirm or withdraw each single-source finding against the live code (D-01).

Output: `139-VERDICTS.md` §§ 5.1 and 5.14 filled, § 4 rows 1 and 14 updated, seven placeholders left.
