<behaviour_preservation>
## The six measured behaviours a naive rewrite silently changes

Each is a property of the current code. A rewrite that gets any one wrong changes **seeded data shape**
in a way `yarn test:unit` will not see and only the E2E suite will — loudly and late.

1. **First-non-nullish key precedence.** The `??` chain at site 1 checks `_constituencyGroups`, then
   `_constituency_groups`, then the bare `constituencyGroups`, then the bare `constituency_groups`.
   The sentinel forms win over the bare forms. `firstDeclaredKey` must walk `rule.keys` in array order
   and stop at the first non-nullish value, which is why key order inside a rule is not cosmetic.
2. **Two payload normalisers, one output.** The `_`-prefixed payload is an object carrying an
   `externalId` or `external_id` string array; the bare payload is an array of reference objects each
   carrying `external_id` or `externalId`. Both normalise to a flat list of external-id strings.
3. **Skip on malformed, do not throw.** A payload that is not an array after normalisation is skipped
   (`:399`, `:452`). Preserve that, including for the jsonb sites.
4. **Skip on missing parent external id.** A row with neither `externalId` nor `external_id` is skipped
   (`:401-402`, `:456-457`, `:515-516`, `:559-560`), not defaulted and not thrown on.
5. **An empty array is a no-op, not a column clear.** `electionResolve` and `constResolve` both skip on
   a zero-length id list (`:514`, `:558`). A rewrite that writes an empty jsonb array instead would
   change every affected row's scoping from "all" to "none".
6. **Rule dispatch order.** Today: elections → constituency groups → `electionResolve(categories)` →
   `electionResolve(questions)` → `constResolve(categories)` → `constResolve(questions)`.
   `LINK_SENTINELS`' array order as landed by `144-02` reproduces it exactly. Keep it.

**Also preserve the collection-key aliasing.** Sites 2 and 3 accept camelCase collection keys
(`data.constituencyGroups` and `data.questionCategories`). `pickCollection` must keep accepting them —
a guard or resolver that rejected them would break a supported public shape — while resolving to the
canonical snake_case entry per D-03a.
</behaviour_preservation>
