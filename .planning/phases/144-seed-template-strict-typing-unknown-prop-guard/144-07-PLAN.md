## The seven gates, in order, at ONE HEAD

**Prerequisites, both non-negotiable:**
- **`yarn db:reset`** for a clean database before the E2E gate. The seed-CLI rows from `144-01` and
  `144-04` used the `negctl144-` prefix and were torn down, but a reset is the only way to state the
  E2E run started from a known dataset.
- **Exactly one fresh dev server on the frontend port**, started by this plan and stopped by it. There
  is no Playwright `webServer`; a stale server steals the port, and the E2E preflight aborts the run
  unless the served application proves it came from this checkout. Confirm no server is already
  listening before starting one.

**The gates, each with its log:**

| # | Gate | Command | Log |
|---|---|---|---|
| 1 | unit | `yarn test:unit` | `gate-unit-1.log` |
| 2 | lint | `TURBO_FORCE=true yarn lint:check` | `gate-lint-1.log` |
| 3 | format | `yarn format:check` | `gate-format-1.log` |
| 4 | build | `yarn build` | `gate-build-1.log` |
| 5 | frontend typecheck | `yarn workspace @openvaa/frontend check` | `gate-svelte-check-1.log` |
| 6 | repo typecheck | `TURBO_FORCE=true npx turbo run typecheck` | `gate-typecheck-1.log` |
| 7 | **E2E, last** | `yarn test:e2e` | `gate-e2e-1.log` |

**Rules:**
- **One HEAD.** Record `git rev-parse --short HEAD` once and assert it is unchanged after gate 7. If
  any gate requires a fix, commit the fix and **re-run every gate from 1** — a gate set taken across
  two HEADs is not a gate set.
- **Gate 2 and gate 6 force the turbo cache** because `lint` and `typecheck` both lack a cache disable
  and a replayed green is a claim about a **previous** tree. **`yarn lint:check --force` is
  forbidden** — yarn appends the argument past the `&&` chain and it silently does nothing.
- **Gate 2 short-circuits on `&&`.** A red means the **first** failing step failed and the later steps
  never ran. Say so explicitly if it happens; never imply a full-gate result.
- **Gate 7 is a cardinal failure condition.** CLAUDE.md admits **no** known-flaky exemption and **no**
  "cannot plausibly affect it" waiver, and a `did not run` counts as a failure, not as a skip. Record
  passed / failed / flaky / skipped / did-not-run as four separate numbers. Pass 0 executes inside every
  E2E setup project, so this phase's reach into the suite is real, not theoretical.
- **Every gate records:** the command verbatim, the exit code, the counts the tool printed, the cache
  verdict where turbo mediates, and a resolvable log path.
- **Gate 5 is not optional.** Neither lint nor build type-checks the frontend source tree, and CI runs
  that type-check as its own step — the Phase-142.1 and Phase-143 precedent.
</gate_protocol>
