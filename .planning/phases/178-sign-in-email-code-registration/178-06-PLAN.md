## Rulings and deviations carried by this plan

1. **The names are the planner's** (item PL-13): `public.recovery_link_request (p_project_id uuid, p_email text) RETURNS jsonb`, answering an object with the members `email` and `mail`, the second `'recovery'` or `'sign-in'`, or SQL null.
2. **Probe row P1 decides one conjunct.** With `P1: held` in the findings, a grant-holder gets the recovery mail whether or not the account has a password: verifying a recovery link stores none, and the reset page sets one. With `P1: not held`, the answer is `recovery` only for an account whose password is set (`private.user_password_set`), and a grant-holder without one gets `sign-in`. The executor reads the line and builds that branch; Task 1's assertions state it either way.
3. **D-05 is honoured here too**: the open invitation that earns the sign-in mail must be one the matrix allows, asked through `private.invitation_mode_allowed`.
4. **The census grows by one public function.** The context's "the 07 census does not grow" is true for the password fact (plan 178-04) and is not a phase-wide statement (item PL-08).
5. **This plan closes on the database rows and the unit rows, not on a full E2E run** (execution rules, "the schema block"): the function has no caller until plan 178-07, whose close is the first full run over it.
