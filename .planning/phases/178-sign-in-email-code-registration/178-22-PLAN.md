## Rulings and deviations carried by this plan

1. **The session is written once by a setup, through a real mailed link, and is read-only** (item PL-11). The account is made by the Edge Function's own pipeline — an invitation seeded for the address, a link asked for, the link opened as received — which probe row P3 showed leaves an empty password. Whether a stored link session lasts a whole run was not measured; it is a session like any other the suite stores, and when the scan project finds it expired the fallback is located: each reading `describe` makes its own in a `beforeAll`.
2. **The promise the setup seeds is a project-scope one**, so no entity row is written on: after the gate such a user would see "nothing to edit", which no test of this plan reaches. A project grant with no password is exactly the session item PL-29 is about: the set-password gate is the Contestant App's, and where the grant gives the admin role the Admin App admits such a session without asking for a password (plan 178-14, ruling 9 and T-178-153). Nothing of that is tested or changed here; this plan's summary records which project role the seeded promise carries and whether the Admin App's role set admits it, so that the stored session's reach is known and not assumed.
3. **The phone-width checks are a spec of their own** (items U-27 ★ and PL-22), in `en`; the six other locales are a person's read, filed by plan 178-23. Its project runs after the signed-out scan project and uses that spec's two reserved candidates and address prefix, one after the other, so the base dataset needs no further rows.
4. **The selector's provider panel is not measured at phone width here**: the base dataset does not allow that mode, and a project that writes the matrix belongs to the permutation chain. Its markup is the paragraph the legacy start page shows.
