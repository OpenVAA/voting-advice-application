## Rulings and deviations carried by this plan

1. **The operation's name is the planner's** (item PL-13): `request-recovery`. Its answer is the existing accepted body; no new answer is added to the closed set.
2. **Probe row P1 decides the token's type.** With `P1: held`, the recovery arm mints with the type `recovery` — the documented one, which also answers 404 for an address with no account, a free second check of the eligibility rule. With `P1: not held`, it mints with the type `magiclink` as the sign-in arm does, and only the link's `type` parameter says `recovery`; the dependency `mintRecoveryToken` is then not added. Either way the link's `type` is a landing hint and decides nothing.
3. **The conformance test is rewritten where the second operation makes its sentences false** (pattern item 13), not worked around: "the one background function, which is the only caller of the link issue" becomes a statement about each of two.
4. **The stack is restarted once, in Task 2**, by `yarn db:stop` and `yarn db:start`, with no E2E run in flight. Docker is not restarted.
5. **The pre-commit control is the invitation contract spec**: it is the suite's own statement of the link-request pipeline, which this plan re-shapes to take a second caller. The first full run over the change is Task 3's.
