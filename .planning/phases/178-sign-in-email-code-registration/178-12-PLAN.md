## Rulings and deviations carried by this plan

1. **Fixtures before screens** (execution rules, order 2): what D-23 puts in its fifth stage. Each screen's own plan then writes its spec first, in these steps, and sees it red.
2. **A page's request gets a witness by interception** (item PL-10). The context says the completion witness is "a service-role field no screen sends", and the pattern map leaves the mechanism open. The step opens a witness with the service role, lets the page's request through with that one member added to its body, and reads the witness. It changes no answer — "the witness changes no answer" is a `describe` of the function's contract test. Its first real use is the tracer's test (plan 178-14); when interception proves unable to carry the member there, the fallback is the contract spec's own method — a further witnessed request for the same address made after the page's — and it is one step of this fixture.
3. **The steps that open a screen by a NEW route key are added with the key** (the last truth). Everything else of each page object is here.
4. **The signed-out scan declarer is not here.** It is written with the spec that uses it and the wiring gate's entry for it (plan 178-21), so that the gate that lists the files allowed to scan is edited once.
5. **The invitation fixture is edited before Phase 177.1 or after it, whichever the tree holds.** Its seeding steps keep the signature the tree has; this plan adds an option to the fixture's constructor and new steps, and changes no existing step's arguments.
