### Sampling rate

- **Per task commit:** the workspace's own unit run for the files touched, plus `yarn workspace @openvaa/frontend check` when a route or a type moved.
- **Per plan close:** the gate driver's rows for what the plan touched; a full wrapper-driven E2E run for every plan that changes a screen, a helper, the callback, the schema or the function.
- **Phase gate:** the full row set on one tree (reset, types with no diff, pgTAP, SQL lint, parity, unit, lint, format, type check, build), one full E2E run on a freshly started server, the two opt-in bank-auth projects each alone (the entry to their flow, the gate table and `[auth]` all change), and the zero-hit searches.

## Per-Task Verification Map

Filled by the planner from the 24 plans' 67 tasks. A task id is `178-<plan>-<task>`. Each row's command is
the task's own `<automated>` block — too long to repeat here, so the row names the plan and the task and
lists the verdict and `yarn` calls the block makes; the block also states its failing direction in
`<fails_when>`. *Requirement* is the plan's; *Threat Ref* lists the threats whose mitigation names the
task, or the plan's range. *Secure Behavior* is the task's `<done>`. *File Exists* says whether the files
the command reads are made by the task itself (a test is committed red and alone first, see the execution
rules) or by an earlier one. Every count in a row is of tests this phase adds, never of today's tree.

How the map reads against the research's Wave 0, which this phase spreads over its first plans and does not
keep as one wave: the drivers, the baseline and the rulings are plan 178-01; the probe rows P1 to P4 and P7
are plan 178-02 (P5 and P6 with the configuration change, plan 178-20; the function's row with plan 178-07);
the dataset is plan 178-03; the truth table and its parity test are plan 178-05; the fixture steps and page
objects are plan 178-12 — before the screens of plans 178-13 to 178-19 that the specs assert.
