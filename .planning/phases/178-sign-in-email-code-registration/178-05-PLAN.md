## Rulings and deviations carried by this plan

1. **Four rulings inside D-05's settled "yes" are built at the research's recommendation and are the operator's to confirm** (items J3a to J3d): open rows only; faction and alliance targets not judged; a disallowed row absent from the claim's answer; the base dataset widened (done in plan 178-03).
2. **The claim is the third place.** D-05 itself says it is beyond the letter of the discussion's ★ ("the code check and the link request") and why: a returning user, who may always ask for a link, would otherwise claim a second, disallowed invitation through it.
3. **The condition is stated once**, in `private.invitation_mode_allowed`, which takes an invitation row; it lives in `506` because the row type does not exist before `305`. The two readers of the matrix live in `301`.
4. **The number of the new pgTAP file is the next free one when this plan runs.** `45` in the frontmatter assumes Phase 177's two files are on the tree; the executor reads the directory, and the unit test finds the file by the tail of its name.
5. **The unit test's TypeScript half is green the moment it is written**: the accessor exists. It is the oracle for the table — a row whose stated answer the accessor contradicts is a wrong row, corrected before anything is committed.
6. **`00-helpers.test.sql` is not edited.** File 39 writes a matrix that allows every mode for both types into its own projects, in its own setup.
7. **D-05's 'timing' is not built for the code check** (item PL-28, added by the revision and put to the operator). D-05 asks that a switched-off mode be indistinguishable from an unknown code 'in status, body and timing'. Status, body and side effects are built and asserted. Timing holds for the link request by construction — its answer leaves before the work. For the code check it does not hold exactly: the condition is asked only for a row that is open and unexpired, so such a row costs one more read — the settings row of its project, by primary key — than a code that names nothing. What that read can tell is narrow: to someone who already holds a real code, and who samples it many times against a code they made up, that the code names an open invitation whose mode is off. Nothing limits that sampling — the per-caller limit on the anonymous operations is Phase 174's filed residual — so the difference is small but not nothing, and it is recorded as accepted (T-178-156), not claimed absent. The option that narrows it reads the settings row on every call of the code check, whatever the code, so that both paths make the same reads; no deterministic test can assert either form.
