## Rulings and deviations carried by this plan

1. **The organization's spec ends on the organization's home** (item PL-21): Phases 175 and 176 built it. It asserts the home's own frame and never where its first task leads, which Phase 177 changes.
2. **The specs run on the base dataset as leaves**, each on rows of its own (items PL-14 and J3d). They depend on the base dataset's setup alone, which places them in the scheduling phase of the other base leaves, before the first setup that clears the base dataset — and they consume none of the stored sessions.
3. **The seeding steps are called in the form the tree holds** (execution rules, Phase 177.1): with the two-argument seeding function, as written here; with 177.1 on the tree, each call passes the confirmation the fixture's signature then takes — true, because each reserved row has no nomination.
4. **A switched-off mode is not walked in a browser here.** The base dataset's settings are shared by every leaf that runs beside these specs, so a spec that switched a mode off would race them; the server's half is the pgTAP section of plan 178-05 and the browser's half — what the screens offer under each matrix — is the closed-project spec's, which owns its settings.
5. **Assumption carried, still unresolved** (UI contract, *research · The count against the server's minute*): a test gives the server's slot back before a press that must send, so no test here shows that 65 seconds of wall clock outlast the server's 60. What is shown is that the page's clock drives the count (the research's A7). The margin stays reasoned from the function's source; it is harmless if it is not needed, and plan 178-23 files the check a person can make.
6. **These tests are written against screens that exist**, so they cannot be seen red for the absence of a feature. Each task's control is a green one of the uncommitted spec; a test that is red there has found a defect, which ruling PROH-178-51 governs.
