## Rulings and deviations carried by this plan

1. **Labels are visible and placeholders go** (item U-02 ★). It changes how the sign-in and reset forms look once their screens are rebuilt; nothing changes yet, because nothing renders these components.
2. **The address rule is the control's own** (item U-16 ★ and the research's § *Don't Hand-Roll*, which the revised UI contract now agrees with): `novalidate` on a form stops the browser's bubble, not the control's verdict. The pattern map's "shared email-syntax rule" is therefore not built.
3. **A test id lands on the control, not on the component's root.** The fixtures fill `login-email` and `register-code`; each field forwards its `data-testid` to its `<input>` and takes a second id for its error.
4. **`PasswordSignIn` reads the contestant context** for the route to forgot-password and for `t` — both stable references. `EmailField`, `RegistrationCodeField` and `EmailEntry` read the component context alone and know nothing of what they are used for.
5. **`autocorrect` and other attributes the typed element may not admit** are set through a spread object when the type check refuses them as literals; the attribute still reaches the DOM, which the unit case asserts.
