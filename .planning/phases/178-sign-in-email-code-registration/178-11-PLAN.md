## Rulings and deviations carried by this plan

1. **The address field is in the markup and not rendered** (item U-07 ★): `display: none`, read-only, no tab stop. It is the form the Chromium guidance gives a change-password form; which managers honour it is a person's check, filed by plan 178-23. Option (b), a visible read-only field, is the fallback and is located in this component alone.
2. **The settings page changes its look** — visible labels where there were placeholders. The UI contract lists it under what no requirement asks for, so that it is not accepted unseen; it is item U-02.
3. **The reset page and the legacy set-password page are not rebuilt here.** Each keeps its button outside the form with its own handler, as today; `onValidityChange` stays for them and for the settings page. Plan 178-19 rebuilds the first and plan 178-16 deletes the second.
4. **`passwordrules` is not in the HTML standard.** It is spread onto the element from an object so that the type check has nothing to refuse (the UI contract's N-10).
5. **The pre-commit run is a full run** (item PL-20): the component is rendered by three pages that four projects open.
