## ⚠ The number nobody has seen

D-A4's class definition is verbatim: *"a comment line that ends without terminal punctuation **and** whose
next line continues the same comment span at the same indent."* `152-RESEARCH.md` § 1.1 implemented that
definition exactly and ran it over every tracked file in the three trees. Taken literally, it covers:

> **14,094 comment lines, in 5,550 wrapped paragraphs, across 747 files** — about **40%** of the 34,885-line
> non-blank comment corpus, and **17× the planning-reference sweep** this phase was scoped around.

**No planning document for this phase contains that figure.** `152-CONTEXT.md`, `.planning/ROADMAP.md` and
`.planning/REQUIREMENTS.md` all size the *planning-reference* class (817 in CONTEXT.md, measured at 888
citation lines / 946 occurrences / 642 spans) and say nothing at all about the size of the *forced-line-break*
class. ROADMAP criterion 1 simply says the scan "returns **zero**". The operator has never seen 14,094,
because the size was never measured before `152-RESEARCH.md` measured it. That is why this plan opens with a
decision checkpoint rather than an edit.

**It is not a false-positive artefact.** All six sites the PR reviewers cited with "remove line breaks" are
ordinary hand-wrapped prose paragraphs, and the clearest of them — a two-line reason-comment in the API-route
adapter wrapping at about 110 characters — carries the reviewer's own words: *"Remove line breaks from
multiline comments **everywhere**."* There is no narrower rule that catches that site and spares the other
5,549 paragraphs.

**It is a one-way door.** The sweep collides with **59 of the 94 files phases 153-160 cite** — 63% — with
phases 158 and 159 alone rewriting 32 of them. Reverting after those phases land is expensive in a way it is
not today. Hence the checkpoint, placed immediately before the task that spends it.

## What is already known, so the decision is cheap

- Prettier does **not** reflow comments — proven by running the repo's own installed binary against a
  302-character comment, which survived byte-identical. So joined lines stay joined.
- There is **no ESLint max-length rule** anywhere in the shared config, so a very long comment line passes
  both `lint:check` and `format:check` untouched. It does contradict the repo's editor configuration, which
  declares a 120-character maximum.
- Joined-length distribution over the 5,550 paragraphs: median 185, 75th percentile 282, 90th percentile 418,
  99th percentile 717, maximum 1,780. **4,437 paragraphs (79.9%) join to over 120 characters.**
- **1,113 paragraphs (20.1%) join to 120 characters or fewer** — those are the "gratuitous break" subset,
  roughly 2,400 lines.
- The structural exclusion set is required under **every** disposition, and it is already built: banner rules
  (1,418), list items (1,258), JSDoc tags (429), hanging indents (567) and comment tables (34) are excluded as
  codified constants in the instrument plan `152-02` committed. **No work is wasted whichever way the
  operator rules.**

Purpose: close criterion 1 at whatever scale the operator sanctions, having shown them the scale first.
Output: a recorded decision, the sweep that implements it, and a proof it changed only comment bytes.
