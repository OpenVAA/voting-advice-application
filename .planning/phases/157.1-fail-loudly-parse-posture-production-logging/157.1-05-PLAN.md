<objective>
Move the last four parse sites onto the outcome, retire the one-off partial-preserve by making it the
shared one, and invert the test that specifies the defect.

**Purpose.** Decision A1(a) put all **six** sites in scope, against a ruling that enumerated five: the
sixth has the identical shape and ten downstream consumers, and leaving it out would repeat exactly the
mistake of fixing instances without retiring the class. Plan 04 moved sites 1 and 2. This plan moves
sites 3 and 4 (the customization two-pass), site 5 (the settings read) and site 6 (the email send
result).

**Criterion 3 is satisfied here, and NOT by a gate edit.** Research correction C-2 inverted decision
B2's premise: the root layout's validity gate already accepts an empty settings result today, because
it is called with the allow-empty option and the validity helper rejects only nullish, error-typed and
empty-with-allow-empty-false results. The outage shape B2 feared belongs to the design B1 rejected. So
under partial-preserve, a malformed settings column already renders on defaults — and one unrecognised
key stops discarding every dynamic setting because the offending member is dropped and the rest
re-parses. The layout's remaining defect is a different one, and plan 06 owns it.

**Site 6 is a write path claiming a success it did not verify.** Its degrade branch is not an empty
literal — it returns a fully populated object reporting zero sends, zero failures and no results. That
shape is invisible to any ban written in terms of empty literals, which is why decision D2's wording
alone does not cover it and why the guard in plan 07 carries a selector that requires the failure branch
to carry an issues or error identifier. Fix the behaviour here and let plan 07 make the shape
unwritable.

**One discretion call is recorded here. D-DISC-4:** the email path surfaces its malformed result as a
failure-typed action result rather than as a throw. A throw at that site lands in a caller's catch and
is logged as a free-form interpolated string, which decision C4's NOTE part 1 forbids for records this
phase writes or touches; a typed failure keeps the structured record at the adapter where the column,
the row id and the issue paths are in scope.
</objective>
