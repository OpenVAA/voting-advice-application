<objective>
Close the phase: measure the one thing no harness here can measure for us, control the one risk raising
the level creates, and run the gate.

**Criterion 5's production half is the reason this plan has a human checkpoint.** The criterion does not
ask whether the resolver returns `'warn'`; it asks that every "degrades with one warning" comment in the
adapter layer be *observed* TRUE in a production-mode build — "measured, not asserted". Nothing in this
repository builds the application in production mode and reads its stdout. A unit test on the resolver
proves something strictly weaker, and shipping that as criterion 5 would be the exact substitution the
criterion's own wording forbids. Research flagged this as a standing risk and instructed that plans carry
it as an explicit human verification. This plan does, with the three-run procedure taken verbatim from
the validation strategy.

**Raising the level creates exactly one new risk, and it is the phase's highest-value security check.**
Fifty-odd `error`-level sites that were only ever visible to a developer are now collectable from
container stdout. Forty of them interpolate a value into the message. Most are benign; one is not
benign and is directly on the settings path this phase touches — the result-validity helper interpolates
a provider error message, which on this stack can echo query text. Research open question 4 recommended
restructuring it and noted it is two lines and in blast radius. **D-DISC-8: restructure that one, and
record the rest as findings.** The audit reads all of them once, because reading them once is the
mitigation the threat register assigned to this plan; restructuring all of them is a different piece of
work with no decision behind it.

**The register is the phase's evidence.** Decision E1(a) required one round trip per instance across
seven rows and fifteen cells. A cell left unfilled means an instance was fixed without ever being proven
broken, which is the one thing this milestone's standing rule does not permit.
</objective>
