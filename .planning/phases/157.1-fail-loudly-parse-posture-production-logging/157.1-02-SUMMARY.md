### 2. [Rule 1 — Factual error in an acceptance criterion] `grep -c "resolveLogLevel"` returns 2 per entry point, not 1

- **Found during:** Task 2 verification.
- **Issue:** The criterion requires `grep -c "resolveLogLevel"` to return **1** on each entry point. It cannot: the resolver has to be **imported** before it is **called**, so a correct implementation yields 2 (one import, one call). The plan's own `<verify>` command checks only that the two files' counts are **equal**, which is the invariant that actually matters for C2.
- **Fix:** Recorded the discrepancy rather than contorting the code to hit 1 (which would have meant an inline dynamic import or an un-imported global). Counts are 2 and 2 — equal, and the `<verify>` command passes.
- **⚠ Carried forward:** same class as wave 0's deviation 1. A checker reading the criterion literally will mis-flag this.

### 3. [Rule 2 — Missing critical functionality] A ninth case, for the never-throws requirement

- **Found during:** Task 1.
- **Issue:** The plan's behaviour list requires "the resolver never throws, for any input, including a non-string", and threat `T-157.1-04` rests on it — both entry points call the resolver at **module scope**, so a throw takes the SSR process down at server start. The wave-0 scaffold enumerated 8 cases and none covered it, so the requirement would have shipped unasserted.
- **Fix:** Added a case over ten hostile inputs (`null`, `0`, `1`, `true`, `false`, `{}`, `[]`, `Symbol`, a function, `NaN`), asserting both that it does not throw and that the returned level is emittable. The implementation guards with `typeof raw !== 'string'` rather than a nullish check for the same reason.
- **Committed in:** `641a041c0`.

### 4. [Rule 1 — Divergence from the research sketch] Whitespace-only is `missing`, not `invalid`

- **Found during:** Task 1.
- **Issue:** Research's sketch tests `raw === ''` **before** trimming, so `'   '` falls through to the vocabulary check and is reported as `invalid` with `provided: ''` — a report that names nothing and tells a deployer their value is wrong without saying what it was.
- **Fix:** Trim first, then test for empty. `'   '` is `missing`, consistent with the spec's "an empty string is identical to unset" and with what a deployer means by a blank value. The spec's `''` case is unaffected and still passes.
- **Committed in:** `641a041c0`.

## Issues Encountered

**The plan halted mid-flight on task 3's precondition, and that was the right outcome.** `.env.example` was unreadable — a standing user-level permission rule (`Read(.env)` / `Read(.env.*)`) denied it, the same boundary that had denied the pattern mapper and the planner. The precondition exists precisely because the file's anchors were carried, unverified, from the research document, and editing a file blind to place a variable *outside* a contiguity-checked block is the move it was written to prevent. Execution stopped with a `blocking-human` checkpoint rather than guessing or hunting for a command shape that slipped past the deny rule. The operator narrowed the rule to the files that actually hold secrets; the anchors were then re-measured from the file itself and **matched** what research had carried.

**The interim state was noisy, by design and briefly.** Between the task-2 and task-3 commits, no deploy surface set the variable, so every boot emitted one `missing` record — research point 2's predicted, self-limiting behaviour, and the reason the plan grouped all three files into one task. Task 3 did not part-complete: the two readable deploy files were left untouched until the third could be done with them.
