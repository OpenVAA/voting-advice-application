<objective>
Move the two shared parse helpers onto the three-state outcome, and let the compiler find every caller.

**Purpose.** Fact 4 is the D8 class in its purest form: `parseAnswersColumn` returns `undefined` for an
absent column at one line and `undefined` for a malformed column six lines later. The two are
indistinguishable **by construction**, and no amount of logging changes that — only the return type
can. `parseImageColumn` has the identical shape and ten downstream call sites; decision A1 put it in
scope precisely because leaving it out would repeat the mistake of fixing instances without retiring the
class.

**The cost is ten mechanical edits, not thirteen** (research correction C-1). The thirteen in the
discussion document conflated ten calls to the image parse helper with three direct derivations inside
the customization path, which receive an ALREADY-VALIDATED value and perform no parse of their own.
Those three are not touched by this phase.

**The named accessor is not the rejected branded-empty.** Decision B1 rejected option (d) because a
symbol tag is erased silently at every nullish coalesce and every spread — which is exactly where the
bug lives. A named accessor inverts all three of those properties: the erasure is a greppable function
call that enumerates every site which chose to collapse the distinction; the type still carries the
distinction upstream, so a new caller must decide; and the erasure happens AFTER the record is emitted
rather than instead of it. The application data model has no third state for an image, so the honest
posture at those ten sites is the same rendering, reached deliberately.

**One discretion call is recorded here.** Research open question 3 flagged the candidate's own answers
read at `supabaseDataWriter.ts:204` as the same severity class as the write-path read-back, while noting
it is a CALL site rather than one of CONTEXT's six PARSE sites, and instructed the planner to name it
rather than silently widen scope. **D-DISC-3: it stays a collapse in this phase**, via the named
accessor, with an in-code annotation naming the choice and citing this plan. Rationale: the generalised
partial-preserve from plan 03 already turns "one bad answer wipes the blob" into "the bad question ids
are dropped and the rest survive", which is the improvement that mattered at that site; and the record
is now emitted at `error`. Branching it on status is a UI decision with no CONTEXT ruling behind it, and
inventing one here would be exactly the scope widening research warned against.
</objective>
