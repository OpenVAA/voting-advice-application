<objective>
Turn the production logger on, in the one way that is mechanically possible on this stack, and make its
own misconfiguration loud.

**Purpose.** Ruling **D9**: `hooks.server.ts:15` and `hooks.client.ts:7` pin the level to `'silent'`
unless `DEV || PUBLIC_DEBUG`, so every "degrades with one warning" comment in the adapter layer is
false in production — zero signal. That is what turns each silent degradation from untidy into severe,
and D9 places this work first because shipping the D8 posture change on a silent logger would produce a
phase whose central claim is untestable in the field.

**The name is settled, and it is not a planner's choice to reopen.** Decision **C3** was overruled by
the operator to "an env", then amended the same day after research proved that C3(b)'s literal name and
decision **C2** (same level in browser and server) are mechanically exclusive: SvelteKit 2.55.0
partitions environment variables on the `PUBLIC_` prefix, serialises only the public half into the
page, and treats an import of the private env module from `hooks.client.ts` as a build error. The
operator ruled: take the substance of (b), take the name from (c). Every occurrence reads
**`PUBLIC_LOG_LEVEL`**. A regression to a bare `LOG_LEVEL` reintroduces a build error.

**Two Claude's-discretion calls are made here and recorded, because CONTEXT does not settle them.**
**D-DISC-1:** `'silent'` is rejected by the resolver — treated as out-of-vocabulary, producing an
`error` record naming it and falling back to `'warn'`. Accepting it would let one environment variable
reintroduce the production silence this phase exists to close, with no signal, which is the same class
of defect as the one being retired. **D-DISC-2:** the development fallback `DEV || PUBLIC_DEBUG` is
retained as the *fallback* rather than overridden, so an explicit `PUBLIC_LOG_LEVEL` wins and a
developer who never sets it keeps `'debug'`; the only behaviour change for someone who never sets the
variable is that production moves from `'silent'` to `'warn'`, which is the point of the ruling.

Output: the resolver and its spec, both entry points, the three deploy-surface files, the backlog item,
and ledger row 5 measured on both halves.
</objective>
