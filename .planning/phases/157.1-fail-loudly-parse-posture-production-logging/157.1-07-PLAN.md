<objective>
Close the class with a mechanism, and prove the mechanism fires before claiming it guards.

**Purpose.** Criterion 6 is the only one of the six that is about the FUTURE: a test must fail when a
boundary schema is written in the degrade-to-empty shape this phase removes. Ruling D8 is explicit that
what is being retired is the class, not its instances — widening the schemas removed the known triggers
and left the class open, and the next schema drift reopens it. Everything plans 03 through 06 did is
undone by one new helper written in the old shape unless something mechanical says no.

**Decision D1(a) picked the mechanism and the tree already has two precedents of exactly this shape**:
an ESLint syntax ban declared inline in the frontend flat config, locked in by a vitest spec that lints
virtual fixtures through the REAL config. It fires in the editor and in `lint:check`, and the self-test
proves it fires rather than assuming it. There is no custom rule plugin in this repository and none is
added here.

**Decision D2(a) picked what is banned: the defect SHAPE.** Banning a library call would miss a new
schema; banning strictness would miss a permissive schema with the same degrade branch. Research wrote
five selectors, executed them against eighteen fixtures — twelve violation forms including four
deliberate evasions, six compliant forms — and scored 5/5 firing correctly with **zero false positives**
across the compliant set. Transcribe them; do not re-derive them.

**Two traps are named because each produces a guard that looks installed and is not.**

The **flat-config REPLACE trap**: a rule's options array is replaced per file, not merged. Research
measured what the adapter path resolves to today — exactly two `no-restricted-syntax` entries, the enum
ban and the dynamic store-import ban. A new adapter-scoped block that omits them deletes both bans for
every adapter file **while producing zero errors**, because the adapter contains no enums and no dynamic
store imports. No gate in this repository would notice. The only detector is a standing regression per
re-included entry, and ledger row 7 exists to measure that detector working.

The **esquery trap**: matching on an argument's name alone fires whenever that attribute is
JavaScript-undefined — measured firing at an empty-object return in a fixture containing no such
identifier anywhere. Every identifier arm must carry its paired type guard.

**One discretion call is recorded here. D-DISC-7: the fifth selector is included.** Research recommends
it and flags the tension: decision D2 rejected banning a nullish-coalesce on a parse result *as the
whole ban*, not as one entry beside the shape ban. It catches fact 5's exact line, its call-name filter
was measured discriminating against an unrelated coalesce, and it is one entry among five rather than
the ban itself. The tension is surfaced here rather than resolved quietly.
</objective>
