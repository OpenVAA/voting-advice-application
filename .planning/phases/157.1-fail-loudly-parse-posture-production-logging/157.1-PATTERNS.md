**Analog B — the partial-preserve donor:** `apps/frontend/src/lib/api/adapters/supabase/dataProvider/supabaseDataProvider.ts:63-90`.
This is the function A2(a) says to *generalise*, verbatim at HEAD:

```ts
/**
 * Validate the stored `app_settings.customization` value, keeping the members zod accepts when one of the others is malformed.
 *
 * A plain whole-object `safeParse` would discard the publisher name over one bad image path, which is a visible regression for a column that is pure presentation. So the top-level members zod flagged are dropped and the remainder is re-parsed. An unrecognised top-level key is reported at the empty path and therefore names no member to drop, which makes the retry fail too and degrades the whole column — the same posture `_getAppSettings` takes.
 *
 * The failure branch never throws: the last resort is the empty customization the `PGRST116` branch already returns. Only the zod issue PATHS are logged, never the offending value (T-157-17).
 * @param raw - The unvalidated JSONB value read from the column.
 * @returns The stored customization, possibly with the malformed members removed.
 */
function parseStoredCustomization(raw: Json): StoredCustomization {
  const parsed = StoredCustomizationSchema.safeParse(raw);
  if (parsed.success) return parsed.data;

  const issues = parsed.error.issues.map((issue) => issue.path.join('.'));
  const rejected = [...new Set(parsed.error.issues.map((issue) => String(issue.path[0])))];
  log.warn(
    'getAppCustomization: the stored customization did not match its schema; the rejected members were dropped.',
    { column: 'app_settings.customization', issues }
  );

  if (raw == null || typeof raw !== 'object' || Array.isArray(raw)) return {};
  const retained = Object.fromEntries(Object.entries(raw).filter(([key]) => !rejected.includes(key)));
  const retry = StoredCustomizationSchema.safeParse(retained);
  return retry.success ? retry.data : {};
}
```

**Copy — four structural moves, in order:** (1) `if (parsed.success) return …` fast path; (2) reduce issues
to dotted paths for the record; (3) the `typeof raw !== 'object' || Array.isArray(raw)` structural
precondition; (4) `Object.fromEntries(Object.entries(raw).filter(…))` + one retry `safeParse`. The whole
body becomes `parseWithPartialPreserve(schema, value, source)` in `parseOutcome.ts`.

**Do NOT copy — three lines, each of which is a defect:**
- `String(issue.path[0])` — this is **fact 3 / the A2 hole**. For a top-level `unrecognized_keys` issue
  `path` is `[]`, so this evaluates to the literal string `"undefined"`, drops nothing, the retry fails
  identically and the column degrades whole. Replace with the `issue.keys` branch (research measured zod
  4.3.6 emits `{ code: 'unrecognized_keys', keys: ['bogusTop'], path: [] }`); `keys` is an **array** — loop it.
- `return {}` (×2, the structural-precondition line and the retry line) — these are the `parseMalformed(issues)`
  arms now, and G1/G2 fire on them post-change.
- `log.warn` — C5(b) ⇒ `log.error`.

**Field names are load-bearing, not stylistic** (research Q1): `status` (not `type` — collides with
`DataApiActionResult`, `lib/api/base/actionResult.type.ts`), `value` (not `data` — collides with the
Supabase destructure `const { data, error } = await this.supabase…` present in every adapter method),
`issues` (matches zod, **and is the identifier the G5 guard selector keys on** — renaming it silently
weakens the guard).

```ts
/**
 * Run `read` with the structured logger capturing into an array, then restore the silent default.
 * The logger's configuration is module-scoped and starts at `'silent'`, so a parse-failure record is invisible until the level is raised. The restore runs in a `finally` so one failing expectation cannot leave the level raised for the rest of the file.
 * @param read - The provider call under test.
 * @returns The call's result and every record emitted while it ran.
 */
async function withCapturedLogs<TResult>(
  read: () => Promise<TResult>
): Promise<{ result: TResult; records: Array<LogRecord> }> {
  const records: Array<LogRecord> = [];
  configureLogger({ level: 'warn', sink: (record) => records.push(record) });
  try {
    const result = await read();
    return { result, records };
  } finally {
    configureLogger({ level: 'silent', sink: undefined });
  }
}
```

body, `call` for `read`, *"@param call - The writer call under test."*

that is the established house shape).
**Do NOT copy:** any impulse to extract it to a shared module. And note `level: 'warn'` needs **no edit**

### 6. The logger (`packages/app-shared/src/logging/`) — vocabulary and contract to consume, not change

**Analog:** `logger.type.ts` (43 lines, read in full) and `logger.ts`.

```ts
/**
 * The four emittable log levels, named as pino names them.
 * `'silent'` is not a level a record can carry; it is only a {@link LoggerConfig} threshold that drops everything.
 */
export type LogLevel = 'debug' | 'info' | 'warn' | 'error';
```

```ts
export type LoggerConfig = {
  /** The minimum level to emit, or `'silent'` to emit nothing. */
  level: LogLevel | 'silent';
  /** Where records go. Defaults to the console when unset. */
  sink?: (record: LogRecord) => void;
};
```

`logger.ts:20-32` — the merge contract, whose docstring **names `LOG_LEVEL` as its motivating hazard**:

```ts
/**
 * Set the log level and, optionally, the sink.
 *
 * An explicitly-`undefined` member is NOT a change and is dropped from the merge. A plain spread would let `configureLogger({ level: undefined })` — which `Partial<LoggerConfig>` makes type-legal, and which is what `configureLogger({ level: env.LOG_LEVEL as LogLevel })` evaluates to when the variable is unset — clobber a working level with a value no threshold can be resolved from.
```

## Shared Patterns

### Structured log record (applies to every new/touched record — C4 NOTE 1)
**Source:** `parseJsonbColumn.ts:25-35` (the call shape) + `packages/app-shared/src/logging/logger.type.ts:13-30` (the contract).

```ts
log.error('A constant message with NO interpolation.', {
  column: source.column,
  id: source.id ?? undefined,
  issues: issues.map((issue) => issue.path.join('.'))
});
```

Three standing obligations: (1) `msg` is a **constant** — all varying data goes in the flat fields bag and
lands in `record.attributes`; (2) attribute values are primitives or arrays of primitives (a new
`rejectedKeys: ['bogusTop']` is a **sibling flat field**, never a nested object); (3) **never the offending
value** (T-157-17) — assert it with `expect(JSON.stringify(records[0])).not.toContain(…)`.

**Known non-conformant site on B2's path, name the choice rather than drift into it:**
`lib/api/utils/isValidResult.ts:21` — `log.error(\`Invalid result from DataProvider: ${error}\`)`, a
free-form interpolated string with no attributes.
