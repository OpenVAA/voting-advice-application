<objective>
Close the drift at source and remove the competing half-check.

Two edits, both small, both consequential. `strictPort: true` in `apps/frontend/vite.config.ts`
turns the silent same-address port drift — the measured mechanism of the original incident — into a
loud bind failure (D-08). Deleting CI's two blind, fail-open `curl` wait loops leaves exactly one
readiness mechanism, the preflight built in plan 01 (D-05). The default port stays 5173; moving it
is explicitly deferred (D-10).

An honest qualification the plan carries throughout, per RESEARCH QUAL-1: `strictPort` closes
**same-address drift** and was measured doing so. It does NOT close the **wildcard shadow-bind**,
where a process holding `*:5173` lets Vite additionally bind `[::1]:5173` with no `EADDRINUSE` at
all — measured live on this machine with `--strictPort` in effect. The preflight is what closes
that. Nothing in this plan may claim `strictPort` "prevents the cause" unqualified.

Purpose: after this plan, a port collision is either refused at bind time or caught at preflight
time — never absorbed silently.
Output: one config line in `apps/frontend/vite.config.ts`; two deleted steps in
`.github/workflows/main.yaml`.
</objective>

  <context>
CONTEXT.md D-08 explicitly instructs the planner to raise this as a decision checkpoint before the
implementing task, because it alters shared developer workflow rather than test-only surface. The
decision was taken as the recommended default on the blank-answer rule, not chosen explicitly by the

**What changes today.** `apps/frontend/vite.config.ts:24-26` sets `port` with no `strictPort`. When
5173 is already held by a same-address listener, Vite prints `Port 5173 is in use, trying another
one...`, serves on 5174, and exits 0 — while Playwright's `baseURL` keeps pointing at 5173. That
drift is the measured mechanism of the original incident (finding F6; reproduced live as RESEARCH
§R5.2 test A2).

**What changes after.** The same situation produces `error when starting dev server: Error: Port 5173
is already in use` and the process EXITS (§R5.2 test B2, measured). Every contributor whose 5173 is
occupied must either free the port or run `FRONTEND_PORT=<port> yarn dev` **and**
`FRONTEND_PORT=<port> yarn test:e2e` — the variable must be exported in the shell for BOTH commands,
because writing it into `.env` moves Playwright but not the dev server (RESEARCH QUAL-2, controlled
experiment).

**What does NOT change.** `FRONTEND_PORT` unset still starts on 5173: `Number(undefined)` is `NaN`,
Vite sanitises it to its default, and `strictPort` alongside `NaN` neither throws nor picks a random
port (§R5.2 tests D/E — tested precisely because it was the obvious way this could break every
developer's `yarn dev`). `vite preview` and the production `adapter-node` container are unaffected —
`server.strictPort` does not apply to either (§R5.1).

**Honest limitation.** This does NOT catch the wildcard shadow-bind. Measured on this machine right
now: Docker Desktop holds `*:5173`, macOS permits Vite to additionally bind `[::1]:5173`, and Vite
started successfully **with `--strictPort`**. `curl localhost:5173` reaches our app while
`curl 127.0.0.1:5173` reaches the foreign one, and no `EADDRINUSE` ever occurs (QUAL-1). Only the
preflight catches that case.

**Reversibility: reversible.** Deleting one config line restores current behaviour. No migration, no
published contract, no dependent phase.
  </context>
