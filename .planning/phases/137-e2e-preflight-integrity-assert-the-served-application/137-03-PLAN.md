<objective>
Prove the guard fails before claiming it guards.

The v2.15 milestone's standing acceptance rule requires every new check to be run as a negative
control **twice**: once against the old assertion to demonstrate blindness, once against the new one
to demonstrate the catch. ROADMAP criterion 1 states it as a phase success condition. This plan
discharges it and lands the durable evidence in `137-NEGATIVE-CONTROL.md` (D-13), following the
`136-VISUAL-DISCRIMINATION-EVIDENCE.md` precedent.

The adversary is a throwaway minimal Vite project staged in the scratch directory (D-11 option B —
the operator's one explicit answer, chosen for reproducibility on any machine over the live sibling
container). It is deliberately built as the hardest adversary that choice allows: a byte-identical
`<title>` and the same `301 → /sv/` redirect shape, so clauses (a) and (c) are genuinely exercised
and genuinely defeated, leaving clause (b) as the only thing standing. The retired check is written
as a throwaway script (D-12) because it never existed in code — only as runbook prose (finding F3).

Neither the adversary nor the retired-check script is committed to the harness. Their source is
quoted verbatim inside the evidence document instead, which is how a reader on another machine
rebuilds them.

Purpose: criterion 1 is the only success criterion whose proof is an *observation of a failure*, so
the evidence must survive the run that produced it.
Output: `137-NEGATIVE-CONTROL.md`.
</objective>
