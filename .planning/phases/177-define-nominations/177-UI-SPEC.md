# Phase 177 — UI Design Contract

> Visual and interaction contract for the surfaces Phase 177 adds or reshapes in the Contestant app: the
> nomination editor (K) — choosing the election and constituency pairs, then one card per pair with an
> election symbol and a party or alliance — the Edit entry and the widened "not editable" note on the
> nominations view (J), what the home's first task leads to, removal, the lock, and the copy that comes
> with them. Generated by gsd-ui-researcher, verified by gsd-ui-checker. It is the sequel of
> `176-UI-SPEC.md` and follows its conventions; the same executors and verifier read both.
>
> **This phase adds no design language.** SvelteKit 2 + Svelte 5 runes, Tailwind 4 + DaisyUI 5, Inter,
> theme colours in `packages/app-shared/src/settings/staticSettings.ts`. The token sections below
> **document the established contract** the surfaces obey; they introduce **no new token, font, spacing
> step, colour, icon or component library**. The load-bearing content is in *Surface Contracts*,
> *Copywriting Contract*, *Locator Contract*, *Axe Scan Entries*, *UI Considerations* and the closing
> *PROPOSED — Operator to Confirm*.
>
> **How to read the evidence marks.** `[tree]` = read on this worktree at HEAD `328bf49b6` on 2026-10-09.
> Phases 175 and 176 are executed and verified on that tree, so nothing below is taken from their plans.
> `[CONTEXT D-nn]` = a locked decision of `177-CONTEXT.md`; `[OD08-xx]` and `[OD09-xx]` = the operator
> decisions of 2026-10-08 and 2026-10-09; `[176-19]` = `176-19-SUMMARY.md` § *For Phase 177*.
> `[computed]` = calculated from the theme tokens for this document. `[not read]` = a fact this document
> could not establish by reading; each is listed under *What reading could not establish*. `[U-nn]` = a
> rule proposed in this document — **PROPOSED — operator to confirm** — all listed together at the end.
> Code is cited by path and a content anchor (a symbol or a quoted line), never by line number. Names of
> symbols, routes, message keys and test ids this phase introduces are suggestions unless a `[CONTEXT]`
> mark fixes them; what they must do is the contract. Frontend paths are relative to
> `apps/frontend/src/` unless they start with `apps/`; `ENTITY/` abbreviates
> `routes/contestant/(protected)/[entityType=servedEntityType]/[entityId=uuid]/`. J is the nominations
> view, K the editor.
>
> **This run was non-interactive, and there is no `177-RESEARCH.md`.** Nothing the context records as
> settled is reopened. Every place where the context leaves a UI question open carries a `[U-nn]` mark and
> is written at that item's ★ option. **The first four items, `[U-01]` to `[U-04]`, are the round the
> context owes the operator** (OD08-E12 (a)): the four situations no source describes. The screens (the
> context's plans 3 and 4) are not planned until that round is answered; the schema and data-model plans

> **Three proposals depart from the text of a locked decision**, and each says so where it is made:
> `[U-08]`, from the sentence `[CONTEXT D-31]` itself marks as inferred; `[U-13]`, from the order in

## Surface Contracts

### Shared premises

- **Two words with one meaning each.** *Editable* means neither lock is on:
  `!contestantCtx.nominationsLocked && !contestantCtx.answersLocked` `[CONTEXT D-13]`. Only the
  nominations lock is enforced by the database. *Admissible* means an election whose
  `nominationShape` admits the selected entity's type — the data package's one function, never
  re-derived on a page `[CONTEXT D-03, D-28]`. Both are asked through one predicate each; no page
  writes either condition out.
- **The editor manages some rows and leaves the rest alone** `[U-05]`. A nomination is *in the editor's
  reach* when its election is admissible for the entity's type and its round is that election's current
  round `[CONTEXT D-19]`. Every other row is listed on J, never shown on K, and never updated or
  deleted by a save.
- **Existing rows are never merged, moved or dropped by the selection step.** Step 1 decides which
  *new* pairs get a card and in what state an existing row's card *starts*. Every existing row in the
  editor's reach has a card on step 2, where the user can see it before anything is written.
- **Nothing is written before Continue on the details step** `[CONTEXT D-18]`. The selection lives in
  the URL; the symbol, the parent choice, the "Other" name and a card's removed state live in the
  page's own state until then.
- **One page per route, one descriptor per type** `[tree: lib/contestant/utils/entityDescriptor.ts]`. No
  `{#if type === 'organization'}` and no ternary on the type appears in a page. This phase adds these
  members; each is a message key picked by type:

  | Member | Candidate | Organization | Read by |
  |--------|-----------|--------------|---------|
  | `nominationsDescriptionEditable` | `contestantApp.nominations.descriptionEditable.candidate` | `….organization` | S2 |
  | `nominationsEmptyEditable` | `contestantApp.nominations.emptyEditable.candidate` | `….organization` | S2 |
  | `nominationsEmptyNoElection` | `contestantApp.nominations.emptyNoElection.candidate` | `….organization` | S2 |
  | `nominationElectionsTitle`, `…Ingress` | `contestantApp.nominations.elections.title.candidate`, `….ingress.candidate` | `….organization` | S4 |
  | `nominationConstituenciesTitle`, `…Ingress`, `…NoElection` | `contestantApp.nominations.constituencies.title.candidate`, `….ingress.candidate`, `….noElection.candidate` | `….organization` | S5 |
  | `electionSymbolInfo` | `contestantApp.nominations.details.symbolInfo.candidate` | `….organization` | S6 |
  | `parentNone` | `contestantApp.nominations.parent.none.candidate` | `….organization` | S7 |
  | `parentOtherLabel`, `parentOtherInfo`, `parentOtherRequired` | `contestantApp.nominations.parent.otherLabel.candidate`, `….otherInfo.candidate`, `contestantApp.nominations.error.otherRequired.candidate` | `….organization` | S7 |
  | `parentNotNominatedHint`, `parentNoOptions` | `contestantApp.nominations.parent.notNominatedHint.candidate`, `….noOptions.candidate` | `….organization` | S7 |

  `nominationParentLabel`, `electionSymbolLabel`, `nominationsDescription` and `nominationsEmpty` are
  176's members, read here unchanged.
- **Reactive accessors are read, never captured.** `nominations`, `nominationsLocked`, `answersLocked`,
  `taskState`, `selectedEntity`, `appSettings`, `locale` and `dataRoot` are reactive accessors: read
  `contestantCtx.X` inside the tracking scope, never destructured; `dataRoot` is never bound to a read
  alias — the selectors' `elections` are derived from `contestantCtx.dataRoot.elections` in the
  consuming scope (`CLAUDE.md` § Context Destructuring Rule;
  `.claude/skills/components/context-reactivity.md`).
- **Vocabulary** `[175-UI-SPEC U-25]`. The UI never says "entity" or "organization": an organization is
  a **party**. The user is never at fault for having no nomination, and removing one is not an error.
- **An id from the URL is data, not a decision.** The ids in the search params are matched against the
  elections and constituencies the application holds; one that matches nothing sends the user to the
  step that collects it. A name is rendered as text, never as markup. The write runs on the user's own
  rights whatever the URL says.
- **RTL is out of scope on this branch.** New markup uses logical utilities where it sets a side, so
  the RTL branch's port stays mechanical.

### S1 — What the first task leads to

### S3 — The editor: addresses, order and what is never shown

**Routes** `[CONTEXT D-18; OD08-E7 (a)]`, in a route group below J and **outside** the `(nominated)`
group, so that an entity with no nomination reaches them:

| Step | Directory | URL below the entity | Route key (suggested) |
|------|-----------|----------------------|------------------------|
| elections — also **the entry** | `ENTITY/nominations/(edit)/elections/` | `…/nominations/elections` | `ContestantAppNominationElections` |
| constituencies | `ENTITY/nominations/(edit)/constituencies/` | `…/nominations/constituencies` | `ContestantAppNominationConstituencies` |
| details | `ENTITY/nominations/(edit)/details/` | `…/nominations/details` | `ContestantAppNominationDetails` |

- **One entry address** `[U-18]`. Home's task, J's Edit and J3's button all link to the elections
  address. Its load decides what the user sees first and forwards there, as the voter's
  `(voters)/elections/+page.ts` does `[tree]`. Nothing else links into the middle of the editor.
- **The chosen ids are search params with names of the editor's own** `[U-18]`:
  `nominationElectionId` and `nominationConstituencyId`, each repeatable. They are not
  `PERSISTENT_SEARCH_PARAMS`, so they are passed from step to step by the step's own navigation and
  are on no link that leaves the editor (T-7). They are read in each step's **own page load**; no
  layout load on the path reads a `url` property `[CONTEXT D-18]`.
- **Existing nominations prefill the selection** `[CONTEXT D-18]`: the entry opened with no id in the
  URL starts from the elections and constituencies of the entity's rows in the editor's reach.

**The guard — what is never shown.** One load of the group decides, before any step renders, and reads
`params` and `parent` alone (a read-recording test beside it, as `(nominated)/layout.tracking.test.ts`
`[tree]`). The two facts it decides on — whether nominations are editable, and which elections are
admissible — are supplied by a load on the `nominations/` path, which J reads too (S2), so that J and
the guard cannot disagree:

| Condition | Outcome |
|-----------|---------|
| a user-level gate is pending | nothing is decided; the gate's view is shown at the URL asked for, as in `(nominated)/+layout.server.ts` `[tree]` |
| not editable — either lock | **redirect to J**, which shows the note `[OD08-E13 (a)]` `[CONTEXT D-13]` |
| no admissible election | **redirect to J**, which shows J5 `[U-01]` |
| otherwise | the step asked for is served |

No frame of an editor page is rendered for a user the guard turns away, no client-side redirect is
added, and J is the explanation: the redirect carries no notice, no toast and no query parameter.

**Which step is shown.** The decisions are those of the shared ordering module both apps call
`[CONTEXT D-15]`, given the admissible elections only `[CONTEXT D-28]` and never
`elections.disallowSelection` `[OD08-E14 (a)]`. *A* is the number of admissible elections.

Without `elections.startFromConstituencyGroup`:

| A | Constituencies of the election(s) | The user sees `[CONTEXT D-16; OD08-E6 (b)]` |
|---|-----------------------------------|---------------------------------------------|
| 1 | one | **the details step at once** — the pair is implied, nothing is chosen |
| 1 | several | **the constituency step**, then details; no election step |
| several | any | **the election step**; then the constituency step unless every chosen election has a single constituency; then details |

With `elections.startFromConstituencyGroup` set to a group G:

| Situation | The user sees |
|-----------|---------------|
| A = 1 and that election has one constituency | the details step at once — the skip comes first: `[CONTEXT D-16]`'s table names no setting |
| no constituency chosen yet | **the constituency step**, as one picker over G (`useSingleGroup`) |
| a constituency is chosen and exactly one admissible election is held there | the details step — a single admissible election is never shown as a choice |
| a constituency is chosen and several admissible elections are held there | **the election step**, listing those elections only; then details |
| a constituency is chosen and no admissible election is held there | the constituency step stays, with one sentence `[U-29]` (S5) |

- **A skip is a redirect** `[CONTEXT D-16]`: the address the user asked for forwards to the step that
  has something to choose, in one navigation. Back from the details step then leaves the editor.
- **A step opened without what it needs** sends the user to the step that collects it: the constituency
  step with no election chosen or implied → the entry; the details step with no pair in the URL → the
  entry. Neither shows an error page.

**The buttons of a step** `[U-19]`. Every step has one filled main button and one ghost **Cancel**
(`common.cancel`, `data-testid="contestant-nomination-cancel"`) under it, which leads to J and writes
nothing. No step counter, no progress bar and no breadcrumb is rendered.

the profile's Cancel does; a successful save leaves without asking.

cards are a `<ul>`. Tab order inside a kept card: the symbol field, the parent group (one tab stop, S7),
the "Other" name when shown, Remove. The symbol field is labelled and described by `Input`
(`{id}-info` `[tree]`). A note is plain text inside its card, read in order before the fields it
concerns. The removed line is a `role="status"`, announced when the card changes state; pressing Remove
moves focus to that card's Keep, and pressing Keep to that card's Remove, so focus is never left on
`<body>`. No motion is added.

### S7 — The parent selector

`[CONTEXT D-05, D-06, D-07, D-29; OD08-E9 (a), E10 (a)]` One component, `EntitySelector`, used by the
candidate's card for parties and by the party's card for alliances `[U-12]`.

**Which options, and what is chosen on arrival.**

| Entity | Election shape | Group | Required | Options, in order `[U-13]` | Chosen on a new card |
|--------|----------------|-------|----------|----------------------------|----------------------|
| candidate | `organization_list` | shown | **yes** | the confirmed parties; "Other" | nothing |
| candidate | `organization_list_and_independents` | shown | a choice is required; "Independent / no party" is one | "Independent / no party"; the confirmed parties; "Other" | nothing |
| candidate | `candidate_only` | not shown | — | — | — |
| party | `organization_list`, `organization_list_and_independents`, `organization_only` | shown | no | "None"; every alliance of the project, confirmed or not; "Other" | **"None"** |

- **Order** `[U-13]`: the option that names no parent first, where there is one; then the listed
  entities, sorted by name in the page's locale; then "Other", last, with its name field directly under
  it. Factions are never options.
- **On an existing card** the stored state decides: a linked parent that is listed → that option;
  `customData.requestedParentOrganization` → "Other", with the stored text in the field; no parent and
  no such key → "Independent / no party" or "None" where the group offers it, and nothing chosen where
  it does not (a party-less candidate in an `organization_list` election); a linked parent that is not
  listed → `[U-04]`, below.
- **Nothing is preselected for a candidate** `[OD08-E9 (a)]`, and "None" is preselected for a party
  `[CONTEXT D-05]`. An untouched group of a candidate is an unanswered one, never independence.

**The control** `[U-12]` — a native radio group:

```
<fieldset role="radiogroup" aria-labelledby={legendId} aria-required={required || undefined}
          aria-invalid={error ? 'true' : undefined} aria-describedby={error ? errorId : undefined}
          data-testid="entity-selector" data-selected-kind="entity|none|other|unlisted|">
  <legend id={legendId} class="small-info uc-first">
    {legend}
    <Icon name="required" class="text-warning" /><span class="sr-only">{t('common.required')}</span>   while required and nothing is chosen
  </legend>
  <p class="small-info mt-sm" data-testid="entity-selector-empty">              only when no entity is listed
  <div class="mt-sm gap-sm flex flex-col">
    <div class="p-sm gap-md min-h-touch relative flex items-center rounded-lg has-[:checked]:bg-base-200"
```

- **The compact card is `EntityCard` as it is** `[CONTEXT D-29]`: `variant="subcard"` (the 44px avatar,
  no card background), `headerOnly`, `action={false}` — the logo or the initials and the name
  `[tree: EntityCard.svelte, "variant === 'subcard' ? 'sm' : undefined"]`. No prop and no variant is
  added. The entity is an object of the data root `[tree: EntityCard.type.ts, "entity: MaybeWrappedEntityVariant"]`:
  the parent-options read is provided to the data root as entities `[CONTEXT D-09, D-29]`, and the page
  reads `contestantCtx.dataRoot` in the scope that builds the options. Providing them must not remove
  an entity another page of the editor relies on (T-6 `[not read]`).
- **The option's name is the label's, said once.** The card is `aria-hidden`: it holds an `<article>`,
  an `<h4>` and an avatar whose image repeats the name, and none of that belongs inside a radio's name
  or among the page's headings. The `<label>` covers the whole row, so the row is the pointer target,
  and carries the entity's name for assistive technology: "Green Party, radio button, 2 of 7". The
  card holds no link and no button (`action={false}`), so nothing focusable is hidden.
- **Chosen is told twice**: by the radio's own mark, and by the row's `base-200` fill.
- **Keyboard**: the group is one tab stop — the chosen radio, or the first when none is chosen; the
  arrow keys move and choose; Space chooses. Focus is shown by the radio's own ring. Choosing "Other"
  with an arrow key does **not** move focus into the name field: the field is the next tab stop.
- **Required**: `aria-required` on the group, and the mark `Input` uses — the `required` icon with the
  sentence `common.required` for assistive technology — beside the legend until something is chosen.
- **The legend** `[U-14]` is the descriptor's `nominationParentLabel` — "List" for a candidate,
  "Alliance" for a party — the label J gives the same fact.
- **A listed entity that has no nomination at this pair** `[CONTEXT D-06, D-07, D-09]` carries a hint
  under its name, the descriptor's `parentNotNominatedHint`, named by the radio's `aria-describedby`
  `[U-15]`. Choosing it makes the save create that nomination, unconfirmed.
- **No listed entity at all**: the line of the descriptor's `parentNoOptions` under the legend; the
  plain options remain. A candidate in an `organization_list` election then has "Other" alone.
- **Every option is rendered**: no search, no paging and no inner scroll region. A project with thirty
  parties gives a card thirty rows.

**"Other"** `[CONTEXT D-21]`. When it is chosen the page renders, through the selector's `detail`
snippet, one `Input type="text"` under its row: label the descriptor's `parentOtherLabel`, info line
the descriptor's `parentOtherInfo`, `required`, `maxlength="100"` `[U-16]`,
`containerProps={{ 'data-testid': 'nomination-editor-other' }}`. The text is trimmed when committed.
What was typed is kept in the page's state while another option is chosen, and shown again when the
user comes back to "Other". On save: the text is stored as `customData.requestedParentOrganization`
and no parent is linked; choosing a listed entity, "None" or "Independent / no party" instead removes
the key.

**A linked parent that is no longer listed** `[U-04]`. The group gains one option, first in the list,
for the parent the nomination has: a plain row — no `EntityCard`, since the entity is not among the
options — whose name is the parent's name (its short name when the name is empty) and whose hint is
`contestantApp.nominations.parent.unlisted` (`data-option-kind="unlisted"`). It is chosen on arrival.
Left chosen, the save leaves the link exactly as it is: the row is not written for its parent's sake,
and a required parent is satisfied. If the user chooses another option the unlisted one stays in the
group until the save, and is gone afterwards. This also covers a parent that never was an option — a
candidate an administrator placed under a faction.

### S8 — Continue on the details step

`[CONTEXT D-31; ROADMAP criterion 4; 176-19, "The form in which a new Continue asks"]` K's button is a
button that saves first. Its label is asked before the save, of the draft; its target after the save,
of the task state as it then stands `[U-22]`.

**Label.**

| The draft | Label | `data-action` |
|-----------|-------|---------------|
| nothing to write; a next step exists | `common.continue` | `continue` |
| nothing to write; no task is left | `common.return` | `return` |
| something to write; at least one card is kept or new; the entity had no nomination, or a next step exists | `common.saveAndContinue` | `continue` |
| something to write; at least one card is kept or new; the task state is known and no task is left | `common.saveAndReturn` | `return` |
| every card is removed | `common.saveAndReturn` | `return` |

"Something to write" means a new card, a removed card, a moved card, or a kept card whose symbol,
parent choice or "Other" name differs from what is stored. For an entity that had no nomination the
label is a prediction: its question lists are not loaded until it has one, so whether the profile is
left to do is not known before the save. Where the profile turns out to have nothing left either, the
button read "Save and Continue" and led home.

**Target** — a sixth function beside the five of `$lib/contestant/tasks` `[tree]`, read after the
rerun of S9 and only once `taskState.known` is true:

| The task state after the save | Target |
|-------------------------------|--------|
| the entity has no nomination left | the entity's home |
| a next step exists | that step's route — the profile, or the questions **list** `[176 U-02]` |
| every task is complete | the entity's home |

- A press with nothing to write writes nothing and goes to the target.
- **A save that fails chooses no target** (S9), as on the profile `[tree]`.
- The page computes its prospective state as the profile and the question page do. The context exposes
  no `entityKnown`, combined `questionsReady` or `requiredNameMissing`, so each of those pages repeats
  one block; `[176-19]` files the accessor that removes it with this phase as its owner
  (`2026-10-09-176-rules-and-helpers-written-twice.md`, item 2). K's label needs "has a nomination"
  alone and must not become a third copy.

### S9 — After the write, and when the write is refused

**After a successful save** `[CONTEXT D-14; ROADMAP criteria 4, 5]`. Before the page navigates, the
entity-level load has rerun and its data has reached both lists that hold nominations — the page data
`contestantCtx.nominations` reads, and the list the user-data store was initialised with, which the
context's two election effects read `[176-19, "a write has to reach both lists"]`. From that moment,
with no full page load:

- home's nomination row is `complete` and reads "View your nominations"; the profile and the questions
  rows are open; a question that now applies is counted, and one that no longer applies is neither
  asked nor counted — its stored answer is kept and is not shown `[CONTEXT D-14]`;
- J lists the nominations as stored, each new or changed one as "Pending confirmation";
- every Continue of the app leads by the new set.

How the load is rerun is the planner's `[CONTEXT RQ-6]`; the load still reads no `url` property, and
its tracking test still passes. No success message is shown on K: the user is on the next page.

**When the write is refused.** Nothing navigates on a refusal, with one exception, and the write is one
transaction, so nothing of it is stored `[CONTEXT D-08]`. After **every** refusal the page re-reads
the settings and the entity's nominations, and decides in this order `[U-21]`:

| What the re-read or the refusal shows | `data-outcome` | What the user meets |
|----------------------------------------|----------------|---------------------|
| a lock is now on | — | **J, with the note** `[CONTEXT D-12; OD08-E13 (a)]`. The draft is dropped: it can no longer be stored. This is the stale client's path — the browser showed the editor, the database refused. |
| the entity's nominations are not those the cards were built on | `changed` | The cards are rebuilt from the nominations as they now are, the draft is dropped, and the message region shows `contestantApp.nominations.error.changed`. |
| the refusal names candidates listed under a nomination that was to be removed or moved | `hasCandidates` | `contestantApp.nominations.error.hasCandidates`; the cards and the draft are kept. |
| the refusal is the limit on nominations waiting for confirmation | `tooManyPending` | `contestantApp.nominations.error.tooManyPending`; the cards and the draft are kept. Subject to the finding of `[CONTEXT RQ-8]` on whether the limit stays. |
| anything else, a network failure included | `failed` | `contestantApp.nominations.error.saveFailed`; the cards and the draft are kept; pressing the button again retries. |

- The message is an `ErrorMessage inline` inside the `role="alert"` region above the main button, the
  profile's shape `[tree: "role=\"alert\" data-testid=\"profile-save-message\" data-outcome"]`. Focus
  returns to the main button, which shows the label it had.
- The first two rows need nothing of the refusal itself. The third and fourth need the page to tell
  those two refusals from the rest `[CONTEXT RQ-3]`; where it cannot, the user gets the last row's
  message, which is true and less helpful.
- A refusal is never shown as its raw database text.

## View Transitions

`CLAUDE.md` § Results Navigation Invariants: *a document View Transition must never run with names while a
modal is open*, and *the `(located)` load must not read the URL tracked*.

- **This phase adds no `view-transition-name`.** Not on a card, an option row, a note or a step's
  selector. The surfaces inherit the standing names: `main-content` (`MainContent`) and
  `persistent-header` (`Header`).
- **No modal is introduced.** Removal is warned on the card `[U-06]`; `PreventNavigation` asks through
  `window.confirm`, which is not a `<dialog>` `[tree]`; `ButtonWithConfirmation` and
  `ConfirmationModal` are not used. `[U-03]` (c) and `[U-06]` (b) are the options that would open one,
  and each names the invariant as its cost.
- **Each step is a page.** Going from step to step is an ordinary navigation and takes the standing
  document transition; choosing an option, pressing Remove or Keep and typing navigate nowhere.
- **A skip and a guard are one navigation each**, decided in a load, so no step that is passed over is
  mounted and no transition starts on a page that is leaving.
- **No load of the editor reads a `url` or `route` property in a layout.** The group's guard takes
  `params` and `parent`; the chosen ids are read by each step's own page load `[CONTEXT D-18]`. The
  entity-level load is unchanged and its `layout.tracking.test.ts` still passes.
- **The extraction leaves the voter's `(located)` load alone**: the ordering decisions move out of
  `(voters)/elections` and `(voters)/constituencies`, and no tracked URL read moves into
  `(voters)/(located)/+layout.ts` `[CONTEXT, standing rules]`.

### The four situations no source describes (OD08-E12 (a))

**U-01 — No election the entity can stand in** (the context's Q1).
A party in a project whose every election takes candidates only — or a candidate where every election
takes parties only — has nothing to choose. The database refuses such a nomination for every writer,
so support cannot add one either unless an election's type is changed.

At the ★ the user meets:

| Surface | What it shows |
|---------|---------------|
| Home | Unchanged: the first row reads "Define your nomination", incomplete, with the `!` badge; the profile and the questions are closed with the reason sentence; the main action is the same row. Home does not know there is nothing to choose. |
| J | Following the row lands here. The title "Nominations"; one sentence, "There is no election in this application in which a party can be nominated. If you think this is a mistake, please contact support."; the Contact support button; **Return** to home. No Edit, no "Define your nomination", no note. |
| K, the selection | Never shown. Every editor address forwards to J. |
| K, the cards | Never shown. |

- [ ] ★ RECOMMENDED (a) As above — one true sentence on the page the user already lands on, and home stays complete in the server-rendered page.
- [ ] (b) The editor opens and says it itself: its first address shows a page with the same sentence and Return. One more page state to build, scan and translate a title for; J's empty state then still offers "Define your nomination", which leads to that page.
- [ ] (c) No new sentence: J shows Phase 176's "No nomination has been defined for your party yet. Please contact support to have one added." It asks support for something the database will refuse.
- [ ] (d) Home says it: the first row is shown closed, with a reason sentence of its own under the list. Home then has to know the elections before it is drawn, so the no-nomination home is no longer complete in the server-rendered page unless a load supplies the answer; one more sentence per type.

**U-02 — Several nominations in one election** (the context's Q3).
An administrator can give a party a nomination in each of several constituencies of one election, and
a candidate can be nominated by several parties at one contest. The selection step holds one
constituency per election and cannot show either.

At the ★ the user meets:

| Surface | What it shows |
|---------|---------------|
| Home | Unchanged: "View your nominations", complete. |
| J | One card per nomination, as today, and Edit. |
| K, the selection | The election step lists that election checked, like any election the user is nominated in. The constituency step shows no selector for it: under the election's name it says "You have several nominations in this election. They are kept as they are; you can change their details in the next step." If no other election needs a constituency, the step is not shown. |
| K, the cards | One card per existing nomination, each with its own symbol field, parent group and Remove. Nothing is preselected away: **the editor never merges, moves or drops a nomination it did not create.** The user cannot add a second nomination to an election. On save, a card nobody changed is not written and stays confirmed; a changed one is updated and waits for confirmation again; a removed one is deleted. Two cards of one contest cannot name the same list. |

So the saved set may hold more than one nomination per election **only where each of them existed
before**.

- [ ] ★ RECOMMENDED (a) As above — nothing an administrator seeded is lost by opening the editor, and the user can still edit the symbol and the alliance of each seeded pair, as the 177-C3 decision says.
- [ ] (b) One per election, for everyone: the selection step preselects the first of them, and saving deletes the others after a warning that lists them. A party's first save undoes the administrator's seeding.
- [ ] (c) Such nominations are shown on the cards step locked: no fields, no Remove, and a line naming support. Safest for seeded data; the user cannot enter a symbol for them, against the 177-C3 decision.
- [ ] (d) No editor at all for such an entity: J shows no Edit and a sentence naming support. The user cannot add a nomination in another election either.

At the ★ the user meets:

| Surface | What it shows |

- [ ] ★ RECOMMENDED (a) As above — "unlocked means you manage your own nominations" holds in the commonest project shape too, with no dialog and nothing deleted before Save.
- [ ] (b) Not removable in the app where the selection is skipped: the card says to contact support. The user of a one-election project can define and edit a nomination and never withdraw it.
