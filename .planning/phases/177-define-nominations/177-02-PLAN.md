## Rulings and deviations carried by this plan

1. **Every template is re-typed, not only the three that hold a refused row** (OD08-E3's NOTE; RESEARCH RQ-1's table). Nothing in the application reads the type before this phase, so no observable behaviour changes; the one dataset that keeps a list-type election is this phase's own, built in plan 177-10.
2. **`ElectionsGenerator` emits the new default** (item P-14): with the type it emits today a template that pairs synthetic elections with fixed party nominations would be refused by the rule.
3. **The schema reaches the database by a reset, not a push**: nothing is deployed and no remote project exists. The reset is the first of the database rows the gate driver runs.
4. **The template files this plan lists are the ones named by RESEARCH; the population is derived again when the plan runs** (`git grep -l "election_type" -- packages/dev-seed/src`), and every file it finds is changed, whether or not this plan's frontmatter names it. A file the search finds that the frontmatter does not name is reported in the summary.
