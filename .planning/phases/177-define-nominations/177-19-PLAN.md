## Rulings and deviations carried by this plan

1. **The view's button in J3 reads "Define your nomination"** — the home's own label for the same action (U-08, the accepted departure from the sentence of D-31 that the context marks as inferred). Its target is as D-31 infers it: the editor.
2. **`nominationsViewTarget` is given the view's fact in a second argument and says which button it is.** `NominationsViewFacts` holds one member, whether an entry to the editor is offered; the answer gains an `action` of `continue`, `return` or `define`, so the page compares no route name. The task state cannot tell J3 from J5: the home asks nothing about elections.
3. **The home's page changes by one attribute.** Its rows and its main action already render whatever route the task state gives them; the change of routing is in `taskStateOf` and in the context's one line that hands the input over.
4. **Three files hold more than five paths between them in one task, and they land in one commit**: the task state, the context, the view and the home change one behaviour that three specs read, and a commit that held some of them would turn a committed test red.
5. **The pre-commit run is a full default run**: the nominations view and the home are read by `contestant-a11y.spec.ts` and by the journey, which a run restricted to the nominations spec's project does not reach. The control before it is a one-project run of the new tests alone, with the two other specs unchanged — a red test in an earlier project of the chain would stop the chain before the new spec ran.
6. **The changed expectations of the two other specs are not shown red first.** They are existing tests whose surface changes; the rule asks that they be seen green on the uncommitted tree before they are committed, which the full pre-commit run does.
7. **The D-14 unit case lives in `taskState.test.ts` and takes its counts from the real `unansweredQuestionsOf`.** The sentence of `taskState.ts`'s header on what its test loads is brought in line with that.
8. **`role="list"` is added to both lists without an accepted-warning comment** (RESEARCH F4: the compiler raises nothing on this version). Flagged assumption A8 — that ESLint raises nothing either — is settled by the lint row: where it raises, the rule is accepted on that line with a reason comment in the project's form and the summary says so.
9. **The third teardown takes the clearing step** (item P-12): `perm-no-nomination`'s entities can now reach a save through the editor, so its teardown removes the nominations the application wrote, those with a parent first, before its prefix delete.
10. **Additive fixture steps, committed first**: the home's fixture can follow the nomination row and say where it led; the editor's fixture can mark the document and assert it is still the one that was marked; the nominations dataset's root hands out the home's task steps, the menu and the questions list where it does not yet.
