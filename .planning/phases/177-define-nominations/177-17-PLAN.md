## Rulings and deviations carried by this plan

1. **The guard's tracer condition is removed here**, with its test case turned round: an entity with a nomination in reach is served. From this commit on the details step is safe for such an entity because every nomination in reach has a card and is named in the desired set.
2. **An election in which the entity holds several nominations needs no constituency choice.** Two small pure functions join `editorFacts.ts`, each with its unit cases: `startingSelectionOf(nominations)` — the elections of the nominations in reach and, for an election with exactly one of them, its constituency — and `constituencyChoiceOf({ chosenElectionIds, nominations })` — which of the chosen elections have a constituency to choose and which are kept as stored. The loads and the election page's Continue ask them; no page counts nominations itself.
3. **The button's label stays the tracer's** in this plan; its full table, and what a refused save shows, are plan 177-18's. What this plan adds to the handler is one branch: with nothing to write it calls no write and goes to the target.
4. **A moved card whose stored parent is not listed** follows plan 177-14's ruling 3; it has a unit case there and no E2E test here.
5. **The first test of the table asserts what the tracer already does**; the control expects the thirteen `edit:` and `remove:` tests red and that one green.
6. **Plan 177-15's ruling 7 names plan 177-16 for the prefill from existing rows and the "kept" section; plan 177-16 builds neither, and this plan builds both.** Nothing of either plan is contradicted by building them here: until this plan the guard turns away every entity that has a row to prefill from.
7. **The "kept" section is seen in no browser on the phase's dataset.** Only one election of the dataset has several constituencies, so whenever an entity holds several nominations there no other election has a constituency to choose and the step is passed over. The section is held by the constituency page's component test; the UI contract's table of scans excludes it by design. Plan 177-21 records it among the states held by a component case alone.
8. **One fixture change, additive**: `addNomination`'s options take an optional election round, for the row of another round. No committed spec passes it.
9. **Two page-local rules cannot be told from the database's in a browser** — that an untouched set makes no call, and that Remove makes none — because the write function also skips an unchanged row. A component test of the details page, in the frame of the constituency page's, holds both with the context's write as a spy.
