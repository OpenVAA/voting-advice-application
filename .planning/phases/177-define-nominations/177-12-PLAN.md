## Rulings and deviations carried by this plan

1. **The keys are read from the UI contract by a command, not retyped**: the table *New messages* is the list, and the verify chain derives it again from the document.
2. **The pair `contestantApp.nominations.parent.other.<type>` gets a descriptor member, `parentOther`.** The contract's table of members does not name one for it, and its own rule — a string that differs by type is picked through the descriptor — needs one. Every other member takes the name the contract gives.
3. **Non-English copy is constructed here** from each catalogue's existing terms and from the notes of *Sentences that will not survive translation as written*; a native-speaker review is filed as a todo by plan 177-21 and does not hold the phase (operator decision C4 (a)).
4. **No E2E run closes this plan**: nothing renders a new key, and the note's two existing reasons are unchanged.
