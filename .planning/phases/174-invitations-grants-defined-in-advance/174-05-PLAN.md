## The wire contract this plan fixes

One endpoint, `POST /functions/v1/account-access`, JSON in and out. Every body carries `operation` and
`project_id` (a uuid).

| Operation | Further fields | Answer |
|---|---|---|
| `check-code` | `code` | 200 `{ "status": "valid" }`, `{ "status": "used" }` or `{ "status": "unknown" }` |
| `request-link` | `email` and/or `code`; optional `locale`; optional `witness` (a uuid) | 200 `{ "accepted": true }`, always |
| `code-sign-in` | `code`, `password` | 200 `{ "result": "signed-in", "access_token": …, "refresh_token": … }` or 200 `{ "result": "invalid-credentials" }` |

A body that is not JSON, names no known operation, carries no uuid as `project_id`, lacks a field its
operation requires or exceeds a length bound is answered 400 `{ "error": "bad-request" }`. A method other than
`POST` and `OPTIONS` is answered 405. A failure of the function's own dependencies during `check-code` is
answered 500 `{ "error": "internal" }`. None of these depends on whether an address, a code or an account
exists. The registration-mode matrix is not consulted by any operation in this phase (178-A4). `witness` is
for the service role: it names a completion record the service role opened beforehand, changes no answer, and
is ignored when it names nothing; a screen never sends it.

## Rulings and deviations carried by this plan

1. **Names (Claude's discretion).** The function is `account-access`; its operations are a discriminated
   body, not sub-paths.
2. **OQ-8.** The project comes from the request body. The function is dispositioned
   `'requires a project term'` in the project-scoping gate.
3. **OQ-4.** The origin is `SITE_URL`. The function asks the auth service whether it would redirect to the
   callback URL — the same question `170-allowlist-probe.sh` asks — and issues nothing when the answer is
   no. A positive answer is remembered per callback URL for at most ten minutes.
4. **OQ-1.** The served-settings check is fail-closed, happens in the background work so it cannot change
   the answer, and its positive result is remembered for at most 60 seconds, never for a worker's lifetime.
5. **OQ-7.** The answer is returned before the work through `EdgeRuntime.waitUntil`. Task 2 measures that
   the work completes under the per-worker policy; if it does not, the task stops with a checkpoint, because
   sending before answering is the timing oracle D-15 forbids.
6. **J4.** The 60-second interval is the database's (174-04); the seven-locale mail is here. The six
   non-English texts are constructed and a native-speaker review is filed in 174-10.
7. **Not as written (item 5 of the phase's review list).** No per-caller limit. Task 2 records what the
   function observes of its caller on the local stack, as data for the todo; residuals R-a to R-d of 174-01.
8. **The slot is not held by a failure.** Both deployment checks run before the database is asked, so they
   take no slot; a failure after the slot was taken calls `invitation_link_release`. The order lives in one
   pure module, `linkIssue.ts`, whose dependencies are injected, so each path is a unit test.
9. **A completion witness.** `request-link` may carry `witness`; the function completes that record at the
   end of its work. It exists so that "no mail was sent" can be asserted after the work is known to be over.
10. **`request-link` with a code and no address** asks for a link to the claimant's own address when the code
    is used (D-17's "a user who claimed but never set a password"). The address stays inside the function.
11. **Twenty-one files and seven tasks.** Each of the five pure modules needs its test beside it; the probe,
    the modules, the orchestration, the handler, its conformance and gates, and the live run are each a task
    of their own, and each of the three restarts is checked in a verify command.
12. **This plan closes on gate rows and one live run, with no E2E run.** No spec of the suite calls an Edge
    Function yet, so a full run could observe nothing about this one; its boundary proof is the run that
    closes 174-06, which adds the contract spec.
