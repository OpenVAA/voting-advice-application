## Rulings and deviations carried by this plan

1. **The gate is `private.caller_entity_ids`** (orchestrator ruling 2; research T-8). `user_can (… 'nomination.read' …)` admits a parent organization's editor for its child candidate, which would let that editor learn the name of another party the candidate stands for. The table-based gate is also the one `get_entity_user_data` uses for the read this one accompanies, so the two cannot disagree about whose entity it is.
2. **Shape A of the research**: one `SECURITY DEFINER` function in `public`, `RETURNS jsonb`, `NULL` for a refusal and an array otherwise.
3. **The function returns the election's and the constituency's names** (D-09 leaves it to the planner; orchestrator ruling 5): the nominations view then resolves no name through the data root.
4. **The registry row for the function** (`scripts/assert-project-scoped-queries.mjs`) is added by plan 176-05, with the adapter's call that needs it; this plan stays out of `scripts/`.
5. **Assumption A7 of the research is carried**: a project admin and a parent's editor get `NULL`. *What falsifies it:* a caller other than the contestant writer. None exists; a later Admin-app view widens the gate then.
