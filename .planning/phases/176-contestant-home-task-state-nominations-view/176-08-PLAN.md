1. **Orchestrator ruling 3.** The no-nomination gate is a route group whose server load redirects to the entity's home. The preview's own rule is plan 176-10's and sits in the preview's own load: a group's layout load does not run again between two pages of the group (research RQ-1, step B).

3. **Research assumption A1 is tested here**: *the application's loads behave as the research's scratch app did.* **What falsifies it:** a `gate:` test red after the group exists — a typed URL that renders the page, or a nomination added behind the user that does not open the profile at the next full load. **What happens then:** the plan stops and reports the request the browser made and the loads that ran; the gate is not turned into a client-side redirect (D-13).

5. **The docs page that names the page files by path** is corrected in plan 176-19.
