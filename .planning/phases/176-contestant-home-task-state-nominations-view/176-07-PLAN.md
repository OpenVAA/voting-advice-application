## Rulings and deviations carried by this plan

1. **The dataset comes before the screens, and the spec grows with them** — a departure from D-21's wave order, in which the template, the spec and the fixtures follow the screens. The orchestrator's rulings 8 to 10 ask for fixtures before specs, a control on an uncommitted tree for a surface still to be built, and a full run at the close of every plan that changes a surface; those can only be met by a dataset that exists when the first screen is built. **This is a departure from D-21's plan-shape clause and not an amendment of it.** D-21 is unchanged; an orchestrator cannot amend an operator's decision and has not. The departure is put to the operator as item C4 of `.planning/v2.16-OPERATOR-DECISIONS-2026-10-09.md`, and plan 176-01 reads that item when the phase starts and stops the phase when it was ruled otherwise. **The fallback, if the operator keeps D-21's order, is a re-plan of plans 176-07 to 176-18 — it is not a move of this plan.** This plan cannot go behind the screens unchanged: plans 176-08 to 176-17 add their tests to the spec it creates, register their fixtures on its composition root, call its state steps, run `--project perm-no-nomination`, and chain their full runs from `176-07-close`; plan 176-08 depends on it. The re-plan is of this kind: the screens are built against their component and server tests alone, with no control and no run of the suite of their own; the dataset, the spec with every test now spread over those plans, the fixtures and the scans become one late plan, whose tests are written against finished screens and can only be shown green; and the suite is run once, on the finished phase. What is lost: every red control, and the knowledge of which plan caused a regression. That re-plan is not written here; it is the orchestrator's to order when item C4 is ruled that way.
2. **Research T-3** (orchestrator ruling 2): the lock is flipped with one key; the template restates the `contestantApp` root whole because a list is replaced whole.
3. **Entities with and without a nomination** (orchestrator ruling 8): the third identity, `ca-nominated`, is seeded with one, so that a test of the questions or of a save need not insert one first.
4. **All three entities are confirmed**, so that the profile task's name clause never applies in this dataset; Phase 175's dataset holds the unconfirmed cases.
5. **Every id of the UI contract's Locator Contract is registered here** (U-19), in one edit of the registry; `profile.nominations` is retired by plan 176-13 with the block it names.
6. **The session helper's settle marker** is the home's status message, which today's home renders for every user; plan 176-14 keeps it true for a user with no nomination.
