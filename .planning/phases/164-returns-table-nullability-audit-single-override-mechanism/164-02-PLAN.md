`00002_anon_select_terms_of_use_and_get_nominations_rls_guard.sql:39` redefines `get_nominations`

**Parse.** For each `RETURNS TABLE (` occurrence: scan backwards to the nearest
`CREATE OR REPLACE FUNCTION public.<name>(` to capture the function name and its declaration line;
scan forwards to the matching `)` at column 0, splitting each intervening line on the first
whitespace run into `[column, sqlType]`. Emit
`{ rpc, file, defLine, returnsTableLine, columns: [{ name, sqlType }] }`.

**Emit deterministically.** Sort RPC records by `(file path, defLine)`. Keep columns in **declaration
order** — that is the RPC's positional contract and sorting them would destroy information. The same
tree must produce byte-identical output on every run, so `--write` followed by
`git diff --exit-code` can only ever be reporting a real change.

**Five assertions, each with its own consequence-naming failure message** (house style — the message
says what broke, what it means, and what to do):

1. **Set equality.** The harvested `{rpc → column names}` map must equal the map recorded in
   `packages/supabase-types/RPC-NULLABILITY.md`. A fourth RPC, a removed RPC, a new column or a
   removed column fails with a message naming the specific item and pointing the reader at the
   artifact and at `--write`. This is the "so a future RPC is not missed" clause of criterion 1 and is
   the only part of it a script can actually deliver.
2. **Duplicate-name guard (the adjacency case).** If the same function name is declared in two
   different scanned files, fail with a message naming **both** file:line pairs. Do not merge the two
   into one row and do not emit two rows silently. This is the failure mode a migrations-scoped scan
   would have produced invisibly.
3. **Fail-closed on empty (the empty case).** A `.sql` file that declares no `RETURNS TABLE` function
   contributes zero rows and is **not** an error — most files in the tree are like that. But a total
   harvest of zero RPCs, or a scan root that does not exist or cannot be read, exits **1** with a
   message naming the scanned root. A green "0 RPCs found" would be a gate that cannot fail.
4. **The cast grep.** Build a regex whose column alternation is the **harvested** snake_case column
   names (the union across all RPCs, deduplicated, sorted for stability) — never a hand-written list,
   which is what makes the gate self-maintaining when a fourth RPC arrives. Match
   `.<column> as <string|number|boolean>( | null|undefined)+` over the roots `apps`, `packages` and
   `tests`, for `*.ts` and `*.svelte`, excluding `node_modules`. **Any hit is a violation**, reported
   with file:line and the matched text. The roots deliberately exclude `scripts/`, so the script
   cannot match its own alternation string — the classic self-match failure. Note in the failure
   message that a *comment* quoting the pattern counts as a hit and must be reworded, not tolerated.
5. **Override cross-check.** Every column key declared in
   `packages/supabase-types/src/database.overrides.ts` must appear in the harvested set for its RPC.
   This is belt-and-braces against the type-level constraint (which is the primary instrument) and
   catches the case where the package is somehow not typechecked.

**Two modes.** Default (no flag) = derive, run all five assertions, print a summary line naming the
three RPCs and their column counts (expect `resolve_email_variables` 4, `get_nominations` 32,
`get_candidate_user_data` 15), exit 0 or 1. `--write` = regenerate
`packages/supabase-types/RPC-NULLABILITY.md` in place and exit 0. Parse it as
`process.argv.includes('--write')` declared immediately after the `REPO_ROOT` constant. There is **no
in-repo analog** for a `--write` mode in this script family — no existing `scripts/assert-*.mjs`
reads `process.argv` — so design it explicitly and document it in the docblock.

`--write` must **never** run in CI. The gate's value is that a stale artifact is a red build, not an
auto-fixed one.
