## Observations (not threats, not counted)

1. **T-179.2-04 verification drift.** Plan 01 declared `git diff --quiet 73100378b HEAD -- apps/frontend/src/lib/auth/roles.ts` as the check that `ADMIN_GRANTS` is untouched. It exits 1 at HEAD: commit `beaa1d932` (plan 04, deviation 1) added `if (typeof token !== 'string') return undefined;` to `decodeTokenPayload` and one docstring clause, so `readSessionGrants` fails closed on a session with no access token. The grant tables and `hasAnyGrant` are byte-identical to `73100378b`, so the threat stands closed; the plan 01 SUMMARY's "unchanged since `73100378b`" was true when written. Anyone re-running the literal check should compare the two grant constants instead.
2. **Unregistered flags: none.** The four SUMMARY `## Threat Flags` sections map to the register (T-179.2-01/02, -05 to -10, -11/12/14, -15 to -17). Two surfaces the SUMMARYs do not list were read and need no new threat: `/admin/password-reset` is open to any signed-in user but returns only that user's own verified address and sets only that user's own password; the Admin login's "Forgot Password?" links carry the typed address in `?email=`, and the three new Admin routes are registered in `lib/analytics/pageviewRoutes.ts` with `NO_PARAMS`, so the query is not sent to analytics.
3. **Scope of the evidence.** The pgTAP file `39-invitations.test.sql`, the unit tests and `admin-account-flows.spec.ts` were read, not run, for this audit; the SUMMARYs record the run of record `tests/e2e-runs/179.2/179.2-final-3` (726/726).
