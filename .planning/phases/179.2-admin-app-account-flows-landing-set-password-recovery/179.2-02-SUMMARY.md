# Phase 179.2 Plan 02: The `next` contract, the Admin App's entry screens and recovery, from shared screens Summary

**An Admin App request now asks for a link that lands in the Admin App. On the wire this is a closed `app` field; the function writes `next=/admin` from a constant map, and the frontend lands it through one own-key allow-list, `MAILED_LINK_LANDINGS`. The Admin App gains forgot-password, "email sent" and password-reset pages, built from three screens it shares with the Contestant App, and a refused Admin App link lands on the Admin login. The targeted run of every leaf was green on the committed tree: 722 of 722.**

## Accomplishments

- **The wire contract (`account-access`).**
  - `contract.ts`: `LINK_APPS = ['admin']`, `LinkApp`, `isLinkApp`, and `RequestRecoveryRequest.app` (`null` when absent). Any other present value makes the body malformed.
  - `signInLink.ts`: frozen `APP_NEXT = { admin: '/admin' }`. `buildSignInLink`'s optional `app` appends `next` after `type`; with no app the link is byte for byte what it was.
  - `linkIssue.ts`: `IssueRequest.app`. A sign-in request passes `null`; a recovery request passes its `app` to both mail kinds.
  - The `index.ts` docstring is restated.
- **The writer.** `RequestPasswordRecoveryOptions.app?: 'admin'` is sent only when set. The Contestant App's body stays `{ email, locale }`.
- **The landing.**
  - `MailedLinkLanding = { home, resetPassword, login }`. `MAILED_LINK_LANDINGS` holds `/admin` (the Admin App's three routes); the frozen default is the Contestant App's three.
  - `mailedLinkLanding(next)` uses `Object.hasOwn`, so `constructor` and `__proto__` answer the default.
  - `verifyMailedLink`'s recovery arm, failed claim and final failure read the entry. `safeRedirectTarget`, `localizeAppPath` and `landingRoute` are gone from the module. `email_change` failures stay with the Contestant App.
  - The confirm page's load and action, and the callback, read `next` through the same table before they refuse a link.
  - `isAdminOnly` (`$lib/auth/homeApp.ts`, exported from `$lib/auth`) decides the confirm page's Cancel.
- **The entry flow.**
  - `$lib/contestant/entryFlow` was moved with `git mv` to `$lib/auth/entryFlow`, and every importer was rewritten (frontend and tests).
  - `EntryFlowHolder` carries the contestant context's rules verbatim: the bounded wait, `askedAgain` decided before the request, the held code kept beside a request made with it, `resend` and `clear`.
  - The contestant context forwards its four functions to its holder. The admin context holds one whose request asks `requestPasswordRecovery({ email, locale, app: 'admin' })` for the forgot-password origin and nothing else. `logout` clears it after a sign-out that worked.
- **Shared screens.** `ForgotPasswordScreen`, `EmailSentScreen` and `PasswordResetScreen` live in `$lib/dynamic-components/accountScreens`, each with its type, component test and docstring. The Contestant App's three pages render them with the same test ids and keys as before.
- **The Admin App.**
  - New routes `AdminAppForgotPassword`, `AdminAppEmailSent` and `AdminAppResetPassword`, each with a page (and the reset page's session-checked server load), added to `PAGEVIEW_ROUTES`.
  - The login gains two `Button` links under the submit, with the labels `contestantApp.login.forgotPassword` and `contestantApp.login.noPasswordYet` (`admin-login-forgot-password`, `admin-login-no-password-yet`). They carry the typed address.
  - `LoginError` gains `'authError'` → `adminApp.login.errors.linkFailed`, in seven locales. The direct `locals.supabase.auth` reads under `routes/admin` stay one, the login action's.
- **Docs.** `login-and-password-reset` (the landing table by `next`, Recovery in the Admin App), `backend/edge-functions` (the optional `app`) and `admin-app` (Login and Protected pages). The generated component and route pages are regenerated, and `validate:links` exits 0.
- **E2E (`admin-account-flows`).**
  - Helpers: `requestRecovery`, `invitationFlow.askForRecovery`, and a `next` option on `assertSignInLinkShape`, `signInLinkToOpen` and `recoveryLinkToOpen`.
  - Fixtures: the Contestant App's forgot-password, email-sent and password-reset fixtures take an optional `{ route, container }`. The spec's fixture module exposes the Admin App's instances, and `adminLoginPage` gains four steps.
  - Tests: four new journeys and five scanned screens (10 scan tests), registered in check 4a of `assert-a11y-scan-wiring.mjs`.
