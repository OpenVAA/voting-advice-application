## Accomplishments

- `$lib/auth/gates`: `firstNeededGate(facts, gates)`, which has no default list, the frozen `SET_PASSWORD_GATE`, `Gate` and `UserGateFacts`. `ADMIN_GATES = [SET_PASSWORD_GATE]`. `CONTESTANT_GATES = [SET_PASSWORD_GATE, identityProvider, termsOfUse]` runs on the shared runner, and the set-password predicate now exists only in `$lib/auth/gates/gates.ts`.
- `routes/admin/(protected)/+layout.server.ts` decides four things in order:
  - **Session:** with no session it redirects to the login with `loginFailed`.
  - **Admission:** a user whose session holds no `ADMIN_GRANTS` match gets `{ admitted: false }`, before anything is read.
  - **User-level data:** a failed read signs nobody out. With no session left it redirects to the login with `loginFailed`; with one left it answers a 503.
  - **Gate:** `firstNeededGate({ user }, ADMIN_GATES)`.

  It reads no `url`, `route` or `params` and returns no session. The universal load signs out a user who was not admitted. It uses the server's user during server rendering and reads it again with the tab's own client in the browser, then passes `gate` on.
- `SetPasswordGate` and `GateOutlet` (which holds the focus move that used to be in the contestant layout) live under `$lib/dynamic-components/gates`. Both protected layouts render the outlet. `ContestantSetPasswordGate` and `AdminSetPasswordGate` are the thin wrappers, with root test ids `contestant-set-password-gate` (unchanged) and `admin-set-password-gate`.
- Moved:
  - `passwordSetter`, `passwordValidator`, `emailField` and `emailEntry` to `$lib/components`.
  - `emailSentPanel` and `contactSupport` to `$lib/dynamic-components`.

  Nothing remains at the old paths, and no file imports from them. `ContactSupport` reads the app context; outside the Contestant App it always leads to an email.
- One `LogoutButton` takes `logout`, an optional `redirectTo`, an optional `warning` and `logoutModalTimer`, and reads no app context. The Contestant App passes `contestantLogoutWarning(contestantCtx)`; the Admin App passes `redirectTo="AdminAppLogin"`. `Banner.svelte` imports it once. `NothingToEdit`, `ReadFailure`, the entity home and the shared set-password view render it, and every test id is unchanged.
- New leaf project `admin-account-flows`, with spec, fixtures, `testIds.admin`, `ADMIN_ACCOUNT_FLOWS_ADDRESS_PREFIX`, and its name in `data-setup-perm-1e1cg1co`'s dependencies.
- Instruments: `179.2-totals.mjs` (exits 0 on the baseline, 1 on a planted `+1` row and 2 on an unreadable file), the ledger (rows `179.2-01-1` to `-10`, all `confirmed`) and the deltas table.
