## Shared Patterns

### Grant-shape checks (apply to the confirm page, both protected server loads, the admin universal load)
**Source:** `apps/frontend/src/lib/auth/roles.ts` via the `$lib/auth` barrel: `ADMIN_GRANTS`, `CONTESTANT_GRANTS`, `hasAnyGrant`, `readSessionGrants`. Never compare `role` strings or write new shape arrays. `isAdminOnly` is declared once.

### Context reads (apply to every moved or new `.svelte` and context file)
Destructure stable refs only (`getRoute`, `t`, `sendEntryLink`, `setPassword`, `logout`). Read `ctx.appSettings`, `ctx.entryFlow` and `ctx.user` inside `$derived`/markup. The pattern comment used across the analogs: "Stable references are destructured. `appSettings` is a reactive accessor, read as `contestantCtx.appSettings` inside its tracking scope: see CLAUDE.md "Context Destructuring Rule"."

### Page save/submit shape (apply to the admin password-reset page and the shared SetPasswordGate)
`status = $state<'idle' | 'saving' | 'failed'>('idle')`, `mounted` via `onMount`, a submit `Button` outside the form with `form={formId}`, and `ErrorMessage inline role="alert"` on failure. See `routes/contestant/password-reset/+page.svelte`.

### Server redirects
Always `buildRoute({ route: <RouteKey>, locale, errorMessage? })`. A server load never returns `session`.

### Component docstrings / hygiene
`<!--@component ... -->` blocks with `### Properties`, `### Accessibility` and `### Usage` (as in `SetPasswordGate.svelte`). Keep no "moved from" narrative in moved files.

### i18n
New strings under `adminApp.*` in an existing file (e.g. `messages/<locale>/adminApp.login.json`) in all 7 locales, flagged for native review. Reuse the neutral `contestantApp.setPassword.*`, `contestantApp.emailSent.*` and `contestantApp.login.forgotPassword` keys.
