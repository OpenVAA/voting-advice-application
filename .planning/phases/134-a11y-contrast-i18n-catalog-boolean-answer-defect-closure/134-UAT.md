## Tests

### 1. Native-speaker review of the six constructed non-English `selectExact` singular forms (D-18)

steps: |
  This is a language review, not a click-through. Read the six non-English singular strings
  below and judge each as a native (or fluent) speaker of that locale. Every string is quoted
  verbatim from `apps/frontend/messages/{locale}/questions.json` as it actually shipped in
  commit `3b098a22e` — not as the plan predicted it — so what you read here is what a user sees.

  The key is `questions.multiChoice.selectExact`. It is an MF2 plural declaration
  (`input count`, `local countPlural = count: plural`) with a `countPlural=one` branch and a
  `countPlural=other` branch. Only the `one` branch is under review; the `other` branch is
  pre-existing, natively authored text, shown here purely as the register/wording baseline the
  singular should match.

  | Locale | Singular (`countPlural=one`) — UNDER REVIEW | Plural (`countPlural=other`) — pre-existing baseline | Rendered at count=2 |
  | --- | --- | --- | --- |
  | `da` | `Vælg 1 mulighed.` | `Vælg {count} muligheder.` | `Vælg 2 muligheder.` |
  | `et` | `Vali 1 valik.` | `Vali {count} valikut.` | `Vali 2 valikut.` |
  | `fi` | `Valitse 1 vaihtoehto.` | `Valitse {count} vaihtoehtoa.` | `Valitse 2 vaihtoehtoa.` |
  | `fr` | `Sélectionnez 1 option.` | `Sélectionnez {count} options.` | `Sélectionnez 2 options.` |
  | `lb` | `Wielt 1 Optioun.` | `Wielt {count} Optiounen.` | `Wielt 2 Optiounen.` |
  | `sv` | `Välj 1 alternativ.` | `Välj {count} alternativ.` | `Välj 2 alternativ.` |

  `en` (`Select 1 option.` / `Select 2 options.`) is NOT under review — it was authored, not
  constructed, and is HIGH confidence.

  **Read this before flagging `sv` as a bug.** `Välj 1 alternativ.` and `Välj 2 alternativ.` are
  byte-identical apart from the numeral, which looks exactly like a copy-paste error. It is not:
  Swedish *alternativ* is invariant between singular and plural (ett alternativ / två alternativ),
  so the singular branch legitimately differs only in the count. Confirm rather than assume — but
  the identical pair is expected, not a defect.

  **To see the string in a running app** (optional — the table above is sufficient to review the
  wording): the helper renders only when a multi-choice opinion question's *effective minimum
  equals its effective maximum* (`QuestionChoices.svelte:420-421`), i.e. a "pick exactly N"
  constraint. The seeded `e2e/base` multi-choice question carries a 2..3 window, so it renders
  `selectRange` instead — walking the seeded voter or candidate journey will NOT show you this
  string. You would need to author (or seed) a question with `min === max === 1` and open it with
  the locale switched. That is why this item cannot be discharged by clicking through the app,
  and why no E2E spec covers the singular branch.

expected: |
  Each of the six singular strings is grammatically correct and idiomatic in its locale, uses the
  same register and imperative form as the pre-existing plural baseline beside it, and applies the
  correct singular case/inflection for the noun after the numeral 1 (this is where a constructed
  form is most likely to be wrong — e.g. Finnish partitive vs. nominative, Estonian partitive,
  Luxembourgish noun form).

  A reviewer finding any string wrong should supply the corrected text for that locale; the fix is
  a one-line edit to the `countPlural=one` value in
  `apps/frontend/messages/{locale}/questions.json`, with no code change and no catalog-shape
  change. The `countPlural=other` values must not be touched — they are natively authored and
  mirror `src/lib/i18n/translations/`, which the key-set parity check compares against.

why_human: |
  These six strings were CONSTRUCTED by an agent from the existing plural strings. No singular
  form of this message existed anywhere in the repo to copy — `src/lib/i18n/translations/` carries
  only the plain `Select {count} options.` shape, which is why the pre-fix app rendered
  "Select 1 options." for a pick-exactly-1 question in the first place. Confidence in the six
  non-English singulars is MEDIUM, and the operator accepted them landing in-tree on the explicit
  condition (D-18) that a native speaker reviews them before milestone close.

  No automated check can assess grammaticality. The build-time render proof in Plan 03 confirms
  the correct *branch* is selected and that no locale falls through to its raw key path — it says
  nothing about whether the words are right. Prettier, the key-set parity check, svelte-check and
  the E2E suite are all equally blind to this: a grammatically wrong but well-formed string passes
  every one of them.
