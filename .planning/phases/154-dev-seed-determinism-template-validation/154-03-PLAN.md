<objective>
Make the determinism contract true: replace both wall-clock reads with generation from one fixed,
resolved reference window, and invert the wave-1 negative controls into the committed cross-time
stability guard.

This is the phase's ⚠ DECIDE, already settled by D-C1: a single exported `SEED_REF_DATE` constant,
overridable per template, with both consuming sites reading ONE resolved value rather than re-reading
the template. The rejected shapes are not reopened here — deriving the date from the numeric seed,
requiring every template to declare it, and a fixed date with no override were each rejected with a
recorded reason.

**This plan MUST NOT start before plan 01 has run and recorded the negative control.** That is the
ordering invariant of criterion 2 and the reason `154-01` is an explicit `depends_on` edge rather
than an implicit one. `154-02` is also a dependency because both plans edit
`packages/dev-seed/tests/template.test.ts`.

Purpose: turn four written determinism claims from false-across-days into true.
Output: the fixed reference window through every layer, the guard committed, the docs moved with the
code.

**The leading task is a tracer:** it wires the reference window end-to-end through every layer this
phase modifies — template type declaration, strict schema validation, run-context resolution,
generator consumption, emitted row — for ONE of the two date sites. Proving that whole path on one
site before expanding to the second is what turns an architectural dead end into a one-commit
discovery. The expansion task then adds the second site, and the third task adds the public surface
and the docs.
</objective>

<assumption_delta_decision>
**Detector signal disposition.** The deterministic detector fired on a `pluralization` signal for the
term `second`, from the phrase `second pass` in the roadmap entry. That signal is a **FALSE POSITIVE**
— `second pass` is editorial prose describing a roadmap correction round, not an architectural
pluralization of any noun. No plural-carrier decision is owed for it.

**There IS a genuine adjacent transition in this phase, of the `chosen` family, and it is recorded
here.**

- **Noun that becomes primary:** the *resolved reference date carried on the seed context* —
  `Ctx.refDate: Date`, resolved once per pipeline run in `buildCtx`. Before this phase the primary
  carrier of "when is now" was an implicit read of the system clock performed independently inside
  each faker call. After it, the primary is one explicit resolved value that both call sites read.
- **Decision: `promote`.** The explicit resolved reference date is promoted to the sole primary, and
  the wall-clock read is eliminated entirely. There is no surviving `now` fallback anywhere on the
  path: `Ctx.refDate` is declared REQUIRED rather than optional precisely so that no consumer can
  reach a `?? new Date()` shape, and no call to `faker.date` in the package source remains without a
  reference date.
- **Rationale:** an `add-alongside` — keeping a live wall-clock fallback next to the new field — would
  silently reopen the drift the moment any consumer took the fallback branch, and the determinism
  claim would again be true only by inspection rather than by construction. Promotion is what makes
  the claim structurally true, and it is what the "one resolved value, not a re-read of the template
  at each site" wording of the locked decision requires.
- **Accepted debt:** none, because this is not an `add-alongside`. The only residual is the
  discretionary literal value of the constant, which is reversible and additive.

Advisory and non-blocking — this block informs and records; it does not gate the phase.
</assumption_delta_decision>
