<objective>
Fix invite-candidate end to end: decode JWT segments as base64url on the admin-authorisation path, and
fail loudly when `SITE_URL` is unset instead of silently addressing invite links at the wrong host.

Purpose: REVIEW-EDGE-01's decode feeds `isAdmin`, so a decode failure is an authorisation failure, and
REVIEW-EDGE-02's seventh site is the one no review comment named and the one CONTEXT calls arguably the
worst of the seven. This plan also establishes the CANONICAL text of the two modules the other two Edge
Functions copy, because Supabase treats each top-level function directory as its own deployment unit and
this repository has no shared directory convention.

Output: `jwtSegment.ts` and `envConfig.ts` with their tests, and an `invite-candidate/index.ts` that uses
both.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller-supplied `Authorization` bearer token to `invite-candidate` | The token's decoded `user_roles` claim drives the `isAdmin` predicate that authorises candidate invitation. |
| Edge Function to Supabase auth admin API | `inviteUserByEmail` is called with a `redirectTo` built from configuration. |
| operator configuration to Edge Function runtime | `SITE_URL` decides which origin an invited candidate is sent to. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-155-07 | Denial of Service | JWT segment decode at `invite-candidate/index.ts:81` | medium | mitigate | Task 1 replaces the base64 decode with a base64url decode, so a token whose payload happens to contain a base64url-only character no longer turns an authorisation check into an opaque 500. |
| T-155-08 | Elevation of Privilege | the `isAdmin` predicate fed by that decode | high | mitigate | Same fix. The decode is on the authorisation path, so its correctness is an access-control property, not a cosmetic one; the permanent negative control in the suite is what keeps it correct. |
| T-155-09 | Spoofing | invite `redirectTo` built from an unset `SITE_URL` | high | mitigate | Task 2 throws naming `SITE_URL`. Previously an unset variable addressed the invite link at the Supabase API origin, which is a link a recipient may follow to an origin the operator did not intend. |
| T-155-10 | Information Disclosure | the new throw message | low | mitigate | The message names only the variable; the existing catch returns a fixed opaque response, so the name does not reach the caller. |
| T-155-11 | Tampering | non-UTF-8 claim values mis-decoded into a role comparison | low | mitigate | The `TextDecoder` step makes the decoded payload the bytes the issuer signed rather than their latin1 reinterpretation. |
| T-155-SC | Tampering | package installs | high | mitigate | This plan installs nothing. `155-RESEARCH.md` section Package Legitimacy Audit records that the phase adds no external package; no `[ASSUMED]` or `[SUS]` entry exists, so no legitimacy checkpoint is required. |
