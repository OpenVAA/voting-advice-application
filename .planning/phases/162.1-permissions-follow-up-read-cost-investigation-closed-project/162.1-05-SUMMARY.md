## Accomplishments

- `openForVoters?: boolean` is declared in both `Template` and `TemplateSchema`, so `TEMPLATE_KEYS_MATCH_SCHEMA` holds. Both carry JSDoc.
- `SupabaseAdminClient.setProjectOpenForVoters(open, projectId?)` updates that one column. It never creates a project row, and on failure it throws an error prefixed `setProjectOpenForVoters`.
- Writer `write(rows, prefix, { openForVoters })` has a new Pass 7 that runs after every other pass, and only when the value is defined. The class docblock now says dev-seed never *creates* `projects` rows.
- `perm-closed-project` is built on `buildMinimal`: 1 candidate, 1 opinion question and `access.voterApp: true`. It is registered in `BUILT_IN_TEMPLATES`, and the README documents it with the default-project caveat.
- Both writer callers pass the template's value: `cli/seed.ts` and the E2E `setupFromTemplate.ts`.
- The teardown CLI calls `runTeardown(prefix, client, { reopenProject: true })`. Step 4 reopens the project after storage cleanup. `TEARDOWN_USAGE` and the README describe this.
- Live checks:
  - The seed printed `f`.
  - Seeding then tearing down printed `t`, and the CLI reported "Project reopened to voters".
- Gates: `yarn typecheck`, `yarn lint:check`, `yarn format:check` and `yarn test:unit` all exit 0. The full E2E suite passed 158/158, with 0 unexpected, flaky or skipped.
