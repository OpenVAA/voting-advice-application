## Implementation Decisions

### Item 1: the grant model's read cost

- **D-01 — Residual (a) is FIXED by reordering the five authenticated SELECT policy quals to variant B** (the `authenticated_select_*` policies)
  (operator, 2026-09-18): `user_can(project, …)` first, then the table's public assembly (the anon qual,
  verbatim), then the entity `user_can` disjuncts in their current order. Tables: `candidates`,
  `organizations`, `factions`, `alliances`, `nominations`. Operator's reason: *"the all nominations route is
  not important and even less so for logged in candidates. Admins may however more often need that data."*
  Expected effect (spike 028, municipal scale): candidate whole-project 7.15 s → 4.65 s, admin unchanged
  1.30 s, no-grant 4.3–4.8 s → 3.8 s. **Only the order changes**: no conjunct, function or table.
- **D-02 — The reorder's correctness gate is spike 028's instrument**, run against the committed schema:
  visible sets `EXCEPT ALL` in both directions and the 2,120-probe truth grid, all 0
  (`.planning/spikes/028-disjunct-order-fix/run.sh` with `VARIANT=B_project_public_entity`). The pgTAP estate
  must stay green, and 162-17's guard perturbations G8A and G8B must still redden on exactly their recorded
  assertions (spike 028 `perturb.sh`). ROADMAP criteria 3 and 4 of Item 1.
- **D-03 — A timing monitor lands with the fix**, so a future edit that puts the project check or the
  public check out of order shows up as a number. Form is planner's discretion (pgTAP structural assertion on
  disjunct order, and/or a trimmed spike-026 timing cell). It must be **observed red** on the shipped order
  (or on variant A) before it is accepted.
- **D-04 — Residual (b), the anon storage read at 6.4x, is ACCEPTED** (spike 027): `public-assets` is a public
  bucket, downloads never evaluate `storage.objects` RLS, and only anon `list` pays the cost, which no code
  calls. The acceptance is recorded in the schema comment beside `storage_path_is_public`, with the coupling:
  **if the bucket ever becomes private, (b) becomes hot and must be re-measured.**

### Item 2: a project that is not open for voters

  `$layouts/main` is already used by `routes/(voters)/+layout.svelte` with
  `dynamic.voterAppNotAccessible.{title,content}`. The closed-project state renders that page (or the same

  explicit "project not open" branch that reaches D-05's page. Static settings stay usable (name, colors,
  fonts) since dynamic settings are unreadable in that state. ROADMAP Item 2 criteria 3–4.
- **D-21 (formerly D-06a) — Reachability and proof** (ROADMAP Item 2 criteria 1, 2, 5, unchanged): a **new** dev-seed template
  with a project `open_for_voters = false` (the existing templates stay open); an E2E spec visiting the voter
  app against it, **observed red first** on today's tree; pgTAP coverage for the closed state on
  `app_settings`, `elections` and `questions`. Discharges `WINDOWS.md` 268.
  **Amended after research:** anon closed-state reads of those three tables are already asserted
  (`16-anon-visibility.test.sql` Section 5, closed `project_b`); the new pgTAP coverage targets the gaps: the
  `get_questions` / `get_nominations` RPCs on a closed project, grant-holder reads on a closed project (D-17), and
  anon's EXECUTE on `project_open_for_voters`. The E2E spec runs as a terminal Playwright node (it closes the
  suite's one served project), per RESEARCH.

### F1 follow-up: adapter auto-pagination (spike 030)

- **D-07 — Every multi-row read in `supabaseDataProvider.ts` goes through one paging helper**: `elections`,
  `constituency_groups`, `constituencies`, the `get_nominations` RPC (inside its election × constituency
  fan-out), and the `candidates`/`organizations` reads in `getEntityData`. Not paged: `get_questions` (one
  aggregated row) and the `app_settings` single reads.
- **D-08 — Every paged table read sorts on a unique key**: add `id` as the tie-breaker after `sort_order`.
  Spike 030 measured `order('sort_order')` alone losing 768 of 36,056 rows to duplicates across pages.
  `get_nominations` already orders `sort_order NULLS LAST, id`.
- **D-09 — Last-page detection is spike 030 option (c)** (operator: recommended option). The page size is one
  static setting, **50000**, equal to `config.toml`'s `max_rows`. A page shorter than requested ends the
  read, **except** when its length is a non-zero multiple of 1,000: then issue one confirming request at the
  next offset and log a console warning naming a probable server `max_rows` below the configured page size.
  Unit tests cover: single page; exact multiple of the page size; the suspicious-short-page path; an
  empty result; an error mid-read.

### F4/F3 follow-up: storage cleanup and the leak policy (spike 029)

- **D-10 — Policy C1+** (operator: recommended option): keep random UUID file names (already the status quo in
  `supabaseDataWriter.#uploadCandidateFile`), fix cleanup, and accept that a file which was public stays
  reachable by its URL after unpublishing (spike 029 S2). Record the acceptance in the storage schema's
  comments.
- **D-11 — Fix `public.delete_storage_object`**: it POSTs to the bulk route, which only accepts `DELETE`
  (pg_net logs `404 Route POST:/object/public-assets not found`), and pg_net 0.14's `http_delete` takes no
  body. Delete **one object per call** via `net.http_delete` on `/storage/v1/object/{bucket}/{path}`
  (verified in spike 029: `200 Successfully deleted`).
- **D-12 — Fix folder cleanup** in `cleanup_entity_storage_files`: Storage does not expand prefixes, so
  enumerate `storage.objects WHERE bucket_id = … AND name LIKE prefix || '%'` and delete each object.
- **D-13 — Cleanup for photos stored in `answers`** (spike 029 S4): when a candidate/organization answer's
  image path is replaced or removed, the old object is deleted, like `cleanup_old_image_file` does for `image`.
- **D-14 — The fix is proven by observing files disappear**, not by the trigger firing: a test that replaces
  an image, replaces an answer image, and deletes an entity, then asserts the old objects are gone
  (`storage.objects` row absent and/or HTTP 4xx). Its absence is how F4 went unnoticed from `11f877913`
  (2026-08-17) until now. The test must be observed red on today's tree.
- **D-15 — dev-seed portraits use random UUID names** too (`packages/dev-seed/src/supabaseAdminClient.ts`
  `uploadPortrait`), so seed data follows the convention it demonstrates. Teardown must still find them (it
  lists folders).

### Added after research (operator answers, 2026-09-18)

- **D-16 — Corrected premise for D-06: a closed project breaks EVERY route, including both login pages.**
  Research (162.1-RESEARCH.md) found `_getAppSettings` already maps PostgREST `PGRST116` to `{}`. The failure is
  the root `+layout.svelte` validity check (`isValidResult(data.electionData)` without `allowEmpty`), which
  renders `ErrorMessage` for `/en`, voter routes, `/en/candidate/login` and `/en/admin/login`. **The candidate
  and admin apps must keep working on a closed project** (candidates answer before a project opens). The plan
  reproduces this red first before fixing it.
- **D-17 — Grant holders see the real voter app on a closed project** (operator: recommended option). Anon
  sees `MaintenancePage` with `dynamic.voterAppNotAccessible`. A signed-in caller whose grants let RLS return
  the project's data gets the normal app (a preview). The state is decided on data the caller can actually
  read, not on a client-side role check.
- **D-18 — No orphan sweep** (operator). The fixed triggers act on future changes only. Orphans left since
  `11f877913` stay; recorded as a known residue in the storage schema comment and SUMMARY.
- **D-19 — dev-seed teardown reopens** a project the closed-project template closed (`open_for_voters =
  true`) (operator: recommended option).
- **D-20 — D-11/D-12 must not trust stored paths** (research: a live pg_net probe showed `..` segments are
  resolved before sending and the query string survives, so a crafted path left the Storage object namespace).
  Delete only paths that (a) match a strict whitelist of the upload convention
  `<project_uuid>/<table>/<entity_uuid>/<uuid>.<allowed_ext>` (dev-seed may use its own filenames under the
  same folder, and D-15 moves them to UUIDs), (b) lie inside the row's own folder, and (c) are no longer
  referenced by the new row. pgTAP proves crafted paths (`..`, `?`, `#`, `%`, another project's or entity's
  folder) enqueue **no** request.
