# Phase 162.1 Plan 06: UUID-Named Seed Portraits Summary

**dev-seed now uploads each portrait as `<project>/candidates/<candidate>/<random uuid>.jpg`, the same naming the app's own uploads use. Teardown still removes every portrait. A re-seed over an existing seed keeps exactly the current portraits: every one survives, and the storage cleanup deletes every superseded one within about a second.**

## Performance

- **Duration:** 19 min (2026-09-18T20:51:05Z to 21:10:25Z). The full E2E suite took 10.7 min of that.
- **Tasks:** 2 (a TDD tracer, then the re-seed proof, README and gates)
- **Files modified:** 7 source/test/docs files plus 4 evidence files

## Accomplishments

- `Writer.uploadPortraits` passes `` `${crypto.randomUUID()}.jpg` `` to `uploadPortrait`. The old literal filename is gone from `packages/dev-seed`; `git grep` finds it only in the pgTAP case that uses it as a deliberately non-UUID name.
- The docblocks of `uploadPortraits`, `uploadPortrait` and `listCandidatePortraitPaths` give the reasons for the change: the cleanup trigger only deletes UUID object names (D-20), and a fixed name can be guessed. They also state that the listing does not depend on file names.
- Tests:
  - The writer test checks the UUID pattern and the path built from it, and a new case checks that two candidates get different names.
  - The admin-client and teardown fixtures now use UUID-shaped names.
  - The integration helper's docblock describes the new naming.
- **Live tracer:** `yarn db:reset-with-data` wrote 327 portrait objects, all named `<uuid>.jpg` (the check returned `0/true`). `yarn db:seed:teardown` removed all 327 and left 0 objects under the default project's candidate folders.
- **Re-seed proof (D-15 x D-11):** the plan's chained command passed:
  - It runs `yarn db:reset-with-data` then `yarn db:seed:default`, and the poll converged after 1 s (0 missing current portraits, 0 unreferenced objects).
  - `yarn db:reset` then exited 0.
  - In an earlier exploratory run, 378 objects existed just after the second seed. The first poll, 11 s later, found 327, one per candidate `image.path`.
- The README says that portraits have random names, that teardown does not depend on the names, and that a re-seed replaces each portrait while the cleanup deletes the old one. It also says the seed-42 determinism claim does not cover `image.path`.
- Gates: `yarn typecheck`, `yarn lint:check`, `yarn format:check` and `yarn test:unit` all exit 0 (dev-seed 795/795, frontend 1665/1665). The full E2E suite passed 158/158 with 0 unexpected, 0 flaky and 0 skipped.
