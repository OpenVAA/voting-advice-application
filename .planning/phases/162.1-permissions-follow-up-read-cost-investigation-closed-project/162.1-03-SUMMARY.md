# Phase 162.1 Plan 03: Folder and answer-photo storage cleanup Summary

**Deleting an entity now deletes every whitelisted object in its own folder, because the trigger lists the folder from `storage.objects` with `starts_with` and sends one single-object DELETE per name. A new `cleanup_old_answer_files` trigger on `candidates` and `organizations` deletes answer photos a row no longer references, including after a question-delete cascade strip. Both disappearances were watched red in committed state before their fix and green after.**

## Accomplishments

- **D-12:** `cleanup_entity_storage_files` loops over both buckets. For each, it runs `SELECT o.name FROM storage.objects o WHERE o.bucket_id = bucket AND starts_with(o.name, path_prefix)` and calls `PERFORM public.delete_storage_object(bucket, object_name)` once per name. The ten `cleanup_storage_on_delete` triggers are unchanged. The prefix WARNING that 162.1-02 left behind no longer fires.
- **D-13:** `cleanup_old_answer_files` returns early when `answers` is unchanged. Otherwise it takes the old paths from `referenced_storage_paths(jsonb_build_object('answers', OLD.answers))`. It deletes only paths that start with the row's own folder and are not in `referenced_storage_paths(to_jsonb(NEW))`. It never reads `questions`.
- **D-14 complete:** the `storage-cleanup` project now covers image replace (from 162.1-02), entity delete and answer-image replace.
- **D-20 preserved:** every delete still goes through `delete_storage_object`'s bucket check and whitelist. No second URL-building path exists.
- **Docs:** `SKILL.md` (§ 8 trigger conventions, Service Patterns § 4, Freshness Record) and `rls-policy-map.md` (coverage row) are updated. The `04-admin-crud.test.sql` header note is corrected; no assertion was touched.
