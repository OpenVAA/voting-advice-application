host, including a hosted project left at Supabase's default 1,000.

Facts (verified in `node_modules/@supabase/postgrest-js` 2.99.3 by research):
- `.range(from, to)` sets the `offset` / `limit` URL params (overwriting), `.order()` APPENDS columns (`order=sort_order.asc,id.asc`), and an RPC builder (`this.supabase.rpc(...)`) is a filter builder that also supports `.range()`.
- The client-side provider is the Supabase one unconditionally (`apps/frontend/src/lib/api/dataProvider.ts`), whatever `staticSettings.dataAdapter.type` names; the server-side local adapter is separate. The page size is therefore declared on BOTH `dataAdapter` variants through one shared field, so it is readable without narrowing and a `local` configuration cannot make the client provider throw.
- `import { log, staticSettings } from '@openvaa/app-shared'` is the frontend idiom; `log.warn(message, fields)` exists (`packages/app-shared/src/logging/logger.ts`).
- The provider test's `createMockSupabaseClient` chain has `select/limit/order/eq/in/single` + a thenable; `rpc` returns a bare Promise (no `.range`).
- Frontend unit tests consume the BUILT `@openvaa/app-shared`; build it before running them after a settings change: `yarn build --filter=@openvaa/app-shared`.
