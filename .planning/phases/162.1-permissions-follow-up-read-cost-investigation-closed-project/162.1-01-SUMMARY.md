**2. [Rule 1 - Bug] Post-navigation focus reset was one-shot and missed a heading rendered after the first frame**
- **Found during:** Task 3's full E2E gate. Run `tests/e2e-runs/162.1-01` gave 154 passed and 1 failed: `a11y-smoke` "navigation-a11y — focus lands on heading after Q→Q nav", with load 46.7 at start. The same test failed in `162-14-wave5`, which left it open after a green re-run.
- **Issue:** the root layout ran `querySelector('[data-focus-on-nav]') ?? querySelector('h1')` once, in the first rAF after `afterNavigate`. The voter question heading is not in the SSR HTML (`DCL fon=false h1=false`) and renders client-side after an async gap (lazily imported icon modules), so if a frame paints first, nothing is ever focused. This is a real WCAG defect on slow devices, not only a test race. It predates this plan and is unrelated to the RLS reorder: the voter path is anon, and only the authenticated quals changed.
- **Diagnosis (confirmed, not assumed):** an instrumented, never-committed copy of the spec recorded focus, rAF and DOM timelines. (a) Delaying only the icon-module fetches by 1.5 s reproduced the red: the rAF ran at 392 ms with no heading, the heading rendered at 398 ms, `focus()` was never called, and focus stayed on BODY. (b) A deterministic A/B detached the heading on first render and re-inserted it 500 ms later: the one-shot layout failed the spec with focus on BODY, and the fixed layout focused the heading the instant it was re-inserted. Delaying REST alone, 20x CPU throttling, and zero-delay rAF did not reproduce it, which narrowed the gap to the async module loads.
- **Fix:** `focusNavigationTarget()` focuses immediately if the target exists. Otherwise it waits with a MutationObserver, bounded by 10 s. Each navigation cancels the previous wait, and the wait is abandoned if focus moves in the meantime, so it never takes focus back from the user. `preventScroll: true` is kept.
- **Verification:** 6 unit cases, with the late-render case flip-tested red against the one-shot form. typecheck, lint:check, format:check and test:unit exit 0. Full E2E `tests/e2e-runs/162.1-01-run02` gave 155 passed, 0 unexpected, 0 flaky and 0 skipped, with load 57.3 at start.
- **Files modified:** `apps/frontend/src/lib/utils/focusNavigationTarget.ts`, `.test.ts`, `apps/frontend/src/routes/+layout.svelte`
- **Committed in:** `fd7d0a246`
