## Rulings and deviations carried by this plan

1. **The reads are made on the fixed tree, with the class taken away in the page for the comparison.** The
   research added a rule to the unfixed page; this plan removes the class from the fixed one. The two states
   differ by that class alone, which is also all that differs between the trees (plan 01's fix commit touched
   one line of one file), so one session on one tree gives both sides.
2. **The read session starts its own dev server**, on the project the suite seeds, as `tests/README.md`
   § *Run* describes for a session outside the wrapper, and runs three of the suite's setup projects with
   `--no-deps`. It is the research's own method. It restarts no stack and resets no database. It is one
   command with one teardown, so that no path out of it leaves the server or the dataset behind.
3. **The read session accepts the terms as the suite's pending user** — settled by the orchestrator
   (2026-10-07). It does so twice, once on each path, in a session nothing else runs beside; `auth-setup`
   registers that user anew, without an acceptance, between the two and at the start of every later run.
4. **Focus in a browser is read for one outcome and the control.** The pending user edits one entity, so the
   stored session reaches an entity page by its URL (a rerun, no navigation) and the root (a redirect). The
   selection screen and the "nothing to edit" view need a pending user with several entities or none, which
   only the service role can make; plan 01's component cases show those two with the real views mounted. That
   those two stay at component level is settled by the orchestrator (2026-10-07): the operator ruled one E2E
   check.
5. **The reads' tolerance is half a pixel, and that is the intended strictness** — settled by the
   orchestrator (2026-10-07). A host that renders the view differently produces a finding to report, not a
   relation to loosen: "in Finnish nothing moves" and "half of the label's growth" are asserted as written.
6. **The registration page is checked on a reconstruction.** The real page needs the identity-provider flow,
   which the default suite does not set up and which no file of this phase touches. The reconstruction is
   repeated with the real class, its control is the same page with the class removed, and the residue is filed.
7. **A read session is void on a host Sleep entry inside its window, with no marker of the wrapper's.** It
   is the one place in the phase where a later attempt is licensed without `VOID-host-suspend.txt`: the reads
   do not go through `tests/scripts/e2e-run.sh`, so its heartbeat never sees them, and the session's own
   record of the host's power log is the only evidence a suspend leaves. The session writes that record as a
   marker of its own, and nothing but a Sleep entry voids it.
8. **Bank-auth is not run** (PROH-174.1-05): `174.1-verdict.mjs scope --complete` shows that no auth,
   function or schema file changed.
9. **The faint border of the unticked checkbox at 1280px, which the research saw and did not measure, is not
   filed**: nobody has confirmed it. The summary says so.
