## WR-03: every `.label` wraps by the project's own rule

**Verified.** DaisyUI 5.7.46's `.label` sets `white-space: nowrap`. Four components patched it with `whitespace-normal` (`TermsOfUseForm`, `TrackingOptOut`, `ElectionSelector`, the `Input` row label in `input/shared.ts`); the labels of `EnumeratedEntityFilter`, `NumericEntityFilter` and the admin `LanguageSelector` did not wrap.

**Decision check.** D-05 chose wrapping at every width for the consent sentence and D-03 put the fix in the component that forces the width. Moving the wrap into the project's own `.label` rule keeps D-05's outcome for the consent label and extends it to every label; it does not reverse either decision, and the operator's choice of "wrap everywhere" over a breakpoint is unchanged.

**Red** (8636a4da8): the new `src/lib/components/labelWrap.test.ts`: **exit 1**, 2 of 2 failed. The `.label` rule of `app.css` sets no `white-space`, and four components carry `whitespace-normal` beside `label`.

**Fix** (03ff63060): `app.css`'s `.label` rule, which already cancels DaisyUI's colour mute in the same un-sublayered `utilities` block, sets `white-space: normal`, with the WCAG reason beside it. The four per-site utilities and their comments are removed. `Input.labelWrap.svelte.test.ts` now asserts that every in-row label carries `label` and no one-line or word-breaking utility, and names `labelWrap.test.ts` for the rule.

**Green:** vitest over `src/lib/components` and `src/lib/contestant/components`: **exit 0**, 453 passed. The phone-width specs and the visual-regression spec run in the E2E close.

**Not added:** a phone-width overflow check of the voter filter options. No E2E dataset holds a party or candidate name long enough to overflow a 9rem cell, so such a check would pass before the fix as well and show nothing.
