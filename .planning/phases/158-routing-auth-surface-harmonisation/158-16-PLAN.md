observation half of the carried serialisation obligation and the integration gate the
credential-lifetime work needs before it can safely change anything.

collections structurally cannot express a role assignment — so it is minted at run time, exactly as
the candidate identity already is.

Playwright wiring with an explicit file match, one spec, and a recorded scheduling measurement.

  <action>
    ONE spec file with ONE test, carrying every assertion below, so the phase adds one test to the
    suite count rather than three.

    **Cold entry.** Navigate to the admin home as a fresh document load, not as a click-through
    from another address. Assert the settled address is inside the admin surface AND is not the
    admin login address, and assert a piece of content that exists only past the authorization
    gate. The address assertion alone cannot distinguish a landing from a bounce that returned,
    because a redirect is followed silently; the pair can.

    **Reload.** Reload the page — a real browser reload, which produces a new server-rendered
    request. Repeat both address assertions and the content assertion. This is the half the
    universal-load defect broke, and it is the only reason the spec is written this way: a warm
    client-side navigation re-runs the universal load in the browser, where the session is present
    regardless, so a navigation-only spec would pass while the defect was live.

    **The endpoint.** Issue an authenticated request to a jobs endpoint through the page's own
    request context, so it carries that context's cookies. Assert the status is a success status,
    and assert the body parses as a list. When it is not a success, distinguish the two refusal
    statuses in the assertion message — one means no session reached the endpoint, the other means
    the identity was not an admin, and naming which saves a debugging cycle.

    **The payload observation.** Before loading an admin feature page, seed the browser context
    with this application's four browser-script-inaccessible cookie names carrying uniquely
    recognisable values, alongside the real session cookies. Load the page, read the rendered
    content, and assert in ONE expectation that none of the four values appears AND that a
    prefixed session cookie name does appear. The positive half is the control: without it, a
    payload carrying nothing at all passes trivially.

    **The job-write round trip.** Submit the argument-condensation form with a valid election and a
    question identifier that does not resolve. Question resolution raises before the language-model
    provider is constructed, so the failure path runs and reaches a real job-record insert under
    the admin's own credentials — the whole surface the credential-lifetime work later moves.

    Three things this gate must get right or it measures nothing:

    - **Resolve the election at run time** from the database by its external identifier, through
      the admin client, and assert it resolved. A transcribed identifier, or one belonging to
      another project, makes the insert fail for a reason unrelated to what is under test.
    - **Avoid both vacuous branches.** The feature returns success WITHOUT any write when no
      supported question survives filtering and again when no nominated entity is found. The gate
      must fire during question RESOLUTION, upstream of both. Assert that a job row was actually
      written; a gate that asserts only on the form's response would pass against both vacuous
      branches.
    - **Never reach the provider.** Assert the response and the written row rather than any model
      output, and state in the spec's own comment why the failure path is the observation point.

    Then read the job row back through the admin client, assert its author is the test admin's
    address and its end status is the failed value, and leave the row for the teardown to remove.

    Write the spec's docstring to say plainly: this is the first end-to-end coverage the admin
    surface has ever had; it exists because two green full-suite runs said nothing about a total
    admin outage; and here is which of the five assertions guards which failure.
