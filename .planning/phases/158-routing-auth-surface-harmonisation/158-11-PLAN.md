<objective>
Criterion 9's first half: the request hook gates `/admin`, not only `/candidate`, and it does so
from ONE table keyed on route id rather than from two near-identical conditionals.

Purpose: the admin subtree has no hook gate of any kind today — its only protection is the
protected layout's own load. The phase's thesis is one place per concern and a test that fails
when a second appears; two hand-written auth arms in the same function would be exactly the
duplication being removed. `158-01` has already turned this function into a route-id-keyed shape
with two predicates and two route-builder calls, so this plan's edit is ADDITIVE on top of that
rewrite rather than a second rewrite of the same lines.

Output: `isAdminRoute` and a declared gate table in `$lib/routes/`, a hook that loops over the
table, a consistency guard that fails when an app subtree has no row, and three recorded negative
controls.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated request → the admin subtree | Untrusted input crosses here; until this plan lands, nothing in the request hook stops it and only the protected layout's load does. |
| route id → gate decision | The hook trusts SvelteKit's resolved route id to decide which app a request belongs to. A predicate that matches by substring rather than by segment lets a sibling path borrow another app's gate. |
| gate table → request hook | A single shared table now decides two apps' redirect behaviour; a wrong row is an outage or a hole in both. |
