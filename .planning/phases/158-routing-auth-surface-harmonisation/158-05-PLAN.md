<objective>
Collapse three duplicated login implementations onto one shared server helper in the auth
library, keeping each entry point as its own thin wrapper (D-G3), and extract the admin
permissions mapping to that same library (REVIEW-RT-05).

line for line — same sign-in call, same session read, same JWT-claims decode, same failure
ladder — differing only in the role predicate and the redirect target. A shared helper removes
the duplication without inventing the role switch D-G3 explicitly rejected.

Output: `$lib/auth/roles.ts`, `$lib/auth/passwordLogin.ts` with a unit spec, two wrappers
reduced to roughly a quarter of their length, and a committed measurement of whether the
generic API login route has any caller at all.

<assumption_delta_decision>
**Transition detected:** derived → chosen, on the identity of the primary noun. Before this
plan the primary noun is the *route* — three routes, each owning its own login implementation.
After it the login *operation* is a named thing (`passwordLogin`) and the routes become
transports for it.

**Decision: `add-alongside`.** The operation is promoted to a named module while all surviving
route entry points are kept, exactly as D-G3(a) specifies.

**Rationale:** form actions and a JSON endpoint have genuinely different error and redirect
semantics; funnelling them through one transport forces one of them to be emulated. D-G3
rejected that (option b) and rejected a role-parameterised single route (option c) on the
explicit ground that the role parameter would be attacker-controlled input on the login path.

**Accepted debt, stated plainly:** `add-alongside` leaves N transports over one operation, so
a future change to login semantics must be checked against each transport rather than one.
**What would force a later promote:** if a third caller-facing surface needs login (a mobile
client, an admin API), or if the transports' wrappers start diverging again beyond their role
set, redirect target and log label — at that point the operation should become the primary
surface and the transports thin adaptors generated from it.
</assumption_delta_decision>
