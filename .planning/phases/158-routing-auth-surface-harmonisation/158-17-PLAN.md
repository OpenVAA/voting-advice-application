<objective>
Criterion 12: an admin job stops borrowing the HTTP request's credentials for its whole
multi-minute run, and takes its own instead — resolved once at job start, with persistence and
automatic refresh disabled so no cookie write is ever attempted on an already-committed response.

Purpose: phase 157.2 landed the analysis and named the remedy at both construction sites, and
deliberately landed nothing else, because the change is live on the admin write path and the suite
had no gate for it. The plan before this one built that gate. This plan spends it.

Output: a job-scoped client factory reachable through the existing seam, both job features
rewritten to use it, the two deferred markers replaced by an account of what was done, a round trip
whose red half is the coupling itself, and the end-to-end gate run before and after.
</objective>

| Boundary | Description |
|----------|-------------|
| initiating HTTP request → a multi-minute job | The job currently borrows the request's credential and its transport, and outlives both. |
| job credential → the row-level policies | Every write the job makes is authorised as the initiating admin; where that authority comes from is what this plan moves. |
| job client → the response's cookie jar | The current client's cookie adapter can attempt a write on a response that has already been generated. |
