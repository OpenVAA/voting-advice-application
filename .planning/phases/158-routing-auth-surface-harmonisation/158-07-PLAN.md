## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| identity provider → callback endpoint | The upstream error value arrives from outside and is reflected onto a query string the browser then follows. |
| callback endpoint → preregistration page | The error value crosses as a query parameter and drives what the user is shown. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-158-36 | Tampering | An upstream-supplied error value reflected into a redirect URL | high | mitigate | The value is put on the query side by the route builder, which encodes it; the path is fixed by the route map and cannot be steered by the value. The double-encoding check ensures the hand encoding is removed rather than layered, so the value cannot be smuggled through as a pre-encoded path fragment. |
| T-158-37 | Spoofing | The redirect target itself becomes attacker-influenced | high | mitigate | Every target is now a `ROUTE` map key, not a string; an attacker-supplied value can only ever land in a query parameter. This is strictly stronger than the current concatenation. |
| T-158-38 | Information Disclosure | The error union silently widens to any string, so an upstream value is echoed verbatim to the user | medium | mitigate | The pass-through case is represented explicitly rather than by widening the union, and the consumer's handled set is measured against the producer's set with the result recorded. |
| T-158-39 | Repudiation | The sweep's boundary is invisible, so excluded sites read as oversights | medium | mitigate | A written scope statement enumerating the excluded sites with the reason, required by the acceptance criteria. |
| T-158-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan installs no packages. Any proposed dependency is blocked behind a human checkpoint plus a legitimacy check before install. |
</threat_model>
