**Gate rules.**
- Never read a gate's status through a pipe. Run each command plainly and record `$?` immediately into
  `GATES.md` with the command, the date-time and the totals line.
- Every `tests/scripts/e2e-run.sh` run uses `run_in_background: true`, tees its output to
  `<run-dir>/console.log`, and is polled every 60-90 seconds. Its exit code is the verdict (0 success;
  1 Playwright failures; 3 database preparation; 4 readiness timeout; 5 dev server or occupied port;
  6 unconfirmed preflight; 130 interrupted - never a pass).
- Authoritative counts come from the run's report, not the console tail: decode the
  `playwrightReportBase64` zip embedded in the HTML report under the run directory (`report.json` ->
  `{ total, expected, unexpected, flaky, skipped }`). `total == expected` with `unexpected`, `flaky` and
  `skipped` all 0 is what establishes 0 did-not-run. A test that did not run is a failure.
- Disk (orchestrator ruling 4): before any full-suite run, `docker builder prune -af`, then measure the
  Docker VM with `docker run --rm alpine df -h /`; at least 15 GiB available is required. Never restart
  Docker and never prune images or volumes - a second, unrelated Supabase stack runs on this host. If
  the VM is still below 15 GiB after the prune, stop and report rather than run.
- A failing gate is fixed at its root in the plan that owns the code (a deviation recorded in the
  summary), then the gate chain re-runs from the failed link. No gate is skipped, waived or marked
  known-flaky.
