## Rulings and deviations carried by this plan

1. **Ruling O-Q3.** D-19's "one adapter-level write against the local database" is a gated frontend
   integration test in the mould of dev-seed's. No CI job runs it; the closing gate of 173-13 shows it ran.
2. **More files than the phase's aim of about fifteen, in six tasks.** Renaming a member of the user-data
   type would be one typechecked unit, every reader changing in the commit that changes the type. It is
   split so that each task leaves a tree that typechecks: Task 2 renames in the types and the store and
   keeps the old names served through one transitional type and two delegates; Task 3 switches the load,
   the context and the pages; Task 4 deletes the transitional type, the delegates and the interim reader.
   The transitional names live for two commits and are held to zero by Task 4's search.
3. **The single-entity rule moves from the writer into the load** and becomes type-generic: exactly one
   served entity, of either type. Before 173-05 an organization editor cannot pass the login form, so
   nothing a user can see changes here.
4. **Pages are made to compile and not throw for an organization, and nothing more.** The profile's
   person-name fields, the preview and the question scope stay candidate-shaped for Phase 175 (D-19).
5. **The interim outcome for zero or several entities is not pinned by any new test.** It is replaced in
   173-10.
6. **The load's dead branch for a missing entity object goes here.** With the entity typed as a
   non-optional union the branch can no longer be written honestly; it was unreachable already, since the
   read throws on no row. Its error code, map entry, seven messages and docs mention stay until 173-10
   retires them with the screen (D-11).
