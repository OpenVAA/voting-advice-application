## Rulings and deviations carried by this plan

1. **Ruling O-Q2.** The coarse role tests the admin shapes first. Without it, D-12 would lock out of the
   Admin App every administrator who also edits an organization, as it does today for one who edits a
   candidate.
2. **The role-based sign-out leaves the load here, not with the screen in 173-10.** The reorder of item 1
   would otherwise sign an administrator who also edits a candidate out of the Contestant App. The
   `userNotAuthorized` member of the contestant login-error union has no producer in the app from this plan
   on; it is retired in 173-10 with the other retired code.
3. **D-12 lands before the route move.** From this plan an organization editor passes the login form. The
   load then serves them if the project serves organizations and they edit exactly one entity; otherwise it
   ends in the interim `loginFailed` sign-out, which 173-10 replaces with the screen. No gap.
4. **`user` leaves the entity data.** One page read it (the settings page); it now reads the user-level
   accessor. The one-entity read no longer looks the user up.
5. **More files than the phase's aim of about fifteen:** six are new matcher files and their
   tests, and the gate rename reaches every test that pins the gate's content.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| login form → app | a token's grant shapes decide who may enter the app at all |
| token → coarse role | one word summarises a set of grants and is read by the Admin App |
| URL segment → route | a param matcher is the first thing an attacker-supplied segment meets |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-173-18 | Elevation of privilege | the entry gate widened to organization editors | medium | mitigate | it is an entry gate: row-level security decides every read and write, and an organization editor's rights are already in the permission matrix; unit cases pin exactly two admitted shapes and the refusal of `faction` and `alliance`; PROH-173-13 |
| T-173-19 | Elevation of privilege | removing the role check lets a non-contestant session into the protected tree | medium | mitigate | the served-filtered list, read from the table through the caller's own rights, decides; a user with no editable entity ends in the interim sign-out now and the "nothing to edit" screen from 173-10; no entity is read that the list does not hold |
| T-173-20 | Denial of service | an administrator who also edits an entity locked out of the Admin App | medium | mitigate | the admin shapes are tested first; two writer cases and one admin-identity case pin it |
| T-173-21 | Tampering | a crafted route segment reaching a load or a query | low | mitigate | allowlist matcher over the served vocabulary, canonical-uuid matcher, and a sub-path matcher that rejects the empty string and any extra segment; each with a unit test |
