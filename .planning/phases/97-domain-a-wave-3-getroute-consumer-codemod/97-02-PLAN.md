<objective>
Rewrite the `getRoute` producer to be rune-native (CTX-08, locked D-04) and migrate the 13 non-template `getRoute` consumer sites that the codemod's `.svelte`-template regex cannot catch (CONS-02 manual tail). This is a surgical, single-producer change + a manual script-block sweep, landing as ONE separate commit (D-05) BEFORE the mechanical codemod runs in Plan 03.

The current producer (`getRoute.svelte.ts:35-43`) uses `writable<RouteBuilder>(buildFn())` + `afterNavigate(() => store.set(buildFn()))` — a workaround for the `toStore` short-circuit trap (the `$app/state.page` proxy's object reference is stable, so `toStore`'s wrapping effect never re-fires). The spike-012 Approach-C shape replaces this with a pure `$derived.by` that reads `page.params`/`page.route`/`page.url` as SEPARATE fields — each per-field read forms a fine-grained dependency that every navigation invalidates, so no `afterNavigate` republish is needed.

Because the producer's return type changes from `Readable<RouteBuilder>` to `{ readonly current: RouteBuilder }`, the 3 `fromStore(getRoute)` consumers + their 13 `getRouteState.current(...)` call sites must migrate in the same commit (otherwise they reference a deleted store shape — build break, Pitfall 4).

Purpose: Removes the last `toStore` short-circuit workaround for `getRoute`; gives the codemod (Plan 03) a real `getRoute.current(...)` target to rewrite `$getRoute(` into; drops candidateContext's last `svelte/store` import (completing the CTX-07 deferred tail).
Output: One commit (producer rewrite + type change + 13 script-block migrations).
</objective>
