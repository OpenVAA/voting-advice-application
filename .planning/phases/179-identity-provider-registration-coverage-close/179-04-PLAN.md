## Rulings and deviations carried by this plan

1. **The selector is a cookie of the test's browser context** (Pattern 9, discretion of D-20 "how the mock issuer's selector is addressed"). Cookies are host-scoped, so the application on the same host receives it too; it reads no cookie it does not name, and `cookies.test.ts` pins only the names the application sets.
2. **The direct-call spec survives as a spec** (discretion of D-20): it is the only test that sees the function's answers to tokens no browser flow produces; under J4 (179-15) it calls the function as the server does.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a test's browser context → the mock issuer | the selector cookie chooses the identity and the outcome |
| the SvelteKit server → the mock's token endpoint | server-to-server; carries the code only |
| committed test keys → anything that trusts them | the mock signs with keys that are public by being committed |
