## Decisions Made

- **Two declared ranges in the ranged case, not one.** The plan asked for a ranged case and a fallback case. A single `[0, 10]` case would be satisfied by a fix that hardcoded `0–10`, which is the same defect wearing a different number. The off-centre `[3, 6]` case makes range-awareness the only way to pass.
- **Re-run the RED after `eslint --fix`.** The first RED run (`vt-R1-RED-1.log`) executed against bytes whose imports the linter then reordered. Certifying a red half with a log produced from bytes other than the ones committed would make the "byte-identical instrument" claim rest on an unstated approximation. `vt-R1-RED-2.log` is the authoritative red, taken from the committed bytes; `-1` is kept rather than overwritten.
- **Let a malformed range throw.** `min > max` reaches `faker.number.int` and fails the seed run loudly. Substituting a fallback there would hide a bad template — the identical failure shape as the defect being fixed, and the same reason `distance.ts`'s throw was left alone.
- **Keep the draw a single faker read.** The pinned-seed determinism contract depends on the number of faker reads per question, not on their values. One `faker.number.int({ min, max })` call whatever the range preserves it by construction.
