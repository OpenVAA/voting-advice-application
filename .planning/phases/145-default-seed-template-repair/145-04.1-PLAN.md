<objective>
Close the second, independent defect that `145-04` unmasked: the synthetic answer emitter produces
`number` answers in a hardcoded `0–100` regardless of the range the question itself declares, so the
`default` template's one number question (`[0, 10]`) receives 294 out-of-range answers out of 327.
Once anon could see candidates, the voter app started normalizing those answers, `normalizeCoordinate`
threw, and every route past the first answered question rendered `Loading…` forever.

Fix it at the producer — the emitter reads the declared range — and pair the fix, so this repair is
held to the same standard as the one it unblocks.

Purpose: `145-05` cannot measure criterion 1's after half while the app throws on render. This plan is
the minimum that makes that measurement possible, and it fixes the class rather than the instance so
the next narrow-range number question does not reopen it.

Output: a range-aware emitter, a guard observed red then green against a byte-identical instrument, a
re-seeded database with zero out-of-range answers, and a ledger section recording all of it.
</objective>
