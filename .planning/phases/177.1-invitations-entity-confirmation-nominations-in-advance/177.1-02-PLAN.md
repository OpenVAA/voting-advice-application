## Rulings and deviations carried by this plan

1. **Names and messages** are the execution rules' § *Names this phase introduces* — binding, so that the tests written first and the functions written second agree.
2. **The checks move; their words do not.** The validator runs the shape checks in `set_entity_nominations`' order (object, `election_id`, `constituency_id`, the `id`'s form, the symbol's type and length, the parent's object, kind, `entity_type`, `entity_id`, the `other` name's type, blank and length). The context checks stay in `set_entity_nominations` after the call, in their present relative order: a repeated `id`, an `id` outside the reach, an election other than the row's, the move, the election the caller cannot read, and `keep` on a new object. For an object with a single fault the message is unchanged. For an object with two faults the first message may now be the shape fault; file 43 asserts single-fault objects (the research read its 28 object assertions), and the run of file 43 decides.
3. **Fallback, located (J4).** If a file-43 assertion turns red because of that reordering, the validator is split into two functions — `private.nomination_object_head_checked` (object, `election_id`, `constituency_id`, the `id`'s form) and `private.nomination_object_tail_checked` (symbol and parent) — with the context checks between them, the same messages, and file 46's VAL block covering both. The summary says which form was built and why.
4. **The cross-project refusal lives in the resolve function** (the operator's ruling names "the shared resolve-or-create function"), so for `set_entity_nominations` it is raised in the write pass; the call is one statement and nothing is stored. For an entity editor, a parent of another project was refused before by the parent insert policy with `42501`; it is now refused first with `22023` and the new message. File 43 asserts no such case (the research's reading; the run decides).
5. **The key name `requestedParentOrganization` stays the writer's constant** (`c_requested`), as the triggers also read it by name; the validator owns the shapes, the trim and the caps.
6. **[BLOCKING] schema push.** There is no remote project: the schema reaches a database only through `yarn db:reset` applying the regenerated migration. The database rows of Task 2 are that push, and the plan cannot pass without them.
