# Phase 177.1 — Execution Rules

> Read once by every executor of a Phase 177.1 plan, before its first task. Each plan names this file in its
> `<context>`. A plan's own blocks add to these rules and never relax them. Where a plan and this file
> disagree, stop and report.

**A hook line of the form `CONTEXT WARNING NN%` in a tool's output belongs to the orchestrator. Ignore it and
keep working; it is never a reason to stop, to shorten a task or to hand a plan back unstarted.**

## The shell

- Begin every shell call that runs `yarn`, `npx` or `node` with
  `export PATH="$HOME/.nvm/versions/node/v24.21.0/bin:$PATH"` (the shell's default Node is below the floor).
- A status is read from the command itself, never through a pipe: `cmd > file 2>&1; s=$?`. A commit follows a
  gate with `&&`, never `;`.
- **No gate set, E2E run, batch or pgTAP run of more than one file is made in the foreground.** Launch it in the
  shell tool's background mode as `( caffeinate -dimsu <command>; echo $? > <marker>.exit ) > <marker>.log 2>&1`
  and poll with one short foreground command per poll (a bounded loop of at most 45 one-second waits that ends
  when the `.exit` marker exists). Ceilings: 25 minutes for one full run or gate set. A foreground command over
  600 seconds trips the executor's watchdog.
- Before a long run: `pmset -g batt`. No run is started on battery below 30 %.
- An `<automated>` block is run from a script file taken byte for byte from the plan
  (`$U/<plan>-t<N>-verify.sh`) with `bash`, never pasted into the login shell. Its log, exit status and head are
  kept beside it.

## The shared local stack

The `voting-advice-application-infra` worktree uses the same Supabase project id (`openvaa-local`) and ports:
a reset, a start or an E2E run from one worktree acts on the other's database.

- **Before every `yarn db:reset`, every gate set with a database row, every E2E run and every batch**, the
  executor checks, and the drivers refuse (exit 2) when: (a) a `started` marker without an `ended` beside it,
  younger than ten minutes, exists at any depth under `tests/e2e-runs/` of this worktree **or of any other
  worktree `git worktree list --porcelain` names**; (b) anything listens on 5173 or on `FRONTEND_PORT` (default
  5273); (c) the stack is running and its edge-runtime container serves functions from a directory that is not
  this worktree's `apps/supabase/supabase/functions` (the stack was started by another worktree). A check that
  cannot look (a failed `docker inspect`, an unreadable directory) refuses: it is not an answer of "idle".
- On a refusal: **stop and report** what was found, build nothing further, and wait for the orchestrator. The
  executor never stops, starts or resets a stack another worktree started, and never restarts Docker.
- On `ENOSPC`: `docker builder prune -af` first.
- The phase ends with the stack reset from this worktree and `yarn db:seed:default` (plan 08).

## Commits

- Each commit holds the executor's own files only, named by pathspec: `git commit -m "…" -- <paths>`; a new file
  is added by explicit path first. Never `git add -A`, never `git stash`. `CAND-APP-PLAN.md` is never staged. On
  `index.lock`, wait a few seconds and try again. The branch is `feat/entity-signup-multi-grant`; no branch is
  created or switched.
- A commit that changes `$S/schema/`, `$S/migrations/00001_initial_schema.sql`,
  `packages/supabase-types/src/database.ts` or a pgTAP file carries `[db]` in its subject. A schema commit holds
  the regenerated migration (`yarn schema:regenerate`) and the regenerated types (`yarn db:types`, on a freshly
  reset database); the regenerated migration diff is read before the commit.
- `yarn assert:comment-hygiene` runs on the working tree before every commit that adds or changes a comment
  under `apps/`, `packages/` or `tests/`.
- Every commit message ends with these two lines:
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`
  `Claude-Session: https://claude.ai/code/session_01V9mPvkv81Z7zSHGWgcrg62`
- The executor edits none of `.planning/STATE.md`, `177.1-CONTEXT.md`, `177.1-RESEARCH.md`, `177.1-PATTERNS.md`
  and `CLAUDE.md`, and edits `.planning/ROADMAP.md` and `.planning/REQUIREMENTS.md` only where plan 07 says so
  (D-18, D-20). A sentence the work made false elsewhere is reported, not edited.

## Comments, titles and logs

A comment, a docstring, an SQL header and a test title describe the code as it is, to someone reading it cold:
no account of what the code used to do, no decision, plan, ruling or requirement id, nothing addressed to a
reviewer. The ids of a PLAN.md (`D-06`, `J2`) stay in the PLAN.md and the SUMMARY.md.

No address, registration code, token, link or password is written into a log line, an error message, a test
title, a file under the phase directory or a run's kept evidence.

## Searches and checks

- Every population of something on the tree is a command plus the relation it must satisfy. Code is never bent
  to a count or a search, and a check is never edited to pass; a correct implementation in another form is
  reported with the stage it fails.
- A count of lines naming a symbol is also tripped by a comment: count call sites by a form a comment cannot
  match, or with `177.1-arity.mjs`, which skips comments and string literals.
- `git grep -E` on this host does not read `\b`: use `([^A-Za-z_]|$)`.
- An agent's diagnosis of a cause is unconfirmed until re-tested in isolation; a summary says which statements
  were observed and which inferred.

  variable, every name schema-qualified, `search_path = ''`.
- `yarn db:reset` never runs while an E2E run is in flight; the drivers refuse.

## E2E

- **No red E2E test is committed outside the red window**, and no commit outside it turns a committed E2E test
  red. A change a run can observe — a dataset, a fixture step's behaviour, a spec's expectation — stays in the
  working tree until a run of that uncommitted tree has passed, then is committed as one commit.
- A run of an uncommitted tree goes directly through the wrapper:
  `tests/scripts/e2e-run.sh --run-dir $R/<label> --no-db-reset`, then `node tests/scripts/e2e-evidence.mjs $R/<label>`,
  judged with `node $P/177.1-verdict.mjs control <label> --full --dirty-only <path>… --green`.
- A plan that closes on a full run uses `bash $P/177.1-e2e.sh <label> [--require-project <name>]…`, judged at once
  with `node $P/177.1-verdict.mjs e2e <label> --same-projects-as <its predecessor in the chain>`.
- **Void** is decided by the wrapper's marker alone (status 8 with `VOID-host-suspend.txt`): a void run is kept
  and made again under `<label>-r2`, `-r3`. A red run without the marker is a failure; with no other cause,
  `pmset -g log` is read before the tree is blamed. A did-not-run is a failure. Nothing is retried until green
  on an unchanged tree; no test is skipped or annotated to pass. Nothing under `tests/e2e-runs/` is deleted.
- A dev server is started by the wrapper and by nothing else. No spec waits a fixed time.
- A spec seeds through the fixture's steps and the admin client's methods, never by a direct RPC; it holds hard
  assertions only and no locator in a test body.

## An interrupted cycle

From the step that writes uncommitted changes until the step that commits them, the working tree holds exactly
the files the plan's `<uncommitted_changes>` block names, and a copy of each as the pre-commit run ran it is kept
beside the run (`$R/<label>.<file name>.kept`). The next executor either goes on from the working tree (or from
the kept copies) or discards the change with `git checkout -- <the named files>` and starts that task again. The
gate driver and the E2E driver refuse a tree with uncommitted changes outside `.planning/`.
