**Seven standing constraints, all load-bearing:**

1. **`TURBO_FORCE=true` on every ledger-bearing invocation (D-02a).** `turbo.json:13-17` declares
   `lint` with **no** `"cache": false`, unlike `test:unit`. At a clean tree `@openvaa/frontend#lint`
   is a cache HIT, and a replayed exit 0 under the narrowed config is indistinguishable from a
   measured blind GREEN — which is **exactly** what rows B1-B4 exist to produce. **`yarn lint:check
   --force` does NOT work**: yarn appends the argument to the end of the `&&` chain rather than passing
   it to turbo. Do not use it and do not substitute it. **A row that cannot show `executing` is not a
   measurement** — re-run it.
2. **One injection live at a time.** Never two at once, never across a task boundary, never across a
   break in the session.
3. **No commit while an injection is live**, and **no commit while the config is narrowed**. Ledger
   edits are committed between loop iterations or at task close.
4. **No `yarn dev`, no `yarn test:e2e`, no Playwright command, no `supabase functions serve` while any
   injection is live or the config is narrowed** — not in this terminal and not in another. The E2E
   gate belongs to `143-03`, after the last revert.
5. **`yarn lint:check` short-circuits on `&&`** (`package.json:33` — `turbo run lint && eslint … tests
   && yarn typecheck:tests`). A **RED row means the FIRST failing step failed**; the later `eslint
   tests` and `typecheck:tests` steps **never ran**. Every red row's `Outcome` cell must say so
   explicitly rather than implying a full-gate result.
6. **Count errors, not problems.** The frontend lint is error-free but **not warning-free**: a
   pre-existing `unused-imports/no-unused-vars` warning at
   `apps/frontend/src/lib/contexts/candidate/candidateContext.svelte.test.ts:39` appears in **every**
   run. The `Errors` cell counts errors; a clean run reads `0 errors (1 pre-existing warning)`.
7. **Log paths must resolve.** Write the **resolved** `$TMPDIR` into the ledger header. On this machine
   it is `/var/folders/3p/10hbv0415234v3x5ctp50l4m0000gn/T/` (the same value
   `142.1-NEGATIVE-CONTROL-LEDGER.md` records). An unresolvable log path is not evidence.
