Prove the fix holds across a run long enough to exercise the observed failure rate — and make the
proof auditable rather than asserted.

The observed baseline is one failure in eight full-suite runs. Sixteen is deliberately twice that
rate (D-13). The batch is a serial, unattended, local host run — not a container — because proving
it in a place the failure never happened is weaker evidence, not stronger (D-14), and because the
1-in-8 was observed exactly here. It runs inside Phase 138 rather than being interleaved across
later phases (D-15).

Purpose: criterion 3. And nothing more than criterion 3 — a green batch is not a diagnosis, and this
plan runs only after criteria 1 and 2 are already discharged.

Output: `tests/scripts/determinism-batch.sh` and `138-DETERMINISM-LEDGER.md` with sixteen mechanically
derived rows.

Create `tests/scripts/determinism-batch.sh`: a serial loop that invokes the single-run wrapper N times
and emits the per-run ledger rows. It orchestrates; it does not re-implement the wrapper.

House style as established in plan 01: shebang form, header block with Usage / Prerequisites / a
numbered "The script automatically:" list, `set -euo pipefail`, script-location-relative path
detection, env-var defaults in the brace-default form. Add to the header the realistic wall-clock
estimate and the statement that this is an unattended batch.

Arguments:
  - `--runs <N>` — default 16. **Validate it strictly:** a non-integer, or a value below 1, exits
    non-zero printing usage. A value of 1 is permitted for self-testing but the ledger must record
    that a single run does not satisfy the acceptance threshold.
  - `--project <name>` — passthrough to the wrapper, for the fast self-test only. When present, the
    emitted ledger is marked `SELF-TEST — not gate evidence` in its header so a scoped run can never
    be mistaken for the gate.
  - `--ledger-dir <path>` — where run directories are created; defaults under the git-ignored run
    directory created in plan 01.

Ordered behaviour:
  1. **Pin the code state.** Read `git rev-parse HEAD` once, before the loop. Every iteration
     re-reads it and ABORTS the batch if it changed — "16 consecutive runs" means 16 runs of one
     tree, and a mid-batch commit silently invalidates the evidence.
  2. **Assert the environment posture once, loudly.** `CI` must be absent; if it is set, exit
     non-zero with an explanation naming what it would buy (three retries per test and a single
     worker). Unset the three forcing knobs and record that the batch did so. Record the effective
     retry count and worker count into the ledger header.
  3. **Loop serially.** One iteration at a time, never concurrently. Per iteration: create
     `run-NN` (zero-padded), invoke the wrapper with that run directory, and capture its exit status.
     The wrapper owns database reset, readiness polling, dev-server spawn with log redirection, the
     Playwright invocation, the preflight-verdict capture and teardown; do not duplicate any of it
     here.
  4. **Derive the row mechanically.** From the run's machine-readable results file, extract integers
     for executed, passed, failed, flaky and did-not-run, and extract the outcome of the EPERM-07
     step specifically by its step title. From the wrapper's outputs take the exit status, the
     preflight-failure count, the start and end timestamps and the git HEAD. Nothing in a row is
     transcribed from console text.
  5. **Enforce the validity rules as code, not as instructions.** A run is VALID only if: the
     preflight-failure count is zero; the executed count equals the expected count (135 for a full
     gate run; the value is a script constant with a comment naming plan 01 as the reason it moved
     from 134); the failed and did-not-run counts are zero; and the wrapper exited zero. A run that
     is not valid ABORTS the batch immediately — it does not continue and hope.
  6. **On abort, record and stop.** Append an abort row naming the run index, the reason and the
     failing test if any, then exit non-zero. Never silently skip a run and never renumber to hide a
     gap; the consecutive count is what criterion 3 measures.
  7. **Measure before committing to the whole batch.** After run 1, report that run directory's size
     on disk and the projected total for N runs. There is no trustworthy full-suite artifact
     measurement in the record, and the suite retains a trace for every test. Prune green runs to the
     machine-readable results, the captured stdout and the dev-server log, retaining the full report
     only for a run that is not green — and state the pruning policy in the emitted ledger header so
     a reader knows what was kept and why.
  8. **Emit the ledger.** Write or append the per-run table to the ledger path, one row per run, plus
     a header block carrying: batch start, git HEAD, the environment posture, the expected executed
     count, the pruning policy, and the run count requested.

Exit zero only if all N runs were valid.
