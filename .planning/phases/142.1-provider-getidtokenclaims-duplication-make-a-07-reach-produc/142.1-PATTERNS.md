## Pattern Assignments

### `lib/api/utils/auth/decryptAndVerifyIdToken.ts` (service, transform) — **CREATE**

**Analog:** `lib/api/utils/auth/getIdTokenClaims.ts` — the deleted file. This is not a "similar"
analog; the core is that file with `:31-42` (the result union) and `:77-84` (the hardcoded claim
mapping) removed, and `:26-28` converted from properties to getters (D-07).

**Import block to copy verbatim** (`getIdTokenClaims.ts:1-3`) — note the ordering
`jose` → `$lib/server/constants` → `$lib/utils/constants`, which is what `simple-import-sort`
settles on:

```typescript
import * as jose from 'jose';
import { constants } from '$lib/server/constants';
import { constants as publicConstants } from '$lib/utils/constants';
```

**Lazy-getter pattern + the A-07 guard comment** (`getIdTokenClaims.ts:6-25`) — moves **verbatim**
per D-22. Its final two lines are the load-bearing clause the three new getters (D-07) each repeat:

```typescript
  /**
   * Parsed lazily, ON READ, rather than at module-evaluation time. A malformed
   * `IDENTITY_PROVIDER_DECRYPTION_JWKS` used to throw a bare `SyntaxError` at IMPORT
   * time, outside any `try`, so it could never reach `getIdTokenClaims`'s catch and
   * could never carry a `code`. Every read happens inside that `try`, so the
   * misconfiguration now surfaces as a coded failure like the other two.
   *
   * Do not simplify this back into a plain property: that reinstates an
   * uncatchable import-time crash.
   */
  get privateEncryptionJWKSet(): Array<jose.JWK> {
    try {
      return JSON.parse(constants.IDENTITY_PROVIDER_DECRYPTION_JWKS || '[]');
    } catch {
      // Opaque identifier only -- the malformed value is NOT echoed.
      throw Object.assign(new Error('Cannot decode ID token: the configured decryption JWK set is not valid JSON.'), {
        code: 'ERR_JWKS_MALFORMED'
      });
    }
  },
```

⚠ **Two convention notes the excerpt binds:** (a) the message text is a *sentence*, never the
malformed value — the `// Opaque identifier only` comment is part of the pattern, not decoration;
(b) `getIdTokenClaims.ts:29` closes with `} as const;`. The core must **not** — RESEARCH § 1.2 row 3
requires an explicit exported `DecryptAndVerifyOptions` interface so the default-parameter type and
the explicit-options call sites in the five repointed tests agree.

**Coded-throw pattern** (`getIdTokenClaims.ts:56-68`) — the exact `Object.assign(new Error(…), { code })`
form, and the split-branch comment at `:46-53` that D-22 moves verbatim (excerpted in full under
**Shared Patterns § Leak-safety** below):

```typescript
    if (privateEncryptionJWKSet.length === 0) {
      throw Object.assign(new Error('Cannot decode ID token: no decryption JWKs are configured.'), {
        code: 'ERR_JWKS_EMPTY'
      });
    }

    const privateEncryptionJWK = privateEncryptionJWKSet.find((jwk) => jwk.kid === kid);

    if (!privateEncryptionJWK) {
      throw Object.assign(new Error(`Cannot decode ID token: JWK not found: kid=${kid}.`), {
        code: 'ERR_JWK_KID_MISMATCH'
      });
    }
```

**Statement-order convention** (`getIdTokenClaims.ts:44` → `:56` → `:62`): `decodeProtectedHeader`
**first**, then empty-set, then kid lookup. The *provider* copies use the opposite order
(`idura.ts:116` parses the env var first). Copy the **helper's** order — RESEARCH § 1.2 row 4 shows
reversing it silently changes `token-endpoint.test.ts`'s ten failure modes from uncoded to
`ERR_JWKS_EMPTY`.

**Module-header docblock convention:** every peer in this directory opens with a `/** … */` block
naming purpose and constraints (`signicat.ts:1-12`, `__fixtures__/keys.ts:1-9`, which ends with the
hard rule `NO Deno imports. NO SvelteKit imports. Pure jose v6 only.`). The core's header is the
right place for A-09's rule: *never re-export this from `providers/index.ts`*.

**Analog C — the `jose` mock:** `getIdTokenClaims.test.ts:44-64`, lifted verbatim including its

// ESM exports are not configurable, so vi.spyOn won't work.
//

// returning the same `JWTVerifyGetKey`-shaped function that `createLocalJWKSet`
// produces. Keeps incorrect test usage (e.g. forgetting to call the factory) a

      // members the local JWKS does not provide, but production code under test only

⚠ **One `vi.hoisted` call, one object** (RESEARCH § 3.2): the port must merge `mockConstants` and
`localJwksState` into a single `vi.hoisted(() => ({ mockConstants, localJwksState }))`, not two
calls — the two analogs each declare only their own.

**Analog D — the coded-error assertion + its guard comment:** `getIdTokenClaims.test.ts:236-241`.
This is the real in-tree instance of the `Do not weaken this back to a bare success check`
convention, and its placement is part of the pattern: the comment sits **immediately above** the
`expect`, and it explains *why the sibling test's title would otherwise be indistinguishable*:

```typescript
      // Assert the CAUSE, not just that it failed. `success: false` alone is satisfied
      // by any rejection whatsoever -- a bad signature, a wrong audience, or a function
      // that has stopped succeeding altogether -- so it cannot distinguish this test
      // from its sibling below, whose title names a different cause.
      // Do not weaken this back to a bare `success` check.
      expect(result).toMatchObject({ success: false, error: { code: 'ERR_JWKS_EMPTY' } });
```

and its sibling at `:262-268`, which names the *contrast* explicitly:

```typescript
      // A DIFFERENT code from the sibling above: that fixture is a misconfiguration
      // (no JWKs configured at all), this one is a key-rotation miss (a JWK set that
      // does not carry the token's kid). The two codes are what make the two titles
      // differ observably. Do not weaken this back to a bare `success` check.
      expect(result).toMatchObject({ success: false, error: { code: 'ERR_JWK_KID_MISMATCH' } });
```

Two further in-tree instances confirm the wording generalises rather than being copy-paste:
`__tests__/authorize-endpoint.test.ts:239` (`Do not weaken this back to a bare 'rejects' matcher.`)
and `lib/i18n/tests/overrides.test.ts:37` (`Do not weaken this back to 'typeof result': every one of
those wrong values is a string.`). The new `ERR_JWKS_MALFORMED` test — which has no counterpart
anywhere today — needs a comment of this class written fresh in the same register.

**Analog E — value-asserting sibling, byte-unchanged (D-02d's untouched control):**
`signicat.test.ts:58-65`. Do not touch it; it is what the ledger cites as collateral control:

**Analog F — the fixture factories:** `providers/__fixtures__/keys.ts` (`createTestKeySet`) and
`__fixtures__/tokens.ts` (`createTestJwe`). **Their only consumer today is their own smoke test**,
`__fixtures__/fixtures.test.ts` — the new provider tests are their second consumer, which is D-13's
whole point. The consumption conventions the smoke test establishes:

### `routes/api/oidc/token/+server.ts:26-30` and `callback/+server.ts:73-76` (route handler) — **MODIFY**

      throw e;

    console.error('Callback token exchange failed:', e);
    throw redirect(303, '/candidate/preregister?error=token_exchange_failed');

**The site being modified** (`token/+server.ts:26-30`; `callback/+server.ts:73-76` identical modulo

**Conventions the analog binds:**
- **A `Do not simplify this back into …` reason comment above the new line** — the third in-tree

  `routes/api/cache/+server.ts:69`).
- **Label-prefixed message, comma-separated value** — `console.error('Label:', value)`, never
  interpolated.
- **The log emits the code only** — never `error.message` (D-22 leak-safety; the message carries the
  incoming kid). Note the *existing* logs pass the whole `e`; the new ones must not.
- **A-07's placeholder clause:** the uncoded case logs `claims.error.code ?? 'none'`, and the comment
  must say in as many words that `'none'` is a **log placeholder, not a fourth error code** (D-08).
- **Written inline in both files, not via a shared helper** (A-07) — a shared module would force the
  D-22 leak-safety rule to be restated in a third place.

## Shared Patterns

### Leak-safety (the A-07 comment block)
**Source:** `getIdTokenClaims.ts:46-53`
**Apply to:** the extracted core (moves here verbatim, D-22); referenced by the new provider tests'
kid-mismatch assertions (D-23) and by both `console.error` sites (D-09).

```typescript
    // Split from a single `!privateEncryptionJWK` branch so the two failure modes are
    // distinguishable -- by an on-call engineer and by a test. An EMPTY set is a
    // misconfiguration (the JWKs never parsed out of the environment); a kid MISS is a
    // key-rotation incident. Both codes are opaque failure-class identifiers and must
    // stay that way: no JWKS contents, no configured kids, no issuer and no audience
    // may be added to either message. The kid-miss message carries only the incoming
    // kid, which comes from the caller's own token and is an identifier, not a secret.
    // Do not merge these back into one branch -- the two are then indistinguishable.
```

**Move it unrewritten.** Every rewrite of a load-bearing warning is a chance to drop the clause that
made it load-bearing — the "incoming kid is explicitly permitted" sentence is the one D-23's
`rejects.toSatisfy` assertion tests against.

### Coded-throw / coded-catch
**Source:** `getIdTokenClaims.ts:56-68` (throw) · `idura.ts:148-161` = `signicat.ts:111-124` (catch)
**Apply to:** the core (throw side) and both provider methods (catch side, unchanged).
`Object.assign(new Error('…'), { code: 'ERR_…' })` → `if (e instanceof Error && 'code' in e)` →
`{ success: false, error: { code } }`. jose's own coded errors flow through the same arm untouched
(D-08). Uncoded throws land in `error: {}`.

### The `Do not …` reason-comment convention
**Sources, all in-tree:** `getIdTokenClaims.ts:13-14` (`Do not simplify this back into a plain
property`), `:53` (`Do not merge these back into one branch`),
`getIdTokenClaims.test.ts:240,267` (`Do not weaken this back to a bare 'success' check`),
`__tests__/authorize-endpoint.test.ts:239`, `lib/i18n/tests/overrides.test.ts:37`,
`routes/api/oidc/token/+server.ts:44`, `routes/api/oidc/authorize/+server.ts:53`,
`routes/api/cache/+server.ts:69`.
**Apply to:** all four new getters (D-07), the three coded-throw branches, every strengthened test
assertion (D-15, D-14, D-23), and both new `console.error` calls (D-09).

**The convention's three invariant properties**, read off eight instances:
1. It sits **immediately above** the line it protects, never at the top of the block.
2. It names the *specific* weaker form that must not return (`a plain property`, `a bare 'success'
   check`, `a bare 'rejects' matcher`, `'typeof result'`, `the console.error below`) — never a generic
   "do not change this".
3. It states the **consequence** in the same breath (`that reinstates an uncatchable import-time
   crash`; `every one of those wrong values is a string`; `it cannot distinguish this test from its
   sibling below`).

A comment satisfying only (1) and (2) is decoration. The consequence clause is what a later reader
weighs against the convenience of weakening the assertion.

### Deep-equality over shape matchers
**Source:** `idura.test.ts:94-101` / `signicat.test.ts:58-65` — `expect(x).toEqual({ …whole object… })`
**Apply to:** D-14's two claims tests. Never `toContain` / `toHaveProperty` — a superset or a dropped
claim must red. This is F20-4's lesson, recorded at `142-NEGATIVE-CONTROL-LEDGER.md` row 10.

### Test-file module conventions (this directory)
**Sources:** `getIdTokenClaims.test.ts:1-13` · `idura.test.ts:1-13` · `signicat.test.ts:1-12` ·
`__fixtures__/fixtures.test.ts:1-14`
**Apply to:** every test file this phase creates or edits.
- A `/** … */` header naming the module under test and what is verified, ending `@vitest-environment node`.
- Import order: `jose` → `vitest` → module under test → `import type` last (all four files agree).
- Nested `describe` per concern inside one top-level `describe(<subject>)`.

### Server-only import discipline
**Source:** `providers/index.ts` re-exports only the provider surface; `__fixtures__/keys.ts:1-9`
ends `NO Deno imports. NO SvelteKit imports. Pure jose v6 only.`
**Apply to:** the extracted core. It imports `$lib/server/constants`; SvelteKit's `$lib/server` guard
rejects a client import at build time, and `providers/index.ts` is the one place a client-reachable
import could be introduced by accident (A-09). Record the rule in the core's header docblock.
