## ⚠ THE INVERSION — read this before reading any row

**Carried verbatim from D-17 into every injection task of this phase:**

> **Strengthening before collapsing reds the new assertions against the uncoded copies. That red is the
> correct diagnosis, not a regression.**

**In Phase 139 a green under injection was the finding. In Phase 142, and in the `NEW-assertion
outcome` column here, a RED is the success signal.** The four rules, from
`142-NEGATIVE-CONTROL-LEDGER.md:41-62`:

- The **`NEW-assertion outcome`** column is *expected: **FAIL (red)***. That red **is** the evidence.
- A **green** NEW half is a **failure of the remediation**, not a success. It means the strengthened
  assertion is still blind to the regression its own title promises to catch.
- The **`File outcome`** column may read red for *collateral* reasons, and it is a **separate cell**
  (D-21). Separating them is precisely what stops a collateral red being credited as the negative
  control.
- A red **on the wrong axis** — an unrelated sibling matcher, a whole-file collection error, an
  endpoint-level test that was already red before the injection — is **not** creditable. Only a red
  that **names the strengthened assertion** may fill the `NEW-assertion outcome` cell.

**This phase's own sentence, which the template did not need:** in **`142.1-01` every OLD-half
observation is expected GREEN, and that green *is* the blindness demonstration** — it shows the
`typeof … === 'function'` guard cannot see a regression its own title promises to catch. That is the one
place in this phase where Phase 139's polarity still applies. **The polarity inverts at `142.1-02`**: a
green there is a failure, not a success.

An executor pattern-matching on 139's record will otherwise read a correct remediation as a regression
and "fix" it by weakening the assertion. That is `142.1-RESEARCH.md` § Pitfall 1, and it is the single
most likely way this phase produces worthless evidence.

## Measurement, never citation — the clause that keeps this ledger honest

`141-ASSERT10-LEDGER.md:47-52` states that its template document *"is never the source of truth for any
outcome here — its rows were re-run, not copied."* **142 needed a subtler version of that clause,
because its D-06 expressly permitted citing 139's OLD half. 142.1 needs the blunt version.**

The rule:

1. **The literal string `cited` is not a legal value in any cell of this ledger.** Criterion 4 is
   categorical: the 2026-08-11 sweep never enumerated `providers/idura.test.ts` or
   `providers/signicat.test.ts`, so there is no recorded observation of these guards anywhere to
   borrow, and no pre-specified injection to reuse. A row that borrowed one would be borrowing from a
   document that does not contain it.
2. Every row's **`OLD half (measured)`** cell therefore states a measurement taken **in `142.1-01`, on
   the untouched pre-collapse tree**, with the log path and the HEAD it was taken at.
3. Every row's **`NEW-assertion outcome`** cell states a measurement taken **in `142.1-02`**, after the
   collapse, with its own log path and its own (later) HEAD.
4. `142.1-RESEARCH.md` § 6.2 carries `[MEASURED]` annotations from the research pass, several of them
   taken on the structurally identical Signicat site as an *analogue* for Idura. **Those are
   pre-registered expectations, not evidence.** They tell a row what it should see; they never fill a
   cell. Each row's cells are filled from that row's own logged run.

## A note on "the first line of output" — this transcript is not doctored

`141-ASSERT10-LEDGER.md:60-71` discloses that the literal first line of each of its runs is dotenv's
banner, and that the recorded "first line" is the first *verdict-bearing* one.
`142-NEGATIVE-CONTROL-LEDGER.md:87-101` gives the vitest equivalent. 142.1's, since every run in this
phase is a frontend-workspace vitest run:

- Every `npx vitest run` emits a **`RUN  v3.2.4 <workspace path>`** banner first, followed by a blank
  line. It carries no verdict.
- Frontend-workspace runs — which is **all** of them here — additionally emit a **vite /
  vite-plugin-svelte warning block** before any test output.
- Where a row quotes runner output, the quotation therefore begins at the first **verdict-bearing**
  line — the `✓`/`×` file line, the `FAIL` line, the `AssertionError` block, or the
  `Test Files … / Tests …` summary — with the banner and any plugin preamble filtered. This is stated
  rather than silently elided, because a reader reproducing a row will see the banner first and should
  not conclude the transcript was trimmed to flatter it.
- **Every row states the observed counts**, not merely the exit code. A scoped run that collected the
  wrong file, or a `-t` filter that matched nothing, reports a green exit with a count that gives it
  away; the count is what makes the cell checkable.

Stated explicitly, because a ledger that merely *had* the property without saying so could not be
checked by a later reader.

is recorded by name in its row's `Collateral` column:
