### EFLOW-10 bank-auth (Phase 122)

> **AUDIT VERDICT (confirmed by reading `tests/tests/specs/candidate/candidate-bank-auth.spec.ts` + `.planning/idura-ftn-auth-plan.md`):** the existing spec is the seam to reuse — **extend/retarget it to Idura-only; do NOT plan a live IdP redirect.**

**What the existing spec already does (no live IdP).** `candidate-bank-auth.spec.ts` generates a synthetic JWE-encrypted `id_token` (RSA-OAEP-256 enc + RS256 sig via `jose`, `buildTestIdToken`, lines 60–111) and POSTs it **directly to the `identity-callback` Edge Function** (`${SUPABASE_URL}/functions/v1/identity-callback`) — there is **no live IdP redirect** (spec header lines 18–20 state this explicitly). It is provider-shape-agnostic: the synthetic token mirrors the standard OIDC JWE id_token both Signicat and Idura return (per idura-ftn-auth-plan.md line 29 — same standard-claims shape, same `jose` RSA-OAEP-256 decryption). It already asserts: candidate creation + name claims (lines 195–229), `app_metadata.identity_provider` / `identity_match_prop` / `identity_match_value` (lines 226–228), magic-link `session.action_link` (lines 251–288), CORS preflight (lines 290–301), reject missing/invalid token (lines 303–332).

**The 122 verdict (122.2 — Idura ONLY, drop Signicat):**
1. **RETARGET / EXTEND** `tests/tests/specs/candidate/candidate-bank-auth.spec.ts` to assert the **Idura `sub`-based identity match** — `sub` is the persistent per-tenant pseudonym Idura uses for identity matching (replacing `birthdate`; idura-ftn-auth-plan.md lines 48, 135, 192).
