<objective>
FLATTEN-02 (part 1 — the load-bearing correctness step): repair every production site that
destructures `appSettings` / `dataRoot` / `locale` out of a `get*Context()` call, converting them to
aliased `ctx.X` reads, and move the three names from "stable / safe-to-destructure" to "reactive
accessor / MUST read via ctx.X" in CLAUDE.md's Context Destructuring Rule.

This is the research's CRITICAL finding (research "CRITICAL: appSettings/dataRoot/locale Become
Reactive Accessors"): once plan 04 flattens these to bare reactive fields, destructuring them captures
the value once at component init and never updates — the exact Phase-61 destructure-trap class of bug
(green build, silently broken runtime: settings stop updating on navigation). Repairing the
destructure sites NOW — while the handles are still `{ current }` (so the change is a safe no-op
behaviorally) — and BEFORE the bare-field codemod is the only ordering that keeps the build green at
every step (research Pitfall 2: "fix all destructure sites BEFORE removing the .current accessor").

Purpose: Eliminates the destructure-trap exposure that the flatten raises (REQUIREMENTS line 20-22:
"Flattening to public fields raises trap exposure, so the audit pass is mandatory") and updates the
locked CLAUDE.md contract.
Output: ~29 components/routes converted from `const { appSettings, ... } = get*Context()` to
`const ctx = get*Context(); ... ctx.appSettings.current`; CLAUDE.md Context Destructuring Rule updated;
spike-009 PASS-2 audit reports zero traps for the three names.
</objective>
