<objective>
FLATTEN-02 (part 2 — the bare conversion + consumer codemod, ONE atomic green boundary): convert the
producers' `appSettings` / `dataRoot` / `locale` from own-enumerable `{ current }` handle objects into
own-enumerable BARE reactive accessors, and in the SAME commit run the idempotent codemod that rewrites
every consumer `<handle>.current` → `<handle>`. After this plan, consumers read `ctx.appSettings`
(bare) and the build/unit/svelte-check/E2E are all green.

CRITICAL spread-safety mechanism (research Open Question #1 + Pitfall 3, empirically confirmed):
`{ ...appContext }` (the three downstream orchestrator spreads) copies ONLY own-enumerable properties
and silently drops PROTOTYPE getters. A bare `get appSettings()` on the class prototype would be
dropped. The proven fix is `Object.defineProperty(this, 'appSettings', { get() {...}, enumerable: true })`
in the constructor — an OWN-enumerable accessor that survives the spread (verified: `{...o}` copies a
defineProperty enumerable getter). This is the load-bearing design choice that makes "bare field" and
"spread-safe" coexist.

This plan MUST land as a single green commit (FLATTEN green-at-every-boundary contract): converting the
producer to bare WITHOUT the consumer codemod (or vice versa) leaves a red build. Do both, gate once,
commit once. autonomous:false — the final task is a blocking human-verify checkpoint for the full E2E
gate (requires `yarn dev` + seed running + a mandatory dev-server restart per project memory
`e2e_hmr_staleness_restart`).

Purpose: Delivers FLATTEN-02 success criterion 2 (consumer `.current` reads flattened to bare
class-field reads via an idempotent codemod; back-compat handles removed from producers) while
preserving the spread-of-context contract and the destructure-trap contract (already repaired in plan 03).
Output: producers exposing bare reactive accessors; ~189 consumer reads flattened; spread test on bare
form; full green gate incl. E2E.
