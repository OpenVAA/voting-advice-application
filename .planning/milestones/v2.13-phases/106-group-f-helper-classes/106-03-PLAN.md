Convert the `storageState()` handle in `utils/persistedState.svelte.ts` into a real Svelte 5 class (e.g.
`class PersistedStateImpl<TValue> implements PersistedState<TValue>`) with a `$state` value field, a `get current()`
reactive read, and IMPERATIVE persistence inside arrow `set`/`update` methods (NEVER `$effect` — decision A7/§21,
so the class constructs outside any effect context: SSR/factory-safe). The versioned-payload read

default-persist-on-init (CR-01) behaviors are preserved verbatim. `localStorageState`/`sessionStorageState` stay
thin wrappers that `return new …(...)`. The `PersistedState<TValue>` interface and all 7 consumers
(`userPreferences` via appContext, `answers` via answerStore, candidate stores, tracking sessionId, voterContext)
stay byte-identical (A4).

`{ current, set, update }` API now (CLASS-01). The imperative-persist-not-`$effect` discipline is the one that
keeps the class factory-constructable (no `effect_orphan`), so it is the load-bearing invariant.
Output: the persisted-state class landed; the existing `persistedState.svelte.test.ts` (versioned + raw + CR-01 +
