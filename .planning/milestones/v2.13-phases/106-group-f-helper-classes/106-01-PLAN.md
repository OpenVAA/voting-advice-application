  <behavior>
    - A fresh PopupStore has `.current === undefined` (empty queue).
    - `push(item)` makes `.current` the first enqueued item (FIFO head).
    - `push(a); push(b)` keeps `.current === a`; after `shift()`, `.current === b`.
    - `shift()` on an empty queue is safe (no throw) and leaves `.current === undefined`.
    - `const { push, shift } = new PopupStore()` then calling `push`/`shift` detached still mutates the same
      instance (arrow-field `this` capture, §18 / spike 020 Group E).
  </behavior>
  <action>
    Define `class PopupStore` in this file with: a private `#queue = $state<Array<PopupQueueItem>>([])` field
    reassigned wholesale on push/shift (per §17 — no `{current}` handle needed, the getter tracks); a
    `#current = $derived(this.#queue[0])` field (or a `get current()` reading a `$derived` — match the darkMode
    private-field + prototype-getter shape); and `push`/`shift` as ARROW-FUNCTION FIELDS (`push = (item) => { this.#queue = [...this.#queue, item]; }`,
    `shift = () => { this.#queue = this.#queue.slice(1); }`) because both are destructured/passed as handlers
    (§18). Resolve the class/type NAME CLASH with the existing `PopupStore` interface: keep the public interface
    in popupStore.type.ts named `PopupStore` (appContext.type.ts imports it — do NOT rename it), and in THIS file
    import that type under an alias (e.g. `import type { PopupStore as PopupStoreApi } from './popupStore.type'`)
    so the local `class PopupStore` does not collide, then declare `class PopupStore implements PopupStoreApi`.
    Keep the `popupStore()` factory export: `export function popupStore(): PopupStoreApi { return new PopupStore(); }`
    (decision A1 — factory wrapper stays; consumers call `popupStore()` unchanged). Do NOT add `$effect`
    (decision A6/§20 — none needed). Do NOT rename instance/variable names or the `*Store` class name (rename is
    Phase 114). Update the file header doc comment to describe the class shape.
  </action>
