<objective>
Convert the `voterContext` orchestrator (559 lines, ~25 surface members, 5 $effect blocks, 4 $derived projections, 4 sub-store producers) to a Svelte 5 class `VoterContextProvider implements VoterContext`. This is the HIGH-risk core of CLASS-05. It depends on Plans 01+02 (the sub-store classes its producers instantiate must already be class-shaped).

Purpose: CLASS-05 SC-1 requires voterContext itself to be a class; SC-2 requires every reactive accessor to stay reactive via `ctx.X` (the CLAUDE.md destructure-trap contract). The decisive simplification (110-PATTERNS.md §1, re-verified: `{ ...voterContext }` → zero hits) is that NO consumer spreads voterContext, so its OWN members are exposed as plain prototype getters (the natural class shape; §17) — it does NOT need the Phase-109 own-enumerable discipline AppContextProvider required. The own-enumerable concern applies ONLY to the INHERITED appContext members, which arrive already own-enumerable from the Phase-109 AppContextProvider instance and are reproduced via `Object.assign(this, appContext)`.

Output: `voterContext.svelte.ts` as a class with byte-identical `initVoterContext()`/`getVoterContext()` factory wrappers; all reactive accessors as prototype getters; resetVoterData as an arrow field; the inherited appContext spread reproduced; route/component consumers untouched.
</objective>
