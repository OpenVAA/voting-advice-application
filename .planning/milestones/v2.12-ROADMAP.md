## Why superseded

The Phase 102 spike answered "what is the cleanest idiom for the `{ readonly current }` handle?" with a
get/set-accessor pair + plain getter, keeping a per-context handle object. A follow-on spike line
(017–023) then asked the deeper question — "should each context become a Svelte 5 class?" — and answered
**yes**, proving it on three real production contexts (`dataContext`, `filterContext`, `darkMode`) with
zero consumer churn and full green gates. The class idiom subsumes the handle-idiom decision: a reactive
class `$state` field replaces the handle entirely, collapses the `{ current, instance }` split (spike 017),
and drops the producer `untrack` workaround. Continuing the Phase 103 handle codemod would have rewritten
consumers toward a shape the class migration then re-rewrites — so it was abandoned in favor of starting
the class migration as v2.13.
