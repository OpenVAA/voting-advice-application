<objective>
Assign `view-transition-name`s across the EXPANDED VT-02 surface set so the View-Transitions mechanism from Plan 01 produces element-stable cross-fades instead of a perceived full-page redraw, and place the per-route `data-focus-on-nav` / `tabindex="-1"` markers (the per-route half of NAVA11Y-02) on the question heading so the root `afterNavigate` focus hook lands correctly.

Singleton chrome (`Header`, `MainContent`) is named IN-component (safe — never appears twice). SHARED components (`Hero`, `QuestionHeading`, `QuestionActions`, `Tabs`) are named at the ROUTE CALLSITE via `style`/`restProps` so names stay unique-per-snapshot (Pitfall 4) and survive the Phase-100 questions-layout hoist (forward-compat: names live on shared components, not on leaf-page wrapper divs Phase 100 may delete).

The entity-detail drawer tabs are LOCAL `bind:activeIndex` state (not a navigation), so the global `onNavigate` hook never fires for them. Per resolved guidance O-1 / user request 99-1, honor the request with a MINIMAL LOCAL `startViewTransition` wrapper (same cross-fade, same `shouldAnimate()` gate — NOT new choreography), implemented as an opt-in `transitionOnChange` prop on the shared `Tabs` component so the results entity tabs (already navigation-driven) are unaffected.

Purpose: Covers VT-02 (expanded surface set) and the per-route marker half of NAVA11Y-02. Depends on Plan 01 for the `shouldAnimate`/`startViewTransition` helper and the active `onNavigate` coupling.
Output: `view-transition-name` placements + the local Tabs transition wrapper + heading focus markers.
</objective>
