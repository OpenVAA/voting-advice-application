<objective>
Fix the CONS-03 admin auth-reactivity production bug as the FIRST work of Phase 97 (locked decision D-01), BEFORE the codemod runs. This plan is the clean standalone first commit of the phase (D-05/D-09): it leaves `getRoute` a `Readable` store, so AdminNav's six `$getRoute('...')` template calls still build green here — they are rewritten later, atomic with the producer rewrite, in Plan 02. Two coordinated edits in separate commits (D-05):

1. **Root cause** — `adminContext.svelte.ts:97-99` spreads `...authContext` into the admin context. Object spread invokes `authContext`'s `get isAuthenticated()` ($derived) exactly ONCE at adminContext-init time and captures the boolean by value, so `adminContext.isAuthenticated` is a static value that never reacts to session changes. Replace `...authContext` with explicit delegating getters/forwards so the `$derived` stays live.
2. **Consumer symptom** — `AdminNav.svelte:32` destructures `isAuthenticated` out of the context. Per the CLAUDE.md "Context Destructuring Rule", reactive accessors must be read via `ctx.X` aliased through `$derived`, never destructured.

Purpose: Restore correct auth-state gating of the admin nav (a real production bug — the nav could show authenticated links to a logged-out user, or hide them from a logged-in one, until a hard refresh). This is V4 Access-Control display correctness, not privilege escalation (the `admin/(protected)/` routes are independently server-guarded and untouched).
Output: Two separate commits (adminContext, AdminNav); the codemod's Pass-2 audit later (Plan 02) verifies the trap count drops 2→1.
</objective>
