<objective>
Remove the `svelte/store` seam from the **app/tracking/survey/locale/darkMode layer**: drop `import { fromStore, toStore } from 'svelte/store'` from `appContext.svelte.ts` and convert every store-shaped export (`appSettings`, `locale`, `locales`, `darkMode`, `appType`, `appCustomization`, `userPreferences`, `surveyLink`/`surveyLinkStore`, `sendTrackingEvent`/`sessionId`/`shouldTrack`, `openFeedbackModal`) to pure `{ current }` (+ `set`/`update` where the producer is writable) rune handles; rewrite `appContext.type.ts` + `trackingService.type.ts` to drop `Readable`/`Writable` from `svelte/store`; and migrate the 5 app-seam route consumers (`Header.svelte`, `Banner.svelte`, `+layout.svelte` [app-seam part], `admin/+layout.svelte`, `admin/login/+page.svelte`) off `fromStore` to direct `.current` reads.

This is an **atomic producer-drop + consumer-migration unit**: `adminContext.svelte.ts` spreads `...appContext` (so admin consumers inherit the same store shapes), and the 5 route consumers call `fromStore(appSettingsStore)` etc. — the instant the producer stops returning a store, all 5 break. They MUST land in this same plan. `getRoute` is already a rune-native `{ current }` handle (CTX-08) and is NOT a store — `Banner.svelte`'s `fromStore(getRouteStore)` is the one app-seam read that just becomes `getRoute.current(...)`.

**Wave 2 / depends_on 98-01:** this plan and Plan 01 both edit `routes/+layout.svelte` (Plan 01 removes the `get` data-seam usage; this plan removes the `fromStore` app-seam usage). Sequencing after Plan 01 avoids a same-file write conflict and lets this plan remove the now-`get`-free `import { fromStore } from 'svelte/store'` line entirely.

Purpose: Close the app-layer half of CLEAN-01 (zero `svelte/store` in `lib/contexts/app/**` + the 5 consumers) while preserving auth-consuming-layout behavior — explicitly do NOT regress the CONS-03 admin-auth-reactivity fix that landed in Phase 97.
Output: Rune-native `appContext` with no store seam; 5 consumers reading `.current` directly.
</objective>
