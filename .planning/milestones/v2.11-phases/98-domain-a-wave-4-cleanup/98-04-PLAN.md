<objective>
Add the CLEAN-02 ESLint guard: a scoped `no-restricted-imports` flat-config override block in `apps/frontend/eslint.config.mjs` that bans `import ... from 'svelte/store'` in `src/lib/contexts/**` + `src/routes/**` (matches the D-02 scope), so any future reintroduction fails `yarn lint:check`. Per D-01's Claude's Discretion clause, use the built-in `no-restricted-imports` core rule (in-repo precedent at `shared-config/eslint.config.mjs:144`) rather than authoring a custom plugin — identical enforcement, ~15 lines, zero new dependency (RESEARCH "Don't Hand-Roll").

**The flat-config replacement landmine (RESEARCH Pitfall 3):** flat config REPLACES (does not deep-merge) an array-valued rule when a later config object re-declares the same rule key for a matching file. `...sharedConfig` already sets `no-restricted-imports` with the deep-relative-`lib` `patterns` ban. Because this override targets a narrower `files` glob and is placed AFTER `...sharedConfig`, its `no-restricted-imports` value REPLACES the inherited one for in-scope files. Therefore the override MUST re-include the inherited `patterns` ban (`{ regex: '^(\\.\\./){2,}lib(/|$)', message: ... }`) alongside the new `paths: [{ name: 'svelte/store', ... }]`, or contexts/routes silently lose the deep-relative-import protection.

**Wave 4 / depends_on 98-03 — MUST BE LAST:** the guard fails the lint gate on any still-present `svelte/store` import. It can only land after Plans 01-03 have driven the acceptance grep to zero (green-tree invariant). Adding it earlier would make `yarn lint:check` fail on the not-yet-cleaned files.

Purpose: Close CLEAN-02 — reintroducing `svelte/store` into a migrated context/route file fails lint; `yarn lint:check` exits 0 on the cleaned tree.
Output: A scoped `no-restricted-imports` override in the frontend ESLint flat config.
</objective>
