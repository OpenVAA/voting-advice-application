# Plan 135-01 — Dark-theme axe parity for the four fixture-driven entries

## Context

Phase 134 built one typed `AXE_ROUTES` table covering all seven scans, but only the
three `raw` entries emit a `-dark` twin. The four fixture-driven entries — `questions`
(located), `results`, `voter-detail-drawer`, `results-filter-drawer` (answered) — run
**light only**. Phase 134 recorded this in-file at `a11y-smoke.spec.ts:396-401` as a
known gap with an explicit reason: giving them dark twins scans four surfaces in dark
for the **first time ever**, so the fallout is unbounded, and it doubles a full voter
walk per entry in a suite that runs 3× at the determinism gate.

That fallout is now in scope. **This is the risky plan of the phase — do it first so
whatever it surfaces has runway.**

The dark mechanism is OS-media emulation only: `darkMode.svelte.ts` reads `matchMedia`,
there is no toggle or storage. The raw runner's existing `-dark` twin is the exact
precedent (`a11y-smoke.spec.ts:419-424`).
