# Plan 135-02 — Seeded equal-min/max question + `selectExact` standing guard

## Context

Phase 134 added `questions.multiChoice.selectExact` to the runtime catalog in all 7
locales and proved it renders correctly by importing the compiled Paraglide output and
exercising all 14 plural branches at build time. But **no seeded question has an equal
min/max**, so the running app always takes the `selectRange` branch: the key has no E2E
coverage and no standing regression guard. A future break in that string ships silently.

The existing multi-choice question `test-e2e-base-qu-opin-base-7-multichoice`
(`base.ts:867-878`) carries `minSelections: 2, maxSelections: 3` **deliberately** — it is
Phase 129 D-07 constraint edge-coverage for the range case. **Do not repurpose it.** Add a
second multi-choice question with `minSelections === maxSelections`.

The `selectExact` string at count=1 renders `Select 1 option.`; at count=2,
`Select 2 options.` Choose the exact-count value deliberately and say why — an exact-1
question also exercises the MF2 `countPlural=one` branch, which is the branch with the
constructed non-English forms and therefore the one most worth guarding.
