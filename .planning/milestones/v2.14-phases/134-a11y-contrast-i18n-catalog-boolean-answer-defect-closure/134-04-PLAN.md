<objective>
Add a cross-catalog key-set parity check to the frontend unit suite so a key added to only one of
the two i18n catalogs fails CI instead of shipping and rendering its own name (D-10).

Purpose: FIX-02 exists because `src/lib/i18n/translations/` (type generation) and
`apps/frontend/messages/` (runtime Paraglide) are independent, and adding to the former alone
type-checks. Seven real user-facing bugs lived in that gap. This ~30-line assertion closes the
class permanently.

Output: two named-direction set-difference assertions per locale in the existing i18n test file,
plus a recorded negative control proving the guard fires.

**Sequencing:** this test fails by construction until Plan 03 has landed all 7 keys. It is
deliberately in a later wave for that reason.
</objective>

  <action>
Add to the existing `translations.test.ts` — do not create a new file, and do not write a second
flattener. The host file's `flattenKeys` already treats an array value as a leaf, which is
precisely what makes Plan 03's MF2-shaped `selectExact` comparable against the string-shaped
type-gen entry; a naive recursive flattener would produce phantom keys under `match` and both
break this test and mask real drift.

Add a `translationsDir` constant beside the existing `messagesDir`, resolved through
`fileURLToPath(import.meta.url)` the same way, pointing at `..`/`translations`.

Add a `getTranslationKeys(locale)` helper that reads the locale directory, filters to entries
ending in `.json` (the directory also holds `index.ts` and `translations.type.ts`), parses each,
and flattens each with the **filename minus `.json` as the prefix**. This prefixing is load-bearing:
`translations/` is UNWRAPPED so the namespace comes from the filename, while `messages/` is WRAPPED
so its top-level key already is the namespace. Without the prefix every single key mismatches.

Add an explicitly documented `EXPECTED_MESSAGES_ONLY` set built as `lang.` + each locale code.
Document why: `messages/{locale}/lang.json` is the locale display-name catalog and has no
`translations/` counterpart by design. Do not implement this as "skip the file `lang.json`" — a
blanket file exclusion would also hide a genuine regression inside that file.

Add a `describe.each(translationLocales)` block named for catalog key-set parity holding two tests:
one asserting the set difference `translations \ messages` is empty, one asserting
`messages \ translations \ EXPECTED_MESSAGES_ONLY` is empty. Pass a message string to each
`expect` naming the direction and its consequence — the first means `t()` will render the raw key
to a user; the second means `TranslationKey` will not type the key. Assert on the array of missing
keys so the failure output is the drift itself, not a diff of two thousand-element arrays.
  </action>
