<objective>
Stop the candidate questions overview from discarding a legitimately saved boolean `false`
(FIX-03), using the same canonical emptiness predicate the completion gating 175 lines away
already uses.

Purpose: a candidate who answers a boolean opinion question "No" sees it as unanswered on the
overview — no answer readout, and an "Answer this question" primary call to action — while the
page's own completion counter already treats it as answered. That internal contradiction is the
bug's signature.

**Documented roadmap deviation (D-12, operator-approved):** the ROADMAP and REQUIREMENTS text
prescribes an explicit `== null` check. This plan uses `isEmptyValue()` instead. With `== null`,
a saved `''` or `[]` would start rendering as answered on the overview while
`unansweredOpinionQuestions` still counted it unanswered — trading one inconsistency for another.
Plan 07 corrects the roadmap wording; this deviation must also be named in the SUMMARY.

Output: one guard swapped, plus the recorded repo-wide sweep proving it is the only such guard.
</objective>
