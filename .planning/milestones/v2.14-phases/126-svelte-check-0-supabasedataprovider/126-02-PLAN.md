<objective>
Generify `toDataObject` over the row type, backward-compatibly (D-05), so typed rows (the `get_nominations` Row element, `.from()` Row types) flow through instead of being discarded at the `Record<string, unknown>` seam — while every existing call site, including the Phase-127 `supabaseDataWriter.ts` sites, keeps compiling UNCHANGED.

Purpose: The current `toDataObject(row: Record<string, unknown>, …)` seam forces provider call sites to pass `row as Record<string, unknown>`, discarding the typed row the regen (plan 126-01) makes available. A defaulted generic parameter removes that input-cast need on the provider side (a plan 126-03 cleanup) without touching the Phase-127 writer. The internal pipeline (`localizeRow` → `mapRow`) is already generic (`mapRow<TRow extends Record<string, unknown>>`), so this only widens the public seam to match.

Output: A backward-compatible generic `toDataObject` signature and updated/locked-in unit tests, with svelte-check count unchanged and unit tests green.

## Artifacts this plan produces
- New generic signature: `toDataObject<TRow extends Record<string, unknown> = Record<string, unknown>>(row: TRow, locale, defaultLocale?, additionalLocalizedFields?): Record<string, unknown>`.
- Optionally one added typed-row assertion in `toDataObject.test.ts` locking the generic.
- No new file paths; return type unchanged (`Record<string, unknown>`); no runtime change.
