# Plan 136-04 — F2: suite-wide raw-i18n-key scanner

## Context (from the sweep, §F2)

`apps/frontend/src/lib/i18n/wrapper.ts:40` returns the **raw dotted key** on a catalog miss. The
sweep cross-matched every regex in the E2E suite against all **598 English keys** and found **21
sites where the matcher is satisfied by the exact failure it guards**. The sharpest is
`voter-journey.spec.ts:1338` — `toContainText(/Yes/i)` against `common.answer.yes`, which is the
only standing check on the boolean-answer render path (Phase 134's FIX-03 territory).

**Why a scanner beats 21 site fixes:** it covers all 598 keys and every key added later. It would
have caught `selectExact` in Phase 134 without needing a seeded equal-min/max question. Site fixes
close 21 holes; the scanner closes the class.

Phase 135 established the a11y routes already walk the real surfaces in both themes (16 project
tests, 7 surfaces × 2). That walk is the natural carrier — the pages are already loaded and settled.

## Tasks

<task number="1" name="Build the raw-key scanner">
<action>
Add a helper (e.g. `tests/tests/utils/rawKeyScan.ts`) that, given a settled page, asserts no visible
text node — and no accessible name (`aria-label`, `alt`, `title`, `placeholder`) — equals or contains
a string matching the raw-key shape rendered by a catalog miss.

Derive the key set from the actual catalog rather than hardcoding a regex guess: read the runtime
Paraglide catalog (or the type-gen source) and build the set of dotted key paths, then assert none
appears in the rendered surface. Deriving from the catalog is what makes it cover future keys.

Guard against false positives: real content could legitimately contain a dot-separated token. Prefer
exact-match against the known key set over a loose `/\w+\.\w+\.\w+/` pattern, and state how you
handled any legitimate collisions you found.

Wire it into the a11y scan runners so every scanned surface is checked — the pages are already
loaded and settled there, so the marginal cost is a DOM read.
</action>
<read_first>
- apps/frontend/src/lib/i18n/wrapper.ts (line ~40 — the raw-key fallback behaviour)
- tests/tests/specs/a11y/a11y-smoke.spec.ts (the AXE_ROUTES table and the three runners)
- .planning/audits/2026-08-11-fake-guard-sweep.md (§F2 — the 21 sites and the method used to find them)
- apps/frontend/messages/en/*.json (the runtime catalog shape)
</read_first>
<acceptance_criteria>

</acceptance_criteria>
</task>
