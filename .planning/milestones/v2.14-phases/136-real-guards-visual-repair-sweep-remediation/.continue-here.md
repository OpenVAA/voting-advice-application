# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each was discovered through actual failure this session.
> Acknowledge each explicitly before proceeding.

- [ ] **CONSTRAINT: Port identity by process type is defeated.** "Assert the :5173 listener is a `node` process" (Phase 135 DEF-135-03) is INSUFFICIENT — a foreign Vite dev server from an unrelated project (`~/Desktop/Treader/treader/apps/web`) IS a node process, passed the check, and two full runs silently scanned a page reading *"An example document"*. **Mitigation:** assert the served application by response content — `curl -s http://localhost:$PORT/ | grep -q '<title>Election Compass</title>'`. `FRONTEND_PORT` is honoured. A false-green from a foreign server is undetectable after the fact: report, counts and assertions all look normal.

- [ ] **CONSTRAINT: A guard derived from the thing it guards can be self-defeating.** The raw-i18n-key scanner was first built deriving its expected key set from the runtime catalog. Deleting a key removed it from the scanner's expectations at the same instant the app began rendering it raw — the scan went GREEN on the exact defect it exists to catch. **Mitigation:** the key set is now the UNION of runtime catalog + type-gen source + generated `TranslationKey`. Generally: whenever a guard derives its expectation from a source that a real regression would also mutate, the derivation must be widened or cross-checked. **This class is not limited to i18n — check any derived expectation set.**

- [ ] **CONSTRAINT: A guard is not known to be a guard until observed failing.** Every plan in phases 134–136 required a negative control, and they repeatedly changed the outcome: it broke the scanner design above; it showed the old perf budget did not move at all (55ms) under an injected regression that moved the new metric 441→6993ms; it showed 11 subset matchers passed a no-op filter (17 vs 25 failures under an identical stub); it showed the F14 matcher had drifted from reality because it had never been exercised. **Mitigation:** never mark a guard done on a passing run alone.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Process-identity port check | A foreign dev server passes "is it node?"; two runs scanned the wrong app | blocking | Assert served-app response content, not process type |
| Self-defeating derived guard | Expectation set derived from a source a real regression also mutates → green on the defect | blocking | Union/cross-check the derivation; add a floor (e.g. `MIN_EXPECTED_KEYS`) so an emptied set fails loudly |
| Guard accepted without a negative control | Assertion passes today, cannot fail tomorrow | blocking | Inject the regression, observe the failure, revert, re-confirm green |
| Threshold bump as flake "fix" | Raising 10000ms preserves the flaky shape, moves the goalposts | advisory | Assert work done (operation counts), not elapsed time |
| Ambient `.env` masking a CI skip | `dev-seed`'s barrel calls `process.loadEnvFile` at module scope, so the integration test ran locally by accident while CI silently skipped for phases | advisory | Reproduce CI conditions (move `.env` aside) before trusting a local green |
| Bare `npx playwright test` | Pulls in the perm-seeded `_probes` project (needs out-of-band seeding) → spurious failures | advisory | Use the canonical `yarn test:e2e` (carries `--grep-invert @probe`) |
| `setsid` on macOS | Absent; a backgrounded runner woke later and launched a SECOND concurrent suite against the same DB, producing a garbled "failure" | advisory | A `mkdir` lock was added; discard and restart the count on any concurrency doubt |
