# Phase 129 — UI Design Contract

> Visual and interaction contract for the new question-input components (MultipleText,
> number-scale slider, multi-choice categorical), the alliance card render, and the
> `/nominations` fetch. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase extends an existing, mature design system** (SvelteKit + Tailwind v4 + DaisyUI,
> Inter font, `staticSettings` DaisyUI theme tokens). The token sections below **document the
> established contract** the new surfaces must obey — they are NOT a redesign. The load-bearing
> new content is in **Component & Interaction Contracts** and **Locator Contract** (the 129.2
> mandate). Do not re-specify or re-theme what the codebase already ships.

## Spacing Scale

The project uses **Tailwind's default 4px-based scale** via utility classes (`gap-*`, `p-*`, `m-*`, `h-32`,
`w-32` = 8rem etc. — Tailwind numbers are 0.25rem units, i.e. multiples of 4px). Declared tokens the
new inputs must use (Tailwind class → px):

| Token | Value | Tailwind | Usage in this phase |
|-------|-------|----------|---------------------|
| xs | 4px | `gap-1` / `p-1` | Inline icon-to-label gap inside a row control |
| sm | 8px | `gap-2` / `p-2` | Gap between a MultipleText row's input and its remove/reorder buttons; checkbox-to-label gap |
| md | 16px | `gap-4` / `p-4` | Default vertical gap between MultipleText rows; between slider and its value label |
| lg | 24px | `gap-6` / `p-6` | Padding around the input group / question body |
| xl | 32px | `gap-8` | Section breaks |
| 2xl | 48px | `gap-12` | Major section breaks |
| 3xl | 64px | `gap-16` | Page-level spacing |

Exceptions:
- **Existing choice-input control size is `h-32 w-32` (Tailwind `32` = 128px) radios** in `QuestionChoices` (`QuestionChoices.svelte:262`). The new **checkbox** multi-select mode MUST reuse this exact control box size so radio and checkbox modes are visually identical — this is a preserve-not-redesign constraint, not a new token.
- **Touch targets ≥ 44×44px** for all new interactive controls (remove-row button, reorder buttons, slider thumb, checkbox) — WCAG 2.1 AA target size. Icon-only Buttons use `variant="icon"` which already satisfies this.

## Typography

Inter, **two weights only** (400 regular / 700 bold — the only weights the font URL loads). Sizes are
DaisyUI/Tailwind utility classes already in use; the new surfaces must reuse these existing roles rather
than introduce new sizes.

| Role | Size | Weight | Line Height | Applied via |
|------|------|--------|-------------|-------------|
| Body | 16px | 400 | 1.5 | default (`text-base`) — slider value label, MultipleText row inputs, choice labels |
| Label | 14px | 400 | 1.4 | `small-label` / `text-sm` — checkbox choice text (matches existing `QuestionChoices` `small-label`), min/max helper text |
| Heading | 20px | 700 | 1.2 | `text-lg`/`text-xl` bold — question title (existing, unchanged) |
| Display | 28px | 700 | 1.2 | `text-2xl`+ bold — page/section headings (existing, unchanged) |

Weights: **regular 400, bold 700** — do not introduce 500/600 (not loaded). Emphasis = 700 or a
semantic color, never an unloaded intermediate weight.

## Color

DaisyUI semantic tokens from `staticSettings.colors` (light / dark pairs). The new surfaces reference
tokens by DaisyUI class (`bg-base-100`, `text-primary`, `radio-primary`, `range-primary`, `btn-warning`),
never literal hex. 60 / 30 / 10 mapping:

| Role | Value (light / dark) | Usage |
|------|----------------------|-------|
| Dominant (60%) | `base-100` `#ffffff` / `#000000` | Page + input-group background, row input fields, unselected control fill |
| Secondary (30%) | `base-200` `#e8f5f6` / `#101212`, `base-300` `#d1ebee` / `#1f2324` | Cards (EntityCard incl. alliance), member-org subcards, selected-row backgrounds, section surfaces, `line-color` borders (`#d9d9d9` / `#262626`) |
| Accent (10%) | `primary` `#2546a8` / `#6887e3` | See reserved list below |
| Destructive | `warning` `#a82525` / `#e16060` | Remove-row / delete-answer affordances only |

Accent (`primary`) reserved for — **explicit list, nothing else**:
- Primary CTA / main action button (`Button variant="main"` → `btn-primary`)
- **Selected** state of a radio OR checkbox choice (`radio-primary` / `checkbox-primary`)
- Number-scale **slider fill + thumb** (`range-primary`) and its live value label when set by the voter
- **Match-score gauge** on entity cards incl. the alliance card (existing `MatchScore` — unchanged)
- The **"You" / voter answer marker** in display mode (`text-primary`, existing convention in `QuestionChoices` display mode)

Secondary semantic color: the DaisyUI `accent` token (`#0a716b` teal) exists but is used sparingly by
the existing app; **do not introduce new `accent`-token usages in this phase** — the interactive accent
is `primary`. `warning` is the only destructive/error semantic color.

## Copywriting Contract

All copy is **localized** — new keys land in `apps/frontend/src/lib/i18n/translations/<locale>/*.json`
for **every** supported locale. `staticSettings.supportedLocales` = **en, fi, sv** (source of truth);
translation dirs also present and maintained: `da, et, fr, lb`. New keys go under `questions.*`
(opinion/choice inputs) and a new `input.multipleText.*` group (info input). Reuse existing keys where
present — do NOT duplicate.

| Element | Copy (en; other locales required) | Key |
|---------|-----------------------------------|-----|
| MultipleText add-row CTA | "Add item" | `input.multipleText.add` (icon `addToList`, `Button variant="normal"`) |
| MultipleText remove-row control | "Remove item" (aria-label / title on icon-only button) | `input.multipleText.remove` (icon `removeFromList`, `variant="icon"`, color `warning`) |
| MultipleText reorder controls | "Move up" / "Move down" (aria-label on icon-only buttons) | `input.multipleText.moveUp` / `input.multipleText.moveDown` |
| MultipleText empty row placeholder | "" (empty; rows dropped on save) | reuse `Input` placeholder convention |
| Multi-choice range helper (both bounds) | "Select {min} to {max} options." | `questions.multiChoice.selectRange` (ICU: shown when `min !== max`) |
| Multi-choice range helper (exact) | "Select {count} options." | `questions.multiChoice.selectExact` (ICU: shown when `min === max`) |
| Primary CTA — candidate (opinion input) | reuse existing candidate **Save** button label (`candidateApp.*` `save`) — disabled while multi-choice selection is outside min/max (D-07) | existing key, no new copy |
| Primary CTA — voter (opinion input) | reuse existing **Skip** (`questions.skip` = "Skip") — voter action button stays "Skip" while selection is outside min/max (D-07) | existing `questions.skip` |
| Empty state — MultipleText (no values, candidate) | one empty row rendered (or `min` rows if `min > 1`) — no empty-state text needed; the row IS the affordance | n/a (affordance-as-empty-state) |
| Empty state — MultipleText (voter, entity-detail info tab, no values) | reuse existing entity-detail "no answer" convention (`questions.answers.youHaventAnswered` / `entityHasntAnswered` pattern) | existing keys |
| Empty state — alliance section (no alliance nominations for voter's scope) | section not rendered (tab absent) — matches existing per-type results section behavior; no new copy | n/a (existing behavior) |
| Error state — unsupported/failed input | reuse existing inline `error.unsupportedQuestion` fallback (the new branches REMOVE this for number/multi-choice/MultipleText) | existing `error.*` |
| Destructive — remove MultipleText row | Inline, **no confirmation dialog** (single-field, non-destructive to persisted data until save; consistent with existing per-row removal). Below-`min` deletion is **prevented** (button disabled), not confirmed. | — |
| Destructive — delete opinion answer | reuse existing `questions.remove` ("Delete answer") + existing `QuestionActions` delete flow — unchanged | existing `questions.remove` |

**Destructive actions in this phase:** row removal (MultipleText) and answer deletion (opinion). Neither
introduces a NEW confirmation pattern — row removal is inline + reversible-before-save and gated by `min`;
answer deletion reuses the shipped `QuestionActions` flow. No new modal confirmations are added.

## Component & Interaction Contracts

> The load-bearing output of this phase. Each contract binds the executor to a concrete, testable surface.

### C-1 — MultipleText input (UNBLK-01, info dispatch: `QuestionInput.svelte`)
- **Layout:** vertical stack of rows (`gap-4`). Each row = one `Input` (text) + a trailing control cluster (`gap-2`): reorder-up, reorder-down, remove — all `Button variant="icon"`.
- **Value binding:** `Array<string>` via the data class `_ensureValue`; empty rows dropped on save.
- **Add:** a full-width-left `Button variant="normal" icon="addToList"` labelled `input.multipleText.add`, below the last row, appends an empty row.
- **Remove:** per-row icon button (`removeFromList`, color `warning`). Disabled when removing would drop the count below `min` (D-02).
- **Reorder:** up/down icon buttons per row (net-new UI — no existing drag/reorder affordance in the codebase; **buttons, not drag**, for keyboard accessibility and simplicity). Up disabled on first row, down disabled on last. Reordering allowed even at `min` rows.
- **Min/max (D-02):** read from `customData.Question` keys (`minItems` / `maxItems` — researcher recommendation; planner confirms key shape). `min > 1` → render `min` rows initially, prevent deletion below `min`. `max` reached → disable/hide Add.
- **Scope:** candidate INFO questions only; voters see rendered values on the entity-detail info tab (read-only, existing render path).

### C-2 — Number-scale opinion input (UNBLK-05, `OpinionQuestionInput.svelte` new branch)
- **Control:** native `<input type="range">` (DaisyUI `range range-primary`) spanning the question's `min`–`max` (`NumberQuestion.min/max`). **Native range chosen** so keyboard-arrow exact-value stepping works for free (the Phase-130 boundary test drives exact values — hard contract, D-03).
- **Value label:** live numeric value rendered adjacent to the slider (`text-base`, `text-primary` when voter-set); updates on `input`.
- **Step:** integer step by default (`step=1`) unless the question declares otherwise; arrow keys move exactly one step.
- **Display mode (D-04):** same slider rendered **read-only** (`disabled`) with **two markers** — voter value and entity value — mirroring how `QuestionChoices` display mode shows `yourAnswer` (`text-primary`) and `otherLabel`. Reused by `EntityOpinions` via `mode='display'`. EQTYP-02 asserts this in Phase 130.
- **Persistence:** coerce `valueAsNumber` → JS number (existing `Input.svelte:319-322` pattern) → route through `Question.ensureValue` before persist (V5 input validation; backend `validate_answer_value` requires a JSON number).

### C-3 — Multi-choice categorical opinion input (UNBLK-02, `QuestionChoices.svelte` new mode)
- **Extend, do not fork:** add a **checkbox-semantics multi-select mode** to `QuestionChoices` (parallel `selected: Array<Id>` state + own change-dispatch), reusing the existing layout, `h-32 w-32` control box, display-mode scaffolding, and vertical/horizontal grid.
- **Control:** `<input type="checkbox" class="checkbox checkbox-primary …">` replacing the radio; **selected → `checkbox-primary` (primary accent)**.
- **Locator preservation (contract):** each checkbox input MUST keep `data-testid="question-choice"` (currently `QuestionChoices.svelte:270`) — Phase-130 fixtures depend on it. The container keeps `data-testid="question-choices"`.
- **Min/max (D-07):** optional `customData.Question` keys (`minSelections` / `maxSelections`). When set, render localized helper text (`questions.multiChoice.selectRange` / `selectExact`) as a `small-label` below the group. **Zero selections = unanswered** by default.
- **Candidate vs voter divergence (D-07 — do NOT hard-disable inside the shared component):** surface selection-validity to the caller. Candidate app: **Save disabled** while outside min/max. Voter app: action button stays **Skip** while outside min/max. The shared `OpinionQuestionInput` must expose validity (prop/callback), not gate internally.
- **Display mode:** show `yourAnswer` marker(s) for all voter-selected choices and `otherLabel` for entity-selected choices, reusing the existing display-label pattern.

### C-4 — Alliance card render (UNBLK-06, **seed-only per RESEARCH** — no component build)
- **No new component.** Research pinned the residual gap to a single missing array element: `results.sections` in `e2e/base.ts:214` lacks `'alliance'`. Adding `'alliance'` **as the LAST element** (after `'organization'`, preserving the Org-first imputation cascade) makes the existing Phase-69 alliance card render automatically.
- **Visual contract the seed change must produce (verify at D-10):** alliance appears as an `EntityCard` in a results section/tab; card shows the **match-score gauge** (`MatchScore`, via the org→alliance imputation cascade under `organizationMatching: 'impute'` — free, D-09); member orgs render as **clickable in-card children** subcards; the **member-orgs drawer** (EntityDetails children tab) works. Summary line "X candidates across N parties" renders (existing `getAllianceSummary`).
- **Out of scope (leave the TODO):** alliance **submatches** do not render (`showSM` only computed for candidate/organization, `EntityCard.svelte:125-137`) — explicitly NOT blocking the D-09 minimum. Do not build submatch display.
- **Do NOT redesign** any Phase-69 surface (card branch, drawer, results tab). Spec is verify-only for these.

### C-5 — `/nominations` fetch (UNBLK-04) — no visual surface
- Loader-only change (`(voters)/nominations/+layout.ts` adds `getQuestionData({ locale })`). No new UI; existing all-nominations render consumes the now-present question data. Included here for completeness — no design contract needed.
