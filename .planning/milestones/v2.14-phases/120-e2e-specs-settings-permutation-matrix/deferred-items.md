
## DEF-120-03-01 — feedback rate-limit not reset by data-teardown-base (test-isolation gap)

**Found during:** Phase 120 Plan 03, Task 3 (3× determinism gate).
**Issue:** Running `voter-journey` back-to-back via the Playwright project chain (which only re-seeds via `data-setup-base`/`data-teardown-base`, NOT a full DB reset) flakes on the feedback step: the submit button reaches `data-status="error"` instead of `"sent"`. Root cause is the feedback rate-limit trigger `public.check_feedback_rate_limit` (`apps/supabase/supabase/schema/107-feedback.sql:39-94`) — **5 inserts per 5-minute window per client IP**, counter stored in `private.feedback_rate_limits`. voter-journey submits 2 feedbacks per run; across ≥3 consecutive runs sharing localhost IP the counter exceeds 5 within the 5-min window → insert rejected → `error` status (the component's own `ERROR_TIMEOUT=5000` is a red herring; the insert is actively rejected, not slow). `private.feedback_rate_limits` is NOT in the `test-e2e-base-` seed namespace so `runTeardown` never clears it.
**NOT caused by this plan:** the failure is in the pre-existing feedback step (~line 1189), untouched by the EPERM-04/05 edits (lines ~854-1000). A full `yarn db:reset` between runs (the Task-3-specified "clean DB" discipline) clears `private.feedback_rate_limits` and the gate is 3× GREEN.
**Why deferred:** the proper fix is a schema/test-harness change (e.g. a SECURITY DEFINER `public.e2e_reset_feedback_rate_limits()` RPC truncating `private.feedback_rate_limits`, called from `base.teardown.ts`) — out of scope for a test-authoring plan and borderline Rule 4 (schema change). The 3× determinism standard is satisfied with `yarn db:reset` between runs per the Plan-03 Task-3 contract.
**Fix sketch:** add `public.e2e_reset_feedback_rate_limits()` (SECURITY DEFINER, `TRUNCATE private.feedback_rate_limits`) + a `client.rpc('e2e_reset_feedback_rate_limits')` call in `tests/tests/setup/shared/base.teardown.ts` so the re-seed (no full DB reset) path is also clean.

## DEF-120-06-01 — organisation own-answers do not yield a distinct `answersOnly` org match score (behavioural finding)

**Found during:** Phase 120 Plan 06, Task 2 (capturing the live per-mode org scores for EPERM-10).
**Issue:** EPERM-10 predicted three DISTINCT org scores for `matching.organizationMatching` (none = no/0 score, answersOnly ≈ 25% from the org's own partial answers with blanks penalised polar-opposite, impute ≈ 75% member-imputed). The seed (`perm-org-matching.ts`) was designed for this and the DB confirms OR1's own answers (q1='5', q2='1') ARE imported. But the live app renders OR1 at **0% under BOTH `none` and `answersOnly`** and **67% under `impute`** — the organisation's own partial answers do NOT produce a non-zero direct (non-imputed) org match; only imputation (member answers filling the org) yields a non-zero score.
**Root cause (UNCONFIRMED):** the direct org match path (`matchState.svelte.ts` `answersOnly`/`none` branches both skip imputation, match `targets = nominations`) appears not to surface the organisation's own `answers` into the matchable position → the org reads as fully-missing (max distance → 0%). Whether this is an org-answer-loading gap in the Supabase adapter / `data`-package Nomination wiring, or intended behaviour, needs a matching/data-layer investigation.
**Why deferred:** out of scope for a test-authoring phase (Rule 4 — would require a behavioural/architectural change to the matching or adapter layer, not a test fix). The EPERM-10 spec asserts the ACTUAL deterministic matrix (none=0, answersOnly=0, impute=67) and preserves the distinguishability contract: impute≠none/answersOnly at the score layer, none≠answersOnly/impute at the About-page disclosure layer.
**Fix sketch:** verify whether org `answersByExternalId` reach the org Nomination's matchable position in the voter-app adapter; if not, wire org own-answers into the direct (non-imputed) match so `answersOnly` produces a distinct score from `none`. Then re-baseline the EPERM-10 score assertions (likely answersOnly→25, impute→75 per the original seed design).
