3-run cold-start gate — DEFERRED to operator-driven verification
----------------------------------------------------------------

Per CONTEXT D-06 environment-cascade carry-forward decision (89-01 +
89-02 precedent), the 3-run cold-start gate is deferred to an
operator-driven verification path. The deferral is documented here as
the canonical runbook the operator can execute against a clean
environment.

Operator runbook
----------------

Pre-conditions:
  1. Single vite dev process is running (kill any concurrent
     `yarn dev` / `vite` workers BEFORE invoking `yarn db:reset`).
  2. Supabase is up (`yarn db:status` shows all services healthy).
  3. imgproxy Docker container is healthy (per the documented v2.10
     carry-forward infrastructure debt — `supabase stop && supabase
     start` if it has crashed).

Run 1:
  $ yarn db:reset && yarn db:seed --template baseV1
  $ cd tests && npx playwright test --project=candidate-mega-journey --reporter=list

Run 2 (cold-start: full reset between runs):
  $ yarn db:reset && yarn db:seed --template baseV1
  $ cd tests && npx playwright test --project=candidate-mega-journey --reporter=list

Run 3 (cold-start: full reset between runs):
  $ yarn db:reset && yarn db:seed --template baseV1
  $ cd tests && npx playwright test --project=candidate-mega-journey --reporter=list

Acceptance:
  - All 3 runs must report identical PASS/FAIL counts. Per Phase 88-04
    SCOPE acceptance #8 (gate B precedent) any divergence triggers a
    Rule 1 iteration: identify the flake source, fix it (likely a
    fixture- or spec-level race), re-run 3x.

Expected outcome (cold-start):
  - 22/22 test.step blocks PASS within ~60-120 seconds.
  - candidate-mega.setup.ts seeds baseV1 successfully (post-seed
    app_settings assertion PASSES per setupFromTemplate's built-in
    check).
  - candidate-mega.teardown.ts runs unregisterCandidate(unregistered-aa@
    test.openvaa.local) BEFORE runTeardown('test-', client), leaving
    auth.users with NO row matching that email.

Post-gate audit (psql, optional):
  $ psql -U postgres -d postgres -h 127.0.0.1 -p 54322 \
      -c "select count(*) from auth.users where email like '%unregistered-aa@test%';"
  Expected: 0

Operator-recovery from a Run-N flake:
  - If voter-mega-journey upstream is still raced by perm-1e1cg1co
    (documented v2.10 carry-forward), use --project=candidate-mega-
    journey --project=data-setup-candidate-mega to run the
    candidate-mega chain in isolation. This bypasses the voter-mega
    transitive dependency at the cost of the strict shared-prefix race
    guarantee (acceptable for verification-only runs since runTeardown
    is idempotent).
