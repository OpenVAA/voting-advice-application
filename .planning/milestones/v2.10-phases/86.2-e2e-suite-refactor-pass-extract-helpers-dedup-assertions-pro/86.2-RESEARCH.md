## Helper API Trade-offs (Question 3 answer)

CONTEXT.md sketches helper signatures but defers final API to Plan 86.2-01. Below are
the trade-off resolutions informed by anchor-site needs:

### Helper #1 — `settleNetworkIdle` / `gotoAndSettle`

**Should `gotoAndSettle` accept a `waitUntil` option?** YES. Anchor sites use both
`'networkidle'` and `'domcontentloaded'`:

- `candidate-profile-validation:97,203` → `'networkidle'`
- `voter-not-located-redirect:132` → `'domcontentloaded'`
- `voter-results.spec.ts:410,429,479` → `'domcontentloaded'`
- `candidate-settings.spec.ts:707,735` → `'domcontentloaded'`

**Recommended signature:**
```ts
export async function settleNetworkIdle(
  page: Page,
  opts?: { waitUntil?: 'load' | 'domcontentloaded' | 'networkidle'; timeoutMs?: number }
): Promise<void>;

export async function gotoAndSettle(
  page: Page,
  url: string,
  opts?: { waitUntil?: 'load' | 'domcontentloaded' | 'networkidle'; timeoutMs?: number }
): Promise<void>;
```

Default `waitUntil`: `'networkidle'` (matches the primary 86.1 anchor at
`candidate-profile-validation:97,203`). Default `timeoutMs`: `10_000` (matches
anchor). Helper does NOT swallow timeouts (`.catch(() => null)`) by default — caller
opts in via `.catch(...)` post-call if needed (preserves the existing
`candidate-profile-validation:97` semantic where the post-login catch is intentional).

### Helper #2 — `expectLandedOn` / `assertOnRoute`

**Should `expectLandedOn` accept RegExp only or RegExp + string?** RegExp + string +
URL-predicate function — matches Playwright's `toHaveURL` signature exactly. Survey of
the 28 `toHaveURL` call sites shows mostly RegExp + occasionally string (e.g.,
`candidate-password:103: new RegExp(loginUrl)`). No call site uses URL-predicate
functions today, but exposing the option keeps the helper signature aligned with
`toHaveURL`.

**Recommended signature:**
```ts

  pattern: RegExp | string,
  opts?: { timeoutMs?: number }
): Promise<void>;
```

Default `timeoutMs`: `10_000` (matches majority of anchor sites). Helper just delegates
to `expect(page).toHaveURL(pattern, { timeout: opts?.timeoutMs ?? 10_000 })`.

### Helper #3 — `clickAndRaceSettle`

**Should `destinationPredicate` be RegExp only, or RegExp + string + `(url) => boolean`?**
Survey: `voter-matching:194-198` uses a URL-change predicate `(url) => url.toString()
!== urlBefore` AND a regex `/\/results/`. The pattern is "race vs ANY URL change vs
specific destination." Playwright's `waitForURL` accepts all three forms natively.

**Recommended signature:**
```ts
type UrlPredicate = string | RegExp | ((url: URL) => boolean);

export async function clickAndRaceSettle(
  locator: Locator,
  destinationPredicate: UrlPredicate | Array<UrlPredicate>,
  opts?: { clickTimeoutMs?: number; settleTimeoutMs?: number }
): Promise<void>;
```

If `Array<UrlPredicate>` is provided, helper races ALL predicates (matches the
`voter-matching:194-198` pattern of racing URL-change AND specific destination).
Default timeouts: `clickTimeoutMs: 3_000`, `settleTimeoutMs: 5_000` (matches anchor).
The `.catch(() => null)` swallow on the inner click matches the anchor's "stuck click"
defense; helper applies this internally because all anchor uses share the pattern.

### Pattern 1: Free-function helper (NOT class-based)

**What:** Helpers are free functions taking `Page` or `Locator` as the first argument,
returning `Promise<void>` (or a meaningful value). They are NOT classes; they do NOT
wrap state.

**When to use:** Any thin Playwright-API wrapper that has no per-instance state.

**Example:**
```ts
// tests/tests/helpers/settle.helper.ts
//
// Source: distilled from
//   - tests/tests/specs/candidate/candidate-profile-validation.spec.ts:97,203
//   - tests/tests/specs/voter/voter-not-located-redirect.spec.ts:132
// Inherits Phase 83 DETERM-07b hydration-completeness guard pattern.
import type { Page } from '@playwright/test';

type WaitUntil = 'load' | 'domcontentloaded' | 'networkidle';

export async function settleNetworkIdle(
  page: Page,
  opts: { waitUntil?: WaitUntil; timeoutMs?: number } = {}
): Promise<void> {
  await page.waitForLoadState(opts.waitUntil ?? 'networkidle', {
    timeout: opts.timeoutMs ?? 10_000
  });
}

export async function gotoAndSettle(
  page: Page,
  url: string,
  opts: { waitUntil?: WaitUntil; timeoutMs?: number } = {}
): Promise<void> {
  await page.goto(url);
  await settleNetworkIdle(page, opts);
}
```

### Pattern 2: Barrel re-export

**What:** A single `index.ts` re-exports every named helper from the per-domain files.
Callers import from `'../helpers'` (or `'@helpers'` if a path alias is configured).

**When to use:** Always for the per-domain split — keeps caller imports tidy.

**Example:**
```ts
// tests/tests/helpers/index.ts
export { settleNetworkIdle, gotoAndSettle } from './settle.helper';
export { expectLandedOn, clickAndRaceSettle } from './navigation.helper';
export { iterateSelectOptions } from './select.helper';
export { assertDbRowCount } from './db-precondition.helper';
export { walkVoterIteration } from './voter-iteration.helper';
```

### Anti-Patterns to Avoid

- **Stateful helper classes.** A `SettleHelper` class with `new
  SettleHelper(page).settle()` is over-engineering. Plain free functions match
  Playwright idioms.
- **Helpers that hide important assertions.** A helper that internally calls `expect`
  is OK ONLY if the assertion is the helper's primary purpose (helper #2
  `expectLandedOn` is fine; helper #1 `settleNetworkIdle` should NOT internally
  assert anything beyond the settle).
- **Helpers that depend on page-object instances.** Helpers take `Page` / `Locator`,
  not `QuestionsPage`. Keeps helpers reusable across page-object hierarchies.
- **Catch-all error swallowing inside helpers.** The `.catch(() => null)` pattern at
  `candidate-profile-validation:97` is the CALLER's decision (defensive); helpers
  should NOT swallow internally — they should let timeouts surface so the caller
  diagnoses.
- **Helpers that mutate the test seed.** Helper #5 reads via `findData`; it does NOT
  mutate. This boundary keeps refactors safe.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| URL-landing assertion | Custom polling loop | `expect(page).toHaveURL(pattern, { timeout })` | Playwright's built-in handles retry semantics, error formatting, and trace integration |
| Network-idle settle | Custom `setTimeout` + `expect.poll` | `page.waitForLoadState('networkidle')` | Built-in tracks the actual network state; custom timer races against pending requests |
| Click + race against navigation | Custom event listeners | `Promise.race([locator.click(), page.waitForURL(pattern)])` | Built-in `waitForURL` and `locator.click` compose cleanly with `Promise.race`; custom event wiring is fragile across SvelteKit transitions |
| Combobox iteration | DOM-query-based loop | `getByRole('combobox')` + `.nth(i)` | ARIA-roles are the canonical Select.svelte contract (Phase 86.1 RCA); raw DOM queries break when Select.svelte refactors |
| DB row-count assertion | Direct `supabase-js` query | `SupabaseAdminClient.findData(table, filter)` | Existing client handles auth, retries, and error normalization; bypassing it loses telemetry and silent-failure diagnostics |
| Voter-app journey traversal | Custom `for` loop inline | `walkVoterIteration` (helper #6) or `voterNavigation.ts` walkers | Auto-detects category-intro pages; handles Skip-Next budget; survives sibling-spec settings mutation |
| 3-run SHA-identity verdict | Custom diff tooling | `sha-identity-runner.mjs` (verbatim fork from Phase 86) | Lineage from Phase 79 D-11; semantics match `regen-constants.mjs categorizeStatus()`; ALMOST-STRICT fallback is operator-authorized |

**Key insight:** Phase 86.2's helpers are deliberately THIN — they exist to **dedup

## Common Pitfalls

### Pitfall 1: Helper #1 swallowing timeouts changes semantic

**What goes wrong:** If `settleNetworkIdle` internally does `.catch(() => null)`, the
`candidate-profile-validation:97` semantic is preserved by accident — but
`candidate-profile-validation:203` (which does NOT catch) suddenly tolerates timeouts
silently. Hidden flakes.

**Why it happens:** Helper authors are tempted to "make the helper defensive."

**How to avoid:** Helper does NOT catch; callers add `.catch(() => null)` post-call
where needed. Plan 86.2-01 must verify each anchor-site replacement preserves the
original catch/no-catch semantic per-site.

**Warning signs:** A flake in `candidate-profile-validation:203` post-refactor that
wasn't present pre-refactor — caused by helper's internal catch silently masking the
networkidle timeout.

### Pitfall 2: Helper #4 ARIA-role drift

**What goes wrong:** Helper #4 hardcodes `'listbox'` as the role to wait for. If
`Select.svelte` is refactored in the future, the role might change.

**Why it happens:** ARIA-role contracts aren't enforced by TypeScript; the helper has
no compile-time link to `Select.svelte`.

**How to avoid:** Document the ARIA-role dependency in the helper docstring:
`@requires Select.svelte rendering combobox + listbox per Phase 86.1-RCA`. Reference
the spec line `1e-Nc.spec.ts:61-62` which documents the contract.

**Warning signs:** Mass flake in all combobox-iterating specs after a frontend Select
refactor — easily traced to helper #4 via stack trace.

### Pitfall 3: Helper #6 maxSteps default changes the fixture contract

**What goes wrong:** Helper #6 default `maxSteps: 6` matches the Phase 86.1-01 bump.
If a future contributor "tidies up" the default to `5`, the fixture
silently regresses to a state where sort-19+ non-Likert questions cause timeouts.

**Why it happens:** Lineage of the 3 → 6 bump is captured in `voter.fixture.ts:97-122`
comment block; the helper file's own block-comment must replicate this lineage.

**How to avoid:** Helper #6 docstring MUST cite Phase 86.1-01 + the sort-17/18/19
non-Likert opinion-question types. Reference `packages/dev-seed/src/templates/e2e.ts:666`
where the number question is defined.

**Warning signs:** `voter-app` cluster #2 reopens with the same fixture-loop-stall
symptoms documented in `85-04-SUMMARY.md` cluster #2.

### Pitfall 4: Plan 86.2-02 propagates a helper to a site with extra logic

**What goes wrong:** A spec uses `waitForLoadState('networkidle')` AND a custom
`expect.poll` after it. Plan 86.2-02 replaces the `waitForLoadState` with helper #1
but the poll-after-settle becomes redundant — propagation creates a behavioral diff.

**Why it happens:** Per-line replacement without reading the surrounding logic.

**How to avoid:** Plan 86.2-02 task verify steps must run per-spec smoke after EACH
file replacement. Per-site judgment is mandatory; CONTEXT explicitly permits leaving
sites inline with a `// reason:` comment when the inline code has extra logic.

**Warning signs:** Per-spec smoke fails post-replacement on a file that was
previously green. Plan 86.2-02 must revert the replacement and add a `// reason:`
inline annotation.

### Pitfall 5: 3-run gate uses wrong seed for the bump-aware fixture

**What goes wrong:** Plan 86.2-03 invokes `yarn db:reset && yarn dev:clean` but does
NOT apply `--likert-only`. The voter.fixture's 6-iteration Skip-Next loop covers
sort-17/18/19 non-Likert questions, so the default e2e seed (with non-Likert
questions present) MUST work — but if the operator unintentionally passes
`--likert-only`, the comparison anchor would be against a different dataset.

**Why it happens:** CLAUDE.md "Common Workflows" canonical Likert-only chain caveat
flags this exact issue.

**How to avoid:** Plan 86.2-03 explicitly invokes `yarn db:reset` WITHOUT `--likert-only`
(matching Phase 86.1-04 Task 2's invocation). The 3-run gate runs against the default
e2e seed (mixed Likert + non-Likert opinion questions) because the fixture's bump
handles this case by design.

**Warning signs:** 3-run gate produces a different SHA than the pre-86.2 anchor;
diff shows voter-detail / voter-results cells passing/failing inconsistently.

### Pitfall 6: Forgetting D-08 `git -c core.hooksPath=/dev/null` on a commit

**What goes wrong:** A Plan 86.2-0X task commits without the hook bypass; pre-commit

**Why it happens:** Per memory `project_gsd_repo_hook_workaround.md`, global git
