## Phase Boundary

Extract reusable helpers and propagate the 15 `Phase 86.1 post-fix` annotations
(scattered across 9 files: `playwright.config.ts`, `voter.fixture.ts`,
`variant-startfromcg.ts`, 6 spec files) into a coherent helper layer in
`tests/tests/helpers/` so Phase 86.3 (and subsequent suite maintenance) can
re-use the patterns instead of re-inventing them inline.

**This is a test-infrastructure-only refactor phase, not a feature or bug-fix phase.**

Scope:
1. Extract 6 helpers from the 86.1 post-fix patterns.
2. Propagate the helpers across the existing suite (replace inline workarounds
   with helper calls where the pattern actually applies — not every site).
3. Verify SHA-identity against the post-86.1 / post-87-post-fix anchor — no test
   outcome should change.

**Out of scope:**
- Authoring new tests (Phase 86.3 owns that).
- Un-skipping source-skipped tests (Phase 86.3 owns that).
- Touching `97f55cb41 chore(87-post-fix)` work — that commit is treated as
  final (D-02). 86.2 builds on top of current HEAD.
- Production-code (`apps/frontend/**`) changes.
- Playwright 1.58.2 → 1.59+ upgrade.
- New page-object methods or fixture refactors beyond what helper extraction
  requires (page-objects stay as-is; helpers are a separate layer).

## Implementation Decisions

### Phase ordering + 87-post-fix scope

- **D-01 — 86.2 → 86.3 sequential.** Phase 86.2 commits + verifies BEFORE
  Phase 86.3 starts. 86.3 then USES the new helpers when implementing the
  8 source-skipped tests. Cleaner contract; mirrors Phase 86.1's wave
  structure (refactor first, then verify).

- **D-02 — Treat `97f55cb41 chore(87-post-fix)` as final.** Phase 86.2 starts
  from current HEAD and refactors forward. 87-post-fix is considered Phase
  87's stabilization investment that landed early; 86.2 does NOT audit,
  revert, or re-attribute any of those 30+ file changes. Phase 86.2 only
  extracts helpers / dedups patterns that emerged from the 86.1 post-fix
  work scattered across 9 files.

### Helper extraction

- **D-03 — Extract all 6 patterns identified during discussion.** The 86.1
  post-fix annotations cluster into these helpers:

  | Helper | Pattern | Anchor site(s) |
  |--------|---------|----------------|
  | `settleNetworkIdle(page)` / `gotoAndSettle(page, url)` | Insert `page.waitForLoadState('networkidle')` between `goto` and assertions to cover cold-start hydration races | `candidate-profile-validation:202`, `voter-matching:186`, `voter-not-located-redirect:105` + 3-4 other sites |
  | `expectLandedOn(page, predicate)` / `assertOnRoute(page, routePattern)` | Assert page LANDED on a target route (URL-predicate wait), not just LEFT `/login` | `candidate-profile-validation:85` + auth-redirect call-sites |
  | `clickAndRaceSettle(locator, destinationPredicate, opts)` | Bound `.click()` with short timeout, race against destination URL/state — prevents 90s test-timeout retries | `voter-matching:186`, navigation/feedback flows |
  | `iterateSelectOptions(comboboxLocator)` | Locate `<Select>` combobox + iterate options (NOT radiogroup pattern) | `voter-not-located-redirect:61` (the Select-vs-radiogroup RCA finding) |
  | `assertDbRowCount(spec, expectedCount, table)` or test-level precondition asserter | Assert exactly N rows of a specific shape in DB before running the test body (catches dataset-drift early) | `results-sections:177` (the 2-elections precondition) |
  | `walkVoterIteration(page, idx, { allowCategoryIntro })` | Per-iteration handler that branches on EITHER category-intro page (only `voter-questions-category-start`) OR regular question page (`question-next` or Skip) | `voter.fixture.ts:113` (the category-intro branch added during 86.1 post-fix) |

  Phase 86.2 IS allowed to refine these names + signatures during plan/execute —
  the API shape is Claude's discretion (D-EXEC), the SET is locked.

- **D-04 — Inline workarounds stay inline.** Three 86.1 post-fix touchpoints
  are NOT extracted because they are one-off domain workarounds:
  - `applyLikertOnlyFilter` calls in `variant-multi-election.setup.ts` +
    `variant-constituency.setup.ts` — one-line setup-file additions; trivially
    duplicated without a helper.
  - `variant-startfromcg.ts` template content change (dropping
    `test-cg-municipalities` from E1) — domain-specific template edit.
  - `playwright.config.ts` dependency rewires (project ordering) — config-
    level, no helper abstraction applies.

### Helper layer architecture

- **D-05 — Per-domain helper files in `tests/tests/helpers/`.** The directory
  exists but is currently empty. 86.2 populates it with separate files split
  by concern:

  ```
  tests/tests/helpers/
  ├── index.ts                  # barrel re-export
  ├── settle.helper.ts          # settleNetworkIdle / gotoAndSettle
  ├── navigation.helper.ts      # expectLandedOn / clickAndRaceSettle
  ├── select.helper.ts          # iterateSelectOptions
  ├── db-precondition.helper.ts # assertDbRowCount
  └── voter-iteration.helper.ts # walkVoterIteration (extracted from voter.fixture.ts)
  ```

  Page-objects in `tests/tests/pages/` stay as-is — helpers are a separate
  layer, not extensions of page-object classes. Fixtures in
  `tests/tests/fixtures/` stay as-is, except `voter.fixture.ts` may
  internally call `walkVoterIteration` after the helper is extracted (the
  fixture's PUBLIC API — `answeredVoterPage` — is unchanged).

## Specific Ideas

### Plan 86.2-01 helper API sketches (Claude discretion to refine)

```ts
// tests/tests/helpers/settle.helper.ts
export async function settleNetworkIdle(page: Page, timeoutMs = 10_000): Promise<void> {
  await page.waitForLoadState('networkidle', { timeout: timeoutMs });
}

export async function gotoAndSettle(
  page: Page,
  url: string,
  opts?: { waitUntil?: 'load' | 'domcontentloaded' | 'networkidle'; timeoutMs?: number }
): Promise<void> {
  await page.goto(url);
  await settleNetworkIdle(page, opts?.timeoutMs);
}

// tests/tests/helpers/navigation.helper.ts
export async function expectLandedOn(
  page: Page,
  pattern: RegExp | string,
  timeoutMs = 10_000
): Promise<void> {
  await expect(page).toHaveURL(pattern, { timeout: timeoutMs });
}

export async function clickAndRaceSettle(
  locator: Locator,
  destinationPredicate: RegExp | string,
  opts?: { clickTimeoutMs?: number; settleTimeoutMs?: number }
): Promise<void> {
  await Promise.race([
    locator.click({ timeout: opts?.clickTimeoutMs ?? 5_000 }),
    locator.page().waitForURL(destinationPredicate, { timeout: opts?.settleTimeoutMs ?? 5_000 })
  ]);
  await expectLandedOn(locator.page(), destinationPredicate, opts?.settleTimeoutMs);
}
```

These are sketches — Plan 86.2-01 refines based on anchor-site needs.
