## Critical Anti-Patterns (do NOT repeat these)
- **ANTI-PATTERN: silent catch in async submit handlers** — the ToU layout's
  `catch (error) { logDebugError; status='error' }` left no visible UI signal
  for `status==='error'`, masking a 406 as a 10-second timeout in tests.
  Structural mitigation: every async submit handler whose failure isn't
  immediately visible MUST render a status-bound error surface
  (`data-testid="X-save-error"` pattern adopted in
  `candidate/(protected)/+layout.svelte`).
- **ANTI-PATTERN: concatenating `?next=…` onto a `buildRoute()` result without
  knowing whether the base carries a query string** — produced the
  `?electionId=…?next=…` 500. Structural mitigation: ALWAYS route next-param
  appends through a `withNext(base)`-style helper that picks `?` vs `&`.
- **ANTI-PATTERN: `client.setPassword` (admin `auth.admin.updateUserById`)
  in tests after `verifyOtp`** — revokes all refresh tokens for the user,
  leaving the browser-side Supabase client with no GoTrue-accepted session.
  Structural mitigation: tests use the user-side `auth.updateUser({password})`
  path only (already enforced; vestigial admin call removed from
  `candidate-profile.spec.ts:159` this session).
- **ANTI-PATTERN: relying on Mailpit search-result count for indexing across
  test iterations** — Mailpit's default 50-result ceiling silently masks new
  emails once the queue saturates. Structural mitigation: per-recipient
  `clearMailboxForRecipient` in `beforeEach` on any spec that fires Mailpit
  emails repeatedly.
