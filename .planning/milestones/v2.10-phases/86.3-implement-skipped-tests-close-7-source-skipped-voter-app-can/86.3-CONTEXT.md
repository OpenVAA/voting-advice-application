### Plan 86.3-01 (SETTINGS-01 wave A — cells #1/#2/#3 shared reactivity fix)

Likely root cause path:

```svelte
<!-- apps/frontend/src/routes/(voters)/+layout.svelte (current — mount-time capture) -->
<script>
  const ctx = getVoterContext();
  // PROBLEM: $appSettings read once at mount; subsequent appSettingsValue
  // updates via $effect don't propagate to topBarSettings.
  topBarSettings.push({
    showFeedback: $appSettings.header.showFeedback, // ← non-reactive
    showHelp: $appSettings.header.showHelp           // ← non-reactive
  });
  onMount(() => {
    if ($appSettings.notifications.voterApp) {
      popupQueue.push({ … }); // ← reads once
    }
  });
</script>
```

Fix sketch (Claude refines in plan):

```svelte
<!-- Option A: $derived push -->
<script>
  const ctx = getVoterContext();
  const topBarConfig = $derived({
    showFeedback: ctx.appSettings.header.showFeedback,
    showHelp: ctx.appSettings.header.showHelp
  });
  $effect(() => { topBarSettings.set(topBarConfig); });

  $effect(() => {
    if (ctx.appSettings.notifications.voterApp) popupQueue.push({ … });
  });
</script>
```

May land as ~30-60 LOC per the v2.11+ deferred item's existing estimate
("Refactor mount-time `$appSettings` reads in `(voters)/+layout.svelte`
topBarSettings/popupQueue.push to reactive — ~30-60 LOC"). 1h cap applies.
