### WR-04: `popupQueue` destructure stable-reference assumption — documented

**Files modified:** `apps/frontend/src/routes/(voters)/+layout.svelte`
**Commit:** `089d52dbd`
**Applied fix:** Confirmed via source audit that `popupQueue` is a stable
instance reference per CLAUDE.md "Context Destructuring Rule §1":

- `popupStore()` at
  `apps/frontend/src/lib/contexts/app/popup/popupStore.svelte.ts:23`
  returns an object literal `{ push, shift, subscribe }`. The `push` /
  `shift` methods are bound function references that close over a
  module-internal `$state` queue.
- AppContext exposes `popupQueue` at
  `apps/frontend/src/lib/contexts/app/appContext.svelte.ts:226` as a
  plain context property (`popupQueue,` in the `setContext` object
  literal), NOT as a getter / `$derived` / `$state`.

Therefore destructuring `popupQueue` from `initVoterContext()` is safe:
the captured reference is the live class-instance-like object, and
`popupQueue.push(...)` mutates the closure-scoped queue correctly.

Added a 10-line documentation block above the destructure (line 36-45)
documenting the stability check and warning future maintainers that
swapping `popupQueue` for a `$state`/`$derived` getter would silently
break consumers without a migration to `ctx.popupQueue.push(...)`.
