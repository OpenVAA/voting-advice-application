## 3-Run SHA-Identity Gate Spec (Plan 86.3-05)

**Mechanism:** `.planning/phases/86.1-…/post-fix/sha-identity.mjs` (verbatim reuse from Phase 86.1-04 → 86.2-03).

**Invocation pattern:**

```bash
yarn db:reset
for i in 1 2 3; do
  yarn test:e2e --reporter=json --output=run-${i}.json 2>&1 | tee run-${i}-stderr.log
  sha256sum run-${i}.json >> sha256.txt
done
node .planning/phases/86.1-…/post-fix/sha-identity.mjs run-{1,2,3}.json
```

**Acceptance:**
1. All 3 SHA-256 hashes identical (true reliability — not flake-recovered).
2. Fresh anchor captured against post-86.3 HEAD (per Open Question §5 — test outcomes CHANGE in 86.3, so reuse of 86.2-03 anchor is invalid).
3. CASCADE count ≤ 5 (Phase 87 Task 0 binding pre-gate).
4. `did not run` count = 0 (D-09 + memory `feedback_e2e_did_not_run.md`).
5. SKIPPED_TESTS const in `tests/scripts/diff-playwright-reports.ts` reflects final disposition for all 8 cells.

**Failure handling:**
- If SHA-identity fails (runs diverge): same as 86.2-03 — diagnose timing changes; remediation is a follow-up task in Plan 86.3-05 OR rollback of the cell-fix that introduced the divergence.
- If CASCADE > 5: Plan 86.3-05's SUMMARY surfaces the new cascades; operator picks roll-back-one-cell vs re-route-to-Phase-87-revisit.
- If `did not run` > 0: treated as failure per D-09; same handling as CASCADE > 5.
