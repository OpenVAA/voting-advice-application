# Phase 91 Plan 01: TIR6 perm + edit test additions — foundation (buildMinimal + candidateSessionMinter + named-params refactor)

## One-Liner

Refactored shared.ts builders to named-params + parameterised buildCandidate.answersByExternalId (D-91-PD-07); authored buildMinimal helper (fresh-minimal Template composition) and candidateSessionMinter helper (Playwright storage-state mintor); ported 6 minimal-topology perm templates to consume buildMinimal — foundation for Plan 91-02's 9 new TIR6 perms.

## What Shipped

### Task 0 — Named-params refactor for shared.ts builders (commit 31e2d0ff7)

- `buildQuestions / buildStandardCandidateAnswers / buildCandidate / buildElectionConstituencyNoms` now accept a single named-options object. Interface types exported: `BuildQuestionsOptions`, `BuildStandardCandidateAnswersOptions`, `BuildCandidateOptions`, `BuildElectionConstituencyNomsOptions`.
- `buildCandidate.answersByExternalId` is now OPTIONAL. Default behaviour at the leaf-builder level: empty answer map. The assembling layer (perm template OR `buildMinimal` helper) is responsible for population.
- `buildQuestionCategories` + `buildOrganizations` stay parameterless per D-91-PD-07 (single-param functions stay positional).
- All 12 perm template call sites migrated to named-params (`perm-localisation-positive` only uses `buildOrganizations()` — parameterless — so needs no migration; the rest each pass `answersByExternalId: buildStandardCandidateAnswers({ prefix: P })` explicitly to preserve byte-for-byte behaviour for the candidates that previously got auto-populated answers).

### Task 1 — buildMinimal helper + vitest coverage (commit aab17c239)

- `packages/dev-seed/src/templates/_helpers/buildMinimal.ts` exports `buildMinimal(opts: BuildMinimalOptions): Template`. Single named-options API.
- Default shape (D-91-PD-02): 1 election / 1 CG / 1 CO / 2 orgs / 1 candidate / 1 opinion Likert5 question / 0 info questions / 1 nomination per (election × constituency × candidate) / `app_settings = MINIMAL_BASE_APP_SETTINGS`.
- `candidateAnswersDefault` defaults to `'all'` (D-91-PD-07) — every candidate carries an answer to every seeded question. Per-question default values:
  - info question (`text`) → `{ value: { en: '[<extId>] desc' } }`
  - opinion Likert5 (`singleChoiceOrdinal`) → `{ value: '3' }` neutral
  - opinion boolean → `{ value: true }`
  - opinion categorical → `{ value: <first-category-id> }`
- Per-candidate override via `answersByCandidate[bareId] = 'none'` (clean candidate) OR explicit map (BARE question external_ids; helper normalises to FULL prefixed keys). Global override via `candidateAnswersDefault: 'none'`.
- `settingsOverlay` applies via JSONB-safe deep-merge (strips `undefined` values per Pitfall 9).
- `nominationsInElectionIndices: [0]` (with `elections: 2`) reproduces the perm-missing-nominations shape (zero nominations in el-2).
- `customDataByQuestion` keyed by BARE question external_id; helper writes into `question.custom_data` on the matching row.
- `_helpers/index.ts` barrel re-exports `buildMinimal` + `BuildMinimalOptions`.
- 8 vitest cases (RED → GREEN; all green on first GREEN implementation):
  1. Default 1c/1opin/0info shape; candidate has answer to the 1 seeded opinion question (default `candidateAnswersDefault='all'`).
  2. `settingsOverlay: { access: { answersLocked: true } }` deep-merges; preserves base `access.candidateApp/voterApp/adminApp/underMaintenance` defaults.
  3. `elections: 2, nominationsInElectionIndices: [0]` → every nomination references el-1; zero el-2 references.
  4. `customDataByQuestion: { 'qu-opin-l5-1': { hero: '🗳️' } }` injects `custom_data.hero` on the BARE-matched question.
  5. Explicit `answersByCandidate: { 'cand-1': { 'qu-opin-l5-1': { value: 5 } } }` overrides default fill (only the explicit entry, no auto-fill).
  6. Multi-candidate + multi-question default-all: 2 candidates × 3 questions → each candidate's answersByExternalId has 3 entries; info-question answer shape verified.
  7. `answersByCandidate['cand-2'] = 'none'` → cand-2 clean (empty map), cand-1 retains default-all fill.
  8. `candidateAnswersDefault: 'none'` → every candidate clean.

### Task 2 — 6 perm template ports (commit 31ae3eb81)

- **`perm-1e1cg1co`**: pure `buildMinimal({ externalIdPrefix: 'e2e-perm-1e1cg1co-', candidates: 2, opinionQuestions: 1 })`.
- **`perm-disable-voter-app`**: `buildMinimal({ ... settingsOverlay: { access: { voterApp: false } } })`.
- **`perm-disable-candidate-app`**: `buildMinimal({ ... settingsOverlay: { access: { candidateApp: false } } })`.
- **`perm-per-app-notifications`**: `buildMinimal({ ... settingsOverlay: { notifications: { voterApp: {...}, candidateApp: {...} } } })`.
- **`perm-missing-nominations`**: `buildMinimal({ elections: 2, organizations: 1, candidates: 1, nominationsInElectionIndices: [0] })` — buildMinimal extended with `buildSingleOrgNoms` branch to support `organizations: 1` without emitting an orphan or-2 parent row.
- **`perm-localisation-positive`**: HYBRID port — `buildMinimal({ organizations: 1, candidates: 0, opinionQuestions: 0, infoQuestions: 0 })` authors the topology + app_settings; the result is spread + overridden with the hand-authored bespoke `question_categories`, `questions`, `candidates`, `nominations` fields the L10N spec's `[Q1]/[Q2]/[Q3]/[Q4]` markers + `[en-answer-q1]/[en-answer-q3]` content + `disableMultilingual` customData + `allow_open: true` flags depend on byte-for-byte.

All 6 ports preserve their per-perm `externalIdPrefix` verbatim (D-91-PD-03 invariant).

### Task 3 — candidateSessionMinter helper + vitest coverage (commit 8cb3f7b18)

- `tests/tests/utils/candidateSessionMinter.ts` exports `mintCandidateSession({ externalId, prefix, locale? }): Promise<StorageState>`.
- Looks up the seeded candidate via `SupabaseAdminClient.findData('candidates', { external_id: prefix+externalId })`. Throws if no row matches.
- Synthesises a Playwright-compatible `StorageState` shape: `{ cookies: [sb-access-token, sb-refresh-token], origins: [{ origin: PLAYWRIGHT_BASE_URL, localStorage: [{ name: 'sb-auth-token', value: <session-json> }] }] }`.
- Spec author guidance (in module doc-comment): Plan 91-02 A1/A2/A9 perm setups can update the synth-token block to call `client.client.auth.admin.generateLink({ type: 'magiclink' })` for live-Supabase integration without breaking the PUBLIC interface (`mintCandidateSession({ externalId, prefix, locale? }) → Promise<StorageState>`).
- Module lives under `tests/tests/utils/` (test-only path); not exported from any frontend/package barrel — preserves T-91-A1 threat-register mitigation (no admin-token leakage to production code paths).
- `tests/vitest.config.ts` (new file) — minimal node-env vitest config restricted to `tests/utils/**/*.test.ts` so Playwright spec files in `tests/specs/**` are not picked up.
- 3 vitest cases (RED → GREEN via `vi.mock('./supabaseAdminClient', ...)`):
  1. Returns non-empty `cookies` array (Playwright storage-state shape).
  2. Returned object structurally compatible with Playwright's `test.use({ storageState })` (cookies + origins arrays present; cookies entries have name + value).
  3. Rejects with `/not.*found|candidate/i` error when seeded candidate cannot be resolved.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking issue] buildMinimal needed single-org nomination support**

- **Found during:** Task 2 (porting perm-missing-nominations which uses `organizations: 1`)
- **Issue:** `buildElectionConstituencyNoms` from `shared.ts` always emits both `or-1` and `or-2` parent nomination rows. With `organizations: 1` only `or-1` was seeded, so the `or-2` parent row would orphan-FK on the missing organisation row.
- **Fix:** Added `buildSingleOrgNoms` helper function in `buildMinimal.ts` mirroring the file-local helper from `perm-localisation-positive.ts`. When `orgCount === 1`, buildMinimal calls this branch instead.
- **Files modified:** `packages/dev-seed/src/templates/_helpers/buildMinimal.ts`
- **Commit:** 31ae3eb81 (included in Task 2 commit since it's the change that made `perm-missing-nominations` port viable)

**2. [Rule 3 — Blocking issue] tests/ workspace had no vitest config**

- **Found during:** Task 3 (running candidateSessionMinter vitest)
- **Issue:** Root `vitest.workspace.ts` only includes `packages/**`; `tests/` has no `package.json` or vitest config. The plan's task 3 verify command `yarn vitest run tests/tests/utils/candidateSessionMinter.test.ts` would fail without a discoverable config.
- **Fix:** Added `tests/vitest.config.ts` — minimal node-env config restricted to `tests/utils/**/*.test.ts` so Playwright spec files in `tests/specs/**` are not picked up. Invocation: `cd tests && yarn vitest run --config vitest.config.ts`.
- **Files modified:** `tests/vitest.config.ts` (new file)
- **Commit:** 8cb3f7b18
