<objective>
Fix the runtime error "setAnswers: Answer for number question must be a number" that occurs when saving a `number` question answer in the candidate app (and anywhere `Input`/`QuestionInput` renders a `number` field).

Purpose: The frontend currently emits the raw DOM `<input>.value` (always a string) for `number` inputs. The backend `validate_answer_value` RPC requires a JSON number, so the string fails validation. Coercing the value to a real `number` at the single generic change-handler location honours the backend contract everywhere number inputs are used.

Output: A `type === 'number'` coercion branch in `Input.svelte`'s `handleChange`, emitting `number | undefined` instead of a string.
</objective>
