1. **No performance/analytics dependency exists.** `apps/frontend/package.json` declares none. `yarn.lock` (408 KB / 11810 lines) contains no entry for a Core-Web-Vitals or analytics package. The only `@vercel/*` package installed is `node_modules/@vercel/oidc`, a transitive server-side dependency.
2. **The throwing symbol is absent from the tree.** A recursive grep over `node_modules/` at the repo root, and over `apps/frontend/node_modules/` following symlinks, returned **zero** occurrences of the method name in the reported stack. Zero occurrences under `apps/`, `packages/`, `tests/` too. No file anywhere in the checkout is named for a Core-Web-Vitals library.
3. **The page loads no external script of its own.** `apps/frontend/src/app.html` has no `<script src>`; the only cross-origin head asset is the Google Fonts stylesheet built from `fontUrl` in `routes/+layout.svelte`. `apps/frontend/vite.config.ts` loads exactly four plugins: `@tailwindcss/vite`, `@inlang/paraglide-js`, `@sveltejs/kit/vite`, `vite-plugin-restart`.
4. **The one third-party script our code can inject is Umami.** `apps/frontend/src/lib/components/analytics/umami/UmamiAnalytics.svelte` puts `https://cloud.umami.is/script.js` into `<svelte:head>`. `routes/+layout.svelte:234-237` mounts that component **only** when `appSettings.analytics?.platform` is truthy.
5. **On a normal local stack that gate is closed.** `packages/app-shared/src/settings/staticSettings.ts` sets `analytics: { trackEvents: false }` and no `platform`. The `default` dev-seed template (`packages/dev-seed/src/templates/default.ts`, `app_settings.fixed[0].settings`) writes no `analytics` key at all. Only the E2E template `perm-analytics-tracking` arms `analytics.platform`, with a dummy code. So in ordinary local browsing the Umami script is not in the document.
6. **Even when it is, the currently-served Umami build is guarded.** Fetched 2026-09-22: HTTP 200, 4810 bytes. It constructs `PerformanceObserver` twice and observes `navigation`, `paint`, `largest-contentful-paint`, `layout-shift` and `event` — but contains **zero** occurrences of the reported method name, and every entry read in its fallback path is guarded (`const a = t?.[t.length-1]; a && (e.lcp = ...)`). A *cached older* build in the operator's browser is not excluded by this.
7. **Our code does wrap the click in a View Transition.** `routes/+layout.svelte:153-162` resolves every `onNavigate` inside `document.startViewTransition`; `lib/components/tabs/Tabs.svelte:41-42` does the same for the entity-detail drawer tabs (opted in at `EntityDetails.svelte:146`). Clicking an entity in Results is a param-only soft navigation on `results/[[electionTab]]/[[entityTab=etPl]]/[[entity=etSg]]/[[id]]`. A View Transition suspends rendering and produces no fresh paint entries across the swap — a plausible *trigger* for an observer that re-reads an empty entry buffer per soft navigation, even though the throwing code would still not be ours.

**Leading hypothesis, to be confirmed or refuted by the tasks below, never assumed:** the throwing code is injected into the page by the browser — a Chrome extension, or DevTools' own live-metrics instrumentation — and our View Transition may be what pushes it onto its empty-buffer path.
</prior_evidence>
