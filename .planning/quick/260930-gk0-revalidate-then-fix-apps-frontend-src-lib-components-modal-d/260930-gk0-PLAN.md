<objective>
Revalidate the review finding against `apps/frontend/src/lib/components/modal/drawerHost/DrawerHost.svelte` at HEAD, and fix only what still reproduces.

The finding has two parts:
1. The close animation is gated on the View-Transitions helper called with `undefined`. That helper returns false when `document.startViewTransition` is missing, so browsers without View Transitions would skip the CSS close animation. Only reduced motion should skip it.
2. The focus-entry `setTimeout(DELAY.sm)` is never cancelled when the drawer closes quickly, so focus is pushed into a closing dialog.

Planning-time measurement: **both stated parts are already fixed at HEAD** by commit bcdbe8d13 "fix(165.1): drawer focus guard and a motion gate independent of view transitions" (review comments C-4094919831 and C-4094919891). That commit is carried into this branch's af31f1f0f. `DrawerHost.svelte.test.ts` already pins both fixes. Task 1 re-proves this at run time and records both parts as **DROPPED**, with no code change for them.

The orchestrator also asked for two adjacent edge cases to be considered. Both were reproduced red at HEAD during planning with a throwaway probe test, since deleted:
- **(A) Open then close within two frames.** The open path's `requestAnimationFrame(() => requestAnimationFrame(() => (visible = true)))` is never guarded or cancelled.
  - A close inside those two frames is overwritten: the panel slides back up while the dialog is closing.
  - `visible` is then left `true`, so the next open starts at `translate-y-0` and has no slide-up.
- **(B) A second dismissal during the close animation.** `dismiss()` and `handleEscape` test `shown`. `shown` deliberately lags `drawerHost.current` through the close animation, so Escape, the backdrop and the close button call the outgoing payload's `onDismiss` again. The probe measured 3 calls where 1 was expected.
  - For the results drawer, `onDismiss` is a `goto(...)`, so each extra call is a redundant navigation.
  - `ModalContainer` does not have this defect: its `handleEscape` tests `isOpen`, which drops to false the moment it closes.

Tasks 2 and 3 fix A and B test-first. Each fix is gated on its new test being red against the unmodified component. If a test does not go red, that edge case is recorded as DROPPED and nothing is changed for it.

Purpose: the drawer dismisses exactly once, animates on every close except under reduced motion, and never flashes back up or loses its open animation.

Output:
- a two-guard change to `DrawerHost.svelte` (no new state, no new imports);
- three new component tests in the existing `DrawerHost.svelte.test.ts`;
- a SUMMARY recording the stated finding as DROPPED (with evidence) and edge cases A and B as FIXED (or DROPPED if they did not reproduce).
</objective>
