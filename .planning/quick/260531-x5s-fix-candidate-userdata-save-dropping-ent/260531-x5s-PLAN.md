<objective>
Fix the candidate `userData.save()` bug where an answers-only save replaces the entire `savedData.candidate` object with the bare answers map returned by `updateAnswers`, dropping the entity `id`. The next save then reads `savedData.candidate.id === undefined`, sends `p_entity_id: undefined` to `upsert_answers`, and `JSON.stringify` drops the key → PostgREST 404 "Could not find the function public.upsert_answers(p_answers, p_overwrite)".

Purpose: Restore the documented contract — answers-only saves must preserve the candidate's `id` and static fields so subsequent saves keep working. This unblocks E2E `candidate-mega-journey.spec.ts` step 13.5.

Output: Type-correct return types for `updateAnswers`/`overwriteAnswers`, a `save()` that merges answers into `candidate.answers` (vs. wholesale replace), and a regression unit test for the store.
</objective>
