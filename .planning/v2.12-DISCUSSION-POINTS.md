## B. Phase 102 — Handle-Idiom Spike (HANDLE-01)

**🔒 LOCKED:** This phase IS the decision — it classifies the 40 `{ readonly current }` handles read-only vs read-write and picks the canonical idiom per class, proven on a PoC. **Read-only target is already fixed by HANDLE-02: a plain reactive getter (`ctx.x`, not `ctx.x.current`).** Frontend-only; destructure-trap contract (CLAUDE.md "Context Destructuring Rule") must survive. The boxes below are **framing inputs/guidance the spike should weigh** — the spike confirms or overrides each with evidence.

### 102-1 — Read-write handle target surface
HANDLE-02 says read-write handles get "the chosen runes-native read/write surface (get/set accessor pair **or equivalent**)." Your preferred default:

- [x] **Get/set accessor pair — `{ get current(); set current(v) }`** *(Recommended — smallest consumer-site delta: existing `x.current` reads stay valid, and `x.current = v` writes Just Work; the codemod for read-write handles becomes near-empty)*
- [ ] Getter + explicit setter method (`x.value` read + `x.set(v)` write) — more explicit, but rewrites every write site
- [ ] Let the spike decide per-handle with no default preference

### 102-2 — Cleanliness vs churn philosophy
How aggressively should the spike push toward zero `.current`?

- [ ] **Max-native for read-only (eliminate `.current` everywhere the getter idiom allows); pragmatic for read-write (keep an accessor/handle shape where dropping `.current` adds risk or churn)** *(Recommended — read-only is the bulk of the ~524 sites and the clear win; read-write is small and benefits from the low-delta accessor)*
- [x] Max-native everywhere — drive `.current` to zero on both classes, accept the larger write-site churn
- [ ] Min-churn — keep handle shapes wherever possible, change only what's clearly vestigial

### 102-3 — PoC slice breadth
Success criterion #3 requires "at least one read-only and one read-write handle."

- [x] **Minimal-but-representative: one read-only (e.g. `appContext.darkMode`/`locale`), one read-write (e.g. voter `answers`), plus the special derived `getRoute` handle** *(Recommended — covers all three shapes the codemod will hit without over-building a throwaway)*
- [ ] Strictly the minimum (one read-only + one read-write)
- [ ] Broader slice (a whole context, e.g. all of `appContext`) for higher confidence before the codemod

### 102-4 — Fate of the special `getRoute` derived handle
`getRoute` is a `{ readonly current: RouteBuilder }` **derived** handle (spike 012, `$derived.by` per-field reads) — not a plain value handle.

- [x] **Treat it as read-only and fold it into the plain-getter idiom (`getRoute` callable directly) unless the spike finds the `$derived.by` shape genuinely needs the handle wrapper** *(Recommended — consistency; spike 012 already proved the rune mechanics)*
- [ ] Document `getRoute` up-front as a retained-handle exception (don't touch it in the codemod)
