## A. Cross-cutting decisions (apply to every phase)

- [ ] **A1 — Factory wrappers stay.** Keep the `initXxxContext()` / `createXxx()` factory functions; each now
  `return new XxxContext(...)`. → Preserves all `setContext`/`getContext` call sites and guarantees the class is
  constructed *outside* a bare module scope (factory is called during component init = effect context, so even
  `$effect`-in-constructor is legal — see the `filterContext` proof). Zero call-site churn.
  **NOTE**: Use the export const [getUserContext, setUserContext] = createContext<User>(); idiom recommended by https://svelte.dev/docs/svelte/context
- [ ] **A2 — Prototype getters by default; own-property handles ONLY where a parent spreads the instance.**
  → `darkMode`/`filterContext` use prototype getters (not spread). `dataContext` currently uses *own-property*
  handles because `appContext` does `{ ...dataCtx }`. Once A3 fixes that spread (Phase 109), `dataContext` flips
  to prototype getters too — uniform shape everywhere. (Spread copies only own-enumerable props and silently
  drops prototype getters / `$state` accessors — proof finding A.)
- [ ] **A3 — Fix `appContext`'s spread-of-context to explicit getter forwarding** (Phase 109), rather than
  keeping own-property handles forever. → The clean end-state; lets every context use prototype getters. Touches
  `appContext` + verified against its consumers.
- [ ] **A4 — Convert producers keeping consumers byte-identical; flatten later in Phase 113.** → Each Phase
  106–112 conversion retains the existing `.current` / handle read API (back-compat) so NO consumer changes mid-
  conversion; the single ~524-site flatten codemod runs alone in Phase 113. This is exactly the proof's approach
  (zero consumer churn per conversion) and avoids the v2.12 codemod-collision failure.
- [ ] **A5 — Detachable methods are arrow-function fields** (CONVENTIONS §18). → Anything destructured/passed
  (`const { logout } = ctx`, `onclick={ctx.reset}`) is an arrow field so `this` survives detach. Context methods
  are routinely destructured → apply universally, not selectively.
- [ ] **A6 — No `$effect` for initialization/merge** (§20). → Initial values from `page.data`/`load()` go in
  synchronous field initializers; reactive projections are `$derived` fields. `$effect` only for post-construction
  reactions in component-instantiated classes (e.g. the `filterContext` onChange bridge — legal because the
  factory runs in an effect context). Guards against `effect_orphan` + SSR-skips-`$effect`.
- [ ] **A7 — Persistence stays imperative** (§21). → `localStorageState`/`sessionStorageState`-backed fields
  persist inside arrow `set`/`update`, never `$effect`. Keeps SSR-safety + factory-constructability.
- [ ] **A8 — Version-bridge classes keep `#version` + `untrack` encapsulation** (§22). → DataRoot/FilterGroup
  wrappers keep private `#root` + private `#version` `$state` + arrow `setX(updater)` internalizing `untrack`.
  **Caveat to respect:** a class `#version` read-then-mutate loop spins *silently* (no `effect_update_depth_exceeded`
  throw) — so the `setX`/`untrack` boundary is load-bearing; never read the reactive getter then mutate outside it.
- [ ] **A9 — Destructure trap preserved, not "fixed"** (§19, CLAUDE.md Context Destructuring Rule). → Consumers
  read `ctx.X`, never destructure reactive accessors. The spike-009 audit pass (PASS 4) is mandatory in Phase 113.
- [ ] **A10 — Class naming.** → `class AppContext`, `class VoterContext`, `class DataContextProvider` (proof
  precedent), `class PopupStore`→ keep, etc. Instance/variable names unchanged until Phase 114 (rename). The
  Store→State rename (114) is the ONLY place names change.
- [ ] **A11 — Unit-test medium: headless `*.svelte.test.ts`** with `$effect.root(() => …)` + `flushSync()` (+
  `vi.mock` for `$app/*`), per the Phase-102 PoC + proof precedent. → Discovered by vitest's default glob; runnable
  via `yarn vitest run <file>`. New per-context tests live beside the context.
- [ ] **A12 — Green at every commit boundary, atomic per context.** → Each context conversion is its own commit;
  `yarn build` (client + SSR) + `yarn vitest run src/lib/contexts/` + `yarn svelte-check` green before moving on.
- [ ] **A13 — svelte-check gate = "zero NEW errors," not zero absolute.** → Baseline is **151 pre-existing**
  errors (`qs` decls, supabase `Json` typing, DataWriter Promise typing — proof-confirmed). Hold the 151; fail on
  any net-new. Stash-compare if in doubt.
- [ ] **A14 — Delete leftover spike scaffolding from the production tree.** → Remove
  `apps/frontend/src/lib/contexts/_spikes-017-019/*.spike.svelte.test.ts` (proof says deletable) during Phase 107,
  and confirm no `runes-test/` remnants remain. (The `_poc*` appContext surfaces are removed in Phase 109.)
- [ ] **A15 — ⚠ DECIDE: E2E cadence.** The v2.11 retrospective flagged "defer all live E2E gates to the terminal
  phase" as ⚠️ *Revisit* (7 regressions surfaced only at the end). → **Recommended:** run targeted **live E2E at
  the two orchestrator phases (110 voter, 111 candidate) + the flatten (113)**, plus the full gate at 116 — not
  end-loaded. Costs ~3 extra live runs but catches reactive regressions where they're introduced. *Alternative:
  unit/svelte-check only until 116 (faster, riskier).*
  **NOTE**: Run the extra live runs. The dev server is running, so you can run the e2e at your pleasure.
- [ ] **A16 — Seed/template for live E2E** → `yarn db:reset && yarn db:seed --template e2e/base` (Likert-only where
  the voter-fixture needs it: `--likert-only`). Matches the v2.10/v2.11 green-gate setup.
  **NOTE**: Might be easier to run the whole suite with `yarn db:reset && yarn test:e2e`
