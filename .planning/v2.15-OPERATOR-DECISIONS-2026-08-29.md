## D8 — `requirements mark-complete` rejects annotated Status cells

**RULED: fix the matcher to anchor on the leading word.**

Confirmed in session at `~/.claude/gsd-core/bin/lib/milestone.cjs:188`: `/^(pending|gaps found)$/i`
is tested against the **trimmed whole cell**, so a cell reading
`Pending — measured 2026-08-28 as already satisfied by Phase 144 (…)` does not match. The row
exists but rejects the write, the checkbox flip is rolled back (#2788 defect 2), and the tool
reports `not_found`. Rows holding a bare `Pending` are unaffected — the block is row-specific, as
`154-03` narrowed it.

The matcher must accept a **leading** `Pending` / `Gaps Found` followed by an optional annotation,
and must **preserve the annotation** on write (the annotation carries the finding; normalising the
cell would delete it).

**Caveat recorded deliberately:** `milestone.cjs` is the GLOBAL GSD install, outside this
repository. The patch is therefore not version-controlled here and **`gsd-update` will overwrite
it**. The patch is mirrored in this directory so an overwrite is detectable rather than silent, and
it should be filed upstream.

Rejected: normalising cells to bare `Pending` (deletes the annotations); hand-ticking at each phase
close (recurs in every remaining phase and reintroduces the hand-edit the phases forbid).

## § K — Phase 162 rulings (the section left open)

### K1 — How the `grants` model replaces the 97 policies

**RULED (a): one rewrite with shims, deleted in-phase.**

Introduce `grants` + `user_can(scope, uuid, verb)`; reimplement `has_role` and
`can_access_project` as thin shims over it; migrate all 97 policies; then **delete the shims before
the phase closes**. The shims keep every intermediate commit green and testable, and deleting them
in-phase prevents the two-mechanism state the phase exists to end.

Rejected: parallel-build-then-cutover (two live permission systems on a blocking-ship security
surface); table-by-table (RLS is only as strong as its weakest table, so every intermediate point
has an ambiguous security posture).

### K2 — Criterion 6 (storage through the same helpers)

**RULED (a), WITH AN OPERATOR AMENDMENT.**

Base ruling: storage inherits the rename to `user_can` automatically — `400-storage.sql` already
calls `can_access_project` at 11 sites, so the "one mechanism, not a parallel implementation" half
is true by construction today. The deliverable is the **paired assertion**: a table-level denial
observed denied at the storage level.

**Operator amendment (verbatim intent): the storage schema must cater to separate read and write
permissions.** The read/write collapse at `302-rls.sql:84` vs `:88-89` is not to be reproduced at
the storage layer. Concretely:
- The **`verb` argument of `user_can(scope, uuid, verb)` must be honoured by storage policies**,
  not discarded — storage must be able to grant read while denying write on the same object.
- The paired assertion is therefore **per-verb**: a read-denial observed denied at the storage
  level, and a write-denial observed denied at the storage level, as two separate observations.
  A single undifferentiated access assertion does not satisfy criterion 6.

### K3 — Where the per-project settings live

**RULED (a): typed columns on `projects`, backed by enums.**

Covers candidate self-edit mode (edit freely / suggest for approval / neither) and
nomination-change approval routing (parent-entity / child-entity / invite-by-email). RLS policies
read these values inside `USING` clauses, where a typed column is indexable, constrainable and
cheap; a JSONB probe across up to 97 policies is none of those.

Rejected: JSONB `settings` blob (unvalidated at the DB level, opaque and slow inside predicates);
separate `project_settings` table (adds a join to every policy evaluation on the hottest path).

### K4 — "Level-1 permissions short of full" (criterion 7)

**RULED (a): define it in the phase SPEC, then check the flows.**

Level-1 is defined as **editor minus editor-management** — criterion 1 already describes editor as
"owner rights minus editor management", so the definition follows. Then check the candidate
registration and nomination-confirmation flows against the matrix; that flow check is the
criterion's real ask, and it needs a definition to check against.
