# Page Navigation & Transitions

Implementation blueprint for fixing the perceived "redraw on Q→Q" symptom in
the voter app, plus the same pattern for tab swaps in results. Distilled
from spikes 013, 014a, 014b, 015, 016.

## Requirements

Non-negotiable constraints surfaced during spiking.

- **The user-perceived "full redraw" is a render-cycle problem, not a
  remount-cycle problem.** SvelteKit ALREADY reuses `+page.svelte`
  instances across param-only URL changes — production DOM-tagging
  measured 9/25 (~36%) tracked content elements surviving a Q→Q hop.
  The remaining ~64% are freshly generated by reactive prop propagation
  inside the persistent component shell. Structural remounting is NOT
  the problem to solve; the SWAP ANIMATION is.
- **View Transitions API wraps the DOM swap window** via
  `onNavigate(navigation => Promise(document.startViewTransition(...)))`.
  Browser support: Chrome 111+, Edge 111+, Firefox 144+, Safari 18+. We
  feature-detect via `'startViewTransition' in document` and degrade
  gracefully to instant swap.
- **Read `navigation.to?.url`, NOT `page.url`, inside `onNavigate`** —
  `page.url` still reflects the SOURCE URL during the hook. The
  destination is what the user is going to.
- **`prefers-reduced-motion` is honored on BOTH JS and CSS layers** —
  `matchMedia('(prefers-reduced-motion: reduce)').matches` short-circuits
  `startViewTransition`, AND a CSS `@media (prefers-reduced-motion: reduce)`
  block nulls any animations that escape the JS check. Belt + braces.
- **Focus management is EXPLICIT via `afterNavigate`** — because the page
  component doesn't remount on param-only URL change, focus does NOT
  auto-reset. Apply focus inside `afterNavigate(() => requestAnimationFrame(...))`
  with `preventScroll: true` to a `[data-focus-on-nav]` target.
- **`focus({ preventScroll: true })` is mandatory.** Without
  `preventScroll`, the focus call triggers scroll-into-view that fights
  the existing `goto({ noScroll: true })` guard at
  `[questionId]/+page.svelte:159`, producing unpredictable scroll
  behavior.
- **Route-change announcement uses `aria-live="polite"` route announcer,
  NOT `<svelte:head><title>` updates.** Title-change SPA announcement
  support is inconsistent (VoiceOver announces; NVDA + JAWS often
  don't). A dedicated aria-live region whose text derives from
  `page.params.X` is the universal fix.
- **Adopt the unified-layout-with-empty-leaf shape** for the questions
  branch (matches the existing production results pattern). Layout
  owns rendering; child `+page.svelte` is empty. Variant handling via
  `{#key question.type}` (NOT `{#key question.id}`).
- **CONVENTIONS.md §9 per-field reads on `page`** — when deriving
  `questionId`, do `$derived(page.params.questionId)`, NOT
  `$derived(page).params.questionId`. The proxy-reference trap
  established in Spike 012 applies.
- **`{#key question.type}` not `{#key question.id}`** — keying on the
  variant property (Likert vs open-text vs slider) keeps the input
  mounted within a run of same-variant questions while still cleanly
  remounting at variant boundaries. Identical to production's
  `{#key activeElectionId:activeEntityType}` pattern at
  `results/[[electionTab]]/+layout.svelte:398`.
- **WCAG 2.1 AA gate** — focus must visibly land on the new content
  element (not be lost), screen readers must announce the route change,
  tab order must be predictable. Spike 016 verified these end-to-end.

## How to Build It

The recommended production migration ships in two 1-day waves.

### Wave A (1 day): Transitions + a11y, no structural change

Standalone improvement — works on the existing route structure.

**A.1.** Wire `onNavigate` + `startViewTransition` in the root layout
at `apps/frontend/src/routes/+layout.svelte`:

```svelte
<script lang="ts">
  import { onNavigate } from '$app/navigation';

  function shouldAnimate(destUrl: URL | undefined): boolean {
    if (typeof document === 'undefined') return false;
    if (!document.startViewTransition) return false;
    if (window.matchMedia?.('(prefers-reduced-motion: reduce)').matches) return false;
    return true;
  }

  onNavigate((navigation) => {
    if (!shouldAnimate(navigation.to?.url)) return;
    return new Promise<void>((resolve) => {
      // eslint-disable-next-line @typescript-eslint/no-explicit-any
      (document as any).startViewTransition(async () => {
        resolve();
        await navigation.complete;
      });
    });
  });
</script>
```

**A.2.** Add `view-transition-name` to the chrome-persistent elements
AND the per-question swap elements. Edit:

- `apps/frontend/src/routes/Header.svelte` — assign
  `view-transition-name: persistent-header` to the outer `<header>` so
  the chrome stays planted (excluded from the default
  `::view-transition-*(root)` slide).
- `apps/frontend/src/routes/MainContent.svelte` — assign
  `view-transition-name: question-title` to the title block (currently
  the `<div class="title-block">` wrapper around the `<h1>`).
- The hero `<figure>` — assign `view-transition-name: question-hero`.
- `apps/frontend/src/lib/components/questions/QuestionActions.svelte` —
  optionally `view-transition-name: question-actions` if you want the
  button row to cross-fade independently.

**A.3.** Add CSS keyframes to the root layout's `<style>`:

```css
:global(::view-transition-old(question-title)) {
  animation: 220ms cubic-bezier(0.4, 0, 0.2, 1) both fade-out-up;
}
:global(::view-transition-new(question-title)) {
  animation: 220ms cubic-bezier(0.4, 0, 0.2, 1) both fade-in-down;
}

@media (prefers-reduced-motion: reduce) {
  :global(::view-transition-group(*)),
  :global(::view-transition-old(*)),
  :global(::view-transition-new(*)) {
    animation: none !important;
  }
}

@keyframes fade-out-up {
  from {
    transform: translateY(0);
    opacity: 1;
  }
  to {
    transform: translateY(-10px);
    opacity: 0;
  }
}
@keyframes fade-in-down {
  from {
    transform: translateY(10px);
    opacity: 0;
  }
  to {
    transform: translateY(0);
    opacity: 1;
  }
}
```

**A.4.** Add an aria-live route announcer to
`apps/frontend/src/routes/Layout.svelte` (or somewhere always-mounted
in the chrome):

```svelte
<script lang="ts">
  import { page } from '$app/state';
  import { t } from '$lib/i18n';

  const announcement = $derived.by(() => {
    // Per-field reads (CONVENTIONS.md §9).
    const { params, route } = page;
    if (route?.id?.includes('/questions/[questionId]') && params.questionId) {
      return t('a11y.routeAnnounce.question', { id: params.questionId });
    }
    if (route?.id?.includes('/results')) return t('a11y.routeAnnounce.results');
    return t('a11y.routeAnnounce.default');
  });
</script>

<div aria-live="polite" aria-atomic="true" class="sr-only">{announcement}</div>
```

**A.5.** Add focus management in the same Layout.svelte:

```svelte
<script lang="ts">
  import { afterNavigate } from '$app/navigation';

  afterNavigate(() => {
    if (typeof document === 'undefined') return;
    requestAnimationFrame(() => {
      const target =
        document.querySelector<HTMLElement>('[data-focus-on-nav]') ??
        document.querySelector<HTMLElement>('main h1');
      target?.focus({ preventScroll: true });
    });
  });
</script>
```

Then on the question page's heading (`QuestionHeading.svelte`), add
`data-focus-on-nav` and `tabindex="-1"` to the `<h2>` (or `<h1>` if you
prefer to focus the page title).

**A.6.** Cross-browser QA: Chrome / Firefox 144+ / Safari 18+. Toggle OS
reduced-motion and re-verify. The acceptance bar: 3 navigations →
3 transitions of ~280–320ms each.

### Wave B (1 day): Adopt 014b shape for `/questions`

Optional but recommended cleanup. Converts the questions branch to the

**B.1.** Move all rendering from

**B.2.** The `[questionId]/+page.svelte` becomes an empty leaf:

```svelte

```

the test should still pass without modification because the
URL-driven behavior is identical.

## What to Avoid

Things that look right but aren't. Catalogued during spiking.

- **Do NOT add `{#key questionId}` or `{#key question.id}` around the
  question body.** Forces remount on EVERY Q→Q hop. Wipes local
  `$state`. Defeats Svelte's natural component reuse. Use
  `{#key question.type}` instead — keys only on the variant property.

- **Do NOT read `page.url` inside `onNavigate` for destination-based
  decisions.** `page.url` reflects the SOURCE URL until SvelteKit
  completes the swap. Read `navigation.to?.url` instead. (Spike 015
  iteration 3 — escape-hatch test caught this.)

- **Do NOT write `:global(@media ...)` in Svelte component CSS.** The
  Svelte CSS parser rejects this with "Expected a valid CSS identifier."
  Write `@media ... { :global(...) }` instead — `@media` wraps the
  selector, not the other way around. (Spike 015 iteration 2.)

- **Do NOT call `target.focus()` without `preventScroll: true`.** It
  triggers scroll-into-view that fights `goto({ noScroll: true })`
  patterns. Result: unpredictable scroll position. (Spike 016
  iteration 5.)

- **Do NOT rely on `<svelte:head><title>` updates for screen-reader
  route announcements.** NVDA and JAWS often don't announce SPA
  title changes. Use a dedicated `aria-live="polite"` region
  derived from `page.params.X`. (Spike 016.)

- **Do NOT spend effort on "preventing the chrome from re-rendering."**
  The chrome (`+layout.svelte` files) already persists across all
  nav — Spike 013 captured this. The user's symptom is downstream.

- **Do NOT assume `+page.svelte` remounts on param change.** It
  doesn't (Spike 014a iteration 2 — DOM `data-mount-id` proved
  identity stability). Any feature that relied on remount-driven
  cleanup (initial focus, mount-time analytics events, onMount-set
  scroll position) needs to be ported to an `afterNavigate` or
  `$effect(() => page.params.questionId)` hook.

- **Do NOT default the entire viewport into the transition without
  `view-transition-name` on the persistent chrome.** Without explicit
  names, the default `::view-transition-old(root)` /
  `::view-transition-new(root)` covers EVERYTHING — including the
  Header and drawer — which animates them too. Assign
  `view-transition-name: persistent-header` (etc.) to chrome
  elements to keep them planted. (Spike 015 surprise.)

- **Do NOT trust the mount-ledger's `record()` push under tight nav
  loops.** Spikes 013 and 014a captured this — concurrent component
  init pushes during a fast cascade can drop events. Use the DOM
  `data-mount-id` attribute as the primary identity check; treat the
  ledger as a secondary signal. (For production code that needs
  airtight observability, mutate via `events.length=N; events[N]=…`
  or `queueMicrotask` to avoid the race.)

## Constraints

Hard facts that bound the implementation.

- **Browser support for View Transitions API:** Chrome 111+, Edge 111+,
  Firefox 144+, Safari 18+. Detect via `'startViewTransition' in document`.
  Below these versions: instant swap with no animation (graceful fallback).
- **Animation duration:** ~280ms per transition for the recommended
  fade-up/down on title + cross-fade on body. Each transition's total
  wall-clock time in the spike was 300–320ms (includes browser
  snapshot capture overhead).
- **Focus latency:** `afterNavigate` + `requestAnimationFrame` fires
  ~23ms after click. Focus lands on the new element during the last
  ~250ms of the animation (out of ~272ms total). This is the
  "feels deliberate" window.
- **`+page.svelte` instance reuse:** Applies to URL changes that match
  the SAME route file. `/questions/q1 → /questions/q2` reuses. `/questions
→ /results` does NOT (different route files; layout chain
  changes — Spike 013 captured ResultsParentLayout mount on the
  crossing).
- **Production DOM survival rate:** 9/25 (~36%) tracked elements
  survive a Q→Q hop. This is what View Transitions wraps in animation
  — 64% of the visible content is genuinely new on each navigation.
- **`{#key}` block scope:** Only the contents INSIDE the `{#key}` block
  remount. Layout-owned `$state` outside the `{#key}` (answer
  accumulator, progress counter) survives the keyed remount. Plan
  state ownership accordingly.
- **`<svelte:head>` title updates synchronously with `page.params`
  changes — beats the visual animation by ~250ms.** Most users won't
  notice; screen readers that DO announce title changes (VoiceOver)
  get the new title before the animation completes. The
  aria-live announcer fires at the same moment for consistent
  cross-AT behavior.
- **CONVENTIONS.md §9 per-field reads on `page` are required** — the
  `$derived(page.params.X)` shape was established by Spike 012 and
  re-applies across all 013-016 spike code.
