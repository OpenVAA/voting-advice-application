# Lens: Localization · ID prefix `I18N`

**Applies when** the PR adds or changes user-facing copy, message catalogues under `apps/frontend/messages/`, localized content read from the database, date or number formatting, the locale list, or `apps/frontend/src/lib/i18n/`. Non-English catalogues are noise for every other lens but read here for key completeness.

## List

New and changed message keys as _key_ → _namespace_ → _locales it exists in_ → _where it is used_. Then each localized-content read the diff adds: _file:line_ → _how the locale is chosen_.

## Evaluate (criterion slugs)

- `i18n-no-literal`: every user-facing string goes through `t()` (the wrapper in `apps/frontend/src/lib/i18n/`) over the Paraglide messages — including `aria-label`s, titles, placeholders and error messages a user can see. Grep the diff's `.svelte` files for quoted English between tags and in those attributes.
- `i18n-catalogue-complete`: a new key exists in every supported locale's catalogue under `apps/frontend/messages/<locale>/`, or follows the documented fallback; keys sit in an existing namespace (`yarn assert:i18n-catalog-namespaces`). Compare key sets across the locale folders for the namespaces the diff touches.
- `i18n-no-concat`: no sentence assembled by concatenating messages or values. Interpolation and plurals use message parameters, so word order can differ by language.
- `i18n-content-locale`: localized database content is resolved with the locale helpers (`getLocalized` in `packages/app-shared/src/data/`, `apps/frontend/src/lib/utils/localizedText.ts`), never `[0]`, `.en` or the first key. The active locale comes from Paraglide's runtime, not a parameter threaded by hand.
- `i18n-format`: dates, numbers and percentages use `Intl` with the active locale.
- `i18n-overrides`: runtime translation overrides (`apps/frontend/src/lib/i18n/overrides.ts`) still apply to the new keys; a key read outside `t()` bypasses them.
- `i18n-supported-locales`: nothing hard-codes the locale list; it comes from `staticSettings.supportedLocales`.
- `i18n-default-locale`: nothing hard-codes a default or fallback locale such as `'en'`, in source, seed templates or tests. The default is the `isDefault` entry of `staticSettings.supportedLocales` (first entry otherwise): `defaultLocale` from `apps/frontend/src/lib/i18n/init.ts` in the frontend, the same lookup on `staticSettings` elsewhere.
